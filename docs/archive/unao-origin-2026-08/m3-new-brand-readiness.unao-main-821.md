> 새 브랜드로 전환할 수 있도록 미리 재료를 모아둔다.
> **갱신 방식**: append/update. 마일스톤이 끝날 때마다 해당 절을 갱신한다.

## 0. 현재 판정

**PARTIAL — 전환 가능하며, 이제는 "보험"을 넘어 독립 성장 엔진 검증 단계로 진입한다.**

코드 자산은 재사용 가치가 충분하다. 그러나 **운영·콘텐츠 구조를 그대로 가져가면
새 브랜드에서도 "퍼온 글 99.4% + 봇 댓글 93.5%" 구조가 반복된다.**
가능한 시나리오는 하나뿐이다 — **핵심 도메인만 재사용하고 운영/크롤러/SEO는 재설계**.

2026-08-21 기준 새 브랜드는 **소란소란**, 도메인은 **soransoran.com**으로 확정됐다.
SEO 제목 기준은 **"소란소란 - 40대 50대 여성을 위한 커뮤니티"**다.

> ⚠️ **SEO 제목과 서비스 본질은 다르다.**
> 서비스가 대상으로 삼는 사람은 여전히 **40대 중반~60대 중반 여성(핵심 50대)** 이다.
> SEO 제목만 `40대 50대`로 좁힌 것은 **초기 포지셔닝·검색 키워드 전략**이다 —
> 검색어는 넓힐수록 아무에게도 닿지 않고, 새 도메인은 좁은 주제로 시작해야 신뢰가 붙는다.
> **이 축소를 제품·콘텐츠·톤에 그대로 적용하지 않는다.** 60대 초반 이용자를 배제하지 않는다.
> 서비스 표현에서 "시니어·어르신·노인·실버"를 쓰지 않는 규칙도 그대로다.

이제 M3의 목적은 단순히 "우나어가 죽으면 갈아탈 예비 사이트"가 아니다.
우나어가 기술적으로 생존하더라도 네이버·구글 검색 성장 속도가 회복되지 않으면,
소란소란을 독립적으로 키워 어느 쪽이 더 빠르게 DAU와 커뮤니티 참여를 만드는지 비교한다.
우나어보다 소란소란의 성장 곡선이 명확히 빠르면, 우나어를 종결하고 소란소란에 운영 자원을 집중한다.

## 1. 현재 위기

### 사실 (실측)

| 항목 | 상태 | 근거 |
|---|---|---|
| 네이버 유입 | **붕괴** | 2026-08-12 11:00 KST 이후. 일 1,541 → 7~10 |
| 네이버 색인 | **0** | 08-11 4,600 → 08-13 0 (Search Advisor) |
| 네이버 노출 | **0** | 08-14 이후 0 (08-18 툴팁: 노출 0 · 클릭 0) |
| 네이버 수집 | **0** | 08-13 3,380 → 08-15 150 → 08-16~ 0 |
| 홈페이지 색인 | **미색인** | "문서가 성공적으로 수집됐습니다. 미색인 문서로 검색대상이 아닙니다" |

**기술적 차단은 아니다.** URL 검사 8개 항목이 전부 통과한다 —
`200 OK` · `robots.txt 수집 가능` · `로봇 메타 노출 가능` · `색인 허용 여부: 예`.
그런데 **`색인 완료: 아니오`**다. 우리가 막은 것이 아니라 네이버가 색인하지 않았다.

### 대응은 이미 했다 (merge 완료, 되돌리지 말 것)

- **PR #387** 커뮤니티 soft404 → 404 복원 (`loading.tsx` 제거)
- **PR #388** fallback description 고유화 (duplicate description 재생산 차단)
- **PR #389** magazine/jobs soft404 → 404 복원
- 프로덕션 실측: 네이버가 지적한 soft404 13건 **전부 404 반환 확인**

### 그러나 회복 여부는 미확정이다

```
08-16  네이버 마지막 수집 · 이후 0
08-17  진단 데이터 마지막 갱신
─────────────────────────────────────
08-18  PR #387/#388/#389 배포  ← 네이버가 아직 보지 못한 시점
```

**수집이 0인 구간에 우리 수정이 들어갔다.** 네이버는 고친 결과를 아직 크롤링하지 않았다.
수집 요청은 이미 3회 있었다(08-12 18:37 · 08-13 21:15 · 08-16 07:49). 그럼에도 색인 0이다.

### Google은 보완재가 되지 못한다

```
28일 클릭 85 · 노출 577 · 일평균 클릭 3.3
그중 38클릭(45%)이 "우리 나이가 어때서" 브랜드 검색
색인 6,220 / 미색인 15,796 — 색인률 28%
색인된 6,220개 중 28일간 노출된 URL은 398개(6.4%)
```

**신규 발견 유입은 28일간 47건, 하루 1.7건이다.** Google이 우리를 막은 것이 아니라,
상위에 올릴 이유를 찾지 못하고 있다.

이 수치는 단순한 부진이 아니라 **Google SEO 성장 엔진 실패**로 본다.
색인이 일부 되어도 클릭·노출이 폭발하지 않으면 DAU 1만·10만 서비스로 갈 수 없다.
소란소란은 이 실패를 구조적으로 반복하지 않기 위해 SEO-first로 설계한다.
초기 목표는 페이지 수가 아니라, 네이버·구글이 한눈에 이해하는 대표 브랜드·대표 주제·대표 URL을 만드는 것이다.

### 결론

서비스 종료까지 고려해야 하는 **생존 위기**다. 회복 여부를 우리가 통제할 수 없는 구간에 있다.

## 2. North Star (불변)

> **40대 중반~60대 중반 여성, 특히 50대 여성이 반복 방문하는 커뮤니티.**
> 사용자가 **"나만 그런 게 아니구나"**를 느끼고 댓글과 글을 남기는 공간.

- **일자리 플랫폼이 아니라 커뮤니티다.** 일자리·돈·노후·일은 커뮤니티 안의 생활 축이다.
- **핵심 주제**: 갱년기, 남편, 자녀, 가족 갈등, 부모 간병, 건강, 노후, 돈, 일, 외로움, 불안, 생활 고민
- **외부글은 트래픽용 복붙이 아니라 대화를 여는 seed다.**
- 금지 표현: 시니어·어르신·노인·실버 → "우리 나이", "우리 또래", "40대 50대 여성", "인생 2막"

## 3. 새 브랜드를 준비하는 이유

1. **회복 실패 대비.** 네이버 색인·수집이 우리 통제 밖이다. 회복되지 않을 가능성에 보험이 필요하다.
2. **단순 복제가 아니다.** 같은 North Star를 가진 **더 작고 밀도 높은 제품**으로 재시작한다.
3. **자산은 가져가고 부채는 두고 간다.** 코드 자산(커뮤니티 구조·댓글·인증·선별 큐)은 활용하되,
   레거시 운영·비용 비효율·저품질 신호는 가져가지 않는다.

### 도피가 아닌 이유

이 준비는 **"옮기자"가 아니라 "옮길 수 있는가, 옮긴다면 무엇을 버려야 하는가"**를 묻는다.
**네이버가 회복되면 이 문서는 현재 서비스 개선 로드맵으로 그대로 쓰인다.**
봇 비율 93.5%, 회원 글 0.6%, 발행 134건은 새 브랜드로 가든 안 가든 똑같이 고쳐야 할 문제다.
어느 쪽이든 버려지지 않는 작업이다.

### 2026-08-21 전략 갱신 — 병렬 운영과 전환 판정

우나어와 소란소란은 일정 기간 병렬 운영될 수 있다. 목적은 두 서비스를 모두 오래 끌고 가는 것이 아니라,
**검색 성장 엔진이 어느 쪽에서 더 빨리 회복되는지 검증**하는 것이다.

우나어가 네이버에서 일부 회복되고 Google에서도 어느 정도 노출되더라도,
예전처럼 폭발적인 노출·클릭·신규 유입으로 돌아오지 않으면 운영을 계속하는 것이 손해일 수 있다.
이 경우 우나어는 "기술적으로 생존했지만 성장 엔진이 약해진 서비스"로 판정한다.

소란소란은 우나어와 독립적으로 운영한다. 새 도메인·새 브랜드·새 검색 신뢰를 쌓고,
우나어의 저품질 신호·중복 URL·과도한 자동 발행·운영 복잡도를 가져가지 않는다.

> **분리 범위 정본 (2026-08-22 갱신)** — "완전 분리"가 아니라 **선택적 분리**다.
>
> ```
> 🔴 분리한다   repo · DB · 계정 · 도메인 · 인프라 · 콘텐츠
>               로고 · OG · favicon · manifest · public asset · 3원 심볼
>               verification · AdSense · Play 앱 ID · localStorage 키
>
> ✅ 재사용한다  메인 브랜드 컬러 #FF6F61  (창업자 결정 · 임시 채택 · 교체 가능 구조)
>               디자인 시스템 뼈대 (Pretendard · 타이포 스케일 · 터치 타겟 · shadcn 구조)
> ```
>
> ⚠️ **컬러 재사용은 "복제 사이트" 리스크가 아니다.** 검색엔진이 판정하는 것은
> 도메인·URL·콘텐츠·구조이지 CSS 색상값이 아니다. 시각적 복제 리스크는
> **로고·구도·OG 형태**에서 발생하며, 그쪽은 그대로 금지된다.
소란소란이 우나어보다 빠르게 색인·노출·클릭·DAU·참여를 만들면,
우나어를 종결하고 소란소란에 콘텐츠·봇·운영 자원을 집중한다.

#### 병렬 운영 판정 시점

판정은 **소란소란 오픈일(D-day) 기준**으로만 한다. 아무 때나 비교하지 않는다.

| 시점 | 무엇을 본다 | 무엇을 판정하지 않는다 |
|---|---|---|
| **D+7** | 색인·수집·기술 정상성 — sitemap 제출, robots 정상, 색인 시작 여부, 크롤 오류 0 | 🚫 **성장률·성패를 판정하지 않는다** |
| **D+30** | 초기 검색 성장률 비교 — 색인 수 증가 곡선, 노출·클릭 추이, 첫 유입 전환 | 종결 결정은 아직 하지 않는다 |
| **D+90** | 우나어 유지 / 소란소란 집중 / 우나어 종결 중 하나를 결정 | — |

> 🔴 **D+7에 성급한 실패 판정 금지.**
> 새 도메인은 검색엔진 신뢰를 쌓는 데 최소 수 주가 걸린다. 색인이 붙기 전에 비교하면
> 4년 된 우나어가 무조건 이긴다. **그 비교는 아무것도 말해주지 않는다.**
> D+7은 "기술이 정상인가"만 보는 시점이다.

#### 병렬 운영 판정 기준

| 판정 | 기준 | 운영 판단 |
|---|---|---|
| 우나어 유지 | 네이버 유입 50/day 이상 회복, Google 클릭 지속 우상향, 실회원 글/댓글 반응 증가 | 우나어 개선 backlog를 계속 진행 |
| 병렬 지속 | 우나어는 일부 회복했지만 성장률이 낮고, 소란소란은 색인/노출 초기 신호가 붙는 중 | 둘 다 최소 운영하되 신규 투자는 소란소란 우선 |
| 소란소란 집중 | 소란소란이 같은 기간 네이버·Google 노출 증가 속도와 신규 유입에서 우나어를 추월 | 우나어 종결 계획 수립, 소란소란에 자원 집중 |
| 우나어 종결 | 우나어 검색 성장률이 정체되고 운영 비용 대비 신규 유입/참여가 낮음 | 신규 발행·봇·운영 리소스 중단 또는 축소 |

#### 검색 성장 목표

DAU 1만·10만 서비스가 되려면 네이버 Search Advisor와 Google Search Console에서
색인·노출·클릭이 폭발적으로 성장해야 한다. 커뮤니티는 광고비만으로 키우기 어렵다.
검색 유입이 계속 들어오고, 그 유입이 글·댓글·재방문으로 전환되어야 커뮤니티가 살아난다.

따라서 소란소란의 SEO는 부가 기능이 아니라 **핵심 성장 엔진**이다.
첫 개발부터 아래 원칙을 지킨다.

- 홈은 브랜드 대표 URL로 강하게 만든다.
- 시작 주제는 40대 50대 여성, 갱년기, 몸과 마음, 사는 이야기로 좁힌다.
- 게시판 URL은 적게, 깊게 만든다.
- 매거진은 검색 유입용 신뢰 콘텐츠로 운영하되 대량 AI 글 창고로 만들지 않는다.
- 자동 생성 페이지 대량 확장은 금지한다.
- sitemap, robots, canonical, noindex 정책은 단순하게 유지한다.
- 네이버·구글에 보여줄 페이지와 숨길 페이지를 처음부터 분리한다.

#### 병렬 운영 금지사항

```
🚫 우나어 → 소란소란 전체 리다이렉트
🚫 동일 콘텐츠 복붙
🚫 같은 DB/계정/SEO 설정 뒤섞기
🚫 검색엔진이 복제 사이트로 볼 수 있는 구조
🚫 우나어의 저품질 URL/자동 발행/과도한 봇 비율을 그대로 이전
```

소란소란은 우나어의 후속 브랜드가 아니라, **같은 North Star를 가진 독립 성장 실험**으로 시작한다.

### 해석 (중요 — 오해 방지)

| 면 | 성격 | 오해하면 안 되는 것 |

### 왜 이 구조인가 (근거)

- **매거진의 효율이 검증됐다.** GSC 실측에서 매거진 262건이 노출 82·클릭 5를 만들었다.
  글당 효율이 커뮤니티의 3배다. `guide` 4건은 노출 42로 **글당 노출 10.5 — 전 유형 1위**다.
  → **적은 수의 긴 원본 글이 많은 수의 짧은 글을 이긴다.**
- **갱년기 검색어에 이미 노출되고 있다.** "갱년기 극복법"(53위) · "갱년기 끝나는 나이"(30위) ·
  "갱년기 소변 냄새"(34위). 0에서 시작하는 게 아니다. MENOPAUSE 보드는 140건뿐이라 경쟁 글도 적다.
- **route 수를 줄인다.** 현재 공개 route 33개 → 10개 이내를 목표로 한다.

## 6. 외부글 운영 현실과 원칙

### 현실 (이상론 금지)

**회원 글이 일 0.7건이다.** 외부글을 끊으면 하루 1건 미만이 올라온다. 그건 진짜로 죽은 사이트다.
**"외부글을 없애자"는 현실에 맞지 않는다.**

### 진짜 문제

> 문제는 **"외부글이 있다"**가 아니라 **"외부글이 99.4%다"**이다.

외부글은 **대화의 씨앗**이어야지 **사이트의 정체성**이 되면 안 된다. 지금은 정체성이 됐다.

### 실패 조건 (하나라도 해당하면 실패)

- 죽은 사이트처럼 보인다
- AI가 대충 만든 사이트처럼 보인다
- 퍼온 글 모음처럼 보인다
- 출처/자동 발행/스크래핑 냄새가 고객 화면에 남는다
- 연예·자극 유입에 정체성이 끌려간다

### 필요 조건 (4종 세트)

```
① gate         자동 선별 — 위험 글 차단 + 타겟 적합도 판정
② 사람 승인     창업자가 직접 보고 고른다. 자동 승격 경로 없음
③ 제한 발행     하루 상한을 먼저 정하고 시작한다
④ 댓글 유도     대화가 붙을 글만 고른다 (댓글수를 신호로 사용)
```

### 이미 확보한 자산

이번 주에 만든 **cook82 후보 큐**가 정확히 이 구조다.

```
agents/cook82/
  collector.ts       수집 (write 없음)
  gate.ts            v3.2.2 선별 — AI 호출 0원, 위험 4종 차단
  queue.ts           판정 (write 없음)
  review.ts          ★ 사람 승인 — APPROVED로 가는 코드 경로 없음
  publish-bridge.ts  전달 — 유일한 write 지점, 4중 안전장치
```

**실전 검증 완료**: 첫 82cook 글이 Sheet → PUBLISHED까지 성공했고, QA에서
고객 화면 출처 노출 0건 · 제목 rewrite 정상 · SEO 메타 정상을 확인했다.

**빠진 것은 하나 — 발행량이다.** 골라내는 장치는 만들었는데 일 134건 자동 발행은 그대로다.

### 원천별 선별 기준

| 원천 | 대상 | 비고 |
|---|---|---|
| **82cook 자유게시판(bn=15)** | 자유게시판·갱년기 소재 | gate v3.2.2 적용. 실측 PASS 58% |
| **드라마·연예 회상형** | 작품·방송(E4) 유형 | "청춘의 덫 다시보니" 류. **범죄·의혹(E5)·정치연계(E6)는 차단 유지** |
| 그 외 | 미정 | 새 브랜드에서 재검토 |

### 새 브랜드 외부글 운영 원칙 (제안)

```
1. 하루 발행 상한을 먼저 정하고 시작한다 (제안: 10~20건)
2. 모든 외부글은 gate + 사람 승인을 거친다
3. 외부글 : 회원글 비율을 지표로 관리한다 (현재는 측정조차 안 함)
4. 봇 댓글은 "마중물"이지 지표가 아니다 — 실회원 댓글만 KPI로 센다
5. 본문 300자 미만은 발행하지 않는다
6. 고객 화면에 출처·자동발행 흔적을 남기지 않는다 (내부 추적은 유지)
```

## 7. Keep / Drop / Rewrite 기준

### KEEP — 거의 그대로 가져간다

| 항목 | 경로 | 근거 |
|---|---|---|
| 커뮤니티 글/댓글 기본 구조 | `src/app/(main)/community/**`, `Comment` 모델 | 보드-목록-상세-작성 표준 구조. 문제는 구조가 아니라 콘텐츠 |
| Kakao 로그인 | `src/lib/auth.config.ts`, `User.providerId` | 타겟층에 사실상 필수. 실회원 424명이 이 경로로 가입 |

| 제목/description 개선 | `agents/community/title-seo.ts` | 실측 검증됨 — 원문 왜곡 없이 맥락 보강. **Sonnet 고정, Haiku 금지** |

### DROP — 가져가면 위험하거나 불필요

```
무분별한 crawler       네이버카페 crawler + launchd 10개 — 쿠키 수동 갱신·차단 위험
popular crawler        20회 실행 · 발행 0건 · 원인 미규명
과도한 탭              jobs 독립 route · 웃음방 · 화제성 파생 탭
대량 봇 댓글           83계정이 댓글 93.5% 생산
GHA 26개 / cron 116개  최소 3~5개로 재시작
launchd 12개           로컬 맥 의존 = 단일 장애점
```

### REWRITE — 개념은 가져가되 다시 설계

```
게시판 구조            4보드 + 파생탭 → 자유게시판 + 갱년기 2판
SEO 매거진             262건 자산 유지, 시리즈·큐레이션 구조는 단순화
외부글 선별/발행 플로우   cook82 방식으로 통일 + 발행 상한 도입
운영 cron 구조          39개 핸들러(CEO~CDO 가상 조직) → 최소 구성
비용 구조              ISR Writes $56.10 · revalidatePath 167곳 → 설계 시점에 캐시 전략 확정
봇 마중물              개념 유지, 비율 상한 필수 (제안: 30% 이하)
noindex 정책(E0)       HUMOR 전면 googlebot noindex는 저품질 회피 목적.
                      새 브랜드가 애초에 저품질을 안 만들면 불필요 — 재검토
```

## 9. 운영 원칙

1. **현재 서비스 회복 관찰은 계속 우선이다.** 다만 M3의 성격이 바뀌었다.
   ~~M3는 본작업이 아니라 **생존 보험**이다.~~
   → **2026-08-21 갱신**: M3는 대기용 보험이 아니라 **독립 성장 엔진 검증**이다(§0·§3).
   회복 관찰과 소란소란 준비는 순차가 아니라 **병렬**로 간다.
2. **관찰과 준비를 병렬로 돌린다.** ~~대기 시간에만 진행한다.~~
   네이버 관찰은 우리가 통제할 수 없는 대기다. 그 대기가 끝나기를 기다리는 대신,
   같은 기간에 소란소란의 판단 자료와 설계를 쌓는다.
   단, **현재 서비스를 흔드는 변경은 하지 않는다**(4번).
3. **창업자 승인 없는 새 브랜드 실행 금지** — 회복 여부와 무관하게 항상 적용된다.
   금지 대상: repo 생성 · DB 생성 · 배포 · DNS 연결 · **추가** 외부 계정 생성.
   ⚠️ 브랜드명 `소란소란` · 도메인 `soransoran.com` · Gmail `soransoran.community@gmail.com`은
   2026-08-21에 **창업자가 이미 직접 확정·생성했다**(§11). 이 셋은 금지 대상이 아니다.
   그러나 이 예외가 **개발·배포·추가 계정 생성 승인을 의미하지는 않는다.**
4. **현재 서비스에 추가 SEO 변경 금지.** 수집이 0이라 무엇을 바꿔도 네이버가 보지 못하고,
   변경만 쌓이면 나중에 원인 규명이 불가능해진다.
5. **이 문서는 append/update로 계속 갱신한다.** 마일스톤 완료 시 해당 절을 갱신한다.

### 회복 판정 기준 (창업자 확정 필요)

**제안: 2026-08-22까지 네이버 "수집"이 0보다 커지는가.**

색인이나 유입이 아니라 **수집**을 보는 이유는, 지금 네이버가 사이트를 아예 크롤링하지 않기
때문이다(08-16 이후 0). **수집이 재개되지 않으면 우리가 무엇을 고쳐도 네이버는 볼 수 없다.**

```
수집 > 0   →  회복 시작. 기다려볼 가치 있음
수집 = 0   →  우리가 통제할 수 없는 상황. 전환 검토
```

확인 위치: Search Advisor → 요약 → 수집 현황 차트

## 13. 소란소란 D-day 운영 기준 (1차 통합, 2026-08-21)

> **출처**: 우나어 AS-IS 감사 7축(1 SEO · 2 콘텐츠 · 4 봇 · 5 crawler/queue · 6 workflow · 8 관측성 · 10 신뢰)의 통합본.
> **성격**: 구현 명세가 아니라 **운영 판단 기준**이다. "지금 이게 정상인가 장애인가"를 문서로 답하기 위한 표다.

### 13-0. 현재 판정

**🟡 PARTIAL — D-day 기준서와 blocker 해소 후 런칭 가능**

지금 바로 런칭할 수는 없다. 다만 막고 있는 것은 기술이 아니라 **판단 기준의 부재**다.
무엇을 만들지는 감사로 정해졌고, **무엇이 정상이고 무엇이 장애인지가 아직 코드와 문서에 없다.**

### 13-1. 왜 이 기준서가 필요한가

**우나어 실패는 기능이 부족해서가 아니었다.** 기능은 오히려 많았다.
문제는 **기준 없이 자동화와 콘텐츠를 운영한 것**이다.

```
우나어 실측 (2026-08-21)
  글 10,833건 중 사람이 쓴 것 67건 (0.62%)
  최근 7일에도 99.88%가 기계 생성
  색인 후보의 51.3%에 googleBot noindex — "와서 보라"와 "보지 마라"를 같은 URL에
  봇 글 전역 상한이 없어 하루 약 116건이 쌓였다
```

발행 상한을 정하지 않았으니 **멈출 지점도 없었다.**

두 번째 목적은 더 실용적이다. 우나어에서는 아래 14가지 상황 중 **3가지만 정상/장애를 구분할 수 있다(21%)**.

```
창업자: "왜 글이 안 올라와?"
지금:   코드를 읽어야 답할 수 있다
D-day:  §13-4 판정표를 보면 바로 답한다
```

특히 **D+0~D+7은 커뮤니티 글이 0건인 것이 정상**이다. 기준이 없으면 창업자가 매일 불안해진다.

### 13-2. 기간별 운영 원칙

#### D+0 ~ D+7 — 정체성 각인

| 구분 | 내용 |
|---|---|
| **켜는 것** | 매거진 발행 1경로 (사람 검수 후 승인 발행) · **실제 회원 글쓰기·댓글** · GitHub Actions 1개 |
| **끄는 것** | ~~커뮤니티 글·댓글 자동화 전부~~ → **봇 커뮤니티 글·댓글 자동화** · 봇 대댓글 · 봇 연결촉진 · 크롤러 · 시트 |
| **정상** | **봇** 글·댓글 0건 · 봇 로그 0건 · 색인 미형성 |
| **관찰** | **실제 회원** 글·댓글 0건 — 참여 미발생 상태다. 장애가 아니며 봇으로 채우지 않는다 |
| **장애** | 매거진 24h 0건(WARN) · 48h 0건(FATAL) · DB write 실패 |
| **안심해도 됨** | 커뮤니티가 조용한 것. 색인이 아직 안 붙는 것 |
| **즉시 조치** | 매거진 48h 0건 · DB write 실패 알림 · 배포 실패 |

> 🔴 **정정 (2026-08-21)**: 이전 표는 "커뮤니티 글·댓글 자동화 전부 OFF"로 적혀 있어
> **실제 회원 참여까지 막는 것으로 읽혔다.** 정본은 다음과 같다.
>
> **실제 유저 참여는 열고, 봇이 활발한 척하는 것은 막는다.**
>
> D-day부터 **실제 회원 글쓰기·댓글은 ON**이다. OFF 대상은 **봇 커뮤니티 자동화**다.
> 게스트 글쓰기·댓글은 OFF를 권장한다.

발행량은 **일 1~2편 후보**로 두되, 확정 수치가 아니라 **품질·검색 의도·사람 검수를 우선**한다.
좋은 글이 없으면 내지 않는 것이 정상이다.

> 🔴 **D+7에 성패를 판정하지 않는다.** 새 도메인은 검색 신뢰를 쌓는 데 수 주가 걸린다(§3 판정 시점 표).

#### D+30 ~ D+90 — 조건부 확대

확대는 아래를 **전부 충족**할 때만 한다.

```
[ ] 색인율이 제출 대비 충분히 올라왔다
[ ] 실회원 가입이 발생했다
[ ] 실회원 글 또는 댓글이 1건 이상 있다
[ ] noindex 대상이 0건이다
[ ] 봇 글·댓글 절대 cap이 코드 상수로 있다
[ ] heartbeat가 가동 중이다
```

**정상**: 조건이 안 되면 확대하지 않고 그대로 두는 것.
**장애**: 조건 미충족인데 자동화를 늘리는 것.

> 🔴 **사람이 안 오면 봇을 늘리지 않는다. 유입·참여 원인을 다시 본다.**
> 우나어는 반대로 했다. 봇 댓글을 대량 운영한 기간에 실회원 반응은 매우 낮았고,
> **봇 증량이 참여 증가로 이어졌다는 증거는 확인되지 않았다.**

#### 절대 cap 원칙 (비율보다 우선)

초기에는 **비율보다 절대 수치가 중요하다.** 사람 글이 0이면 어떤 비율도 의미가 없다.

```
BOT_POST_DAILY_TOTAL      하루 봇 글 총량        미정 — D+8 전 확정 필요

BOT_COMMENT_PER_POST      글당 봇 댓글 최대      미정 — D+8 전 확정 필요
MIN_PUBLISH_LENGTH        발행 최소 분량         미정 — D+0 전 확정 필요

불변 규칙  실회원 글이 0이면 user-post-wave도 0이다 (구조적으로 그렇게 만든다)
           cap은 코드 상수로 잠근다. 설정값이 아니라 상수여야 한다
```

> 참고: 우나어는 파이프라인별 cap은 있었으나 **서비스 전체 봇 글 총량 상한이 없었다.**
> 회차가 늘면 총량도 함께 늘어나는 구조였다.

D-day 필수는 **화면이 아니라 SSoT(단일 진실의 원천)** 다.

```
최소 요건  문서 · 설정파일 · 리포트 중 하나로
           창업자와 마스터가 "지금 무엇이 켜져 있는지"를 확인할 수 있으면 된다

어드민 화면  D+7 또는 D+30 구현 후보. D-day 필수 아님
            SSoT를 보여주는 UI 구현체이지 SSoT 자체가 아니다
```

> 참고: 우나어에는 부분 heartbeat 2개가 있다 —
> `crawler-health`(24h 무실행 감지) · `qa-verifier`(기대 실행 목록 대조).
> **패턴은 가져가되 커버리지를 write 전 경로로 넓혀야 한다.**

### 13-7. 런칭 blocker (4 + 조건부 1)

```
① 매거진 발행 heartbeat
   D+0~D+7 유일한 발행 경로. 멈추면 D+7까지 빈 사이트가 된다

② BotLog details JSON + postId
   우나어는 정규식 파서 여러 곳에 묶여 지금도 형식을 못 바꾼다
   나중에 바꾸려 하면 같은 덫에 걸린다

③ 자동화 ON/OFF 상태 SSoT
   "정상 OFF"와 "장애"를 구분하지 못하면 D+0~D+7 내내 판단이 불가능하다
   문서·설정·리포트 중 하나면 된다. 화면은 D+7 이후 후보

④ DB write 실패 fallback
   safeBotLog 패턴 이식. 침묵 실패 방지의 최소선

⑤ block/filter — 🟡 조건부 blocker
   D+0~D+7에 회원가입·댓글·커뮤니티 쓰기를 열지 않는다면 D-day blocker가 아니다
   → 그 경우 D+7 또는 D+30 blocker
   🔴 단, 커뮤니티 쓰기 기능을 여는 시점 이전에는 반드시 해결해야 한다
      우나어는 차단을 저장만 하고 어떤 쿼리도 필터로 쓰지 않는다
```
