### 🟢 메인 브랜드 컬러 — `#FF6F61` 유지 (창업자 결정 2026-08-22)

> 🔴 **이전 서술 정정.** 이 문서의 최초본은 `#FF6F61` **전량 금지**였다.
> 창업자 결정으로 **메인 브랜드 컬러는 `#FF6F61`을 그대로 유지한다.**

```
근거   완벽한 새 컬러를 고르는 것보다, 초기 고객에게 익숙하고 따뜻한 인상을 주면서
       빠르게 실행하는 것이 지금 더 중요하다.

전제   #FF6F61 하나로 모든 UI를 처리하지 않는다.
       나머지 색은 소란소란 커뮤니티에 맞게 새로 설계한다. (§3-1 · §3-2)
```

🔴 **`#FF6F61`은 흰 글씨 CTA와 본문 텍스트에 쓸 수 없다.** 실측:

```
#FFFFFF on #FF6F61   2.73 : 1   요건 4.5 — FAIL
#FF6F61 on 웜 배경    2.60 : 1   요건 4.5 — FAIL
면 구분(비텍스트)      2.60 : 1   요건 3.0 — 통과 범위 밖이나 장식 면으로는 성립
```

따라서 **brand signature와 CTA를 토큰으로 분리한다.** 상세 §3-1.
그리고 이 결정은 **임시 채택**이다 — 나중에 토큰 값만 바꾸면 교체되도록 설계한다 (§3-4).

### 🟡 우나어 디자인 시스템 — 일부 승계

우나어의 디자인 토큰·타이포·터치타겟·아이콘 체계는 성숙도가 높다.
WCAG AA 대비를 주석에 명시하는 규율까지 자리잡혀 있다. **버리는 것이 손해다.**

### 🔴 우나어 브랜드 **자산** — 전량 폐기 (컬러는 예외)

로고 4종·OG 2종·favicon 5종·아이콘 11종·브랜드 문자열 369건.
**하나도 가져가지 않는다.** §6 참조.

```
✅ 가져가는 것   컬러값 #FF6F61 (창업자 결정 · 임시 채택 · 교체 가능 구조)
🔴 가져가지 않는 것   로고 · OG · favicon · manifest · 3원 심볼 · public asset 전량
                     도메인 · verification · Play 앱 ID · localStorage 키
```

⚠️ **"컬러를 재사용한다"와 "자산을 재사용한다"는 다르다.** 자산 재사용 금지는 그대로 유지된다.

## 3. 확정된 브랜드 방향 — 「조용한 신뢰」

| 항목 | 정본 |
|---|---|
| **방향명** | 조용한 신뢰 |
| **핵심 감정** | 털어놔도 안전하다 · 소란스럽지 않다 · 광고 같지 않다 |
| **메인 브랜드 컬러** | **`#FF6F61`** — brand signature (창업자 결정 · 임시 채택 · 교체 가능) |
| **CTA 컬러** | **`#B64235`** — `#FF6F61`의 접근성 파생색. brand와 분리한다 (§3-1) |
| **컬러 계열** | 웜 아이보리 · 로즈 베이지 · 웜 그레이 + 딥 코코아/러스트 |
| **베이스 톤** | 웜 아이보리 — 순백보다 눈이 편하고 신뢰감이 높다 |
| **피해야 할 색** | 핑크 · 보라 · 병원 민트/시안 · 형광 · 골드/황토(건강식품 톤) |
| **로고 방향** | 텍스트 워드마크 우선. 심볼 없이 출발 (§9) |
| **OG 방향** | 인물 사진 없이 타이포 중심 + 넓은 여백 (§7 P0) |
| **타이포 인상** | 굵은 워드마크 + 충분한 여백. 장식보다 크기와 간격으로 존재감 확보 |

### 왜 A안인가 (재논의 방지용 기록)

```
North Star = 주간 재방문 참여 유저 수 → 읽기가 아니라 "쓰게 만드는 것"이 목적
정본       = "병원 정보 사이트가 아니라 커뮤니티다"

대안이었던 B안 「부드러운 전문성」(딥그린·정보성)은 매거진 SEO에는 유리하나
"정보 사이트"로 굳으면 참여가 일어나지 않는다. 정본이 명시적으로 경계한 지점이다.

A안은 정본 정합성이 높고, 인물 사진을 쓰지 않는 선택만으로도
우나어와 시각적으로 즉시 구분된다.
```

### 이름과 톤의 관계

"소란소란"은 의성어 반복이라 **밝고 가볍게** 읽힌다.
컬러와 여백을 차분하게 잡아야 이름의 가벼움과 균형이 맞는다.
이름이 이미 밝으므로 **색까지 밝으면 과잉이 된다.** 이것이 A안을 택한 실무적 이유이기도 하다.

## 3-1. 색상 정본 — brand와 CTA의 분리

> 🔴 **이 절이 소란소란 색상 설계의 핵심이다.**
> `#FF6F61`을 메인으로 유지하면서도 50대 사용자가 매일 편하게 읽고 누를 수 있게 만드는 방법이다.

### 왜 분리하는가

```
#FF6F61 은 아름답지만 밝다 (HSL h5 · s100% · l69%).
밝은 색 위에 흰 글씨를 올리면 대비가 확보되지 않는다.

  #FFFFFF on #FF6F61   2.73 : 1     요건 4.5 — 못 쓴다
  #FF6F61 텍스트       2.60 : 1     요건 4.5 — 못 쓴다

우나어는 이 문제를 --primary-text(3.4:1) → --primary-strong 순으로
뒤늦게 덧붙여 해결했다. 소란소란은 처음부터 나눈다.
```

### 분리 원칙

| 토큰 | 역할 | 쓰는 곳 | 쓰지 않는 곳 |
|---|---|---|---|
| **brand** `#FF6F61` | 브랜드 시그니처 | 워드마크 · 장식 면 · 포인트 · OG 그래픽 · 활성 표시의 **면** | 🔴 흰 글씨 CTA fill · 본문 텍스트 · 작은 글씨 |
| **cta** `#B64235` | 누르는 것 | CTA 버튼 · FAB · primary button · empty state 버튼 | 넓은 배경 면 |
| **brand-ink** `#9A3A31` | 읽는 브랜드색 | 링크 · 활성 탭 텍스트 · 배지 텍스트 · 강조 텍스트 | 큰 면 fill |

```
같은 색 계열(h5~11)이라 화면에서 하나의 브랜드로 읽힌다.
동시에 각자 자기 자리에서 접근성 요건을 충족한다.
```

⚠️ **`#FF6F61`을 흰 글씨 CTA 버튼 배경으로 쓰지 않는다.** 이 문서 어디에서도 그렇게 읽혀선 안 된다.

### 🔴 `#FF6F61` 사용 금지 목록 (텍스트)

```
🚫 일반 텍스트 · 본문
🚫 작은 라벨 · 캡션 · 메타 정보
🚫 CTA 텍스트
🚫 본문 강조 텍스트
🚫 링크 · 활성 탭 텍스트 · 배지 텍스트
🚫 정보 전달 아이콘 (경고·상태·기능 표시)
```

**대체 토큰**: 위 자리에는 전부 `--brand-ink`(`#9A3A31`)를 쓴다. 배경 위 **6.62:1**이다.

### 비텍스트 사용 — 두 가지를 구분한다

| 구분 | 요건 | `#FF6F61` 사용 | 예 |
|---|---|---|---|
| **장식 면** | 없음 | 🟢 **허용** | 배경 블록 · 밑줄 장식 · 구분 띠 · OG 그래픽 면 |
| **정보 전달 그래픽** | **3:1 이상** | 🔴 **불가** (2.60) | 상태 아이콘 · 활성 표시 · 입력 테두리 · 차트 범례 |

```
같은 색이라도 "예쁘라고 있는 면"과 "뜻을 전달하는 그래픽"은 요건이 다르다.

  장식 면        그것이 안 보여도 사용자가 정보를 놓치지 않는다  → 대비 요건 없음
  정보 전달      그것이 안 보이면 사용자가 뜻을 놓친다           → 3:1 필수 (WCAG 1.4.11)

#FF6F61 은 배경 위 2.60 이라 3:1 에도 못 미친다.
정보를 전달해야 하는 그래픽에는 --brand-ink 또는 --cta 를 쓴다.
```

### 🔴 워드마크 사용 조건 — 유일한 텍스트 예외

> `#FF6F61` 워드마크는 **로고 예외로만** 성립한다. 일반 텍스트 규칙의 예외이지, 규칙의 해제가 아니다.

```
WCAG 1.4.3 로고 예외
  "로고 또는 브랜드명의 일부인 텍스트는 대비 요건이 없다"

실측
  #FF6F61 on #FFF8F6   2.60 : 1
  → 일반 텍스트 요건(4.5) 미달, 큰 텍스트 요건(3.0)에도 미달

🔴 '면제된다'는 것과 '읽힌다'는 것은 다르다.
   법적으로 허용되어도 50대 사용자가 못 읽으면 브랜드가 전달되지 않는다.
```

**D-day 텍스트 워드마크에 `#FF6F61`을 쓰려면 아래를 모두 만족해야 한다.**

| # | 조건 | 이유 |
|---|---|---|
| 1 | **Pretendard Variable 800 또는 900** | 획이 굵어야 낮은 대비를 버틴다. 400·600은 불가 |
| 2 | **충분한 크기** | 모바일 헤더에서도 획이 뭉개지지 않는 크기. 작게 넣으면 조건 위반 |
| 3 | **충분한 여백** | 주변 요소와 붙으면 낮은 대비가 더 불리해진다 |
| 4 | **실제 화면 판독성 확인** | 🔴 코드가 아니라 **실기기 모바일 헤더**에서 확인한다 (§9) |

### 판독성 미달 시 전환 규칙

```
모바일 헤더에서 읽히지 않으면 — 즉시 아래 중 하나로 전환한다.

  1순위   --brand-ink (#9A3A31) 워드마크      배경 위 6.62 : 1
          색 계열은 그대로 유지되므로 브랜드 인상이 깨지지 않는다

  2순위   이미지 로고                          자체 대비를 내장해 설계
          Logo.tsx 만 교체하면 되므로 전환 비용이 낮다 (§9)

🔴 "브랜드 컬러니까"를 이유로 안 읽히는 워드마크를 유지하지 않는다.
   워드마크의 목적은 브랜드 색을 보여주는 것이 아니라 브랜드명을 읽히게 하는 것이다.
```

## 3-4. 유지보수 원칙 — 나중에 한 번에 바꿀 수 있어야 한다

> 🔴 **이번 결정의 전제는 "임시 채택"이다.**
> 디자이너가 합류하거나 브랜드가 성장하면 색 전체를 교체한다.
> 그때 **토큰 값만 바꾸면 전체 UI가 교체되어야 한다.**

### 원칙

| # | 원칙 | 우나어 반례 |
|---|---|---|
| 1 | **hex literal은 토큰 정의 파일에만 존재한다** | 우나어는 토큰이 있는데도 코랄 리터럴이 **39개 파일**에 흩어져 있다 |
| 2 | **컴포넌트는 semantic token만 쓴다** | `bg-[#FF6F61]` 같은 임의값 클래스 금지 |
| 3 | **brand 교체 시 수정 지점은 토큰 파일 1곳** | 우나어는 컬러 변경이 39파일 추적이 된다 |
| 4 | **어드민도 예외가 아니다** | 우나어 어드민은 하드코딩 구역이 되어 48건이 쌓였다 |
| 5 | **색상 리터럴 린트 규칙을 초기부터 넣는다** | D-day 이후로 미루면 이미 늦는다 |

## 5. 수정해서 가져갈 것

> 구조는 유효하나 값·비율·네이밍을 반드시 바꿔야 하는 것.

| # | 자산 | 유지할 것 | 반드시 바꿀 것 |
|---|---|---|---|
| 1 | **컬러 토큰 위계 구조** | 역할별 토큰을 나누는 방식 | 🔴 **`--primary` 단일 이름 폐기.** `--brand` / `--cta` / `--brand-ink`로 **역할 기준 분리** (§3-1) |
| 2 | **읽는 브랜드색 대비 설계** | 개념 유지 | 우나어 `--primary-text`는 3.4:1로 **AA 경계**였다. 소란소란 `--brand-ink`는 **6.62:1** |
| 3 | **작은 글씨용 별도 토큰** | 배지·캡션 대비 확보 | `--brand-ink`가 soft 배경 위 **5.92:1**로 이 역할을 겸한다 |
| 4 | **`--muted-strong` / `--muted-subtle`** | 목록 3단 위계 (제목 > 미리보기 > 메타) | 웜 뉴트럴 계열로 재조정 |
| 5 | **갱년기 카테고리 컬러** | 전용 토큰을 두는 방식 | 🔴 우나어 핑크·마젠타 **폐기.** 갱년기톡은 소란소란의 **주인공**이므로 브랜드 컬러 계열로 승격 (§7 P1) |
| 6 | **IconMenu 구조** | 상단 아이콘 메뉴 행 + FAB | **7개 → 4개로 축소**: 갱년기톡 · 자유게시판 · 매거진 · 베스트 |
| 7 | **Header** | sticky 64px · 좌 로고 / 우 액션 | 🔴 **정사각 로고 슬롯 금지.** 가로형 워드마크 슬롯으로 (§9) |
| 8 | **동적 OG 템플릿** | `ImageResponse` 구조 · 카테고리 배지 + 제목 길이별 폰트 분기 | 그라디언트·배지 컬러·기본 카피 전부 교체 |

| 10 | **manifest** | PWA 매니페스트 자체 | 🔴 `public/manifest.json` **복사 금지** → **`app/manifest.ts` 규약 권장** (타입 안전 + 값 누락 방지) |

| 12 | **localStorage 키** | 클라이언트 설정 저장 방식 | 🔴 `unao-*` **금지** → `soran-*` 네임스페이스 (§8) |
| 13 | **터치 타겟 2단 구조** | 전역 하한 + 개별 상향 | 관계를 **문서에 명시**한다: 전역 `min-height: 44px`(하한) · 인터랙티브 아이콘 버튼 **52px**(기준) |
| 14 | **코드 주석 명명** | 주석으로 의도를 남기는 습관 | 🔴 "시니어" 표현 **전량 치환** → "우리 나이" · "40~60대" · "가독성" |

## 8. 글자 크기 3단계 — 정본

> 🔴 **이 섹션이 이 문서에서 가장 자주 참조될 정본이다.** 구현 전 반드시 읽는다.

### 정본

| 항목 | 값 |
|---|---|
| **기능** | 소란소란에도 **유지한다** |
| **선택지** | **작게 / 기본 / 크게** — 3단계 |
| **기본값** | **기본** |
| **저장 시점** | 사용자가 선택하면 `localStorage`에 저장한다 |
| **저장키** | **`soran-font-size`** |
| **금지 키** | 🔴 `unao-font-size` · `unao-font-default-v2` — 우나어 키를 쓰지 않는다 |
| **금지 표현** | 🔴 "시니어 친화" · "시니어 맞춤" — 코드 주석·UI 문구 어디에도 쓰지 않는다 |

### 크기 기준

```
기본   본문 18px            ← 우나어에서 검증된 값을 "기본" 단계로 승계
작게   기본보다 한 단계 아래   ← 하한 16px. 그 아래로 내리지 않는다
크게   기본보다 한 단계 위
```

⚠️ **"작게"에도 하한이 있다.** 타겟 사용자층을 고려하면 16px 미만은 선택지로 제공하지 않는다.
사용자가 고를 수 있다는 것과, 읽을 수 없는 크기를 제공하는 것은 다르다.

### 구현 규칙

```
1. CSS 변수로 전 컴포넌트에 연동한다.
   개별 컴포넌트에 px를 하드코딩하면 3단계가 일부 화면에만 먹는다.

2. 저장키는 soran-font-size 단일 키로 설계한다.
   우나어는 승격 플래그(unao-font-default-v2)를 위해 키를 2개 썼으나,
   소란소란은 처음부터 기본값이 "기본"이므로 승격 로직 자체가 필요 없다.

3. localStorage 접근은 try/catch로 격리한다.
   Safari 프라이빗 모드 등에서 setItem이 던져도 화면 적용은 반드시 수행되어야 한다.

4. 초기 페인트 flicker를 막는다.
   설정 적용 스크립트를 <head>에서 동기 실행한다.

5. 어드민 화면은 이 설정의 영향을 받지 않게 격리한다.
```

### 🔴 변경 시 검증 필수 (3단계 전부에서 확인)

```
[ ] 게시글 목록      제목 2줄 말줄임 · 메타 정보 줄바꿈 깨짐 없음
[ ] 버튼             텍스트 넘침 없음 · 최소 터치 타겟 유지
[ ] 탭 / IconMenu    4개 항목이 한 줄에 유지되는가 (가로 스크롤 발생 금지)
[ ] 카드 레이아웃     썸네일 비율 유지 · 카드 높이 붕괴 없음
[ ] 모바일 767px     위 4개를 모바일 폭에서 재확인
```

⚠️ 우나어에서 이 검증이 문서화되어 있지 않았다. **"크게"에서만 깨지는 레이아웃은 개발자 화면에서 발견되지 않는다.**

## 9. 텍스트 워드마크 — D-day 조건

> 이미지 로고 없이 D-day 배포가 **가능하다.** 단 아래 6개를 모두 만족해야 한다.

| # | 조건 | 상세 |
|---|---|---|
| 1 | **폰트 고정** | Pretendard Variable **800 또는 900**. 얇은 굵기는 워드마크로서 존재감이 부족하다 |
| 2 | **4글자 반복 리듬 활용** | "소란소란"은 2음절 반복 구조다. 이 리듬 자체가 식별성을 만든다. 심볼 없이도 성립하는 이유 |
| 3 | **자간을 과하게 좁히지 않는다** | 한글은 자간을 좁히면 판독성이 급격히 떨어진다. 좁히더라도 **-2% 내외**까지 |
| 4 | **Logo 컴포넌트 단일 진입점** | 🔴 `src/components/brand/Logo.tsx` **1개소.** 페이지·컴포넌트에서 직접 마크업하지 않는다 |
| 5 | **Header는 가로형 슬롯** | 🔴 정사각 슬롯 금지. 우나어는 가로 2:1 로고를 정사각 박스에 넣어 **워드마크가 읽히지 않는 상태**로 운영했다 |
| 6 | **favicon은 별도 필요** | 32×32에서 한글 4글자는 판독 불가. 축약형(한 글자 또는 심볼)을 별도 설계한다 → P0-6 |
| 7 | 🔴 **색상 판독성을 실기기에서 확인한다** | `--brand`(`#FF6F61`) 워드마크는 배경 위 **2.60:1**이다. 로고 예외로 허용되지만 작은 헤더에서 읽히지 않을 수 있다. 조건·전환 규칙은 §3-1 참조 |

### 이미지 로고로의 무손실 전환

```
Logo.tsx 하나만 교체하면 전 화면에 반영된다.

우나어 반례:
  <Image src="/logo-symbol.png" ...> 가 6개 파일에 각각 하드코딩되어 있다.
  로고를 바꾸려면 6곳을 모두 찾아야 하고, 하나라도 빠지면 두 로고가 공존한다.

→ 소란소란은 D-day에 텍스트로 출발하더라도
  "나중에 교체 가능한 구조"를 처음부터 만든다. 이것이 4번 조건의 이유다.
```

### 🔴 워드마크 색상 판정 절차 (D-5)

```
1. 실기기 모바일 헤더에서 --brand(#FF6F61) 워드마크를 띄운다
   에뮬레이터·데스크톱 축소가 아니라 실제 기기다

2. 판정 질문 — 하나라도 '아니오'면 전환한다
   [ ] 팔을 뻗은 거리에서 "소란소란"이 한 번에 읽히는가
   [ ] 밝은 실외광에서도 읽히는가
   [ ] 획이 뭉개지거나 배경에 잠기지 않는가

3. 전환 (§3-1 판독성 미달 시 전환 규칙)
   1순위  --brand-ink (#9A3A31) 워드마크   6.62:1
   2순위  이미지 로고

⚠️ 이 판정은 D-5에 한다. D-day 당일에 발견하면 바꿀 시간이 없다.
```

| 순위 | 신호 | 목적 | 실패 사례 |
|---|---|---|---|
| **1** | **워드마크 "소란소란"** | 판독 가능한 크기로 | 우나어: 60×29로 축소되어 읽히지 않음 |

## 11. 매거진 / 커뮤니티 통일 원칙

> IA 정본(작전표 §4): **갱년기톡·자유게시판 = 게시판** / **매거진 = 콘텐츠 영역** / **베스트 = 모아보기 영역**

### 공유해야 하는 것 (같은 브랜드로 보이게)

```
1. 헤더 · 푸터 · 워드마크 동일

3. radius · 그림자 · 터치 타겟 동일
4. primary 컬러 동일
```

### 구분해야 하는 것 (역할이 다름을 보이게)

```
5. 매거진   = 이미지 상단 카드 · 넓은 여백 · 읽기 리듬
   커뮤니티 = 텍스트 우선 리스트 · 높은 밀도 · 댓글 수 강조
```

### 🔴 금지

| 금지 | 이유 |
|---|---|
| 매거진과 커뮤니티에 **서로 다른 primary 컬러** | 두 개의 서비스처럼 보인다 |
| **매거진에 글쓰기 버튼 노출** | 매거진은 회원이 쓰는 곳이 아니다 |
| **커뮤니티에 "발행" · 운영자 용어 노출** | 회원이 자기 글을 "발행"한다고 느끼면 진입 장벽이 생긴다 |
| **매거진 글이 커뮤니티 리스트에 섞임** | IA 정본 위반. 데이터 모델에서 커뮤니티 여부를 분리해 구조적으로 막는다 |
| **베스트를 게시판처럼 표현** | 베스트는 모아보기 영역이다. 글쓰기 진입점을 두지 않는다 |

### 권장 안전장치

```
1. 색상 리터럴 린트 규칙을 처음부터 넣는다
   → 토큰 정의 파일 밖에서 #RRGGBB 및 bg-[#...] 임의값 클래스 사용 금지

   → 4번 차단

   → 2번 차단
```
