### ⚠️ 문서 간 불일치가 있다

```
m3 §13-7                      blocker 5개 (4 + 조건부 1)

딥다이브 감사 (2026-08-21)     숨은 blocker 3건 추가 발견
```

**`soransoran-agent-guidelines.md` §6만 읽은 세션은 blocker 3개를 모른다.**
그 문서 자체의 정정은 §5(D-3)에 문서 정정 항목으로 등록했다.

> 🔴 **이 절의 목록이 D-7~D-day 실행 기준의 정본이다.**
> 다른 문서와 다르면 이 목록을 따른다.

### 조건부 blocker 2개

| # | blocker | 조건 | 기한 |
|---|---|---|---|
| **C1** | `safeBotLog` fallback 이식 | 봇이 하나라도 도는 시점 | D-3 |
| **C2** | `UserBlock` filter 실제 적용 | **차단 UI 노출 전** · 그 외에는 D+8 전 | 아래 참조 |

> 🔴 **정정 (2026-08-21)**: 이전 서술은 *"커뮤니티 쓰기를 열지 않으면 D-day blocker가 아니다"* 였다.
> 정본은 **D-day부터 실제 회원 글쓰기·댓글이 ON**이므로 그 조건은 성립하지 않는다.
>
> `C2` 의 실제 조건은 **커뮤니티 쓰기 여부가 아니라 차단 UI 노출 여부**다.
>
> ```
> D-day 차단 UI 숨김 (정본)   → C2 는 D+8 전 blocker
> 차단 UI 를 노출하는 순간    → C2 는 D-day blocker 로 승격
> ```
>
> 🔴 **차단 버튼을 보여주면서 필터가 없는 상태는 금지한다.**
> 우나어는 `UserBlock` 을 저장만 하고 어떤 쿼리도 필터로 쓰지 않는다.
> 사용자는 보호받는다고 믿는데 실제로는 아니다 — **미구현보다 나쁘다.**

### D-day 최소 보호장치 (차단 UI 숨김 전제)

실제 회원 글쓰기·댓글을 D-day부터 열기 때문에, 아래는 **D-day 필수**다.

```
[ ] 로그인 회원만 글쓰기·댓글 가능   (게스트 OFF)
[ ] 신고 기능                        모델 → 액션 → UI → 관리자 → 감사로그
[ ] 금칙어 / 위험 표현 필터
[ ] 기본 rate limit 확인             ⚠️ 우나어 코드에서 미확인 — D-3 에 확인 필요
[ ] 어드민 삭제 / 신고 확인 경로
```

⚠️ **차단(block)은 이 목록에 없다.** D-day 에는 UI 를 숨기므로 `C2` 는 D+8 전으로 둔다.

### 왜 blocker가 8개인가

| 없으면 벌어지는 일 |
|---|
| **B1·B2** 없으면 → 아무것도 시작할 수 없다 |
| **B3** 없으면 → 우나어 46모델을 복사하게 되고, dead model과 destructive seed가 따라온다 |
| **B4·B5** 없으면 → 우나어의 "300자 미만 48%"가 그대로 재현된다 |
| **B6** 없으면 → D+0~D+7 유일한 발행 경로가 멈춰도 아무도 모른다 |
| **B7** 없으면 → 나중에 형식을 못 바꾼다 (우나어는 정규식 파서에 묶여 지금도 못 바꾼다) |
| **B8** 없으면 → "정상 OFF"와 "장애"를 구분할 수 없어 D+0~D+7 내내 판단이 불가능하다 |
