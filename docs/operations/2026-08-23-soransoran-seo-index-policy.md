# 소란소란 SEO 색인 정책

> 작성일: 2026-08-23 · 기준 커밋: `3cbd842`
> 성격: **판단 기준 문서**. 실행 절차서가 아니다.
> 색인 표면(`robots.ts` · `sitemap.ts` · `canonical` · `robots` metadata · `SORAN_ALLOW_INDEXING`)을
> 바꾸기 전에 이 문서를 먼저 읽는다.

---

## 0. 한 줄 판정

> 소란소란의 색인 표면은 **회원이 쓴 글**만이다.
> 기능 화면·운영 화면·발행 경로가 없는 빈 면은 색인 대상이 아니다.

우나어의 네이버 색인 붕괴(4,600 → 0)는 기술 실수가 아니라
**"이 사이트가 무엇인가"를 검색엔진이 판단하지 못한 것**이었다.
소란소란이 지금 가진 최대 자산은 글이 적다는 사실이 아니라, **전부 진짜 회원 글**이라는 점이다.

## 1. 전략 원칙 10개

앞으로의 모든 색인 판단은 이 10개를 기준으로 한다.

**원칙 1 — 색인 표면은 "회원이 쓴 글"만이다.**
공개 대상은 홈 · 커뮤니티 게시판 · 회원 글이다.
기능 화면(`/write` · `/login`)과 운영 화면(`/admin/*`)은 영원히 색인 대상이 아니다.

**원칙 2 — 무엇이 대표 문서인지 검색엔진이 헷갈리지 않게 한다.**
우나어 실패의 핵심 가설은 "사이트 안에서 무엇이 공식/원본/대표 문서이고
무엇이 외부 반응 기반 글인지 네이버가 구분하지 못했다"였다.
소란소란은 모든 글이 회원 원본이라 이 혼선이 없다.
**이 상태를 깨는 어떤 구조도 도입하지 않는다** — 외부글 수집 · AI 발행 · 크롤 재발행.

**원칙 3 — 빈 페이지는 sitemap에 넣지 않는다.**
"준비 중입니다"만 있는 URL을 제출하는 것은 크롤 예산을 버리고 품질 평가를 낮춘다.
콘텐츠가 생기면 그때 넣는다.

**원칙 4 — canonical은 자기 자신을 가리킨다. 상속에 기대지 않는다.**
`src/app/layout.tsx`의 `alternates: { canonical: '/' }`는 **전역 상속**된다.
개별 지정이 없는 페이지는 자기 자신이 아니라 홈을 정본으로 신고한다.
색인 대상 페이지는 반드시 자기 경로를 명시한다.

**원칙 5 — 색인하지 않을 페이지는 canonical이 아니라 noindex로 막는다.**
canonical은 "정본이 어디냐"이고 noindex는 "색인하지 마라"다.
기능 페이지에 canonical을 붙이면 오히려 색인 요청 신호가 된다.

**원칙 6 — 네이버를 기본값으로 삼고, 구글 전용 예외를 만들지 않는다.**
우나어는 `googleBot` 전용 noindex(E0 정책)를 운영하다 정책이 복잡해졌다.
`src/app/robots.ts` 주석에 "우나어의 robots를 복사하지 않았다"는 판단이 이미 기록돼 있다.

**원칙 7 — 수집 요청으로 문제를 풀지 않는다.**
우나어가 실측으로 폐기한 오해다: "수집 요청을 많이 하면 회복된다."
수집 성공은 색인·노출을 보장하지 않는다.
색인이 안 되면 재제출이 아니라 **원인을 찾는다**.

**원칙 8 — 삭제·차단된 콘텐츠는 즉시 색인 표면에서 사라진다.**
`status='PUBLISHED'` 필터가 sitemap과 상세 조회 양쪽에 걸려 있어,
soft delete 즉시 sitemap에서 빠지고 상세는 404가 된다.
**이 이중 필터를 풀지 않는다.**

**원칙 9 — UGC의 외부 링크는 신뢰를 넘기지 않는다.**
본문은 평문 렌더이고 `content-guard`가 링크 도배를 막는다.
**자동 링크화를 도입하는 날 `rel="ugc nofollow"`가 동시에 필요하다.**

**원칙 10 — 색인 정책 변경은 실측 후에만 한다.**
추측으로 건드리지 않는다. 변경 전후를 운영 HTML로 대조한다.
`robots.ts`는 **정적 생성**이라 env를 바꾸면 캐시 없는 재배포가 필요하다.

## 2. route별 색인 정책

| route | robots | canonical | sitemap | robots.txt | 이유 |
|---|---|---|---|---|---|
| `/` | index | `/` | ✅ | — | 브랜드 대표 문서 |
| `/community/menopause` | index | 자기 경로 | ✅ | — | 핵심 주제면 |
| `/community/free` | index | 자기 경로 | ✅ | — | 커뮤니티 폭 |
| `/community/*/[postId]` | index | 자기 경로 | ✅ (PUBLISHED만) | — | 유일한 원본 콘텐츠 |
| `/terms` · `/privacy` | index | 자기 경로 | ❌ | — | 신뢰 신호. sitemap 필수는 아님 |
| `/magazine` | index | **자기 경로** (쪽·분류 포함) | ✅ 목록 + 공개 글 전부 | — | 발행 완료 · 공개 34건 (2026-09-21 코드 대조) |
| `/best` | **noindex, follow** | `/best` 유지 | ❌ | — | 모아보기 로직 없음 (원칙 3) |
| `/write` | **noindex, nofollow** | 상속(무시됨) | ❌ | — | 로그인 필수 기능 화면 |
| `/login` | **noindex, nofollow** | 상속(무시됨) | ❌ | — | 기능 화면 |
| `/admin/reports` | **noindex, nofollow** | 상속(무시됨) | ❌ | ✅ `/admin/` | 운영 화면. 이중 차단 |
| `/api/*` | — | — | ❌ | ✅ `/api/` | — |

**`follow` 차이의 근거**
`/best`는 상단 메뉴에서 도달하는 정식 면이라 크롤러가 다른 게시판으로
이동할 수 있게 `follow: true`. `/write` · `/login`은 로그인 흐름뿐이라 `follow: false`.
(`/magazine` 도 발행 전에는 같은 이유로 `follow: true` 였다 — 지금은 index 라 해당하지 않는다)

**noindex 페이지의 canonical**
noindex가 붙으면 canonical 값은 크롤러가 무시한다.
`/best`의 canonical을 유지하는 이유는 모아보기 구현 시 되돌리기 쉽게 두기 위해서다.

**`/magazine` 의 canonical — 목록별 자기 경로 (2026-09-21)**
`/magazine` 은 index 이므로 canonical 이 실제로 읽힌다.
쪽·분류를 나눈 뒤에도 **지금 보고 있는 목록**을 가리킨다.

```
/magazine                            → /magazine
/magazine?page=2                     → /magazine?page=2
/magazine?page=1                     → /magazine            (기본값은 뺀다)
/magazine?cluster=sleep              → /magazine?cluster=sleep
/magazine?cluster=sleep&page=2       → /magazine?cluster=sleep&page=2
/magazine?cluster=all                → /magazine            (기본값은 뺀다)
/magazine?cluster=<모르는 값>        → /magazine            (전체로 정규화)
```

2쪽 이후를 `/magazine` 으로 몰지 않는다 — 그러면 그 화면들이 1쪽의 복제로 처리되어
깊은 글로 가는 내부 링크가 색인에서 끊긴다.
범위를 넘긴 쪽은 빈 200 이 아니라 **404** 다(soft-404 방지).
규칙 정본은 `buildMagazineListHref()` 하나이고 `npm run check:pagination` 이 고정한다.
목록 정책 전체는 [매거진 전략서](./2026-08-23-soransoran-magazine-strategy.md) §6 D7.

## 3. UGC 색인 리스크 정책

| 항목 | 정책 |
|---|---|
| 사용자 글 색인 기준 | `status='PUBLISHED'` 전량 색인. **길이로 거르지 않는다** |
| 삭제 글 | soft delete 즉시 sitemap 제외 + 상세 404 |
| 삭제 댓글 | 상세에서 미노출 + 댓글 수에도 미집계 |
| 신고 글 | 자동 숨김 없음(운영자 판단). 현재 규모에선 수동으로 충분 |
| 차단 사용자 글 | 뷰어별 개인 설정이므로 **sitemap에 반영하지 않는다**(의도된 설계). 화면에서만 필터 |
| 외부 링크 `rel` | 현재 평문 렌더라 불필요. **링크화 도입 시 `rel="ugc nofollow"` 동시 필수** |
| 빈 면 | 커뮤니티 게시판은 글 0이어도 index(곧 채워짐). **`/best` 는 noindex** — 모아보기 로직이 없어 구조적으로 비어 있다. (`/magazine` 도 발행 전에는 같은 이유였다. **2026-09-21 현재 공개 34건이라 index 다.** 공개 글이 0건으로 돌아가면 다시 건다) |
| 저품질·짧은 글 | 기술적으로 거르지 않는다. `content-guard`가 **입구에서** 방어(최소 길이·링크 도배·금칙어) |

**핵심 구분**: "아직 글이 없는 게시판"(곧 채워짐)과 "구조적으로 빈 면"(발행 경로 자체가 없음)은 다르다.
전자는 index, 후자는 noindex다.

## 4.5 예약 공개 글의 색인 원칙 (7-A)

매거진이 `publishAt` 기반 예약 공개로 바뀐다.
**운영 정본은 [매거진 성장 운영 전략서](./2026-08-23-soransoran-magazine-seo-production-strategy.md) §6** 이고,
여기서는 색인 표면에 걸리는 부분만 정한다.

| 상태 | sitemap | 상세 URL | 목록·관련글·시리즈 UI |
|---|---|---|---|
| 공개됨 (`publishAt <= now` · QA PASS · LOW/MEDIUM) | **포함** | 200 | 노출 |
| **미래 `publishAt`** | **제외** | **404** | 숨김 |
| `BLOCKED` · `HIGH` 미승인 | **제외** | **404** | 숨김 |
| QA FAIL · hero REQUIRED 누락 | **제외** | **404** | 숨김 |

**왜 미래 글이 404 여야 하는가**
sitemap 에서 뺐는데 상세가 200 이면 크롤러가 링크를 타고 들어와 **미완성 글을 색인**한다.
반대로 sitemap 에 넣고 상세가 404 면 크롤 예산을 버리고 신뢰를 깎는다.
**다섯 표면(sitemap · 상세 · 목록 · 관련글 · 시리즈 UI)이 항상 같은 판정을 써야 한다.**

⚠️ 한 곳이라도 빠지면 사고다. 구현 시 다섯 곳을 **같은 함수 하나**로 판정한다.

## 5. Search Console / Naver 제출 게이트

### 보류 기준 (해제 전까지 제출 금지)

> 아래 **해제 조건 4개를 전부** 충족하기 전에는 제출하지 않는다.

**이유**
- 이 상태로 제출하면 첫 크롤에서 "콘텐츠 거의 없는 사이트"로 평가가 굳는다.
- 우나어 실측 교훈: 수집 성공이 색인·노출을 보장하지 않는다(원칙 7).
- 첫인상을 되돌리는 비용이 늦게 시작하는 비용보다 크다.

### 해제 조건 — 4개 AND (하나라도 미달이면 제출 금지)

| # | 조건 | 왜 필요한가 |
|---|---|---|
| **A** | sitemap의 글 상세 URL **20건 이상** | 크롤러가 볼 것이 있어야 한다 |
| **B** | **회원 원본 글 10건 이상** (봇·외부글 0건 — 원칙 2) | 커뮤니티가 목적지다 |
| **C** | **최근 14일 내 회원 글 3건 이상** | 살아있는 사이트라는 증거 |
| **D** | `robots` · `canonical` · `sitemap` · `vercel.app` 감사 **PASS** (§7) | 노출면이 깨진 채로 제출하지 않는다 |

**A와 B를 분리하는 이유**: 매거진은 편집팀 글이라 A만으로도 20건을 넘길 수 있다.
매거진 20건 + 회원 글 3건 상태로 제출하면 "편집팀 블로그"로 인식된다.
매거진은 커뮤니티로 보내는 **통로**이고(매거진 전략 원칙 9), 통로만 색인되고
목적지가 비어 있으면 유입이 그대로 이탈한다. North Star 는 주간 재방문 참여 유저다.

**C가 필요한 이유**: 누적 10건이어도 전부 3개월 전 글이면 크롤러에게는 방치된 사이트다.

### 해제 시 순서

1. **Naver Search Advisor 먼저** (유입 비중 근거)
2. Google Search Console
3. 제출 후 **2주간 색인 수 관찰**

### 제출 후 금지 사항

- **재제출 남발 금지.** 색인이 늦다고 수집 요청을 반복하지 않는다.
- **색인 0이면 재제출이 아니라 원인 조사**(원칙 7). 우나어가 실측으로 폐기한 오해가
  "수집 요청을 많이 하면 회복된다"였다. 4,600건이 0이 된 원인은 지금도 미확정이다.
- 2주 관찰 기간에는 `sitemap`·`robots`·`canonical` 을 **건드리지 않는다.**
  변수를 바꾸면 원인 분리가 불가능해진다.

## 7. 변경 시 PASS 기준

색인 표면을 건드린 뒤 배포하면 아래를 실측한다.

```
1. /                    robots meta 없음 (홈 index 유지 — 가장 중요)
                        canonical = https://soransoran.com
2. /community/*         robots meta 없음 · canonical 자기 경로
3. /community/*/[id]    robots meta 없음 · canonical 자기 경로
4. /magazine            robots meta 없음 · canonical 자기 경로(쪽·분류 포함) · HTTP 200
                        범위 초과 쪽은 404 (빈 200 아님)
   /best                noindex, follow · canonical 유지 · HTTP 200
5. /write · /login      noindex, nofollow · HTTP 200
6. /robots.txt          Allow: / · Disallow: /api/ · /admin/ · 전체 Disallow: / 0건
7. /sitemap.xml         홈 + /magazine 목록 + 공개 매거진 글 + 공개 커뮤니티 글
                        /best · /write · /login · /admin/reports 0건
8. 전 route             vercel.app 0건
```

**4·5번의 HTTP 200 유지가 중요하다** — 사용자는 정상 이용하고 크롤러만 제외하는 것이 목적이다.

## 8. 알려진 이슈

### I1 — 게시판 slug를 검증하지 않는다 (2026-08-23 발견 · 미수정)

글 상세는 `postId`만으로 조회하고 `boardSlug`가 그 글의 게시판인지 확인하지 않는다.

```
/community/menopause/{갱년기톡 글 id}   200   canonical = /community/menopause/{id}
/community/free/{같은 갱년기톡 글 id}    200   canonical = /community/free/{id}   ← 잘못된 자기참조
```

**왜 문제인가** — 같은 글이 게시판 수만큼의 URL을 갖고, 각 URL이 **자기 자신을 canonical로 신고**한다.
색인되면 duplicate content가 된다. 우나어 실패 패턴 F3와 같은 계열이다.

**현재 완화 요인**
- sitemap에는 올바른 경로만 들어간다(잘못된 URL은 제출되지 않음)
- 내부 링크가 전부 올바른 경로를 쓴다
- 게시판이 2개라 변형 URL이 글당 1개뿐

**권장 조치** — 상세 페이지에서 `post.boardType`과 `boardSlug`가 일치하지 않으면 `notFound()`.

⚠️ 이 문서는 판단 기준 문서다. 조치는 별도 배치에서 한다.
