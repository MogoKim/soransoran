## 0. 이 문서의 역할

이 문서는 소란소란의 **콘텐츠 끝 도달 → 회원가입 → 첫 참여** 영역에서 현재 유효한 목적·정책·설계와
다음 행동을 정하는 단일 정본이다. 새 Codex 세션은 이 문서를 기준으로 판단하고 Claude Code에 한 단계씩
실행을 맡긴다.

- 운영 문서의 권위 지도는 [`README.md`](./README.md)를 따른다.
- 고객·제품 본질·장기 North Star는 [`NORTH-STAR.md`](./NORTH-STAR.md)가 정한다.
- D100 콘텐츠 공급·Persona·대화·자동 운영은 D100 canon과
  [`CURRENT-MILESTONE.md`](./CURRENT-MILESTONE.md)가 정한다.
- 이 문서는 전환 정책, 가입 제안, 전환 측정, 고객 구성, 회원 영역 어드민의 의미를 정한다.
- 콘텐츠 주제와 발행 결정은 정하지 않는다.
- 코드·DB·schema·migration·외부 콘솔·merge·배포는 이 문서만으로 자동 승인되지 않는다.
- 기획이 바뀌면 구현보다 먼저 이 문서를 갱신한다.

## 1. 프로젝트 정의

| 항목 | 정본 |
|---|---|
| 프로젝트명 | **소란소란 콘텐츠 끝 도달 → 회원가입 전환** |
| 목적 | 로그인되지 않은 방문자가 콘텐츠 끝에 도달했을 때 승인된 가입 제안을 받고, 목표 여성 고객의 실제 가입과 첫 참여로 이어지게 한다 |
| 핵심 고객 | **50대 여성 → 40대 후반 여성 → 60대 초·중반 여성** |
| 현재 목표 | 최소한의 전환 기준선을 만들고, 실제 숫자를 보며 한 번에 하나씩 개선한다 |
| 현재 비목표 | 개인 추적·페이지별 전환 최적화·A/B 플랫폼·마케팅 발송·범용 분석 플랫폼 |

### 한 줄 정본

> **콘텐츠를 끝까지 살펴본 로그인되지 않은 방문자에게 방해를 최소화한 가입 제안을 하고, 실제 목표 고객의 가입과 첫 참여로 잇는다.**

### 상위 흐름

```text
로그인되지 않은 방문자
→ 공개 커뮤니티 글 또는 공개 매거진 글 열람
→ 가입 제안 기준 도달
→ 가입 제안 실제 노출
→ 카카오 시작
→ 기존 온보딩·약관 완료
→ 실제 가입 완료
→ 첫 글 또는 댓글
→ 장기적으로 7일 내 재방문 참여
```

`끝 도달`은 실제 독해 완료를 의미하지 않는다. 그래서 프로젝트명과 현행 지표에서 `완독`을 사용하지 않는다.

## 2. 왜 지금 하는가

- 현재 유입과 회원 수가 적어 고객 구성 숫자만 관찰한다고 전환이 저절로 늘지 않는다.
- 표본 1명의 비율로 시장 가설이나 콘텐츠 전략을 확정하지 않는다.
- 유입이 늘 때까지 기다리지 않고, 먼저 가입 제안과 최소 측정 기반을 준비한다.
- 정책 없이 팝업부터 만들면 사용자 경험과 데이터 의미가 함께 흔들린다.
- 반대로 미래 분석까지 한꺼번에 만들면 속도와 유지보수를 해친다.

따라서 원칙은 다음과 같다.

> **사용자 경험·숫자의 의미·개인정보·확장 안정성에 직접 영향을 주는 것만 먼저 정하고, 나머지는 실제 질문이 생길 때 추가한다.**

## 3. 측정의 세 축

세 축을 하나의 숫자나 한 화면으로 섞지 않는다.

| 축 | 질문 | 현재 상태 |
|---|---|---|
| A. 가입 전환 | 로그인되지 않은 방문자가 콘텐츠 끝에서 가입 행동으로 움직였는가 | MC-M3 설계 승인 · 미구현 |
| B. 고객 구성 | 실제 가입자가 목표 여성·연령대와 맞는가 | 고객 구성 어드민 Production PASS |
| C. 가입 후 가치 | 가입 후 글·댓글·재방문 참여로 이어지는가 | 글·댓글·7일 내 참여 일부 측정, 재방문은 미측정 |

- A는 익명·집계 중심의 발생 횟수다.
- B는 가입 완료 회원의 구성과 참여를 기존 DB 사실로 집계한다.
- C의 진짜 재방문은 회원 방문일 근거가 필요하며 MC-M7에서 다룬다.
- 익명 전환 집계와 회원 재방문 데이터를 한 테이블이나 한 전환율로 합치지 않는다.

## 4. 가입 제안 대상

### 로그인되지 않은 방문자

현재 유효한 로그인 세션이 없는 방문자를 뜻한다. 여기에는 다음이 모두 포함된다.

- 아직 가입하지 않은 사람
- 가입했지만 로그인이 풀린 기존 회원
- 다른 브라우저나 기기에서 접속한 기존 회원

인증 전에는 이들을 정확히 구분할 수 없다. 따라서 `순수 신규 비회원` 또는 `신규 가입 후보 수`라고
표현하지 않는다.

### 상태별 처리 `확정`

| 상태 | 가입 제안 |
|---|---|
| 로그인되지 않은 방문자 | 대상 |
| 로그인했지만 온보딩 미완료 | 대상 아님. 기존 온보딩 복귀 경로 사용 |
| 가입 완료 회원 | 대상 아님 |
| 로그인한 관리자·운영자·시험 계정·Persona | 로그인 상태이므로 노출·집계 대상 아님 |
| prefetch·스스로 밝힌 자동화 요청 | 화면 mount가 없거나 서버가 걸러 집계 대상 아님 |
| 로그아웃한 관리자·운영자 | 인증 전이라 일반 방문자와 구분할 수 없음. ①~④에 섞일 수 있음 (§8-10) |

가입 전 성별은 알 수 없으므로 팝업 노출 단계에서 여성을 골라낼 수 없다. 실제 가입 후의 성별·연령 품질은
고객 구성 축에서 확인한다. 현재 가입 접근 정책은 이 프로젝트가 임의로 바꾸지 않는다.

## 5. 가입 제안 기준 도달

### 5-1. 적용 화면 `확정`

- 공개 커뮤니티 글 상세 전체
- 공개 매거진 글 상세 전체

홈·게시판 목록·관리자 화면에는 적용하지 않는다. 커뮤니티와 매거진 중 하나만 먼저 통과 처리하지 않고,
Preview에서는 두 유형을 함께 검증한다.

### 5-2. 커뮤니티 `확정`

다음을 모두 만족할 때 `가입 제안 기준 도달`로 본다.

1. 로그인되지 않은 상태다.
2. 같은 페이지에서 본문 끝을 먼저 통과했다.
3. 현재 화면에 공개된 댓글·답글 목록의 마지막 지점까지 도달했다.
4. 목록 아래 감지 지점이 연속 1초 이상 화면에 보였다.
5. 다른 팝업·시트·댓글 작성창·답글 작성창·키보드가 열려 있지 않다.

포함:

- 공개된 회원 댓글
- 공개된 비회원 댓글
- 공개된 답글
- 가입 제안이 뜨기 전에 사용자가 펼친 답글

제외:

- 삭제·숨김 댓글
- 접힌 채 화면에 보이지 않는 답글
- 인기 댓글 영역에 중복 노출된 같은 댓글
- 댓글 작성 입력창
- 페이지가 열린 뒤 추가됐지만 아직 화면에 반영되지 않은 댓글

답글을 펼치면 감지 지점은 펼친 목록의 마지막 아래로 이동하고, 그 지점이 다시 연속 1초 이상 보여야 한다.

댓글이 없으면 다음을 기준으로 한다.

```text
본문 끝 통과
→ `아직 댓글이 없어요` 영역 확인
→ 그 아래 감지 지점이 연속 1초 이상 표시
```

충돌 UI가 닫힌 뒤에는 과거의 도달 상태만으로 팝업을 즉시 열지 않는다. 감지 지점이 다시 연속 1초 이상
보여야 한다.

### 5-3. 매거진 `확정`

```text
매거진 본문
→ 본문 안의 기존 CTA·필요한 안내
→ 본문 카드 끝 감지 지점이 연속 1초 이상 표시
```

본문 아래 연관 글 영역은 도달 기준에 포함하지 않는다.

### 5-4. 현행 측정 명칭 `확정`

| 화면 | 명칭 |
|---|---|
| 커뮤니티 | `댓글 끝 도달` |
| 매거진 | `본문 끝 도달` |
| 공통 | `가입 제안 기준 도달` |

`완독`, `댓글 완독`, `본문 완독`처럼 실제 독해를 단정하는 표현을 지표명으로 사용하지 않는다.

## 6. 가입 제안 디자인·문구·상호작용

### 6-1. 디자인 `확정`

| 항목 | 계약 |
|---|---|
| 방향 | B 「이야기를 이어가는 자리」 |
| dim | **48%**, Header를 포함한 전체 화면 |
| 크기 | **S2**, 고정 높이가 아닌 콘텐츠 기반 높이 |
| 모바일 | 전체 폭 하단 팝업, 위쪽 모서리 22px |
| 데스크톱 | 본문 폭 안 하단 중앙 카드, 최대 폭 600px |

| 보조 버튼 | 높이 52px |
| 사용하지 않음 | 드래그 손잡이·스와이프 닫기·불필요한 일러스트 |

| 좌우 여백 | 20px |
| 제목 줄간격 | 1.35 |
| 제목 → 불렛 | 14px |
| 불렛 사이 | 10px |
| 불렛 → CTA | 22px |
| CTA → 보조 버튼 | 4px |

### 6-2. 문구 `확정`

```text
마음에 남은 이야기를
계속 이어가세요          ← 두 번째 줄만 브랜드색

내 이야기를 글로 남기기
마음에 닿은 글에 공감하기
댓글로 편하게 이야기 나누기

카카오로 시작하기
계속 둘러볼게요
```

불렛은 정확히 세 개다. 세 번째 문장은 댓글이 회원 전용이라는 주장이 아니다. 현재 비회원 댓글 경로는
그대로 유지한다.

### 6-3. 열림과 레이어 `확정`

- 가입 제안 기준 도달 뒤에만 연다.
- 다른 팝업·시트·댓글 작성창·답글 작성창·키보드가 열려 있으면 열지 않는다.
- 도달 1초 타이머가 도는 중에 충돌 UI가 열리면 타이머를 취소한다. 충돌 UI가 닫힌 뒤 감지 지점이 다시
  연속 1초 보여야 연다(§5-2).
- 레이어 의미 순서는 `Toast > 가입 팝업 > dim > Header·댓글 작성 독·스레드 이동 버튼`이다.
- 구현 시작값은 `Toast z-70 > 가입 팝업 z-60 > dim > Header z-50`이다. 기기별 충돌은 MC-M4 Preview에서
  실측하고 실측 결과로만 조정한다.

### 6-4. 닫기 `확정`

- X
- dim 탭
- 데스크톱 ESC
- 모바일 뒤로가기
- `계속 둘러볼게요` 보조 버튼

모바일 뒤로가기는 글을 떠나지 않고 팝업만 닫는다. 닫은 뒤 스크롤 위치와 이전 초점을 복원한다.

### 6-5. CTA와 복귀 `확정`

- CTA는 중간 로그인 안내 화면 없이 카카오 인증을 시작한다.
- CTA는 기존 `KakaoSignInButton`을 그대로 지나며 인증 호출을 복제하지 않는다. 가입 팝업 전용 시각
  variant만 추가해 B안 모양과 높이 56px를 맞춘다.
- 누르는 즉시 `카카오로 이동 중…`으로 바꾸고 재클릭을 막는다.
- X와 보조 버튼도 진행 중에는 비활성 상태로 보인다.
- bfcache로 글이 복원되면 진행 중 상태를 반드시 초기화한다.
- 기존 필수 온보딩과 약관 동의를 생략하지 않는다.
- 가입 완료 후 커뮤니티는 댓글 영역, 매거진은 본문 끝으로 돌아온다.
- 인증 취소·실패 시 원래 글로 돌아와 Toast로 알린다.
- 성공·취소·실패 직후 팝업을 바로 다시 띄우지 않는다.

Toast 문구 `확정`:

```text
카카오 로그인을 완료하지 못했어요. 읽던 글에서 다시 시도할 수 있어요.
```

#### 취소·실패 복귀 경로 `확정`

현재 Auth.js는 카카오 취소·실패(`OAuthCallbackError`)를 callback 정보 없이 `/login?error=…`으로 보낸다.
원래 글 복귀는 다음 방식 하나로 구현한다.

- `OAuthCallbackError`일 때만 `/login` 서버 경로가 Auth.js callback URL 쿠키를 제한적으로 읽는다.
- 설치된 Auth.js 버전이 실제로 쓰는 secure·non-secure callback 쿠키 이름만 허용하고, 이 의존성은 계약 시험으로
  고정한다.
- callback 값은 기존 `toInternalPath`로 검증하고, `/onboarding?callbackUrl=…`은 정확히 한 단계만 벗긴다.
- 외부 URL·프로토콜 상대 URL·잘못된 값으로는 절대 redirect하지 않는다. 정상적으로 복구할 수 없으면 `/login`의
  안전한 오류 화면에 남긴다.
- 원래 글로 돌아올 때는 고정 fragment만 쓰고, 처리한 뒤 `history.replaceState`로 제거한다. 성공 복귀 위치
  (댓글 영역·본문 끝)도 같은 고정 fragment 규칙을 따른다.
- 브라우저 표식과 이벤트에는 콘텐츠 경로·ID·slug를 넣지 않는다(§8-2).

### 6-6. 접근성과 움직임 `확정`

- `role="dialog"`, `aria-modal`, `aria-labelledby`를 적용한다.
- 닫기 버튼에는 접근성 이름을 둔다.
- 열리면 팝업으로 초점을 이동하고 내부에서 순환시킨다.
- 닫으면 이전 초점과 스크롤 위치를 복원한다.
- 하단에서 부드럽게 등장한다.
- `prefers-reduced-motion`에서는 이동 없이 바로 나타난다.

## 7. 노출 빈도

### 사업 정책 `확정`

- 같은 브라우저에서 최초 실제 노출 시각 기준 **24시간 최대 1회**다.
- 닫기에 따른 7일 재노출 금지는 없다.
- 노출 기록에 개인정보나 회원 식별 정보를 넣지 않는다.

### 브라우저 저장 `확정`

- 24시간 노출 제한: 별도 localStorage 키에 최초 노출 시각만 저장한다.
- localStorage를 사용할 수 없어 24시간 제한을 지킬 수 없으면 팝업을 열지 않는다.
- 열람·도달 중복 방지는 브라우저 저장소를 쓰지 않고 tracker mount 안의 메모리 상태로 한다(§8-2).
- 인증 왕복 표식은 §8-4 계약을 따른다.
- 기존 조회수·글쓰기 인증 키와 공유하지 않는다.
- 어떤 브라우저 계측 표식에도 콘텐츠 경로·ID·slug를 넣지 않는다.

정확한 키 이름은 구현에서 정하되 위 내용 밖의 값을 저장하지 않는다.

## 8. MC-M3 최소 측정 계약

2026-10-07 창업자 승인: Codex [2] 보정안을 포함한 MC-M3 최소 측정 설계와 `SignupFunnelDaily` schema
설계를 승인한다. migration 생성·적용, commit·push·merge·배포는 각각 다음 단계에서 별도 승인한다.

### 8-1. 다섯 단계 `확정`

| 단계 | 내부 이름 | 화면 의미 | 한 건의 의미 | 기록 시점 |
|---|---|---|---|---|
| 1 | `logged_out_view` | 로그인되지 않은 상태의 콘텐츠 열람 | 로그인되지 않은 상태로 공개 상세의 tracker가 처음 mount된 방문 1회 | mount 직후 |
| 2 | `prompt_reach` | 가입 제안 기준 도달 | 같은 방문에서 §5 기준을 처음 충족한 1회. 24시간 제한 때문에 팝업이 열리지 않아도 센다 | 감지 지점이 연속 1초 표시를 처음 충족한 때 |
| 3 | `prompt_impression` | 가입 제안 실제 노출 | 가입 제안 dialog가 실제로 열린 1회 | 24시간 노출 기록 저장에 성공하고 dialog가 열린 때 |
| 4 | `auth_start` | 카카오 시작 | CTA가 받아들여져 카카오 인증 호출을 시작한 1회 | 기존 카카오 버튼의 시작 훅, 인증 호출 직전 |
| 5 | `signup_complete` | 이 출입구를 거친 확인된 가입 완료 | 서버가 최초 온보딩 전환을 확인했고 유효한 귀속 표식이 전달된 가입 1건 | 가입 트랜잭션 커밋 뒤 같은 서버 요청 안 |

CTA 클릭과 인증 시작은 현재 한 동작이므로 별도 단계로 쪼개지 않는다. 온보딩 시작 시각의 서버 정본이
없으므로 `onboarding_start`를 만들지 않는다.

### 8-2. 방문 정의 `확정`

- 방문은 콘텐츠 상세 tracker의 **최초 mount 1회**다.
- 같은 mount의 rerender는 중복하지 않는다.
- 새로고침은 새 방문이다. 새 탭도 새 방문이다.
- bfcache가 기존 페이지 상태를 그대로 복원하면 새 mount가 아니므로 다시 세지 않는다.
- `logged_out_view`·`prompt_reach` 중복 방지는 mount 안의 메모리 상태로 한다. sessionStorage·localStorage를
  쓰지 않는다.
- 콘텐츠 경로·ID·slug를 payload나 브라우저 계측 표식에 저장하지 않는다.

### 8-3. 판정 주체 `확정`

| 값 | 결정 주체 |
|---|---|
| 집계 날짜 `day` | 서버. 요청 처리 시각의 KST 날짜이며 클라이언트 날짜를 받지 않는다. KST helper를 클라이언트 번들로 끌고 오지 않는다 — 공용 함수를 재사용하면 server-only 경계를 증명하고, 경계가 흐려지면 중복 구현 없이 중립적인 작은 KST 모듈로 추출한다 |
| 로그인 상태 | 서버. ①~④는 화면 렌더 때와 기록 요청을 받을 때 모두 세션이 없어야 기록한다. 화면 렌더의 판정은 같은 요청의 기존 세션 판정을 공유한다(§8-11) |
| 실제 가입 완료 | 서버 (§8-5) |
| 수집 활성 여부 | 서버 gate 하나 (§8-7) |
| `step`·`contentType`·`entryPoint` | 클라이언트가 보낼 수 있는 유일한 값. 서버가 허용값으로 검증한다 |
| 증가 | 서버의 원자적 upsert `+1` |

- `contentType`: `community` | `magazine`
- `entryPoint`: 현재 `content_end` 하나
- 요청에 `step`·`contentType`·`entryPoint` 외 필드가 하나라도 있으면 그 요청 전체를 집계하지 않는다.
- 세 값 중 하나라도 허용값이 아니면 그 요청을 집계하지 않는다.
- 집계하지 않는 경우에도 응답 방식은 사용자 읽기·인증·가입 흐름에 영향을 주지 않는다.
- 서버 안전은 정확한 same-origin 검증과 엄격 payload 검증을 함께 쓴다. `Sec-Fetch-Site` 하나를 유일한 근거로
  삼지 않는다.

### 8-4. 인증 왕복 표식 `확정` — A안

- `auth_start` 때 별도 localStorage 키에 `contentType`, `entryPoint`, `expiresAt` **세 값만** 저장한다.
- 만료는 30분이다. 기존 글쓰기 인증 표식과 같은 창이다.
- 온보딩 폼이 표식을 읽어 가입 서버 액션에 **선택 인자**로 전달한다. 표식이 없거나 읽을 수 없어도 가입은
  그대로 진행한다.
- 서버는 허용값과 만료를 검증한다. 하나라도 맞지 않으면 귀속하지 않는다.
- 표식은 가입이 성공한 뒤에만 제거한다. 실패 후 다시 시도할 때 귀속을 잃지 않기 위해서다.
- 실제 가입 완료는 서버가 확인하지만 **귀속 표식 자체는 클라이언트가 전달한 값**이다. 서버는 그 값이 실제
  가입 제안에서 왔는지 증명할 수 없다. 위조로 늘릴 수 있는 양은 실제 신규 가입 1건당 최대 1건이다.
- 쿠키 방식은 현재 범위에서 제외한다.

### 8-5. `signup_complete` `확정`

- 실제 온보딩 완료는 서버가 확인한다.
- DB에서 `isOnboarded=false → true` 전환을 **성공시킨 요청 하나만** `signup_complete` 기록 자격을 가진다.
- 현재 코드는 완료 여부를 먼저 읽은 뒤 갱신한다. 이 read 후 update만으로 동시 요청에서 계정당 정확히 1회가
  보장된다고 보지 않는다. 구현은 `isOnboarded=false`를 조건으로 한 **원자적 최초 전환**을 쓰고, 그 전환이
  실제로 일어난 요청만 기록 자격을 갖는다.
- 필수 Agreement 동의 행은 지금처럼 같은 가입 트랜잭션 안에서 저장한다.
- 계측은 가입 트랜잭션이 커밋된 뒤, 유효한 귀속이 있고 제외 계정이 아닐 때만 집계 upsert 1회를 `await`한다.
  계측 실패는 가입 트랜잭션을 롤백하지 않고 가입 응답도 실패로 바꾸지 않는다.
- 이를 위해 `after()` 도입·Next 업그레이드·새 dependency 추가를 하지 않는다. 온보딩 경로 성능 비교가 §8-13 기준을
  넘으면 MC-M4 FAIL이다.
- 관리자와 allowlist 계정은 기록하지 않는다.
- 서버가 보장하는 것은 **실제 최초 온보딩 완료 여부**뿐이다. `content_end` 귀속은 서버가 검증한 클라이언트
  값이지 서버가 발생 출처를 증명한 값이 아니다(§8-4).
- 정상 제품 흐름에서는 다른 브라우저·카카오톡 인앱 브라우저로 넘어가 표식을 잃은 가입이 빠질 수 있으므로
  **보수적 관측값**으로 읽는다. 귀속값을 위조할 수 있으므로 수학적 하한이나 감사·과금급 지표로 보장하지
  않는다.
- 표식 만료 30분 안에 다른 입구에서 가입을 마치면 `content_end`로 귀속될 수 있다.
- 집계 날짜는 가입 완료 시각의 KST 날짜이므로 `auth_start`와 날짜가 다를 수 있다.

### 8-6. 분석 단위와 표시 `확정`

- 전체 · 커뮤니티 · 매거진. 전체는 저장하지 않고 두 유형의 합으로 계산한다.
- 게시판별·페이지별·글별 집계는 만들지 않는다. MC-M6에서 실제 사업 질문이 생길 때만 별도 승인한다.

표시 가능한 운영 비율은 세 개뿐이며 항상 분자·분모와 함께 표시한다.

1. `prompt_reach` / `logged_out_view` — `끝 도달 관측 비율`
2. `prompt_impression` / `prompt_reach` — `노출 정책 작동 비율`
3. `auth_start` / `prompt_impression` — `CTA 반응 비율`

`signup_complete`는 절대 확인 건수로만 표시한다. `열람 → 가입 전환율`과 `카카오 시작 → 가입 완료율`은
표시하지 않는다.

### 8-7. Preview·Production gate `확정`

writer는 다음 세 조건을 **모두** 만족할 때만 활성화한다.

1. `VERCEL_ENV === 'production'`
2. `SIGNUP_FUNNEL_COLLECTION_START`가 유효한 KST 날짜(`YYYY-MM-DD`)
3. 현재 KST 날짜가 시작일 이상

- 수집 시작일과 기록 스위치는 이 env 값 하나로 통일한다. 별도 on/off 값을 두지 않는다.
- 같은 gate를 가입 전환 어드민 reader에도 적용한다.
- gate가 비활성이면 writer와 reader 모두 집계 테이블을 read·write 하지 않고, 어드민은 `수집 전` 또는
  `비활성`을 표시한다.
- Preview·개발·시험 환경은 이 gate로 제외된다. Preview가 어떤 DB에 연결돼 있든 Production 카운터를 쓰지
  않는다.
- env 추가와 외부 콘솔 변경은 MC-M5에서 별도 승인한다.

### 8-8. 저장과 보관 `확정`

`SignupFunnelDaily` 한 테이블이다. 0031 migration으로 Production DB에 빈 표가 생성됐다(§18 상태).

```text
SignupFunnelDaily
- day          KST 'YYYY-MM-DD' 문자열, 서버 결정
- step         다섯 단계, 코드 검증 문자열
- contentType  community | magazine, 코드 검증 문자열
- entryPoint   현재 content_end, 코드 검증 문자열
- count        정수, 기본 0
- updatedAt    마지막 증가 시각

복합 키(day, step, contentType, entryPoint)
```

- 회원가입 전환 전용이다. 범용 이벤트 저장소로 쓰지 않고 다른 분석 목적의 행·열을 섞지 않는다.
- `step`·`contentType`·`entryPoint`는 DB enum 대신 코드에서 허용값을 검증하는 문자열이다. 새 출입구가
  추가돼도 기존 `content_end` 숫자의 의미를 바꾸지 않는다.
- 증가는 원자적 upsert `+1`이며 Raw SQL을 쓰지 않는다.
- 익명 일별 집계는 **최소 24개월 보존**한다. MC-M3에서는 자동 삭제 job을 만들지 않는다. 삭제 정책은 실제
  데이터와 사업 질문이 생긴 뒤 별도 승인한다.

### 8-9. 저장 금지 `확정`

- IP
- 원문 User-Agent
- 회원 ID
- 영속 익명 브라우저 ID
- 카카오 ID
- 이메일·전화번호
- 성별·출생연도
- 닉네임
- 콘텐츠 ID·post ID·slug
- 제목·본문·댓글
- 전체 URL·callback URL

테이블에는 이 값을 담을 열 자체가 없어야 한다. 성별·연령은 전환 집계에 복제하지 않고 고객 구성에서 본다.

### 8-10. 제외와 해석 한계 `확정`

| 대상 | 처리 |
|---|---|
| Preview·시험 환경 | gate로 제외 |
| 로그인된 회원·관리자 | ①~④에서 제외 |
| 관리자·allowlist 계정 | ⑤에서 제외 |
| 로그아웃한 운영자·관리자 | 인증 전이라 일반 익명 방문과 **구분할 수 없다**. ①~④에 섞일 수 있다 |

- 익명 endpoint는 위조 요청으로 숫자를 부풀릴 수 있다. 이 집계는 감사·과금급 지표가 아니라 **운영 관측
  지표**다.
- 초기 집계는 고유 사람 수가 아니라 단계별 **발생 횟수**다. 한 사람의 완전한 퍼널이라고 표현하지 않는다.
- 로그인되지 않은 기존 회원의 재로그인이 `auth_start`에 섞일 수 있다.
- 날짜 경계를 넘는 방문은 단계별 날짜가 다를 수 있다. 하루 단위 비율보다 누계를 우선한다.
- 수집 시작 전 날짜는 0이 아니라 `UNKNOWN`이다.

### 8-11. 성능 불변식 `확정`

이번 계측 때문에 사이트 읽기·스크롤·로그인·가입 속도가 느려지면 안 된다.

- 콘텐츠 렌더링과 사용자 행동은 계측 응답을 기다리지 않는다.
- 계측 전송은 fire-and-forget이며 오류는 사용자 흐름 밖에서 처리한다.
- 도달 감지는 IntersectionObserver를 쓴다. 지속적인 scroll listener를 두지 않는다.
- 가입 제안 팝업은 본문 layout shift를 만들지 않는다.
- 공개 콘텐츠 최초 렌더에서 신규 집계 DB를 읽지 않는다.
- 같은 요청 안의 세션 판정은 `src/lib/request-session.ts`의 요청 단위 캐시(`cache(() => auth())`) 하나를
  `HeaderAuth`·커뮤니티 상세·매거진 상세가 공유한다. 매거진은 판정 1회를 유지하고 커뮤니티는 2회에서 1회로
  줄인다. 새 인증 DB 조회와 공개 페이지 critical path의 새 DB 조회는 0이다.
- 집계 조회는 가입 전환 어드민에서만 한다.
- Preview·수집 비활성 상태에서는 집계 테이블 query를 하지 않는다.

### 8-12. 유지보수·레거시 정리 `확정`

- 기존 코드를 수정할 때 대체된 옛 코드·링크·분기·helper를 남기지 않는다.
- 낡은 정본 버전·절 번호를 가리키는 주석을 현재 절로 고친다.
- 쓰지 않게 된 import·타입·상수를 제거한다.
- 이벤트 이름·허용값·비율 정의는 코드에서 한 곳에만 둔다.
- 인증·온보딩 로직을 복사하지 않고 기존 경로를 사용한다.
- 주석 처리된 코드와 임시 호환 경로를 두지 않는다.
- 삭제 전 rg로 참조를 확인한다.
- 수정 범위 안의 레거시는 정리하되 범위 밖 전역 리팩터링은 하지 않는다.
- 새 정책과 충돌하는 옛 문장은 정본에서도 제거한다.

## 9. 기존 데이터와 계측의 역할

| 기존 구조 | 사용 여부 |
|---|---|
| `Agreement(TERMS_OF_SERVICE).agreedAt` | 전체 가입 완료 시각의 제한적 서버 근거로 유지 |
| `Post`·`Comment` | 가입 후 첫 글·댓글과 참여 집계에 재사용 |
| 고객 구성 쿼리·어드민 | 그대로 유지, 복제하지 않음 |
| GA4 | 보조 분석. 어드민 숫자의 정본으로 사용하지 않음 |
| `Post.viewCount` | 전체·누적·커뮤니티 중심이라 전환 분모로 사용하지 않음 |
| `KakaoSignInButton` | 단일 카카오 시작 경로로 그대로 사용. `auth_start`는 기존 시작 훅에서 기록하고 인증 호출을 복사하지 않음. 가입 팝업 전용 시각 variant만 추가 (§6-5) |
| 가입 서버 액션 | 실제 가입 완료의 유일한 서버 근거. §8-5의 원자적 최초 전환으로 보강하고 온보딩 로직을 복사하지 않음 |
| 글쓰기 인증 marker·view beacon | 구현 패턴으로 참고. 키·쿠키·엔드포인트를 공유하지 않고 변경하지 않음 |

`User.createdAt`은 인증 계정 생성 시각이지 가입 완료 시각이 아니다. 가입 완료일로 사용하지 않는다.

현재 GA4 page_view는 `page_path`에 query를, `page_location`에 query·hash가 포함된 전체 주소를,
`page_title`에 게시글·매거진 제목을 보낸다. 로그인·온보딩 화면에서는 callback 경로가 함께 전송된다. 이는
신규 퍼널과 분리된 `MC-M3P` 정합성 작업으로 다룬다. 이번 전환 작업은 GA4 제품 코드나 장기 분석 구조를
확장하지 않고, 신규 DB 집계는 GA4에 의존하지 않는다. 전환 구현은 인증 왕복 상태를 URL query로 표시하지
않는다.

## 10. 회원 어드민 정보구조

상위 운영 메뉴를 늘리지 않는다. `회원` 아래에 공통 하위 탭을 둔다.

```text
회원
├─ 회원 관리
├─ 고객 구성
└─ 가입 전환
```

### 회원 관리

- 현재 경로: `/admin/members`
- 회원 목록·상세·차단·신고 관련 운영

### 고객 구성

- 현재 경로: `/admin/members/composition`
- 실제 가입 완료 고객의 여성·연령 구성
- 글·댓글·가입인사 참여
- 가입 후 7일 내 참여
- 성별·연령 미확인과 차단 고객

### 가입 전환 `확정`

- 경로: `/admin/members/conversion`
- 관리자 권한 확인은 기존 어드민 권한 경로를 재사용한다.
- 표시: 수집 시작일, 수집 상태, 다섯 단계 건수의 전체·커뮤니티·매거진, §8-6의 비율 세 개와 분자·분모,
  §8-10 해석 한계
- 초기 범위는 수집 시작일부터 오늘까지 누계다. 시작 전 날짜는 `UNKNOWN`이다.

- 개인정보·회원 목록·콘텐츠 목록·차트·복잡한 기간 선택 없음
- 고객 구성 숫자를 중복 표시하지 않고 해당 탭으로 연결

### 공통 하위 탭 `확정`

세 화면은 같은 회원 생애 흐름에 속하지만 답하는 질문이 다르다. 하나의 거대한 대시보드로 합치지 않고,
세 화면이 같은 공통 하위 탭 컴포넌트 하나를 사용한다. 회원 상세 화면에는 탭을 붙이지 않는다.

새 상위 메뉴, 임시 텍스트 링크, 화면마다 다른 내비게이션을 추가하지 않는다. 탭을 도입할 때 회원 목록의
`고객 구성 보기 →` 텍스트 링크와 고객 구성 화면의 `← 회원` 되돌아가기 링크처럼 탭이 대체하는 옛 링크를 함께
제거한다.

## 11. 완료된 고객 구성 하위 프로젝트

고객 구성은 폐기하거나 다시 구현할 대상이 아니다. 전환 프로젝트의 완료된 보조 측정 축이다.

현재 카카오 동의와 회원 DB가 수집·보관하는 이메일·성별·출생연도·전화번호는 이 프로젝트가 삭제하거나
수집 중단하지 않는다. 이 값은 고객 구성과 향후 승인된 고객 운영의 원재료다. 전화번호 보유를 광고성
메시지 발송 자격으로 간주하지 않으며, 카카오 메시지·알림톡·SMS는 채널·동의·철회·제외목록·발송이력을
별도로 설계하고 승인하기 전에는 시작하지 않는다.

### CB 목적

카카오에서 이미 받은 회원정보를 바꾸지 않고, 실제 가입 완료 여성의 연령 구성과 참여가 목표 고객 가설에
맞는지 집계한다.

### 핵심 대상

다음을 모두 만족하는 회원을 핵심 고객 지표에 넣는다.

1. 카카오 인증 계정이 있음
2. `isOnboarded=true`
3. 저장 성별이 `female`
4. Persona·운영자·관리자·bot·시험용 allowlist 계정이 아님

확인된 남성은 핵심 고객 지표에서 제외한다. 성별 미확인은 여성으로 추정하지 않고 별도 표시한다.
출생연도 미확인은 여성 전체에는 포함하되 연령 분석에서 별도 표시한다. 차단 여성은 구성에는 포함하고
차단 수를 표시하되 현재 참여 지표에서는 제외한다.

### 연령 구간

```text
45세 미만
45~49세
50~54세
55~59세
60~64세
65~69세
70세 이상
연령 미확인
```

`기준연도 - 출생연도`를 분석연령으로 사용하며 만 나이라고 부르지 않는다. `ageBand`를 회원 테이블에
중복 저장하지 않는다.

### 참여 의미

- 현재 공개된 실제 회원 글 작성 여부
- 현재 공개된 실제 회원 댓글 작성 여부
- 글 또는 댓글 작성 여부
- 가입인사 작성 여부는 일반 글과 분리
- 게시판별 참여 회원 수
- 가입 완료 뒤 7일 안의 글·댓글 참여

한 사람이 여러 건을 써도 참여 회원 수에서는 한 명으로 센다. 숨김·삭제 활동과 차단 회원의 활동은 현재
참여에서 제외한다. 개인별 이름·이메일·전화번호·출생연도 원문은 화면에 표시하지 않는다.

- 글은 실제 회원이 작성한 `PUBLISHED`만 포함하며 가입인사는 일반 글과 분리한다.
- 댓글은 실제 회원이 작성했고 삭제되지 않았으며 공개 글에 남아 있는 댓글만 포함한다.
- 게시판 목록은 손으로 적은 별도 배열이 아니라 현재 Prisma `BoardType` 전체를 따른다.
- 가입 완료 시각은 최초 `Agreement(TERMS_OF_SERVICE).agreedAt`을 제한적 근거로 사용한다.
- 약관 근거가 없으면 임의 날짜를 만들지 않고 `산정 불가`, 가입 뒤 7일이 지나지 않았으면 `관측 중`으로 분리한다.

`7일 내 참여`는 같은 가입 세션의 참여도 포함할 수 있으므로 재방문 지표가 아니다.

### 운영 상태 `관측`

- 경로: `/admin/members/composition`
- CB-M0~CB-M4: 완료
- Production·관리자 접근·비로그인 차단·767px 화면 검증: PASS
- 2026-10-06 최초 기준선: 실제 여성 가입 완료 1명, 55~59세 1명
- 표본 1명은 측정 체계가 작동한다는 증거일 뿐 고객 가설의 시장 검증이 아니다.
- 기존 집계 정책은 현재도 유효하다.

상세 구현·검사·배포 경과는 Git의 v3.2 이전 이력에 보존되어 있으며 현행 의사결정에 필요할 때만 조회한다.

## 12. DAU·WAU·MAU와 North Star

현재 익명 일별 집계로는 고유 사용자의 DAU·WAU·MAU·retention을 측정할 수 없다.

기존 DB로 계산 가능한 것은 기간별 글·댓글 작성 고유 회원 수이며, 이것은 `참여 회원`이지 방문 DAU가
아니다.

장기 North Star는 **최근 7일 안에 재방문했고 글 또는 댓글을 남긴 고유 실제 회원**이다. 이를 정확히
측정하려면 향후 로그인 완료 회원 기준의 최소 방문일 근거가 필요하다.

- 익명 브라우저의 사이트 전체 DAU는 현재 만들지 않는다.
- 회원 방문일 계측은 MC-M7에서 D100 North Star 소유권과 경계를 다시 확인한다.
- 익명 전환 카운터와 회원 방문일 데이터는 분리한다.
- 고객 구성의 `7일 내 참여`를 `7일 재방문`으로 바꾸어 부르지 않는다.

## 13. Preview와 Production

- MC-M4 Preview는 커뮤니티와 매거진 두 유형을 함께 검증한다.
- 디자인·접근성·도달 판정·24시간 제한·레이어 충돌·인증 복귀·계측 계약·성능을 검증한다.
- Preview는 §8-7 gate로 Production 집계 카운터를 쓰지도 읽지도 않는다.
- 집계 계약은 in-memory 기록 대상·격리된 DB·가로챈 계측 요청으로 확인한다. PASS 기준은 §8-13이다.
- 실제 전환 수집 시작일은 별도 승인된 MC-M5에서 `SIGNUP_FUNNEL_COLLECTION_START`로 정한다.
- 수집 시작일 이전은 `UNKNOWN`이다.
- 코드 PASS, 배포 PASS, 운영 PASS를 구분한다.

## 20. 영구 안전장치

- 실제 회원 원문과 개인정보를 전환 이벤트에 복제하지 않는다.
- 계측 장애가 글 읽기·로그인·가입·글쓰기·댓글을 막지 않는다.
- 계측이 읽기·스크롤·로그인·가입 속도를 늦추지 않는다.
- 숫자의 단위가 다르면 같은 사람의 전환율처럼 표시하지 않는다.
- 표본이 작으면 퍼센트만 강조하지 않는다.
- 식별 가능한 Preview·시험·운영 계정은 실제 고객 지표에서 제외한다. 인증 전 구분할 수 없는 로그아웃
  운영자는 ①~④에 섞일 수 있으며 이 한계를 숨기지 않는다(§4·§8-10).
- 새 출입구가 추가돼도 기존 `content_end` 숫자의 의미를 바꾸지 않는다.
- 새 정책은 대체한 옛 문장·코드 경로를 함께 제거한다.
- 속도를 위해 안전을 생략하지 않고, 안전을 이유로 범용 플랫폼을 먼저 만들지도 않는다.
