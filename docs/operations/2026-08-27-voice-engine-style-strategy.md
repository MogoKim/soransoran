## 1. Voice Engine 은 rewrite 도구가 아니다

**원문을 멀리 도망가게 만드는 장치가 아니다.**

원문과 댓글이 가진 **실제 사람 말투 · 감정선 · 생활감 · 댓글 반응 포인트**를 분석해
**소란소란의 오리지널 글을 만드는 엔진**이다.

이 둘은 정반대 방향이다.

```
❌ rewrite 도구      원문에서 최대한 멀어지면 성공
                     → 남는 것은 우리가 지어낸 이야기뿐이다

✅ Voice Engine      원문이 왜 사람들에게 닿았는지를 이해하고
                     그 이해로 우리 글을 쓴다
```

🔴 **"원문을 무조건 다르게 바꿔라" 는 지시가 아니다.**
바꿔야 하는 것은 표현 · 구성 · 제목 · 흐름이고,
**보존해야 하는 것은 핵심 상황 · 감정 · 생활 디테일**이다(VE-0 §6).

### 1-1. 타겟

**40대 후반~60대 초반 여성** (핵심 50대).

🚫 시니어 · 어르신 · 노인 · 실버
✅ 우리 나이 · 우리 또래 · 40대 후반~60대 초반 여성 · 인생 2막

## 2. 🔴 자연 유사성과 복제 유사성을 분리한다

이 문서에서 가장 중요한 절이다. **둘을 구분하지 못하면
"비슷하니까 다 지워라" 또는 "다 써도 된다" 중 하나로 무너진다.**

### 2-1. 자연 유사성 — 학습하고 살린다 🟢

우리 또래 수만 명이 **공통으로 쓰는 것**이다. 누구의 것도 아니다.

| 축 | 예 |
|---|---|
| 흔한 생활 표현 | "장 보러 갔다가", "무릎이 시큰해서" |
| 짧은 공통 문장 | "그쵸", "저도 그래요", "어쩔 수 없죠 뭐" |
| 우리 또래 말투 | 어미 · 호흡 · 존댓말 정도 |
| 문장부호 습관 | `..` · `~~` · `ㅠㅠ` · `^^` |
| 말줄임 | 말하다 만 문장 |
| 감정이 새는 표현 | 괄호 안의 딴소리, 되돌아오는 문장 |
| 모바일 입력 흔적 | 줄바꿈 위치 · 짧은 문단 |
| 띄어쓰기 흔들림 | "안파나요" · "다닌는데" |
| 소재와 감정 흐름 | 어디서 시작해 어디로 가는가 |
| 댓글이 붙은 공감 포인트 | 사람들이 실제로 걸린 지점 |

**이것을 지우면 사람 말투가 사라진다.**

### 2-2. 복제 유사성 — 금지한다 🔴

**특정 개인의 것**이다. 옮기면 그 사람의 글이 된다.

| 금지 | 왜 |
|---|---|
| **원문 고유 문장 묶음** | 연속된 문장은 그 사람의 구성이다 |
| **독특한 비유 · 표현 조합** | "기가 막혀서 말이 안 나왔어요" 같은 개인 표현 |
| **원문 문단 구조 전체 복제** | 순서가 곧 서술이다 |
| **댓글 문장 그대로 공개 사용** | 댓글도 저작물이다 |
| **`author` 닉네임 · 식별 단서 노출** | 3~7자 닉네임은 검색으로 특정된다 |
| **단어만 바꾼 유사 글** | 🔴 **가장 위험하다** — 바꿨다고 믿지만 구조가 같다 |

### 2-3. 경계선

```
"무릎이 아파서 병원 갔어요"        → 자연 유사성. 수만 명이 쓴다
"무릎이 시큰거리다 못해 밤에 깨는데   → 복제 유사성. 이 사람의 문장이다
 남편은 코를 골더라구요"
```

**판정 기준은 "흔한가" 가 아니라 "이 사람만의 것인가" 다.**

## 3. AI 티 제거 기준

### 3-1. 🔴 오해부터 걷는다

**AI 티를 줄이는 것은 모든 문장을 매끈하게 고치는 것이 아니다.**
**오히려 그 반대다.**

```
과도한 교정 · 과도한 요약 · 너무 반듯한 구조 · 교과서 같은 공감 문구
                         ↑
                    이것이 AI 티다
```

사람은 한 문단 안에서 화제를 바꾸고 되돌아온다.
결론이 안 난 채 끝내고, 하려던 말을 잊고, 괄호 안에서 딴소리를 한다.

### 3-2. 위험 축 7종

| 축 | 무엇을 재는가 | 높으면 |
|---|---|---|
| **`overSanitizedRisk`** | 너무 깔끔하게 정리해 사람 말투가 사라짐 | 🔴 **AI 티** |
| **`overMimicryRisk`** | 오타 · 문장부호를 일부러 남발 | 🔴 **조롱처럼 보인다** |
| **`naturalnessScore`** | 사람이 쓴 것 같은 자연스러움 | 🟢 좋다 |
| **`voiceRetention`** | 원문 · 댓글의 말투와 감정이 살아 있는 정도 | 🟢 좋다 |
| **`originalityDelta`** | 소란소란 글로 새로워진 정도 | 🟢 좋다 |
| **`sequenceSimilarityRisk`** | 연속 문장 · 문단 구조가 원문과 너무 비슷함 | 🔴 **복제 위험** |
| **`expressionRisk`** | 고유 표현 · 비유 · 개인 디테일 복제 | 🔴 **복제 위험** |

### 3-3. 🔴 두 위험은 반대 방향이다

```
overSanitizedRisk ↑          overMimicryRisk ↑
      매끈하게 다림질              오타를 흩뿌림
           ↖                        ↗
              자연스러운 지점
         (사람이 쓴 것처럼 보이되
          흉내 낸 티가 나지 않는)
```

**한쪽만 보면 반대편으로 넘어간다.** 두 축을 함께 재야 한다.

그리고 `voiceRetention` ↑ 와 `sequenceSimilarityRisk` ↓ 를 **동시에** 만족해야 한다 —
말투는 살리되 문장 구성은 우리 것이어야 한다는 뜻이다.

### 3-4. 판정은 사람이 한다

🔴 **v0 에 자동 판정기를 만들지 않는다.**
"AI 티" 를 기계가 재는 순간 그 지표에 최적화된 또 다른 AI 티가 나온다.

위 7축은 **사람이 판단할 때 무엇을 볼지 정한 것**이지
점수로 합격을 자동 결정하는 장치가 아니다.

## 4. 세대 · 기기 기반 비정형성

### 4-1. 노이즈가 아니라 Voice 자산이다

우리 또래 커뮤니티 글에는 비슷한 오타 · 띄어쓰기 · 문장부호 · 모바일 키보드 흔적이 있다.

실측 예 (82cook · 우나어 원문):
```
"창고형 약국에서파는 약"      ← 띄어쓰기 붙음
"대1 딸이 2년제 전문대 다닌는데"  ← 오타
"턱관절치과 다녀온후..저 망한 게"  ← 말줄임 + 붙임
```

**이것을 전부 교정하면 우리 회원의 글이 아니게 된다.**

### 4-2. 🔴 그러나 매번 따라 하면 안 된다

**낮은 빈도로, 자연스럽게만** 반영한다.

```
❌ 모든 오타를 제거한다        → overSanitizedRisk
❌ 오타를 많이 넣는다          → overMimicryRisk · 조롱처럼 읽힌다
✅ 실제 분포에 가까운 낮은 빈도  → 자연스럽다
```

**빈도는 원문 코퍼스에서 측정한다.** 우리가 정하는 값이 아니라
**우나어 33,031건에서 관찰되는 실제 비율**이어야 한다.

### 4-3. 축 7종

| 축 | 내용 |
|---|---|
| **`typingArtifacts`** | 오타 · 자판 인접 오류 · 반복 입력 |
| **`punctuationHabit`** | `..` · `~~` · `ㅠㅠ` · `^^` · 물음표 개수 |
| **`spacingVariance`** | 띄어쓰기 흔들림의 정도와 위치 |
| **`mobileInputTrace`** | 짧은 문단 · 잦은 줄바꿈 · 문장 중간 개행 |
| **`informalSpacing`** | 구어체 붙여쓰기 ("그니까", "머하러") |
| **`communityRegister`** | 커뮤니티 특유의 어투 · 호칭 · 인사 |
| **`artifactFrequency`** | 🔴 **위 요소들이 나타나는 빈도** — 이 값이 없으면 남발한다 |

`artifactFrequency` 가 핵심이다. 나머지 6축은 "무엇이 있는가" 이고,
이 축만이 **"얼마나 있어야 자연스러운가"** 를 답한다.

## 5. 댓글의 중요성

### 5-1. 댓글은 본문만큼 중요하다

**댓글은 이 세대가 실제로 어떻게 반응하는지 보여주는 유일한 데이터다.**

- 무엇에 공감하는가
- 어디서 반박하는가
- 어떻게 자기 경험을 보태는가
- 어떤 말로 위로하는가

본문은 **한 사람의 말투**이고, 댓글은 **여러 사람의 반응 구조**다.
소란소란의 North Star 가 "댓글을 쓰게 만드는 것" 이므로
**댓글 데이터가 오히려 본문보다 목적에 가깝다.**

### 5-2. 자산 규모

우나어 `topComments` **154,872개** (+ 대댓글 추정 약 71,000개).
소란소란 Micro Seed 는 **0개**.

### 5-3. 🔴 그러나 댓글 문장을 그대로 쓰지 않는다

```
🟢 분석    반응 유형 분포 · 공감 포인트 · 반박 패턴 · 말투 통계
🔴 금지    댓글 문장을 그대로 공개 콘텐츠에 사용
🔴 금지    댓글 작성자 닉네임 노출
```

Voice Engine 은 **본문 말투뿐 아니라 댓글 반응 구조도 분석**해야 하지만,
산출물은 **패턴이지 문장이 아니다.**

### 5-4. 알려진 한계

| 한계 | 영향 |
|---|---|
| 댓글 **200자 절단 4.1%** | 긴 댓글의 뒷부분이 없다. 모르고 학습하면 "200자에서 말을 끊는다" 는 거짓 패턴을 배운다 |
| 댓글에 **날짜 · 순서 정보 없음** | 시간 순 반응 시퀀스 복원 불가. 배열 순서만 있다 |
| **본문 대응 지점 없음** | "본문 어느 문단에 반응했는가" 는 복원 불가 |

**"반응 지도" 는 되지만 "본문 대응 지도" 는 안 된다.**

## 7. 법률 · 운영 경계

**창업자가 10명 이상의 변호사에게 자문했고, LLM 내부 분석과
말투 · 패턴 추출 목적으로 원문 · 댓글을 뜯어보는 것은 진행 전제다.**

🔴 **이 이슈를 blocker 로 다시 세우지 않는다.**

다만 **원문 · 댓글 그대로 SEO/index 공개 발행은 금지**다.
근거는 법이 아니라 실제로 겪은 일이다 — 우나어 색인이 4,600 → 0 이 된 것은
품질 문제가 아니라 **원문을 SEO 노출 방식으로 다룬 구조**의 문제였다.

## 8. schema 설계 반영 지침

🔴 **이번 PR 에서 schema 를 수정하지 않는다.**
아래는 **이후 `VoiceDerived` 설계에 들어가야 할 신호 목록**이다.

### 8-1. 품질 · 위험 축

```
naturalnessScore        사람이 쓴 것 같은 자연스러움
voiceRetention          원문/댓글 말투와 감정이 살아 있는 정도
originalityDelta        소란소란 글로 새로워진 정도
overSanitizedRisk       과교정 위험
overMimicryRisk         과모방 위험
expressionRisk          고유 표현 복제 위험
sequenceSimilarityRisk  연속 문장/문단 구조 유사 위험
```

### 8-2. 문체 · 입력 흔적 축

```
typingArtifacts         오타 · 자판 오류
punctuationHabit        문장부호 습관
spacingVariance         띄어쓰기 흔들림
mobileInputTrace        모바일 입력 흔적
communityRegister       커뮤니티 어투
```

> ✅ **2026-08-27 확정.** 위 13종은 **`VoiceDerived` 필드로 반영**됐다.
> 정본: [`2026-08-27-voice-engine-schema-strategy.md`](./2026-08-27-voice-engine-schema-strategy.md) §2-2
>
> · 품질 · 위험 7종은 `Int?` 스칼라 — 비교 · 정렬이 필요하다
> · 문체 · 입력 5종은 `Json?` — 구조가 열려 있어야 한다
> · **`artifactFrequency` 는 독립 필드**로 뒀다. "무엇이 있는가" 와
>   "얼마나 있어야 자연스러운가" 는 다른 질문이고, 후자가 남발을 막는 유일한 축이다
> · `informalSpacing` 은 `spacingVariance` 의 하위 지표로 접었다
>
> 🔴 `schema.prisma` 는 여전히 수정하지 않았다.
>
> 🔴 **2026-08-26 추가 — 13종은 계산 시점이 둘로 갈린다.**
> 문체·입력 흔적 6종은 원문에서 규칙으로 계산되고(VE-M2 · 비용 0),
> 품질·위험 7종은 **생성물이 있어야** 계산된다(VE-M3 · 첫 LLM 비용).
> `communityRegister` 는 출처 식별 호칭(우갱님들 · 은오님들 · 레테님들 · 82님들)을
> **일반 어투와 분리해** 다룬다 — 지우는 게 아니라 소란소란 내부어로 바꾼다.
> 🔴 치환 결과는 **`소란님들` · `소란소란님들`** 이다. **`우리 또래분들` · `50대 여성분들` 같은
> 타겟 설명어는 쓰지 않는다** — 커뮤니티 안에서 사람들은 서로를 설명하지 않고 그냥 부른다.
> 정본: [VE-M2 VoiceDerived 설계](./2026-08-26-voice-derived-m2-design.md) §3

| **M10** | **Comment / Conversation Engine** | 댓글 말투와 반응 구조 기반 |

**M7 이 M8 앞에 있는 이유**: AI 글과 사람 글의 차이를 **먼저 규칙으로 재 보고**,
그 기준이 선 다음에 LLM 을 붙인다. 기준 없이 LLM 을 부르면
무엇이 좋아졌는지 판정할 방법이 없다.
