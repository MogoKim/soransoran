## 0. 지금 서 있는 자리

[VE-0 계약 §8-1](./2026-08-27-voice-engine-v0-contract.md)이 정한 착수 순서에서 ①~④가 끝났다.

```
① 우나어 심층 데이터 감사 (read-only)          ✅ 완료
② VoiceSource / VoiceDerived / VoiceJudgment    ✅ 완료
③ schema PR                                     ✅ 완료 (0006 · 0007)
④ offline analyzer (LLM 없이)                   ✅ 완료 (VE-M2, 비용 0원)
⑤ 제한적 LLM 실험                               ← 여기부터가 VE-M3
```

| 자산 | 현재 |
|---|---|
| `VoiceSource` | 9,674 |
| `VoiceJudgment` | 3,093 (전부 `referenced` · `approved` **0**) |
| `VoiceDerived` | 9,674 (`method='rule'` · `ruleVersion='voice-m2-rule-v1'`) |
| `VoiceCommentSignal` | 59,252 |

**blocker는 데이터 부족이 아니라 "얼마를 쓰고 무엇을 남길지가 미정"이라는 것**이다.
이 문서가 그 미정을 없앤다.

## A. VE-M3의 목적

### 무엇을 보강하는가

VE-M2는 규칙으로 셀 수 있는 것을 전부 셌다. 그러나 **세는 것으로는 닿지 않는 판단**이 남았다.

| VE-M2가 못 잡는 것 | 왜 |
|---|---|
| 자연스러움 | 오타 개수를 세도 "사람이 쓴 것 같은가"는 답이 안 된다 |
| 과교정 | 매끈함은 정규식에 걸리지 않는다 |
| 원문 모방 위험 | 표현을 바꿔 베낀 것은 문자열 비교로 안 잡힌다 |
| 문장 흐름 유사성 | 20자 연속 일치를 피하면서도 구조는 같을 수 있다 |
| 댓글 반응 해석 | `other` **81%** — 규칙 분류의 천장이다([VE-M2 완료 §6](./2026-08-27-voice-m2-completion.md)) |

### 무엇이 아닌가

🔴 **자동 글쓰기 엔진이 아니다.** Voice Engine은 **학습·판정 엔진**이다.

- 산출물은 **판단 재료**이지 발행물이 아니다
- **Original Lane 자동 발행은 이번 범위가 아니다**
- `rewriteDirection`은 방향 메모이고 `rewrittenBody`는 만들지 않는다
  ([VE-0 §4-1](./2026-08-27-voice-engine-v0-contract.md))

**사람을 건너뛰지 않는다.** 이 원칙은 VE-M3 이후에도 유지된다(§I).

## B. 계산할 7종 신호

전부 **"소란소란이 쓴 글 ↔ 원문"의 비교 축**이다. VE-M2에서 계산하지 않은 이유가 이것이고,
생성물 또는 변환물이 생기는 시점에야 성립한다.

### B-1. `naturalnessScore` 🟢

| | |
|---|---|
| 무엇을 | 사람이 쓴 것처럼 읽히는 정도 |
| rule로 왜 부족한가 | 원문은 **실제로 사람이 썼다**. 오타 개수를 세도 물어볼 게 없다. 판정 대상은 **우리가 만든 글**이다 |
| 입력 | 생성물 + 원문 문체 신호(`typingArtifacts`·`punctuationHabit`·`artifactFrequency`) |
| 출력 | `Int` 0~100 |
| 사람이 어떻게 | **단독으로 읽지 마라.** `overSanitizedRisk`·`overMimicryRisk`와 3개를 함께 본다 |
| 자동 발행 조건 | 🔴 **금지** |

### B-2. `voiceRetention` 🟢

| | |
|---|---|
| 무엇을 | 원문·댓글의 말투와 감정이 살아 있는 정도 |
| rule로 왜 부족한가 | 무엇에 **대비해** 살아 있는지를 재려면 두 텍스트를 견줘야 한다 |
| 입력 | 생성물 + 원문 + `VoiceDerived` 6종 + `legacyLabels`(`emotionTags`·`psychInsight`) |
| 출력 | `Int` 0~100 |
| 사람이 어떻게 | `sequenceSimilarityRisk`와 **동시에** 본다 — 말투는 살리되 문장 구성은 우리 것이어야 한다 |
| 자동 발행 조건 | 🔴 **금지** |

### B-3. `originalityDelta` 🟢

| | |
|---|---|
| 무엇을 | 소란소란 글로 얼마나 새로워졌는가 |
| rule로 왜 부족한가 | "새로워짐"은 차이의 **질**이지 편집 거리가 아니다 |
| 입력 | 생성물 + 원문 |
| 출력 | `Int` 0~100 |
| 사람이 어떻게 | 낮으면 복제에 가깝고, 지나치게 높으면 원문과 무관한 글이 됐다는 신호다 |
| 자동 발행 조건 | 🔴 **금지** |

### B-4. `overSanitizedRisk` 🔴

| | |
|---|---|
| 무엇을 | 너무 깔끔하게 정리해 사람 말투가 사라진 정도 = **AI 티** |
| rule로 왜 부족한가 | 매끈함에는 특징적 문자열이 없다. 없는 것을 정규식으로 잡을 수 없다 |
| 입력 | 생성물 + 원문 문체 신호 + `artifactFrequency` |
| 출력 | `Int` 0~100 (높을수록 위험) |
| 사람이 어떻게 | **`overMimicryRisk`와 반대 방향이다.** 한쪽만 낮추면 반대편으로 넘어간다 |
| 자동 발행 조건 | 🔴 **금지** |

### B-5. `overMimicryRisk` 🔴

| | |
|---|---|
| 무엇을 | 오타·문장부호를 일부러 남발해 **조롱처럼 보이는** 정도 |
| rule로 왜 부족한가 | 빈도는 `artifactFrequency`가 세지만, **"흉내 낸 티가 나는가"**는 다른 질문이다 |
| 입력 | 생성물 + `artifactFrequency`(원문의 자연 빈도) |
| 출력 | `Int` 0~100 (높을수록 위험) |
| 사람이 어떻게 | `overSanitizedRisk`와 **함께** — 둘 사이가 자연스러운 지점이다 |
| 자동 발행 조건 | 🔴 **금지** |

### B-6. `expressionRisk` 🔴

| | |
|---|---|
| 무엇을 | 고유 표현·비유·개인 디테일을 복제한 정도 |
| rule로 왜 부족한가 | **표현을 바꿔 베낀 것**은 문자열 비교를 빠져나간다. VE-M2의 20자 대조로는 못 잡는다 |
| 입력 | 생성물 + 원문 |
| 출력 | `Int` 0~100 (높을수록 위험) |
| 사람이 어떻게 | 개인 특정 가능성으로 읽는다. 높으면 그 표현을 걷어낸다 |
| 자동 발행 조건 | 🔴 **금지** — 다만 **일정 이상이면 발행 후보에서 뺀다**(사람이 뺀다) |

### B-7. `sequenceSimilarityRisk` 🔴

| | |
|---|---|
| 무엇을 | 연속 문장·문단 **구조**가 원문과 너무 비슷한 정도 |
| rule로 왜 부족한가 | 20자 연속 일치를 피하면서도 전개 순서가 같을 수 있다. 그건 문자열이 아니라 **구조**다 |
| 입력 | 생성물 + 원문(문단 경계 포함) |
| 출력 | `Int` 0~100 (높을수록 위험) |
| 사람이 어떻게 | `voiceRetention`과 **동시에** — 말투는 살리되 구성은 우리 것 |
| 자동 발행 조건 | 🔴 **금지** — `expressionRisk`와 같이 후보 제외 판단에만 |

> 🔴 **7종 전부 "자동 발행 조건으로 쓰면 안 된다."**
> 점수가 좋아서 발행하는 구조를 만드는 순간 사람이 건너뛰어진다.
> 점수는 **사람이 무엇을 볼지 정하는 순서**에만 쓴다.

## C. 입력 범위

### 어디서 읽는가

| 대상 | 위치 | 방식 |
|---|---|---|
| 원문 본문 · 댓글 | **우나어 DB** | `UNAO_READONLY_DATABASE_URL` read-only |
| `VoiceDerived` 6종 | 소란소란 DB | 읽기 |
| `VoiceCommentSignal` | 소란소란 DB | 읽기 |
| `legacyLabels` · `contentHash` · `contentLength` · `commentCount` | 소란소란 DB(`VoiceSource`) | 읽기 |

🔴 **원문은 소란소란 DB에 저장하지 않는다.** 이 원칙은 VE-M3에서도 바뀌지 않는다.
필요할 때마다 우나어에서 다시 읽는다 — 그래서 `UNAO_READONLY_DATABASE_URL`이 전제다.

### LLM 입력과 저장의 분리

```
원문 · 댓글  →  LLM 입력으로 쓴다        ✅ 허용
             →  출력 · 로그 · DB 에 문장 그대로 저장  🔴 금지
```

**이 구분이 VE-M3의 핵심 위험 지점**이다. LLM은 원문을 보지만, 그 결과물에 원문이 묻어나오면
`VoiceDerived`가 본문 저장소가 된다. 실제로 legacyLabels 경유로 그런 일이 있었다
([VE-R3.1 · PR #93](./2026-08-26-voice-corpus-import-operations.md)).

방지 기준은 §H에 있다.

## D. cache key 설계

### 초안

```
cacheKey = sha256(
    origin              ·  'unao_cafe' | 'micro_seed' | 'soransoran_own'
  + sourceRef           ·  원천 레코드 id
  + contentHash         ·  🔴 원문이 수정되면 자동 무효화
  + ruleVersion         ·  VoiceDerived 규칙 버전 (입력이 달라진다)
  + taskVersion         ·  VE-M3 작업 정의 버전
  + model               ·  모델이 다르면 다른 결과다
  + promptVersion       ·  프롬프트가 바뀌면 다른 결과다
  + outputSchemaVersion ·  스키마가 바뀌면 파싱 결과가 다르다
)
```

### 목적

| | |
|---|---|
| **재호출 금지** | 같은 원문 · 같은 모델 · 같은 프롬프트 · 같은 스키마면 **다시 부르지 않는다.** 캐시 미스 하나가 돈이다 |
| **결과 분리** | 프롬프트나 모델이 바뀌면 **새 결과로 분리**한다. 덮어쓰지 않는다 — 비교가 불가능해진다 |

### 🔴 NULL 금지

`model`·`promptVersion`은 **NULL이 아니라 빈 문자열**이어야 한다.
Postgres에서 NULL은 서로 같지 않아, UNIQUE 키에 NULL이 들어가면 **중복을 전혀 막지 못한다.**
`VoiceDerived`에서 이미 이 결정을 적용했다(`NOT NULL DEFAULT ''`).

### 🔴 재사용은 `succeeded` 만 (2026-08-27 보정)

초판은 **캐시 행이 존재하기만 하면** 재호출을 건너뛰었다. 그 결과 1차 실행에서 남은
**실패 5건이 재실행을 영구히 막는 상태**가 됐다 — 원인을 고쳐도 `cacheKey` 가 같아
다시 부를 수 없고, 실패가 성공처럼 재사용된다.

| 캐시 status | 처리 |
|---|---|
| `succeeded` | ✅ 재사용. 부르지 않는다 (`cache_hit` 이벤트만 기록) |
| `failed` · `skipped` | 🔴 **재시도한다.** `cacheMiss` 로 세고 다시 부른다 |

- 저장은 `create` 가 아니라 **`upsert`** 다. `cacheKey` 가 UNIQUE 이므로 재시도 시 `create` 는 P2002 로 터진다.
- 재시도 비용은 `VoiceM3CostEvent.retryAttempt` 에 **이전 호출 수를 이어서** 기록한다.
  0 부터 다시 세면 "한 건에 몇 번 돈을 썼는가" 를 비용 원장에서 알 수 없다.
- 실패로 다시 저장할 때 `output` 은 **명시적으로 비운다**. 이전 산출물이 남으면 안 된다.

### 저장 위치는 미정

`VoiceDerived`에 컬럼을 더할지, 별도 캐시 테이블을 둘지는 **VE-M3-1에서 정한다**(§J).
이 문서는 **키의 구성 요소**만 확정한다. `schema.prisma`는 이 PR에서 건드리지 않았다.

## E. 비용 cap 설계

### cap 목록

| cap | 값 | 이유 |
|---|---|---|
| **실행당 itemLimit** | **50건** | 🔴 `tokenCap` 이 정한다 — 1건당 약 5,468 tok 이라 한 실행 상한이 91건이다 |
| `--apply`는 `--limit` 요구 | 필수 | 확립된 게이트 (VE-R3 · VE-M2-2) |
| burst (1회 실행) | **10건** | 첫 실험 크기와 같게 둔다 |
| **1일 soft cap** | **200건** | 하루에 사람이 관찰 가능한 양 |
| **1일 hard cap** | **1,000건** | 초과 시 **즉시 중단** |
| **token cap** | **500K / 실행** | 🔴 건수 cap만으로는 못 막는다 |
| **dollar cap** | **$5 / 실행** | 사람이 감당 가능한 상한 |
| timeout | **30초 / 건** | Micro Seed PROCESSING과 동일 |
| **retry도 cap에 포함** | 필수 | 🔴 cap 밖에 두면 **실패가 많을수록 비용이 커진다** |

🔴 **건수 cap만으로는 폭주를 못 막는다.** 본문 최대 3,000자 글이 몰리면 같은 건수에 토큰이 3배가 된다.
실측 분포: 본문 150~3,000자(중앙값 323 · 평균 539), 45.7%가 300자 미만.

### 실패 시 중단 조건

| 유형 | 처리 |
|---|---|
| 429 · 503 · timeout | 지수 백오프 **최대 3회** (retry는 cap에 포함) |
| 400 · 잘못된 입력 | **skip + 사유 기록**, 재시도 **0** |
| JSON 파싱 실패 | **1회만** 재시도 후 skip |
| 원문 삭제(우나어에 없음) | skip · `deletedDetectedAt` 기록 |
| **연속 실패 5회** | 🔴 **배치 전체 중단** |
| **token cap 도달** | 🔴 **즉시 중단** |
| **dollar cap 도달** | 🔴 **즉시 중단** |

### 🔴 비용 추정 — 모델/단가 미확정

**입력 규모는 실측했다.**

```
1건당 입력 ≈ 1,173자  (본문 평균 539자 + 댓글 10.6개 × 60자)
전량 9,674건 ≈ 11.35M자
한국어 1.3 tok/자 가정 시 ≈ 14.8M 입력 토큰
출력은 JSON 기준 건당 400~500 tok  →  전량 약 4.4M 토큰
```

🔴 **단가는 이 문서에서 확정하지 않는다.**
공식 가격 페이지를 확인하지 않았으므로 **모델/단가 미확정** 상태로 남긴다.

> ⚠️ **정정**: 이전 문서([VE-M2 설계 §5](./2026-08-26-voice-derived-m2-design.md))에
> "Haiku 전량 $35~40" 같은 **추정 금액**을 적었다. 그것은 확인된 가격이 아니라 추정이다.
> **실행 전 공식 가격을 확인하고, 확인한 출처와 날짜를 이 문서에 기록한 뒤** 진행한다.

> ✅ **2026-08-27 — 단가 확정.**
> `gpt-5-nano` $0.05/$0.40 · `claude-haiku-4.5` $1.00/$5.00 (per MTok, 출처·확인일 포함).
> 실측 토큰 환산 시 **전량 약 $2.50 vs $36.80**.
> 🔴 **실험은 단계형이다** — 1차 30건×2모델($0.231) → 필요 시 2차 100건×2($0.770) → 3차 300건 단일(최대 $2.18).
> 🔴 **모델은 여전히 미확정** — 단계마다 멈출 수 있고 사람이 정한다.
> 정본: [모델 선택 — 비용과 품질 기준](./2026-08-27-voice-m3-model-selection-criteria.md)

### 🔴 출력 토큰 상한 — 2026-08-27 1차 실행 실패에서 나왔다

**사고**: `gpt-5-nano` 1차 실행에서 호출 5건이 **전부 `JSON_PARSE` 로 실패**했다.
5건의 출력 토큰이 **정확히 1000** — 우연이 아니라 하드코딩 상한 `maxOutputTokens: 1000` 에 걸려 잘린 것이다.
연속 실패 5회 중단이 작동해 30건 중 5건에서 멈췄고 지출은 **$0.0024** 였다.

**원인**: `gpt-5-nano` 는 reasoning 계열이라 **reasoning 토큰이 `max_completion_tokens` 에 포함된다.**
1,000 을 추론이 다 쓰고 JSON 본문이 나오기 전에 끊겼다.
🔴 이것은 **모델 품질 문제가 아니라 우리 쪽 설정 결함**이다 — 이 실패를 근거로 모델을 판정하지 않는다.

**보정**: 상한을 **모델별로** 둔다. 한 숫자로 두면 둘 중 하나는 항상 틀린다.

| 모델 | `maxOutputTokens` | reasoning | 비용 추정치/건 | 근거 |
|---|---|---|---|---|
| `gpt-5-nano` | **4,000** | 포함 | **4,000** (=상한) | 산출물 450 + 추론 예산 약 3,550 |
| `claude-haiku-4.5` | **1,500** | 없음 | **700** | thinking 미사용. 450 산출물에 여유 3배 |

🔴 **reasoning 토큰도 출력으로 과금된다.** 그래서 reasoning 모델의 비용 추정은
"JSON 크기 450" 이 아니라 **상한 그대로**를 최악값으로 잡는다. 1차 실행의 추정이 실제와 어긋난 지점이 여기다.

🔴 **`tokenCap` 500K · `dollarCap` $5 · `itemLimit` 50 은 바꾸지 않았다.**
상한을 올려도 1건 최악값이 입력 1,745 + 출력 4,000 = 5,745 tok 이라 500K / 5,745 ≈ 87건 — 50 은 여전히 안전하다.

**30건 dry-run 실측 (2026-08-27, 유료 호출 0)**

| 모델 | 입력(추정) | 출력(추정) | 합계 | 예상 비용 | cap |
|---|---|---|---|---|---|
| `gpt-5-nano` | 153,108 | 120,000 | 273,108 | **$0.0557** | ✅ |
| `claude-haiku-4.5` | 153,108 | 21,000 | 174,108 | **$0.2581** | ✅ |

### 🔴 내부 라벨 ≠ provider 모델 ID (2026-08-27 보정)

**사고**: `claude-haiku-4.5` 30건 실행이 **5건 연속 `HTTP_404`** 로 중단됐다.
토큰 0 · **실제 비용 $0.0000** — provider 가 요청 자체를 거부해 과금이 없었다.

**원인**: `M3_MODEL_CANDIDATES` 의 **키(내부 라벨)를 그대로 API `body.model` 에 넣었다.**
`claude-haiku-4.5` 는 Anthropic 에 없는 이름이다(공식 ID `claude-haiku-4-5-20251001`).
`gpt-5-nano` 가 통했던 것은 내부 라벨이 **우연히** OpenAI 실제 ID 와 같았기 때문이다.

🔴 **이것은 Haiku 품질 실패가 아니라 모델 ID 매핑 실패다.** 이 결과로 모델을 판정하지 않는다.

**보정**: 둘을 항상 분리한다. 값이 같은 모델도 예외로 두지 않는다 — 예외를 두면 다음 모델에서 또 헷갈린다.

| | 값 | 쓰이는 곳 |
|---|---|---|
| 내부 라벨 (키) | `gpt-5-nano` · `claude-haiku-4.5` | `cacheKey` · `VoiceM3Run.model` · 보고 · 사람이 읽는 모든 곳 |
| `apiModelId` | `gpt-5-nano` · `claude-haiku-4-5-20251001` | 🔴 **provider 요청 `body.model` 전용** |

🔴 **`cacheKey` 는 내부 라벨을 유지한다.** provider 가 모델 ID 를 개정해도
(`-20251001` 같은 날짜 접미사가 바뀌어도) 실험 비교의 축이 흔들리면 안 된다.
`apiModelId` 는 `run` 코드에 등장하지 않으며, fixture 가 그것을 검사한다.

**남은 실패 5건은 지우지 않는다.** `failed` 는 재시도 대상이므로(§D) 다음 실행에서 자동으로 다시 불린다.
dry-run 실측: `재사용 0건(succeeded) · 재시도 5건(failed) · 신규 25건` · 표본 md5 `d25334ff…` 로 nano 30건과 **동일**.

### 🔴 실패 진단을 버리지 않는다 (2026-08-27 보정)

1차 실행은 `errorMessage` 에 `'JSON 파싱 실패'` 한 줄만 남겨 **원인을 확정할 수 없었다.**
이제 실패 시 아래를 함께 저장한다 — 🔴 **전부 수치 아니면 분류값이며, 응답 전문·원문·댓글·닉네임은 들어가지 않는다.**

```
json=truncated · finish=length · out=4000/4000 · reasoning=3550 · chars=812 · 🔴maxTokens 도달
```

| 항목 | 내용 |
|---|---|
| `finish` | provider 종료 사유. OpenAI `finish_reason` · Anthropic `stop_reason` |
| `out` | 출력 토큰 / 상한 |
| `reasoning` | reasoning 토큰 (모르면 표시하지 않는다 — 0 과 구분한다) |
| `chars` | 응답 **길이**만 |
| `json` | 파싱 실패 유형 `empty` · `truncated` · `fenced` · `not_json` · `invalid` |
| maxTokens 도달 | 종료 사유 + 토큰 대조 **둘 다** 본다 |

🔴 **종료 사유가 비어 있으면 성공으로 세지 않는다** (`NO_FINISH_REASON`).
잘림 여부를 판정할 수 없는 응답을 통과시키면 같은 사고가 조용히 반복된다.
`VoiceM3Run.errorSummary` 에는 실패 사유 분포를 남긴다.

가격 확인 시 아래 형식으로 남긴다.

```
확인일: YYYY-MM-DD
출처:   (공식 가격 페이지 URL)
모델:   (모델명)
단가:   입력 $X / MTok · 출력 $Y / MTok
```

**토큰 규모는 실측이므로 유효하다.** 단가만 채우면 금액이 나온다.

## F. 모델 선택 기준 — 확정하지 않는다

🔴 **이 문서에서 모델을 확정하지 않는다.** Haiku든 OpenAI든 다른 모델이든,
**10건 실험 전 창업자 승인 사항**이다.

### 판단 기준

| 기준 | 왜 |
|---|---|
| **비용** | 전량 9,674건이 대상이다. 배수 차이가 그대로 총액 차이다 |
| **한국어 자연어 감각** | 판정 대상이 40~60대 여성의 실제 말투다. 영어 벤치마크가 답을 주지 않는다 |
| **긴 원문 + 댓글 처리** | 본문 최대 3,000자 + 댓글 최대 103개. 한 건이 길다 |
| **JSON 안정성** | 파싱 실패는 재시도이고 재시도는 비용이다 |
| **캐시 · 재시도 운영성** | 결정성이 낮으면 캐시의 의미가 줄어든다 |

### 판단 방법

**10건 실험 결과를 사람이 읽고 정한다.** 벤치마크 점수가 아니라
"이 판정이 우리 또래 글에 대해 말이 되는가"로 본다.

같은 10건을 후보 모델 2개에 돌려 비교하는 것도 가능하다 — 그러면 실험 cap이 20건이 되므로
그 자체가 승인 대상이다.

## G. 10건 실험 설계

### 무작위가 아니다

10건은 **대표 샘플**이어야 한다. 무작위로 뽑으면 `other` 81% · 짧은 본문 45.7%라는
분포 때문에 **비슷한 글만 10개** 나온다.

### 선정 기준 — 축별로 최소 1건씩

| # | 축 | 선정 조건 | 왜 넣는가 |
|---|---|---|---|
| 1 | 댓글 많은 글 | `commentCount >= 22` (p90 이상) | 반응 해석이 가장 필요한 쪽 |
| 2 | 댓글 적은 글 | `commentCount <= 3` | 신호가 빈약할 때 어떻게 나오는지 |
| 3 | `sourceSpecific` 포함 | `우갱님들`·`은오님들`·`레테님들` 중 1 | 호칭 치환 판단이 걸리는 글 |
| 4 | `targetDescriptorRisk` 포함 | `중년 여성`·`우리 또래` 등 (전체 7건뿐) | 🔴 **생성 금지어가 원문에 있는 경우** |
| 5 | `emotionalPeak` 있음 | `legacyLabels.emotionalPeak` 존재 (34.2%) | 감정 축 라벨이 있는 쪽 |
| 6 | `psychInsight` 있음 | 존재 (99.9%) + 길이 상위 | 해석 라벨이 풍부한 쪽 |
| 7 | `usedAt` referenced | `VoiceJudgment` 존재 (32%) | 우나어 큐레이션이 고른 글 |
| 8 | 짧은 본문 | `contentLength` 150~250 | 표본 부족 구간(`lowSample`) |
| 9 | 긴 본문 | `contentLength >= 1,168` (p90 이상) | 토큰 상한과 처리 한계 |
| 10 | `reactionType` other 다수 | other 비율 >= 90% | 🔴 **규칙이 실패한 바로 그 구간** |
| — | `communityRegister` 비어 있음 | `sourceSpecific`·`generic` 모두 0 | 호칭 신호가 없을 때의 기준선 |

> 축이 11개이고 건수가 10건이므로 **한 글이 두 축을 겸할 수 있다**(예: 긴 본문 + 댓글 많음).
> 겸하는 경우 그 사실을 실험 기록에 남긴다. **축이 하나라도 비면 10건을 다시 고른다.**

### 제외

- `contentLength = 3000` (수집 상한에서 잘린 230건) — 끝이 잘려 흐름 판정이 오염된다
- `legacyLabels` drop 이력이 있는 행

### PASS / FAIL 기준

**PASS** — 아래를 **전부** 만족

| 항목 | 기준 |
|---|---|
| JSON 파싱 | 10/10 성공 |
| 스키마 준수 | 7종 전부 존재 · 타입 일치 · 범위 0~100 |
| **원문 유출** | 출력 JSON에 원문·댓글 **20자 이상 연속 일치 0건** (§H) |
| **닉네임** | 출력에 0건 |
| **생성 금지어** | 출력에 `우리 또래분들`·`중년 여성분들` 등 **0건** |
| 반대 축 정합성 | `overSanitizedRisk`와 `overMimicryRisk`가 **동시에 높지 않다** |
| 비용 | 실행 총액이 dollar cap 이내 |
| 사람 판정 | 창업자가 10건 전부 읽고 **"말이 되는가"에 동의** |

**FAIL** — 하나라도 해당

- 원문·댓글 20자 이상 연속 일치가 **1건이라도** 발견
- 닉네임이 출력에 등장
- 생성 금지어가 출력에 등장
- JSON 파싱 실패가 재시도 후에도 2건 이상
- 점수가 전 건 동일하거나 무의미하게 분포(판정이 작동하지 않는다는 뜻)

🔴 **FAIL이면 배치로 넘어가지 않는다.** 프롬프트·모델·스키마를 고쳐 10건을 다시 돌린다.

## H. 원문 유출 방지

### 금지

| 금지 | 기준 |
|---|---|
| 출력 JSON에 **원문 20자 이상 연속** 문자열 | 공백 정규화 후 비교 |
| 출력 JSON에 **댓글 원문 20자 이상 연속** 문자열 | 〃 |
| **닉네임 저장** | 원문 형태 일체. `authorHash`만 |
| 로그 출력 | 원문 · 댓글 · 닉네임 전부 |

임계값 20자는 VE-R3.1에서 확립됐다 — 한국어 20자면 한 문장에 가깝고, 우연히 겹칠 길이가 아니다.
VE-M2 전량 검증에서 **110,713조각 대조 0건**으로 이 기준이 실제로 작동함을 확인했다.

### 호칭 처리

| 갈래 | VE-M3에서 |
|---|---|
| `sourceSpecific` (`82님들`·`우갱님들`·`레테님들`·`은오님들`) | **분석 신호로만 사용.** 생성물에 그대로 쓰지 않는다 |
| 소란소란 생성 호칭 | **`소란님들` · `소란소란님들` · `소란님` · `소란소란님`** |
| 🔴 **생성 금지어** | **`우리 또래분들` · `중년 여성분들` · `50대 여성분들` · `같은 세대 분들`** 및 타겟 설명어 일체 |

**"원문에 있다 ≠ 우리가 써도 된다."** VE-M2 전량에서 타겟 설명어가 원문에 7건 존재했고,
가드가 전부 "생성 금지"로만 분류했다([VE-M2 완료 §5](./2026-08-27-voice-m2-completion.md)).
LLM이 그 표현을 보고 따라 쓰는 것을 프롬프트와 출력 검사 양쪽에서 막는다.

### 검증 방법

10건 실험 직후, 저장 전에 **출력 JSON을 우나어 원문·댓글과 전수 대조**한다.
VE-M2에서 쓴 방식과 같다 — 원문에서 20자 조각을 떼어 출력에 있는지 본다.
**저장은 이 검사를 통과한 뒤에만 한다.**

## I. VE-M3 이후에도 금지되는 것

VE-M3가 성공해도 아래는 열리지 않는다.

| 금지 | 근거 |
|---|---|
| **자동 발행** | 사람을 건너뛰지 않는다 ([VE-0 §4-1](./2026-08-27-voice-engine-v0-contract.md)) |
| **Original Lane index 발행** | 그 레인의 정책·게이트가 하나도 없다 (VE-0 §2-3) |
| **원문 그대로 공개** | 정책 8 영구 noindex · 정책 10 index 전환 영구 금지 |
| **댓글 자동 생성 · 반응 조작** | 정책 14 — 댓글은 반응 지도이지 만들어낼 숫자가 아니다 |
| **사람 승인 없는 rewrite 발행** | `rewriteDirection`은 방향이고 `rewrittenBody`는 만들지 않는다 |
| **publisher 변경** | 원문 그대로 발행이 계약이다 (VE-0 §10-3) |

🔴 **점수가 좋다는 이유로 발행 조건을 자동화하지 않는다.** 7종은 전부 사람이 읽는 재료다(§B).
