# 소란소란 매거진 전략

> 작성일: 2026-08-23 · 기준 커밋: `2a4bcb4`
> 성격: **콘텐츠 운영 전략 문서**.
> 색인 규칙은 [SEO 색인 정책](./2026-08-23-soransoran-seo-index-policy.md)이 정본이다.
> 이 문서는 색인 규칙을 **다시 정의하지 않고 참조만** 한다.

---

## 0. 한 줄 판정

> 매거진은 **우리가 쓴 글**이다. 사람이 검수하지 않은 글이 공개되는 경로를 만들지 않는다.

우나어의 네이버 색인 붕괴(4,600 → 0)는 기술 실수가 아니라
"사이트 안에서 무엇이 원본이고 무엇이 외부 반응 글인지 검색엔진이 구분하지 못한 것"이었다.
매거진은 그 경계를 흐릴 수 있는 유일한 영역이라, 시작하기 전에 규칙을 고정한다.

## 1. 매거진의 역할

### 커뮤니티와 다른 점

| | 커뮤니티 | 매거진 |
|---|---|---|
| 저자 | 회원 | 소란소란 편집팀 |
| 성격 | 경험·질문·대화 | 정리된 설명 |
| 글쓰기 버튼 | 노출 | **노출하지 않는다** (IA 정본) |
| 발행 | 회원이 직접 | 창업자 검수 후 |

### SEO 최전방이지만 목적은 참여 전환

매거진은 검색 유입의 최전방이다. 갱년기·수면·감정 같은 검색어의 착지점이 된다.

**다만 유입 자체가 목적이 아니다.**
North Star는 주간 재방문 참여 유저 수다.
검색으로 들어온 사람이 글만 읽고 나가면 우나어와 같은 구조가 된다.
모든 매거진 글은 **커뮤니티로 돌려보내는 출구**를 가진다(원칙 9).

## 2. 운영 원칙 10개

**원칙 1 — 매거진은 "우리가 쓴 글"이다.**
커뮤니티는 회원 글, 매거진은 편집팀 글. 이 구분이 흐려지면
SEO 정책 원칙 2("무엇이 대표 문서인지 헷갈리지 않게")가 무너진다.

**원칙 2 — 외부글을 수집·요약·재발행하지 않는다.**
크롤·RSS·뉴스 요약 전부 금지. 우나어 실패 F1의 정확한 재현 경로다.

**원칙 3 — 서비스 안에 AI API를 두지 않는다.**
소란소란 런타임에 LLM 호출이 없다. AI는 **창업자의 편집 도구**로만 존재한다.

**원칙 4 — 자동 발행 경로를 만들지 않는다.**
사람이 검수하지 않은 글이 공개되는 경로가 **구조적으로 존재하지 않아야** 한다.
크론·웹훅·에이전트 발행 금지.

**원칙 5 — 최종 원고의 책임은 창업자에게 있다.**
AI 초안은 초안일 뿐이다. 발행은 "창업자가 읽고 고쳤다"는 뜻이다.

**원칙 6 — 하루 2건 대량 발행보다 하루 1건 품질.**
속도를 목표로 삼는 순간 AI티가 난다. 발행 속도는 §4.3.

**원칙 7 — AI티를 지운다.**
반복 문형("~에 대해 알아보겠습니다", "결론적으로"), 균일한 문단 길이,
과도한 불릿, 근거 없는 수치. 발행 전 **소리 내어 읽어보고 어색하면 고친다**.

**원칙 8 — 의료·건강 글은 진단하지 않는다.**
증상 설명과 생활 관리까지. **진단·치료·약 권유 금지.**
모든 건강 글에 병원 상담 권장 문구를 넣는다(§4.4).
이건 SEO가 아니라 신뢰와 안전의 문제다.

**원칙 9 — 매거진 글은 커뮤니티로 돌려보낸다.**
모든 글 말미에 관련 게시판·질문 유도를 둔다.

**원칙 10 — 색인 규칙은 SEO 정책 문서를 따른다.**
이 문서에서 `robots`·`canonical`·`sitemap` 규칙을 다시 정의하지 않는다.
두 문서가 어긋나면 사고가 난다.

## 4. 콘텐츠 전략

### 4.1 주제 클러스터 8개

| 클러스터 | 예시 주제 |
|---|---|
| 갱년기 증상 | 안면홍조 · 발한 · 관절통 |
| 수면 | 새벽에 깨는 이유 · 잠자리 습관 |
| 감정 | 이유 없는 우울 · 짜증 · 무기력 |
| 부부/가족 | 남편과의 거리 · 자녀 독립 |
| 병원/검진 | 언제 가야 하나 · 무슨 과인가 · 검진 항목 |
| 일상관리 | 식사 · 운동 · 체중 |
| 돈/일 | 재취업 · 소득 공백 · 노후 준비 |
| 관계 회복 | 친구 · 모임 · 혼자 있는 시간 |

**관련글은 같은 클러스터 안에서 연결한다.** 클러스터를 넘나들면 주제 신호가 흐려진다.

### 4.2 글 구조 5단

```
1. 공감 도입        "저도 그랬습니다" — 증상·상황을 먼저 인정
2. 쉬운 설명        왜 그런지. 전문 용어를 쓰면 바로 풀어쓴다
3. 체크리스트/실천  오늘 할 수 있는 것 3~5개
4. 관련 글 연결     같은 클러스터의 다른 글
5. 커뮤니티 참여    "여러분은 어떠셨나요" + 게시판 링크
```

**5단이 원칙 9의 실행 수단이다.** 빠뜨리면 유입만 받고 이탈한다.

### 4.3 발행 속도

```
1주차       하루 1건       품질 기준을 잡는 기간
2주차 이후  하루 1~2건     검수 시간이 확보되는 선에서
1달 목표    25~40건
```

**속도가 품질을 넘지 않게 한다.** 검수할 시간이 없으면 그날은 발행하지 않는다.

### 4.4 의료/건강 안전 문구

건강 관련 글에는 **본문 안**과 **글 하단** 두 곳에 둔다.

```
본문 안   증상을 설명한 직후 — "증상이 오래가거나 심하면 병원에서 확인해 보세요."
하단 고정 "이 글은 정보 제공을 위한 것이며 의학적 진단이나 치료를 대신하지 않습니다.
          증상이 있다면 의료진과 상담하세요."
```

**금지 표현**: "~하면 낫습니다" · "~를 드세요"(약·보조제 권유) · 특정 병원/제품 지목 ·
"이것은 ~병입니다"(진단 단정).

## 5. 발행 루틴

```
① 주제 선택       창업자가 클러스터에서 고른다
                  최선은 커뮤니티에 실제로 올라온 질문에서 뽑는 것
② 원고 초안       ChatGPT/Claude 대화창에서 생성 · 글 구조 5단 지시
③ 창업자 검수 ★   사실 확인 · AI티 제거 · 의료 안전 문구 · "우리 나이" 표현 확인
④ 이미지 생성     ChatGPT 등에서 수동 생성 → 내려받아 repo 에 커밋 · alt 텍스트 필수
⑤ repo 반영       콘텐츠 파일 + 이미지를 커밋
⑥ QA              typecheck / lint / build + 배포 후 200 · canonical 확인
⑦ 배포            push → Vercel → smoke
```

**③이 유일한 필수 게이트다.** 다른 단계는 도구가 바뀌어도 되지만
③을 건너뛰면 원칙 5가 무너진다.

**소요 예상**: 익숙해지면 글 1건에 30~60분
(초안 10분 + 검수 20분 + 이미지 10분 + 반영·QA 10분).

## 6. v0 구현 전제

### D1 — v0 는 Git 기반 파일 발행 (확정)

매거진 글을 **repo 안의 콘텐츠 파일**로 관리한다. 커밋 → push → 배포가 곧 발행이다.

**왜 이 방식인가**

1. **원칙 4·5가 구조적으로 강제된다.** 커밋·push 없이는 공개될 수 없고, diff 를 보지 않고 발행할 수 없다.
2. **스키마를 건드리지 않는다.** `Post` 에 slug 가 없고 `authorId` 가 필수인 문제(§9)를 피한다.
3. **이미지가 함께 커밋된다.** 업로드 인프라가 필요 없다.
4. **되돌리기가 `git revert` 한 번이다.**

### 파일 형식 — TS 데이터 파일 + 블록 배열 (6-C 확정)

`src/content/magazine/` 에 **메타데이터 + 본문 블록 배열**을 TypeScript 로 둔다.

```
types.ts     MagazineArticle · MagazineBlock(p/h2/h3/list/callout/image) · MagazineCluster
articles.ts  발행된 글 배열
```

**md + frontmatter 를 쓰지 않는다.** 6-C 감사에서 확인한 근거:

1. **의존성 0.** 파서·렌더러·플러그인을 들이지 않는다.
2. **타입이 SEO 기준을 강제한다.** 이미지 `alt` 는 optional 이 아니라 필수 필드라
   누락하면 빌드가 막는다. `cluster` 오타·slug 형식도 컴파일 타임에 걸린다.
3. **sanitize 가 필요 없다.** 우나어는 DB 에 HTML 을 저장해
   `sanitize-html`(203행) + `dangerouslySetInnerHTML` 이 필요했다.
   우리가 쓴 글만 싣고 HTML 을 쓰지 않으므로 그 표면 자체가 없다.
4. **창업자가 TS 를 직접 쓰지 않는다.** 원고는 대화창에서 나오고 repo 반영은 §5 ⑤ 에서
   Claude Code 가 한다. 창업자는 PR diff 를 검수한다. md 의 작성 편의는 실질 이득이 아니다.
5. **DB 전환 시 손실이 없다.** 블록 배열은 JSON 컬럼에 그대로 들어간다.

🚫 md/frontmatter · markdown parser · sanitize-html · MDX · `dangerouslySetInnerHTML` 도입 금지.

### D2 — URL 은 영문 slug (확정)

```
/magazine/menopause-sleep
/magazine/hot-flash-basics
```

**규칙**: 소문자 · 하이픈 구분 · 주제를 알아볼 수 있게 · 한 번 정하면 바꾸지 않는다.
(slug 변경은 URL 변경이고, 색인된 뒤에는 되돌리기 어렵다)

### DB/admin 발행은 보류

**보류 이유**: admin 발행 화면을 만들면 권한·에디터·이미지 업로드가 함께 딸려온다.
우나어 매거진 상세가 410행이 된 경로가 이것이다.
글이 0건인 지금 그 복잡도를 미리 만들 이유가 없다.

### DB/admin 전환 조건

아래 **셋 중 하나**가 오면 재검토한다.

1. 매거진 글 **50건 이상** — 파일 관리가 버거워질 때
2. **창업자 외 편집자 추가** — git 을 요구할 수 없을 때
3. **예약 발행 · 수정 이력**이 실제로 필요해질 때

**셋 중 하나도 오지 않았다면 Git 기반을 유지한다.**

## 7. SEO 기준

### 색인 규칙은 SEO 정책 문서가 정본

`robots` · `canonical` · `sitemap` 규칙은
[SEO 색인 정책](./2026-08-23-soransoran-seo-index-policy.md) §2 route별 표를 따른다.
이 문서에서 다시 정의하지 않는다.

### 글 단위 SEO 기준

| 항목 | 기준 |
|---|---|
| `title` | 검색어를 앞쪽에 · 40자 내외 · 낚시성 금지 |
| `description` | 본문 자동 절단이 아니라 **직접 작성** · 요약이지 예고편이 아니다 |
| `canonical` | 자기 경로(`/magazine/{slug}`) · SEO 정책 원칙 4 |
| OG 이미지 | 글 대표 이미지 → 없으면 로고 폴백 |
| 이미지 `alt` | **모든 이미지 필수** · "이미지" 같은 무의미한 값 금지 |
| 관련글 | **같은 클러스터** 안에서 2~3개(§4.1) |
| internal link | 본문에서 관련 게시판·다른 매거진 글로 연결 · 억지 삽입 금지 |

### D6 — 첫 글 발행과 같은 PR 에서 색인 전환 (확정)

현재 `/magazine` 은 발행 경로가 없어 `noindex, follow` + sitemap 제외 상태다
(SEO 정책 §2 · §6).

**첫 글을 발행하는 PR 에서 함께 처리한다.**

```
1. src/app/magazine/page.tsx 의 robots 한 줄 제거
2. sitemap.ts 에 /magazine 재포함
3. /magazine/{slug} 는 발행 글만 index
```

**쪼개지 않는 이유**: 먼저 noindex 를 풀면 빈 페이지가 색인되고,
먼저 글만 올리면 색인되지 않는 글이 생긴다. 둘 다 원칙 3(SEO 정책)에 어긋난다.

**발행 글이 0건으로 돌아가면 noindex 를 다시 건다.**

## 8. 우나어에서 가져올 것 / 버릴 것

### 가져올 패턴

| 패턴 | 적용 |
|---|---|
| 관련글 연결 | **같은 클러스터** 기준. 원칙 9의 실행 수단 |
| OG 이미지 폴백 체인 | 대표 이미지 → 본문 첫 이미지 → 로고. 공유 카드가 항상 뜨게 |
| slug 기준 canonical | D2 로 자연히 해결 |
| HTML sanitize | 본문을 HTML 로 렌더한다면 필수 |
| BreadcrumbList JSON-LD | 구조화 데이터 중 **이것만**. 검색 결과 경로 표시에 실효 |

### 버릴 것

| 대상 | 이유 |
|---|---|
| AdSense · NativeAd 슬롯 | 광고 금지. 본문 흐름 절단(우나어 F8) |
| 외부 이미지 프록시 | 외부글 전제. 소란소란은 자체 이미지만 |
| 시리즈(`/series/[seriesId]`) | 글 0건에서 시리즈는 과하다. 50건 이후 재검토 |
| 본문 HTML 파싱 FAQ JSON-LD | 복잡도 대비 실익이 낮다 |
| 목록 필터 동적 로드 | 글 수십 건까지 불필요 |
| 조회 트래커 | 트래킹 금지 |
| 410행 상세 구조 자체 | 통째로 옮기면 관리 불가 |

## 9. 스키마 미결 사항

Git 기반(D1)으로 시작하면 **아래 셋 다 지금은 건드리지 않아도 된다.**
DB/admin 전환을 검토할 때 다시 꺼낸다.

| # | 사실 | 영향 |
|---|---|---|
| **S1** | `Post` 에 **`slug` 필드가 없다** | DB 발행으로 가면 `/magazine/{slug}` 를 위해 스키마 변경이 필요하다 |
| **S2** | `Post.authorId` 가 **필수 + `onDelete: Restrict`** | 매거진 글도 User 행이 있어야 한다. "편집팀" 계정을 만들지 `source: SYSTEM` 으로 둘지 결정이 필요하다 |
| **S3** | Prisma `BoardType` 은 `MENOPAUSE`·`FREE`·`MAGAZINE` — **`BEST` 가 없다** | `board-registry` 의 타입은 4개짜리 superset 이다. 매거진은 DB 개념이지만 베스트는 아니다 |
