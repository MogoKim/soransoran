## 1. 프로젝트 정의

**프로젝트명** `S-MON — Soransoran Monetization`

**목적** `결정`

- 고객 경험과 커뮤니티 참여를 훼손하지 않는 수익 기반을 만든다.
- 검색 · 매거진 · 커뮤니티 방문이 운영비에 지속적으로 기여하게 한다.
- AdSense 와 쿠팡 파트너스를 분리해서 측정한다.
- 광고 구현을 콘텐츠와 자동화에서 분리한다.

**우선순위** `결정`

```text
고객 가치·안전 > D100 핵심 운영·배포 > 진행 중 회원가입 전환 측정 보존 > M-GRAPH·M-AUTO 안정성 > 광고 수익
```

광고 수익은 맨 마지막이다. 앞의 네 가지 중 하나라도 해치면 그 광고는 끈다.
광고 작업은 D100 핵심 운영·배포의 순서를 밀어내지 않고, 진행 중인 회원가입 전환 측정의 연속성을 깨지 않는다.
광고는 North Star(7일 안에 다시 방문해 글이나 댓글을 남긴 실제 사용자 수)를 대신하지 않는다.

회원가입 전환 프로젝트(`MC-*`)와 별도 프로젝트다. 단계 이름은 `MON-*` 을 쓴다.

## 2. 목표 `결정`

- Production 공개 콘텐츠 화면에 **명시적인 광고 슬롯**을 제공한다.
- 전체 · 페이지 · 슬롯 단위로 각각 끌 수 있다.
- 광고 실패가 콘텐츠 실패로 번지지 않는다.
- 소란소란 전용 광고 단위와 보고를 쓴다.
- 화면별 수익과 회원가입 전환 영향을 비교할 수 있다.
- 최종적으로 AdSense 와 쿠팡을 홈 · 목록 · 상세에 단계적으로 적용한다.

## 3. 비목표 — 만들지 않는 것 `결정`

- 광고용 DB · 테이블 · migration
- 광고 관리자 페이지
- 광고 queue · scheduler
- 범용 provider framework
- 상품 자동 추천 AI
- 자체 CMP
- 자체 광고 통계 시스템
- 초기 쿠팡 Open API 연동
- 게시글 · 매거진 원고 안의 광고 데이터
- Google Auto Ads
- 전면 · 앵커 · 팝업 · 자동 삽입 광고
- 본문 문단 사이 광고

필요성이 실제 숫자와 운영 문제로 확인되면 별도 판단 · 승인 뒤에 다시 본다.

## 4. 기대 결과 `결정`

### 코드 결과

- 광고 정본 1개 (이 문서)
- 광고 설정표 1개
- 공통 `AdSlot` 계층
- AdSense loader 1개
- `CoupangUnit` 1개
- 광고 검사 1개
- 전체 kill switch

### 운영 결과

- 광고가 꺼져 있으면 광고 DOM · 예약 공간 · 네트워크 요청이 모두 0이다.
- 광고가 실패해도 본문 · 댓글 · 관련 글은 정상이다.
- 광고 위치별 성과를 따로 본다.
- 회원가입 전환과 성능에 준 영향을 광고 전후로 비교한다.
- 광고 문제가 생기면 빠르게 전체를 끈다.

### 성과를 말하는 기준

| 구분 | 뜻 |
|---|---|
| code PASS | 코드와 검사가 있다 |
| deployed PASS | Production 에 배포됐다 (광고는 꺼진 상태일 수 있다) |
| operating PASS | 실제 방문에서 광고가 안전하게 동작한 관측이 있다 |
| outcome PASS | 수익과 전환 영향을 충분한 표본으로 판단했다 |

- 켠 뒤 첫 48시간은 **기술 안전성**만 본다.
- 첫 7일은 초기 노출 · fill · 클릭을 본다.
- 약 28일 뒤 화면별 수익과 전환 영향을 평가한다.
- 표본이 작으면 성공도 실패도 단정하지 않는다. "광고 운영 완료", "수익화 성공" 같은 표현을 쓰지 않는다.

## 5. 화면별 최종 정책 `결정`

아래는 **최종 상한**이다. 처음부터 전부 켜지 않는다. 켜는 순서는 §12 가 정한다.

### 공통 원칙

- 명시적인 고정 슬롯만 쓴다.
- 광고에는 "광고" 표시를 붙여 콘텐츠와 구분한다.
- AdSense 와 쿠팡을 같은 자리에 동시에 내지 않고, 두 광고를 연속해서 붙여 놓지 않는다.
- 광고 공간을 미리 예약해 화면이 밀리지 않게 한다.
- 첫 화면 · hero 이미지의 로딩 경로에서는 광고를 늦게 불러온다.
- 게시글 배열 · 순위 · 페이지 계산은 바꾸지 않는다. 렌더링할 때 광고 UI 만 끼워 넣는다.

### 홈 — 최대 3개

1. 「지금 뜨는 이야기」 뒤 AdSense (그 섹션이 화면에 있을 때만)
2. 「읽어볼 이야기」 뒤 쿠팡
3. 가입 CTA 뒤, 또는 로그인 상태라 가입 CTA 가 없으면 페이지 최하단에 AdSense

### 커뮤니티 목록 — 최대 3개

1. 실제로 렌더된 4번째 글 뒤 AdSense
2. 실제로 렌더된 8번째 글 뒤 쿠팡
3. 페이지네이션이 실제로 보일 때 그 아래 AdSense

글이 4개보다 적으면 1번 광고는 없다. 8개보다 적으면 2번 광고는 없다.

### 베스트 — 최대 3개

- 커뮤니티 목록과 같다.
- 광고는 순위 배열에 들어가지 않는다. 순위 번호와 페이지 계산에 광고를 세지 않는다.

### 매거진 목록 — 최대 2개

1. 4번째 글 뒤 AdSense
2. 8번째 글 뒤 쿠팡

### 커뮤니티 · D100 상세 — 최대 3개

1. body-end marker 뒤 AdSense
2. 이어읽기 뒤 쿠팡
3. 글쓰기 CTA 뒤 최하단 AdSense

- 켜는 순서는 **최하단 → 쿠팡 → body-end** 다.
- 회원가입 전환 marker 의 위치와 의미는 바꾸지 않는다.
- body-end 뒤 광고는 본문 끝에서 댓글 끝까지의 거리를 늘려 `가입 제안 기준 도달` 비율을 바꿀 수 있다.
  그래서 맨 마지막에 단독으로 켜고, 회원가입 전환 담당과 함께 판단한다.
- 회원 글과 D100 Persona 글은 같은 화면 구성을 쓴다. 광고 때문에 둘을 다르게 렌더하지 않는다.
- D100 게시물 본문이나 DB 데이터에 광고 HTML · 상품 링크를 넣지 않는다.

### 매거진 상세

- 본문 · 본문 안 커뮤니티 CTA · content-end marker · M-GRAPH 관련 탐색(「함께 읽어보세요」)이
  **모두 끝난 뒤**에만 수익 슬롯을 둔다.
- 처음에는 AdSense 1개만 둔다.
- 문맥형 쿠팡은 승인된 `주제 → 상품` 매핑이 있을 때만 둔다.
- 관련 글 사이에 광고를 넣지 않는다. 광고를 M-GRAPH 링크보다 먼저 보여 주지 않는다.
- 원고 block · `articles.ts` · graph 데이터에 광고를 넣지 않는다.

### 광고를 내지 않는 화면

- 로그인 · 카카오 callback
- 회원가입 · 온보딩
- 글쓰기 · 수정
- 관리자 화면 전체
- 신고 · 차단
- 개인정보처리방침 · 이용약관
- 오류 화면 (404 · 500 등)
- Preview 와 Development 환경 전체

## 6. 단순한 기술 구조 `결정`

### 처음에 허용하는 구성

| 구성 | 역할 |
|---|---|
| `AdSlot` | 서버에서 켬/끔을 판정한다. 꺼져 있으면 아무것도 렌더하지 않는다 |
| `AdSenseUnit` | AdSense 광고 한 칸. script 는 한 번만 불러온다 |
| `CoupangUnit` | 쿠팡 배너 한 칸. AdSense 와 섞지 않는다 |
| 광고 config | 전체 · 페이지 · 슬롯의 켬/끔 표. 기본값은 전부 OFF |
| 광고 check | 위치 · 금지 파일 · 기본값 · ID 를 검사한다 |

### 원칙

- 전체 · 페이지 · 슬롯 기본값은 모두 **OFF** 다.
- 켬 조건은 `Production 환경` **그리고** `전체 ON` **그리고** `페이지 ON` **그리고** `슬롯 ON` 이다.
  하나라도 아니면 광고 DOM · 공간 · 요청이 0이다.
- DB schema · migration · Edge Config · 관리자 UI 는 쓰지 않는다.
  전체 kill switch 는 env 와 재배포로 동작한다. 끄는 데 재배포 시간이 걸린다는 한계를 받아들인다.
- 광고는 UI 렌더링 계층에만 둔다.
- 광고는 회원가입 전환과 분리된 UI 렌더링 작업이다. 가입 제안 문구·노출 조건·`content_end` marker·tracker·
  24시간 제한·①~⑤ 집계 코드를 바꾸지 않는다.
- D100 · M-AUTO · M-GRAPH 데이터와 import 관계를 만들지 않는다.
- 광고 코드는 회원가입 전환 계측과 GA 이벤트를 import 하지 않는다. 광고 이벤트를 전환 이벤트에 섞지 않는다.
- 광고 실패(no-fill · 차단 · script 오류)는 광고 칸 안에서 끝난다. 예외가 앱으로 번지지 않는다.
- 광고 칸에는 화면 고정 위치 · 높은 레이어 순서를 쓰지 않는다. 기존 Header · 가입 제안 · FAB ·
  모바일 댓글 입력 바와 겹치지 않게 한다.

### 현재 코드 사실 `사실`

| 항목 | 현재 |
|---|---|
| 광고 코드 · `ads.txt` | MON-2A 기본 OFF 기반 — 홈 최하단 슬롯 1개 · env 기반 `/ads.txt`. env 가 없어 Production 은 광고 흔적 0 · `/ads.txt` 404 |
| 보안 헤더 · CSP | 없음. 외부 script 는 GA · Turnstile · Kakao SDK 를 DOM 에 주입하는 방식 |
| Production 판정 | 회원가입 전환 gate 가 `VERCEL_ENV === 'production'` 을 쓴다. client 용 환경 변수는 없다 |
| 쓰기 FAB | 홈 · 게시판 목록에만 화면 고정. 390px 에서 페이지네이션 마지막 버튼과 겹치는 문제가 이미 기록돼 있다 |
| 모바일 댓글 입력 바 | 커뮤니티 상세에서 조건부로 화면 하단에 고정 |
| 목록 마크업 | 모든 목록이 `<ul>`/`<ol>` 이고 직계 자식이 `<li>` 다. 목록 중간 광고도 `<li>` 여야 한다 |
| 커뮤니티 상세 marker | 본문 카드 바로 뒤 body-end · 댓글 목록 끝 content-end |
| 매거진 상세 marker | 본문 카드 안 끝 content-end. 그 아래 「함께 읽어보세요」 |

## 7. 개인정보 · 동의 `결정`

- 개인정보처리방침 개정판은 **광고 script 를 처음 불러오기 전에** Production 에 배포한다. 개정 배포가 광고
  요청보다 먼저다. 개정판은 배포일부터 시행하며 소급하지 않는다. 방침 배포는 광고 활성화가 아니다.
- 개정판은 위탁 · 국외 이전 · 쿠키 · 행태정보 절에 Google Analytics 와 Google AdSense 를 구분해 적고,
  옛 9조 4항("광고 목적의 추적을 위해 쿠키를 사용하지 않습니다")을 제거한다(MON-2B).
- 별도 사전 공지 배너 · 공지 게시글 · 7일 대기는 광고 운영 gate 가 아니다. 창업자 제공 외부 법률 확인에
  따른 운영 결정이다. 방침 변경은 변경 내용과 시행일을 방침에 공개하고, 법령상 사전 고지가 필요한 경우
  그 법령의 기간과 방법을 따른다.
- 처음 AdSense 는 **전 세계 비맞춤형 광고(NPA)를 우선**한다. NPA 도 빈도 관리 · 성과 집계에 쿠키 또는 유사
  기술을 쓸 수 있다고 방침에 적는다. NPA 가 CMP · 동의 의무를 대신한다고 쓰지 않는다.
- EEA · 영국 · 스위스 방문자에게는 Google 인증 CMP 를 쓴다. 자체 CMP 를 만들지 않는다.
- 동의가 필요한 지역에서는 동의 전 광고 요청이 0이어야 한다.
- Google Auto Ads 는 쓰지 않는다.
- 소란소란 전용 `ads.txt` 를 쓴다.
- 쿠팡 광고에는 광고 · 제휴 고지를 슬롯 바로 옆에 상시 표시한다.
- **법률 확정 판단과 기술 구현을 구분한다.** 이 문서는 법률 판단을 내리지 않는다. 어떤 고지 ·
  동의가 법적으로 필요한지는 창업자가 확인하고, 구현은 확인된 결론만 반영한다.

현재 사실 `사실`: 서비스 코드에는 쿠키 배너 · 동의 상태 · CMP 구현이 없다. EEA · 영국 · 스위스용 CMP 는 AdSense 콘솔의
Google 자체 CMP 로 준비한다. GA 는 운영 도메인에서 동의 절차 없이
로드된다. GA 와 동의의 관계는 S-MON 범위 밖이며 회원가입 전환 정본의 GA4 보정(`MC-M3P`)과 따로 다룬다.

- AdSense 운영에는 소란소란 전용 Google 로그인 계정을 쓴다.

  로그인은 소란소란 전용으로 나누지만 publisher 계정은 하나다.
- 이메일 주소 · publisher ID 는 이 정본에 적지 않는다.
