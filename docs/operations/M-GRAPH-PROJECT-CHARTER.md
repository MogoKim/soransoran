## 1. 이름과 관계

| 구분 | 공식 명칭 | 역할 |
|---|---|---|
| 기존 발행 자동화 | **M-AUTO: 소란소란 매거진 완전 자동화** | 생성·QA·이미지·예약·병합·배포·공개 감시 |
| 이번 성장 프로젝트 | **M-GRAPH: 소란소란 검색 주제망 자동화** | 검색 영토·주제망·시리즈·연결·장기 계획 |
| 전체 시스템 | **소란소란 매거진 자동 성장 시스템** | M-GRAPH + M-AUTO |
| 구현 식별자 | `magazine-topic-network` | 코드·파일·리포트 공통 이름 |

M-AUTO는 M-GRAPH로 교체되거나 며칠 뒤 사라지는 시스템이 아니다.

```text
M-GRAPH  무엇을 왜 어떤 관계로 발행할지 결정한다
    ↓
M-AUTO   정해진 대상을 안전하게 만들고 공개한다
```

M-AUTO는 **공급 엔진**, M-GRAPH는 **편집·검색·성장 설계**다.

## 2. 프로젝트 한 줄 정의

> 소란소란의 정체성과 핵심 독자를 기준으로 실제 검색 수요를 깊게 조사하고,
> 검색 의도·콘텐츠·내부 링크·커뮤니티 전환을 하나의 장기적인 지식망으로 설계한 뒤,
> M-AUTO가 그 지도를 매일 안정적으로 실행하게 한다.

이 프로젝트는 갱년기 SEO 프로젝트가 아니다. `50대 여성 갱년기`는 중요한 시작점이자 첫 조사 후보일 뿐,
소란소란이 앞으로 10년 이상 소유할 검색 영토 전체가 대상이다.

## 3. 창업자 의도 — 바꾸지 않는 것

1. 소란소란은 1~2년 쓰고 끝날 서비스가 아니라 10년, 30년 운영할 플랫폼을 지향한다.
2. 주제가 많다는 것은 문제가 아니다. 필요하면 장기 주제망은 1,000개 이상으로 커질 수 있다.
3. 글 제목을 먼저 대량으로 채우지 않는다. 우리가 가져갈 검색 영토와 실제 검색 수요부터 깊게 조사한다.
4. Google의 연관 검색어를 한 단계만 보는 것이 아니라 관련 가지를 계속 따라가며 좋은 질문을 찾는다.
5. 검색어를 그대로 복사하지 않는다. 검색어 뒤에 있는 실제 질문과 상황을 해석한다.
6. 하나의 글이 검색에서 발견됐을 때 연결된 글도 함께 발견될 수 있도록 주제망을 미리 만든다.
7. 검색 노출 `0`, `1`, `2`는 초기 실패가 아니다. 노출이 적다는 이유로 발행을 멈추지 않는다.
8. 검색 성과가 나와야 다음 캠페인을 만드는 구조를 두지 않는다.
9. 복잡한 판단은 사전 조사와 설계에서 끝내고, 매일의 자동 실행은 단순하게 유지한다.
10. 매거진은 검색용 문서 묶음이 아니라 실제로 궁금한 것에 답하는 읽을 가치 있는 제품이어야 한다.
11. 콘텐츠는 소란소란을 과도하게 광고하지 않되, 독자가 관련 글과 커뮤니티로 자연스럽게 이어져야 한다.
12. 기존 자동화와 예약 재고를 새 프로젝트 때문에 깨뜨리지 않는다.

## 4. 하지 않는 것

- Codex나 Claude가 근거 없이 메인 키워드를 임의 확정하지 않는다.

- Google 연관 검색어가 보인다는 이유만으로 정확한 검색량이 있다고 보고하지 않는다.
- 검색어 하나마다 글 하나를 기계적으로 만들지 않는다.
- D100~D365 제목부터 먼저 채우지 않는다.
- 다음 주제를 매일 동적으로 고르는 복잡한 자동 선정기를 초기 버전에 만들지 않는다.
- Search Console 노출이 있어야 다음 캠페인이 진행되는 게이트를 만들지 않는다.
- 노출이 `0` 또는 `1~2`라는 이유로 제목·본문·캠페인을 성급히 바꾸지 않는다.
- 관련 글을 최신순 또는 같은 카테고리라는 이유만으로 연결하지 않는다.
- 모든 글을 모든 글에 연결해 링크 수만 늘리지 않는다.
- 기존 글과 예약 글을 한꺼번에 재작성하거나 날짜를 재배치하지 않는다.
- M-GRAPH 실패가 M-AUTO의 정상 예약 공개를 막게 하지 않는다.
- 자동화를 이유로 의료·재정·안전 관문을 약화하지 않는다.

## 5. 최종 기대값

### 독자에게

- 검색한 질문에 첫 부분부터 직접적인 답을 얻는다.
- 한 글을 읽은 뒤 다음 궁금증으로 자연스럽게 이동한다.
- 다시 검색하지 않아도 될 만큼 충분한 판단 기준과 행동 정보를 얻는다.
- 정보만 읽고 끝나는 사람은 관련 매거진으로, 경험과 대화가 필요한 사람은 커뮤니티로 이동한다.

### 검색에서

- 한 주제를 얕은 글 여러 개가 아니라 서로 다른 의도를 맡은 연결된 글 묶음으로 다룬다.
- 중요한 글이 고아 페이지로 남지 않는다.
- 하나의 글이 발견됐을 때 주변 글도 발견될 수 있는 내부 구조를 갖는다.
- 어떤 가지가 먼저 반응하더라도 바로 확장할 수 있는 관련 콘텐츠 자산이 준비돼 있다.

### 소란소란에서

- 매거진 유입이 관련 글 열람과 커뮤니티 방문으로 이어진다.
- 소란소란이 40대 중반~60대 중반 여성의 생활 질문을 깊게 다루는 브랜드로 축적된다.
- 창업자가 매일 주제와 원고를 검수하지 않아도 장기 계획이 실행된다.

## 6. 전체 작동 모델

```text
[사전 설계]
소란소란 검색 정체성
→ 핵심 검색 영토 후보
→ Google 실제 검색 조사
→ 연관 검색어 다단계 탐색
→ 검색 의도 통합·분리
→ 기존 글 대조
→ 주제 그래프와 시리즈 설계
→ 장기 주제 지도
→ 실제 발행 구간 편성

[매일 실행]

→ M-AUTO 원고·이미지 생성
→ QA·위험도·중복·hero 검사

[장기 관찰]
검색 노출·클릭·내부 이동·커뮤니티 이동 기록
→ 기존 실행을 멈추지 않고 후속 조사와 다음 장기 계획에 반영
```

## 7. G0 — 소란소란 검색 정체성부터 정한다

첫 작업은 키워드 목록 작성이 아니다. 소란소란이 어떤 검색 질문을 오래 책임질지 정하는 일이다.

각 검색 영토 후보는 다음 질문을 통과해야 한다.

1. 40대 중반~60대 중반 여성, 특히 50대 여성이 실제로 겪는 문제인가?
2. 소란소란의 커뮤니티 정체성과 연결되는가?
3. 한 번 답하고 끝나는 질문이 아니라 여러 실제 상황으로 깊어질 수 있는가?
4. 기존 검색 결과보다 소란소란이 더 생활에 가까운 답을 줄 수 있는가?
5. 관련 매거진 또는 커뮤니티 대화로 자연스럽게 이어질 수 있는가?
6. 10년 뒤에도 다룰 가치가 있는가, 아니면 일시 유행인가?
7. 건강·재정 등 위험도가 높다면 책임 있게 다룰 근거와 검수 경로가 있는가?

이 단계에서 Codex나 Claude가 `수면`, `돈`, `관계` 같은 영역을 근거 없이 확정하지 않는다.
후보를 제시할 수는 있지만, 검색·기존 콘텐츠·커뮤니티·브랜드 근거와 함께 창업자 판단을 받는다.

## 8. G1 — 기존 자산을 먼저 전수 조사한다

새 글을 만들기 전에 다음을 읽기 전용으로 정리한다.

- 공개된 모든 매거진 글
- 예약된 모든 매거진 글
- brief, draft, review 등 아직 공개되지 않은 원고
- 현재 topic queue와 격리 상태
- 기존 `cluster`, `seriesId`, `seriesOrder`
- 현재 `함께 읽어보세요` 선정 방식
- 본문에서 매거진 글끼리 연결할 수 있는 블록과 제약
- sitemap, canonical, JSON-LD, 공개 가드
- Search Console과 분석 도구에서 확인 가능한 현재 기준선

각 기존 글은 다음 중 하나로 분류한다.

```text
KEEP       그대로 유지하고 새 주제망의 노드로 사용
CONNECT    내용은 유지하고 관계 정보만 추가
REFRESH    근거·표현·구조를 나중에 갱신
MERGE      같은 검색 의도의 글과 통합 검토
ISOLATE    소란소란 검색 영토와 연결하지 않음
```

이 분류만으로 기존 글을 수정하지 않는다. 수정은 별도 승인과 검증을 거친다.

## 9. G2 — Google 검색 딥다이브

### 조사 대상

각 후보 키워드를 실제로 검색하고 다음을 기록한다.

- 검색 결과가 실제로 존재하는가
- 자동완성 표현이 있는가
- 연관 검색어가 있는가
- 사람들이 함께 묻는 질문이 있는가
- 어떤 유형의 결과가 상단에 나오는가
- 의료기관·공공기관·뉴스·블로그·커뮤니티 중 누가 차지하는가
- 검색 결과가 충분히 답하지 못하는 질문은 무엇인가
- 소란소란이 더 구체적이고 생활에 가까운 답을 줄 수 있는가
- 해당 검색이 소란소란 커뮤니티의 경험과 연결되는가

### 다단계 탐색

연관 검색어를 다시 검색하고, 거기서 나온 연관 검색어를 다시 따라간다.

```text
seed keyword
├─ related query A
│  ├─ A-1
│  ├─ A-2
│  └─ A-3
├─ related query B
│  ├─ B-1
│  └─ B-2
└─ related query C
```

탐색 깊이를 숫자로 미리 고정하지 않는다. 다음 중 하나가 되면 그 가지를 멈춘다.

- 새 검색 의도가 더 나오지 않는다.
- 표현만 다르고 이미 발견한 질문과 같다.
- 핵심 독자에서 멀어진다.
- 상품 판매·광고·플랫폼 탐색 등 소란소란의 역할과 멀어진다.
- 근거 있고 안전한 답을 만들 수 없다.
- 다른 검색 영토가 담당하는 질문으로 넘어간다.

### 검색 근거 기록

연관 검색어는 시점·지역·개인화에 따라 달라질 수 있다. 각 근거에 다음을 남긴다.

- 원 검색어
- 발견한 표현
- 발견 위치: 자동완성 / 연관 검색어 / 함께 묻는 질문 / Search Console / 커뮤니티
- 조사 일자
- 언어·지역 등 재현에 필요한 조건
- 화면 또는 원자료 경로
- 후속 조사 상태

연관 검색어의 존재는 **검색 흔적**이지 정확한 검색량이 아니다. API나 별도 데이터 없이 수치를 만들어내지 않는다.

## 10. G3 — 검색어가 아니라 검색 의도를 정본으로 만든다

다음 표현은 여러 검색어지만 하나의 글이 답할 수 있다.

```text
갱년기 언제 끝나나요
갱년기 증상 언제까지
여성 갱년기 기간
폐경 후 증상 몇 년
```

반대로 같은 단어가 들어가도 독자 상황이 다르면 분리한다.

```text
갱년기 짜증이 나는 이유
갱년기인 엄마의 짜증을 가족이 대하는 방법
갱년기 짜증으로 부부 갈등이 생겼을 때
```

검색 의도 노드마다 최소한 다음을 기록한다.

| 필드 | 의미 |
|---|---|
| `intentId` | 변하지 않는 고유 식별자 |
| `primaryQuery` | 대표 검색 질문 |
| `queryVariants` | 같은 의도의 다른 검색 표현 |
| `evidenceRefs` | 검색 근거 |
| `audienceSituation` | 누가 어떤 상황에서 찾는가 |
| `answerScope` | 이 글이 답할 범위 |
| `exclusions` | 다른 글이 맡을 범위 |
| `existingSlugs` | 기존 글 재사용·통합 후보 |
| `parentIntentId` | 상위 질문 |
| `nextIntentIds` | 읽은 뒤 이어질 질문 |
| `bridgeIntentIds` | 다른 시리즈로 건너가는 질문 |
| `riskLevel` | LOW / MEDIUM / HIGH |
| `autoEligible` | M-AUTO 자동 처리 가능 여부 |
| `communityDestination` | 연결할 커뮤니티 맥락 |

최종 파일 형식과 저장 위치는 기존 topic queue와의 중복 정본을 피하도록 구현 전에 결정한다.

## 11. G4 — 검색 주제 그래프를 설계한다

좋은 거미줄은 링크가 많은 구조가 아니라 **독자에게 필요한 다음 길이 분명한 구조**다.

### 관계 유형

| 관계 | 의미 |
|---|---|
| `PARENT` | 큰 개념 또는 허브로 돌아간다 |
| `PREREQUISITE` | 이 글 전에 알아야 할 질문 |
| `NEXT_QUESTION` | 이 글을 읽은 뒤 생길 질문 |
| `SIBLING` | 같은 시리즈의 다른 상황 |
| `BRIDGE` | 다른 검색 영토로 넘어가는 연결점 |
| `ACTION` | 병원·검진·생활 실천 등 다음 행동 |
| `COMMUNITY` | 경험과 대화가 필요한 커뮤니티 맥락 |

### 연결 원칙

- 모든 중요한 글은 최소 한 개의 다른 공개 글에서 링크를 받는다.
- 모든 글은 명확한 부모 또는 허브가 있다.
- 본문 링크는 실제 문맥에서 필요한 순간에 넣는다.
- 앵커 문구는 `더 보기`가 아니라 이동할 질문을 설명한다.
- 미래 예약 글은 공개 전 목록·본문·sitemap·관련 글에서 노출하지 않는다.
- 한 화면에 링크를 몰아넣지 않는다.
- 같은 시리즈 안의 연결과 다른 시리즈로 넘어가는 다리 연결을 구분한다.
- 이미 답한 질문을 링크 수를 늘리기 위해 다시 만들지 않는다.

### `함께 읽어보세요`

현재의 최신순·동일 cluster 중심 추천을 최종 형태로 보지 않는다. 목표 구조는 다음 세 역할을 조합한다.

1. **다음으로 궁금할 글** — 현재 질문 이후의 자연스러운 질문
2. **같은 시리즈의 핵심 글** — 전체 맥락을 이해하는 데 필요한 글
3. **다른 주제로 이어지는 다리 글** — 감정→관계, 증상→병원처럼 실제 상황이 이어지는 글

구체적인 개수와 UI는 기존 디자인 시스템과 모바일 가독성을 실측한 뒤 결정한다.

## 12. G5 — 매거진 품질과 소란소란 연결

### 콘텐츠 품질

- 제목만 보고 어떤 질문에 답하는지 알 수 있어야 한다.
- 첫 2~3문단 안에 직접적인 답이 있어야 한다.
- 독자가 다시 검색하지 않아도 될 만큼 판단 기준과 행동 정보를 제공한다.
- 검색 결과를 단순 요약하지 않고 소란소란 독자의 생활 상황을 반영한다.
- 건강·재정 글은 근거와 위험 경계를 분명히 한다.
- 대표 이미지와 alt는 글의 실제 상황과 일치해야 한다.
- 짧게 만들기 위한 글자 수 기준이나 길게 보이기 위한 분량 채우기를 쓰지 않는다.
- 자동 생성 흔적, 반복 문장, 같은 구조의 대량 복제를 허용하지 않는다.

### 제품 디자인

- 첫 화면에서 제목·핵심 답·대표 이미지의 관계가 분명해야 한다.
- 소제목, 여백, 요약, 주의 신호, 실천 항목을 쉽게 훑을 수 있어야 한다.
- 관련 글은 광고 카드가 아니라 다음 질문으로 보여야 한다.
- 모바일에서 본문·이미지·CTA·관련 글이 겹치거나 과밀하면 안 된다.
- 고객용 디자인 시스템을 재사용하며 별도 색·타이포 시스템을 만들지 않는다.

### 소란소란 연결

기본 원칙은 **정보 효용 우선, 브랜드 연결은 문맥 안에서**다.

```text
정보가 더 필요한 사람  → 관련 매거진
경험이 필요한 사람     → 같은 고민의 게시판
대화가 필요한 사람     → 커뮤니티 참여
행동이 필요한 사람     → 체크리스트·검진·진료 정보
```

모든 글에 동일한 가입 문구를 반복하지 않는다. CTA는 해당 글을 읽은 사람이 실제로 다음에 할 행동과 맞아야 한다.

## 13. G6 — 장기 주제망과 실제 발행표를 분리한다

주제가 많아지는 것은 실패가 아니다.

```text
장기 검색 주제망    수백~수천 개 의도 노드까지 확장 가능
확정 발행 구간      현재 시스템이 안전하게 실행할 수 있는 가까운 기간
후속 후보 구간      조사와 관계는 끝났지만 날짜는 아직 고정하지 않은 영역
```

### 순서

1. 검색 영토와 실제 검색 근거를 조사한다.
2. 검색 의도를 통합·분리한다.
3. 기존 글을 노드에 매핑한다.
4. 시리즈·허브·다리 관계를 설계한다.
5. 전체 장기 주제망을 만든다.
6. 그 결과에서 D100~D365 등 실제 발행 구간을 편성한다.

D100~D365는 입력이 아니라 **조사의 산출물**이다. 주제망이 충분하면 D1000 이상으로 확장할 수 있다.

지금 고정하는 것은 `대표 질문·검색 의도·관계·위험도·발행 순서`다. 최종 제목, 본문, description,
이미지와 alt, 최신 근거 문장은 발행 시점에 만든다.

## 14. 검색 성과의 역할 — 발행 게이트가 아니다

초기 검색 노출이 `0`이거나 `1~2`인 것은 실패 판정 근거가 아니다.

```text
노출 0       색인·canonical·sitemap·내부 링크 등 기술 문제만 확인하고 계획대로 계속 발행
노출 1~20    잡음 구간. 제목·본문·순서를 성급히 바꾸지 않고 기록
상승 흐름     후속 조사와 확장 후보로 표시
클릭 발생     주변 의도와 커뮤니티 연결을 우선 검토
```

Search Console과 분석 데이터는 다음 캠페인을 허용하는 게이트가 아니다. 장기적으로 다음을 확인하는 관찰 자료다.

- 어떤 검색 영토에서 처음 발견되기 시작했는가
- 하나의 글이 아니라 연결된 글도 함께 노출되는가
- 검색 유입자가 관련 글을 계속 읽는가
- 매거진 유입이 커뮤니티 이동과 실제 참여로 이어지는가
- 후속 장기 계획에서 어느 가지를 더 깊게 조사할 것인가

검색 성과 때문에 일일 자동 발행을 멈추거나 큐를 매일 재정렬하지 않는다.

## 15. M-AUTO 보호와 레거시 전환

### 보호하는 것

- producer와 auto-register의 역할 분리
- peek/commit 슬롯 계약
- QA, batch QA, 위험 등급, 격리
- hero 필수와 이미지 파일 검증
- run-id 결과 연결
- PR SHA 고정, 파일 범위, CI, merge gate
- 예약 전 비공개
- Production SHA와 도메인 서빙 확인
- 공개 후 본문·이미지·목록 watch
- runtime worktree 격리와 dirty-tree 차단
- launchd 실행·잠금·알림 계약

### 점진적으로 교체할 후보

- 캠페인 관계 없이 개별 주제를 고르는 방식
- 최신 글 또는 같은 cluster 중심의 관련 글 추천
- 화면에서 사용되지 않는 시리즈 정보
- 검색 의도와 관계를 표현하지 못하는 topic queue 구조
- 본문 중간에 관련 매거진을 연결하기 어려운 블록 구조

### 전환 규칙

1. 기존 예약 글의 날짜·시각·slug·본문·hero를 새 프로젝트 때문에 바꾸지 않는다.
2. 기존 예약 재고는 정상 소진한다.
3. 새 필드가 없는 기존 글도 정상 렌더링돼야 한다.
4. 새 검색 캠페인부터 새 계약을 적용한다.
5. 기존 글은 내용 재작성보다 관계 정보 연결을 먼저 검토한다.
6. 새 주제망 정보가 없으면 기존 동작이 유지되는 호환 경로를 둔다.
7. M-GRAPH 오류가 기존 예약 공개를 막지 않게 한다.
8. 새 방식이 실제 캠페인에서 검증되기 전에는 옛 로직을 삭제하지 않는다.
9. 주제 지도와 topic queue가 서로 다른 정본으로 존재하지 않게 한다.
10. 구조 전환은 읽기 전용 진단 → 그림자 계산 → 일부 적용 → 실제 관찰 → 옛 로직 제거 순서를 지킨다.

| **G3 키워드 딥다이브** | 후보 검색 영토의 다단계 연관 검색어 조사 | 주요 가지가 새 의도를 거의 만들지 않는 포화점까지 조사 |

| **G10 첫 실제 캠페인** | 생성부터 공개·연결까지 실제 완주 | 원고·hero·예약·병합·배포·공개·관련 링크 전부 확인 |
| **G11 장기 운영** | 조사·갱신·확장 주기 운영 | 검색 성과와 커뮤니티 신호를 다음 장기 계획에 반영 |

마일스톤은 날짜를 맞추기 위한 체크리스트가 아니다. 앞 단계의 산출물이 없으면 뒤 단계로 가지 않는다.
다만 새 규칙을 만들어 진행을 막는 핑계로 사용하지 않는다. 각 게이트는 구체적인 사고를 막거나 정본 충돌을
방지하는 경우에만 둔다.

## 17. 성공 정의

### 조사 성공

- 메인 키워드가 Codex나 Claude의 추측이 아니라 검색·고객·커뮤니티 근거에서 나온다.
- 각 검색 의도에 증거와 범위가 있다.
- 같은 질문의 표현만 다른 검색어가 중복 글로 분리되지 않는다.
- 소란소란 정체성과 무관한 가지가 제거된다.
- 기존 글을 버리지 않고 재사용·연결·통합 후보로 매핑한다.

### 설계 성공

- 중요한 글은 모두 허브 또는 관련 글에서 연결된다.
- `함께 읽어보세요`가 최신순이 아니라 의도 관계를 반영한다.
- 본문 링크와 관련 글 UI가 독자의 다음 질문을 설명한다.
- 검색 정보와 커뮤니티 전환이 억지 광고 없이 이어진다.
- 장기 주제망과 실제 발행표가 분리돼 있어 수천 노드로 확장할 수 있다.

### 운영 성공

```text
기존 예약 공개 회귀 0
기존 글 렌더 회귀 0
QA·안전 관문 약화 0
이미지 누락 0
미래 글 조기 노출 0
중복 slug·예약일 0
새 캠페인 관계 누락 0
watch 거짓 PASS 0
```

### 장기 성장 성공

- 검색에서 발견되는 주제가 하나씩 늘어난다.
- 발견된 글 주변의 연결 글도 함께 읽힌다.
- 매거진 독자가 소란소란의 다른 글과 커뮤니티로 이동한다.
- 어떤 가지가 반응하더라도 이미 주변 콘텐츠와 연결 구조가 준비돼 있다.
- 창업자가 매일 주제·원고·병합을 직접 관리하지 않아도 장기 계획이 실행된다.

검색 순위, 노출 수, 클릭 수 하나를 프로젝트의 단기 PASS/FAIL 게이트로 사용하지 않는다.

## 18. 역할과 승인 경계

| 역할 | 책임 |
|---|---|
| 창업자 | 검색 정체성·핵심 영토·브랜드 방향·고위험 주제 결정 |
| Codex | 목적·정본·조사 품질·중복·마일스톤·구현 범위·배포 판단 총괄 |
| Claude Code | 승인된 범위의 read-only 조사, 구현, 검증, 증거 보고 |
| M-GRAPH | 확정된 검색 의도·관계·장기 계획 제공 |
| M-AUTO | 정해진 대상을 안전하게 생성·검사·예약·병합·공개 |

### 초기 운영

- G0 검색 정체성과 첫 검색 영토는 창업자가 승인한다.
- 첫 1~2개 실제 캠페인은 Codex가 설계와 결과를 전수 검토한다.
- 이후 창업자는 매일 주제를 고르지 않는다.
- LOW/MEDIUM의 반복 실행은 자동화하고, HIGH·브랜드 경계·새 검색 영토만 사람 판단으로 남긴다.

## 19. 병목 방지 원칙

1. **깊은 복잡성은 사전 조사에 둔다.** 매일 실행기에 동적 판단을 계속 추가하지 않는다.
2. **검색 성과를 기다리지 않는다.** 기술 문제가 없으면 확정된 계획을 계속 실행한다.
3. **한 개의 정본만 둔다.** 주제 지도와 topic queue가 독립적으로 갈라지지 않게 한다.
4. **규칙에는 사고 근거가 있어야 한다.** 막연한 품질 우려로 새 FAIL 게이트를 만들지 않는다.
5. **WARN과 FAIL을 구분한다.** 불확실함을 전부 차단으로 바꾸지 않는다.
6. **기존 정상 경로를 먼저 보존한다.** 신규 기능 때문에 예약 공급이 멈추면 설계 실패다.
7. **한 번에 전면 전환하지 않는다.** 새 캠페인 opt-in으로 시작한다.
8. **수치가 작을 때 과잉 반응하지 않는다.** 노출 0~소수는 기록하되 일일 실행을 바꾸지 않는다.
9. **매일 승인받지 않는다.** 승인 대상은 검색 영토·고위험 주제·구조 변경이다.
10. **완료를 과장하지 않는다.** 설계·구현·가동·실제 캠페인·장기 성과를 분리해 보고한다.

## 20. 혼란스러울 때 보는 질문

아래 질문 중 하나라도 답하지 못하면 구현부터 하지 않는다.

1. 이 작업은 M-GRAPH 전략인가, M-AUTO 실행인가?
2. 실제 검색 근거가 있는가, 아니면 agent가 주제를 지어냈는가?
3. 검색어가 다른 것인가, 검색 의도가 다른 것인가?
4. 기존 글로 답할 수 있는데 새 글을 만들고 있지 않은가?
5. 독자가 이 글을 읽은 다음 무엇을 궁금해할지 설명할 수 있는가?
6. `함께 읽어보세요`의 각 링크에 선택 이유가 있는가?
7. 이 콘텐츠가 소란소란 커뮤니티와 어떻게 연결되는가?
8. 검색 성과가 작다는 이유로 계획을 불필요하게 멈추고 있지 않은가?
9. 새 규칙이 실제 사고를 막는가, 아니면 agent의 불안을 달래는가?
10. 기존 예약 글과 M-AUTO의 안전한 공개를 건드리고 있지 않은가?

## 21. 현재 상태와 바로 다음 단계

### 확정된 것

- 프로젝트 이름과 M-AUTO/M-GRAPH 역할 분리
- 장기 검색 주제망을 먼저 조사하고 발행표를 나중에 만든다는 순서
- Google 연관 검색어의 다단계 딥다이브
- 검색어가 아닌 검색 의도 단위의 정본
- 시리즈·본문 링크·`함께 읽어보세요`·커뮤니티 전환을 함께 설계
- 검색 노출을 일일 발행 게이트로 사용하지 않는 원칙
- 기존 예약 재고와 M-AUTO 보호

### 아직 확정하지 않은 것

- 최종 핵심 검색 영토 목록
- `50대 여성 갱년기`의 실제 의도 지도와 캠페인 구성
- 전체 장기 주제 수
- D100~D365 또는 더 긴 발행표
- 주제 그래프의 최종 파일 형식과 코드 위치
- 관련 글 UI의 최종 개수와 디자인

### 다음 단계

**G0~G2 read-only 진단**부터 한다.

1. 현재 매거진·예약·원고·큐·시리즈·관련 글 구조를 전수 조사한다.
2. 소란소란 검색 정체성 후보를 근거와 함께 제시한다.
3. Google 검색 딥다이브의 실행 절차와 증거 형식을 확정한다.
4. 구현·push·PR·배포 없이 조사 보고만 제출한다.
5. Codex가 이 정본과 대조해 누락·과잉 규칙·기존 자동화 위험을 검토한다.
6. 창업자가 검색 영토와 조사 범위를 승인한 뒤 실제 딥다이브를 시작한다.

## 22. 변경 규칙

이 문서의 목적·창업자 의도·금지사항을 바꾸려면 다음을 한 변경에서 함께 기록한다.

1. 무엇을 바꾸는가
2. 왜 기존 결정이 틀렸거나 부족한가
3. 어떤 실제 근거가 새로 생겼는가
4. M-AUTO와 기존 예약 재고에 어떤 영향이 있는가
5. 성공·실패 판정이 어떻게 달라지는가

Codex나 Claude가 구현 편의를 이유로 이 문서의 목적을 축소하지 않는다. 문서와 구현이 충돌하면
충돌을 보고하고, 창업자 결정 없이 문서를 구현에 맞춰 조용히 바꾸지 않는다.
