# M3 반응 지도 최소 설계

> 작성 2026-08-30 · 상태 **설계 초안 · 구현 미착수**
> 선행: [Persona Architecture 설계](2026-08-30-persona-architecture-design.md) · [Safety / Originality Gate 설계](2026-08-30-persona-safety-originality-gate-design.md)
> 상위: [Micro Seed Lane 헌법](../constitution/MICRO_SEED_LANE_CONSTITUTION.md) §5-3 **M3 Comment Activation Engine** · 원칙 14

---

## §0 이 문서가 정하는 것

Gate ⑤ · ⑨ 판정부가 main 에 들어갔다. 가드는 섰다.
다음 질문은 **"무엇을 만들 것인가"** 이고, 그 첫 조각이 반응 지도다.

> **어떤 글에는 어떤 반응 유형들이 자연스럽게 붙는가.**

이걸 모르면 페르소나 여럿이 한 글에 댓글을 달 때 **전부 비슷한 말을 한다.**
공감 3개가 나란히 달린 글은 사람이 쓴 것처럼 보이지 않는다.

### 🔴 이 문서가 정하지 않는 것

```
🔴 댓글 문장을 어떻게 쓸 것인가        ← Voice Engine · Persona Voice Core
🔴 페르소나를 몇 명 만들 것인가         ← Persona Pool 설계 (별도)
🔴 언제 발행할 것인가                  ← Activity Rhythm · 운영자 승인
```

반응 지도는 **분배의 입력값**이다. 생성기가 아니다.

---

## §1 🔴 먼저 정정 — 원재료는 있으나 그대로 쓸 수 없다

설계에 앞서 실측했고, 전제 하나가 틀렸다는 것이 드러났다.

### 있는 것 🟢

| 자산 | 규모 |
|---|---|
| `VoiceCommentSignal` 적재 | **59,252건** |
| 대상 글 | **9,674건** (글당 평균 **9.1개** 댓글) |
| 기존 `ReactionType` 6종 | `empathy` · `experience` · `question` · `information` · `rebuttal` · `other` |
| `classifyReaction()` | `scripts/lib/voice-comment-signals.mts` — 이미 동작한다 |

**반응 지도를 백지에서 만들지 않는다.** 댓글 6만 건이 이미 유형 라벨과 함께 저장돼 있다.

### 🔴 그런데 분류가 사실상 작동하지 않는다

```
reactionType 분포 (59,252건)

  other         47,840   80.7%   ← 🔴
  question       7,769   13.1%
  empathy        1,842    3.1%
  rebuttal         862    1.5%
  experience       557    0.9%
  information      382    0.6%
```

**80.7% 가 미분류다.** 의미 있게 라벨된 것은 19.3% 뿐이다.

원인은 코드 주석에 이미 적혀 있다 — 분류기가 **좁게 설계됐다.**

```
EXPERIENCE   경험 동사가 있어야 경험이다 (겪었 · 해봤 · 다녀왔 …)
             → "맞아요 저도요" 를 경험으로 잡지 않기 위한 의도적 선택
INFORMATION  주제어가 아니라 행위 안내여야 정보다 (하시면 됩니다 · 참고하세요 …)
             → "어느 병원 가셨어요?" 를 정보로 잡지 않기 위한 의도적 선택
```

**두 선택 모두 옳다.** VE-M2 의 목적은 *"학습에 쓸 경험담을 정확히 골라내는 것"* 이었고,
정밀도를 위해 재현율을 포기한 것이다. 그 목적에는 맞다.

하지만 **반응 지도의 목적은 다르다.** 여기서는 *"이 글에 어떤 반응들이 붙었나"* 의
전체 그림이 필요하고, 80.7% 가 `other` 면 그림이 그려지지 않는다.

### 🔴 그래서 M3 의 첫 작업은 분배 규칙이 아니라 분류기다

```
잘못된 순서   반응 조합 규칙부터 만든다
              → 규칙의 근거가 19.3% 표본뿐이다
              → "공감 3개는 어색하다" 를 뒷받침할 데이터가 없다

옳은 순서     분류기를 반응 지도용으로 넓힌다
              → other 비율을 낮춘다
              → 그 위에서 조합 규칙을 실측으로 도출한다
```

🔴 **기존 `classifyReaction()` 을 고치지 않는다.** VE-M2 계약이고 학습 파이프라인이 쓴다.
반응 지도용 분류는 **별도 함수**로 둔다(§2-3).

## §2 반응 유형 taxonomy

### §2-1 7종 — 요청안과 코드의 대조

| # | 반응 유형 | 기존 `ReactionType` | 상태 |
|---|---|---|---|
| ① | **공감** | `empathy` | 🟢 있다 |
| ② | **경험 공유** | `experience` | 🟢 있다 (좁다) |
| ③ | **조심스러운 조언** | `information` | 🟡 부분 — 정보 안내와 조언이 섞인다 |
| ④ | **다른 관점** | `rebuttal` | 🟢 있다 |
| ⑤ | **질문 / 후속 확인** | `question` | 🟢 있다 |
| ⑥ | **가벼운 유머 / 완충** | 🔴 **없음** | `other` 에 묻힌다 |
| ⑦ | **침묵 / 무반응** | — | 🔴 댓글이 아니라 **분배 결정**이다 |

**5종이 기존 코드로 덮이고, ⑥이 신규, ⑦은 성격이 다르다.**

### §2-2 🔴 ⑦ 침묵은 반응 유형이 아니다

```
①~⑥   생성된 댓글에 붙는 라벨
⑦      "이 페르소나는 이 글에 댓글을 달지 않는다" 는 분배 단계의 결정
```

같은 목록에 두면 *"침묵 댓글을 생성하라"* 는 모순이 생긴다.
⑦ 은 **분배 규칙(§4)** 에 두고, taxonomy 는 6종으로 둔다.

[Architecture §2](2026-08-30-persona-architecture-design.md) 가 이미
*"🔴 침묵 여부 — 아무 말도 하지 않는 것도 선택이다"* 를 **변주 목록**에 넣어 뒀다. 그쪽과 붙인다.

### §2-3 반응 지도용 분류 — `ReactionMapType`

```
🔴 기존 ReactionType 을 바꾸지 않는다. 별도 타입을 둔다.

ReactionMapType
  empathy        공감            "맞아요" · "저도 그래요" · "속상하시겠어요"
  experience     경험 공유        경험 동사 (기존 정의 유지)
  advice         조심스러운 조언   "가보시는 게" · "저라면" — 🔴 단정형은 제외
  perspective    다른 관점        기존 rebuttal
  question       질문 · 후속 확인  기존 question
  levity         가벼운 유머 · 완충 🆕 ㅋㅋ · 농담 · 화제 전환 · 짧은 인사
  caution        주의 · 경고       🆕 조심하세요 · 사기 · 위험
  other          그 외            🔴 아래 참조
```

#### 🔴 `other` 30% 이하 목표를 폐기한다

재분류 실측에서 `other` 는 80.7% → **66.1%** 로만 내려갔다.
잔여 39,187건의 **77.9% 가 21자 이상 완결 문장**이라, 어휘 패턴으로는 더 줄지 않는다.

```
🔴 폐기   "unclassified 30% 이하"
🟢 대체   "분류된 유형이 분배 규칙을 만들 만큼 충분한가"

  levity 12.6% · question 12.4% · empathy 2.5% · advice 2.0%
  rebuttal 1.4% · caution 1.0% · experience 0.9%
  → 7종이 33.9% 를 덮는다. 규칙을 세우기에 충분하다
```

**우리는 `other` 를 생성하지 않는다.** 페르소나는 명시된 유형 안에서만 고르므로
잔여 `other` 가 커도 분배 규칙에는 지장이 없다.

#### 🔴 `support_short` 는 제외한다

짧은 맞장구가 `other` 의 큰 덩어리일 것으로 봤으나, 실측 **0.2%(147건)** 였다.
**독립 taxonomy 로 둘 가치가 없다.** 해당 표현은 `levity` · `empathy` 로 흡수된다.

#### 🔴 `information` → `advice` 로 좁히는 이유

기존 `information` 은 *"하시면 됩니다"* 같은 **행위 안내**를 잡는다.
그런데 Persona 가 낼 반응으로서는 **단정형 안내가 곧 위험**이다
([Safety Gate §5](2026-08-30-persona-safety-originality-gate-design.md) 조언 제한).

```
🔴 생성 금지  "○○ 하시면 됩니다"          단정
🟢 생성 허용  "저라면 한번 가볼 것 같아요"   조심스러운 제안
```

**분류기가 학습 데이터에서 `information` 을 세는 것과,
생성기가 `advice` 를 만드는 것은 다른 일이다.** 지도에는 `advice` 로 적고,
원문에서 관찰된 단정형 안내는 **빈도만 참고하고 생성 목표로 삼지 않는다.**

#### 🆕 `levity` 를 넣는 이유

실제 커뮤니티 댓글의 상당수는 짧은 농담·맞장구·화제 전환이다.
`other` 80.7% 의 큰 덩어리가 여기 있을 것으로 본다(가설 — §8 에서 검증).

**완충이 없으면 대화가 무겁기만 하다.** 무거운 글에 공감·조언만 달리면
읽는 사람이 숨 쉴 곳이 없다.

## §3 글 유형 5종과 반응 계획

### §3-0 🔴 반응 지도는 고정 순서표가 아니다

이전 판본은 조합을 화살표로 적었다 — *"공감 → 경험 공유 → 조언"*.
**그 표기를 폐기한다.**

```
🔴 금지  "1번 댓글은 공감, 2번은 질문, 3번은 조언"
         창업자가 과거에 이 방식을 테스트했고 AI 티가 강하게 났다
         댓글 수가 같고 순서가 같으면, 문장이 달라도 기계로 읽힌다

🟢 대체  확률 · 범위 · 제약 · 자격 조건
         commentCount range · firstRole 후보와 weight · roleWeights
         forbiddenRoles · maxPerRole · persona eligibility
         source comment seed 등급 · silenceRate · seedReuseRate
```

**같은 글 유형이라도 댓글 수와 역할 조합은 매번 흔들려야 한다.**

### §3-1 글 유형 5종 — 확정

[read-only 실측](#§8-4-선행-과제--분류기-재측정) 결과 5종 전부 표본이 충분하다.

| 글 유형 | 글수 | 댓글수 | 글당 평균 | 분류 기준 |
|---|---|---|---|---|
| 생활 정보 · 잡담 | 2,329 | 12,115 | 5.2 | `HOBBY`·`FOOD`·`BEAUTY`·`ENTERTAIN`·`FASHION`·`HUMOR`·`PET`·`DIGITAL` |
| 돈 · 일 · 자산 | 2,125 | 12,939 | 6.1 | `MONEY`·`JOB`·`RETIRE`·`HOUSING` |
| 가족 · 관계 갈등 | 2,040 | 15,189 | 7.4 | `FAMILY`·`RELATION` |
| 외로움 · 감정 토로 | 1,895 | 12,423 | 6.6 | `communitySignal=confession` + 토로 정서 · `MEANING`·`DIGNITY`·`FREEDOM` |
| 건강 · 갱년기 · 병원 | 1,285 | 6,586 | 5.1 | `HEALTH`·`CARE` |

**1차 `desireCategory` + 보조 `communitySignal`·`emotionTags`.**
🔴 VE-M3 신호 7종은 글 유형 분류에 쓰지 않는다 — 카테고리 간 차이가 카테고리 내 산포보다 작다.
`expressionRisk` 만 **감정 강도 참고**로 남긴다(잡담 32.2 vs 나머지 39.8~40.8).

### §3-2 🔴 원문 분포를 목표로 삼지 않는다

실측 교차표에서 가장 중요한 것은 **따라 하면 안 되는 값**이었다.

```
건강 글의 원문 advice 비중  4.2%   ← 전체 평균의 2배
  사람이 다는 조언이니까 가능한 것이다
  🔴 페르소나가 그 비중을 따라 하면 의료 조언 봇이 된다
```

원문에서 가져오는 것은 **역할의 상대 순위**이지 비중 자체가 아니다.

```
🟢 가져온다   외로움 = empathy 최고 · 잡담 = levity 최고 · 가족 = 다양성 최고
🔴 안 가져온다 건강 = advice 최고
```

### §3-3 글 유형별 MVP 반응 계획

🔴 **아래 weight 는 확정 수치가 아니라 출발점이다.** 운영하며 조정한다(§10).

#### 가족 · 관계 갈등

| 항목 | 값 |
|---|---|
| `commentCount` | **2~3** |
| `firstRole` 후보 | `question` .45 / `empathy` .30 / `levity` .25 |
| `roleWeights` | `question` .30 · `empathy` .25 · `levity` .20 · `experience` .15 · `rebuttal` .10 |
| `forbiddenRoles` | 🔴 **judgmental advice** (판단형 조언) |
| `maxPerRole` | 1 (`levity` 만 2) |
| seed 등급 | **B 까지** |

🔴 **주의 — 편들기 · 단정 · 훈계 금지.** *"그건 이혼감이에요"* 류는 조언이 아니라 판결이다.
실측상 이 유형이 반응 다양성이 가장 높다(3종+ 49.5%). 그 폭을 살린다.

#### 외로움 · 감정 토로

| 항목 | 값 |
|---|---|
| `commentCount` | **1~2** |
| `firstRole` 후보 | `empathy` .60 / `levity` .40 |
| `roleWeights` | `empathy` .60 · `levity` .30 · `question` .10 |
| `forbiddenRoles` | 🔴 **advice · caution · rebuttal** |
| `maxPerRole` | 1 |
| seed 등급 | **A 중심 · B 신중** |

🔴 **주의 — 해결책보다 받아주는 말이 먼저다.** 조언이 붙으면 *"들어주지 않았다"* 가 된다.
실측이 뒷받침한다 — `confession` 글의 `empathy` 는 전체의 **2.4배**(6.1% vs 2.5%)이고
`question` 은 오히려 낮다(10.7% vs 12.4%). **털어놓는 글에는 되묻지 않는다.**

#### 돈 · 일 · 자산

| 항목 | 값 |
|---|---|
| `commentCount` | **2** |
| `firstRole` 후보 | `question` .50 / `empathy` .30 / `levity` .20 |
| `roleWeights` | `question` .35 · `experience` .25 · `empathy` .25 · `levity` .15 |
| `forbiddenRoles` | 🔴 **financial advice · `information` 단정** |
| `maxPerRole` | 1 |
| seed 등급 | **A + 제한적 B** |

🔴 **주의 — 투자 · 법률 · 세무 · 채무 조언 금지.** 금액과 결합하면 즉시 C 급이다.
이 유형은 원문에서도 `caution` 비중이 가장 높다(1.3%) — 사람들도 조심하라고 말하는 영역이다.

#### 생활 정보 · 잡담

| 항목 | 값 |
|---|---|
| `commentCount` | **2** |
| `firstRole` 후보 | `levity` .50 / `question` .35 / `empathy` .15 |
| `roleWeights` | `levity` .40 · `question` .30 · `experience` .20 · `empathy` .10 |
| `forbiddenRoles` | **과한 감정 이입** (과잉 `empathy`) |
| `maxPerRole` | 1 (`levity` 만 2) |
| seed 등급 | **B 까지** |

🔴 **주의 — 가볍게 받아야 할 글을 무겁게 만들지 않는다.**
실측에서 `levity` 17.3% 로 최고이고 `empathy` 1.5% 로 최저다. 사람들도 가볍게 받는다.

#### 건강 · 갱년기 · 병원

| 항목 | 값 |
|---|---|
| `commentCount` | **1~2** |
| `firstRole` 후보 | `empathy` .55 / `question` .45 |
| `roleWeights` | `empathy` .45 · `question` .35 · `levity` .20 |
| `forbiddenRoles` | 🔴 **advice · information · caution · experience** |
| `maxPerRole` | 1 |
| seed 등급 | **A 중심 · B/C 매우 신중** |

🔴 **주의 — 의료 조언처럼 보이면 `review` 또는 차단.**
`experience` 까지 막는 이유는 병원 경험담이 사실상 조언으로 읽히기 때문이다.
**개수를 가장 적게 두는 것이 가장 확실한 통제다.**

### §3-4 유형별 seed 등급 강도 요약

| 글 유형 | 최대 등급 | 근거 |
|---|---|---|
| 생활 정보 · 잡담 | 🟢 **B 까지** | `advice` 1.1% 최저 · 위험 낮음 |
| 가족 · 관계 갈등 | 🟢 **B 까지** | 다양성 최고 · 판단형 조언만 차단 |
| 돈 · 일 · 자산 | 🟡 **A + 제한적 B** | `caution` 1.3% 최고 · 금액은 C |
| 외로움 · 감정 토로 | 🟡 **A 중심 · B 신중** | 경험담이 들어가면 받아주기가 깨진다 |
| 건강 · 갱년기 · 병원 | 🔴 **A 중심 · B/C 매우 신중** | 원문 `advice` 4.2% 가 함정 |

## §4 분배 제약과 흔들림

### §4-1 제약 7가지

```
① 고정 순서 금지            firstRole 을 후보군에서 가중 추첨한다
② 같은 role 3연속 금지      maxPerRole 기본 1 · levity 만 2
③ 같은 seed 반복 금지       seedReuseRate — 최근 N건 내 동일 seed 배분 제한
④ 같은 hookType / ending 반복 금지   Voice Variation 직전 3회 제외
⑤ 경험 공유는 Identity 일치 시만     불일치면 공감 · 질문 · 완충으로 낮춘다
⑥ 같은 페르소나가 한 글에 두 번 금지
🔴 ⑦ 일부 페르소나는 침묵한다        silenceRate + mood talkativeness
```

### §4-2 흔들림 규칙

**고정값이 하나도 없어야 한다.**

```
commentCount   range 에서 매번 추첨      같은 유형도 1개일 때가 있다
firstRole      후보군에서 가중 추첨      고정 1순위 없음
role 선택      roleWeights 가중 추첨     forbiddenRoles 는 확률 0 이 아니라 명시 금지
길이 · 강도    mood 가 밀거나 당긴다     Architecture §6
참여 여부      silenceRate 가 먼저 판정   자격이 있어도 침묵할 수 있다
```

🔴 **여러 페르소나가 같은 글에 같은 맞장구를 달지 않게 한다.**
개별 댓글이 자연스러워도 나란히 놓이면 기계다. seed 배분은 **글 단위로** 본다.

### §4-3 🔴 원문의 단조로움을 목표로 삼지 않는다

실측 — 한 글에 붙은 반응 유형 종수다.

| 글 유형 | 1종 | 2종 | 3종 | 4종+ |
|---|---|---|---|---|
| 가족 · 관계 갈등 | 17.5% | 33.0% | 31.0% | 18.5% |
| 외로움 · 감정 토로 | 24.7% | 33.5% | 25.5% | 16.3% |
| 돈 · 일 · 자산 | 29.8% | 35.2% | 24.5% | 10.6% |
| 건강 · 갱년기 · 병원 | 29.9% | 38.8% | 20.7% | 10.7% |
| 생활 정보 · 잡담 | 30.4% | 38.6% | 24.0% | 7.0% |

🔴 **1종 비율(17.5~30.4%)을 재현 목표로 삼지 않는다.**
원문에는 사람이 하나만 달고 지나간 글이 섞여 있지만,
**우리는 페르소나를 여러 명 붙이므로 같은 역할이 겹치면 즉시 티가 난다.**

🟢 가져오는 것은 **유형 간 상대 순위**다 — 가족이 가장 다양하고 잡담이 가장 단조롭다.

### §4-4 첫 댓글은 "받아주는 말" 후보군

실측상 5종 전부에서 `question` · `levity` · `empathy` 가 상위 3종이다.

```
🟢 후보군    question · empathy · levity     유형별 weight 는 §3-3
🔴 고정 아님  "첫 댓글은 공감" 으로 정하지 않는다. 후보군에서 추첨한다
🔴 제외      advice · information · caution · rebuttal 로 시작하지 않는다
```

**근거** — 원문 첫 댓글에서 `information` 은 0.7~1.5% 로 전 유형 최저권이다.
**대화는 받아주는 말로 시작한다.**

⚠️ 단 건강 글만 첫 댓글 `advice` 5.0% 로 유일하게 눈에 띈다.
**첫 댓글 조언 금지가 건강 유형에서 가장 중요하다.**

### §4-5 댓글 수 — 원문보다 적게

원문 평균은 5.1~7.4개지만 **MVP 는 1~3개**다.

```
회원 4명 규모에서 페르소나 댓글 9개는 비율이 뒤집힌다
[전략 §6] 초기 활성 3~5명 · Architecture dailyCap 과 함께 본다
```

## §4-6 source comment seed 기반 재맥락화

### 🔴 용어부터 고정한다

```
🟢 쓴다     source comment seed 기반 재맥락화
🔴 안 쓴다  "댓글 복붙 허용" · "약간 수정" · "살짝 고쳐서 가져오기"
```

**댓글 문장을 그대로 가져오는 시스템이 아니다.**
반응 seed 를 페르소나의 **identity · voice variation · mood · memory 에 맞게 다시 말하는** 시스템이다.

### 본문과 댓글의 기준이 다르다

원문 본문은 originality 를 강하게 보고, 원문 댓글은 그보다 유연하게 다룬다.
그 계약은 [Safety Gate §3-②](2026-08-30-persona-safety-originality-gate-design.md) 에 고정돼 있고,
**이 문서는 그것을 따른다.**

| | 원문 **본문** | 원문 **댓글** |
|---|---|---|
| 희귀도 기준 코퍼스 | 본문 **2,504건** | 댓글 **59,252건** |
| 문장 | 🔴 재사용 금지 | 🟡 **A 등급 한정** 유사 표현 seed |
| **① 20자 룰** | 🔴 유지 | 🔴 **유지 — 완화하지 않는다** |
| 역할 · 순서 · 밀도 · 감정 흐름 | 참고 | 🟢 적극 참고 |

🔴 **코퍼스를 섞지 않는다.** 댓글 생성물을 본문 코퍼스로 재면 자연스러운 짧은 반응이
오탐되고, 반대로 재면 본문에 쓰면 안 될 구어 표현이 통과한다.

### seed 등급 A / B / C

등급은 [Gate §3-②](2026-08-30-persona-safety-originality-gate-design.md) 의
**빈도축 + 내용안전축** 2축으로 정해지고, **더 엄격한 쪽**을 따른다.

| 등급 | 문장 | 역할 | 제약 |
|---|---|---|---|
| **A** | 🟢 유사 표현 seed 가능 | 🟢 | 🔴 동일 문장 반복 금지 · 외부 호칭 금지 · **20자 룰 유지** |
| **B** | 🟡 페르소나 말투로 **재작성** | 🟢 | 감정 방향·역할은 사용 가능. **1인칭 경험은 identity 일치 시만** |
| **C** | 🔴 재사용 금지 | 🟢 **역할 · 구조만** | 의료·법률·재무 조언 · 식별 디테일 · 구체 경험 사실 · 닉네임 · 출처 흔적 |

🔴 **빈도가 높아도 내용이 위험하면 C 다.** 유형별 강도는 §3-4 를 따른다.

### 경험이 없는 페르소나는 등급을 낮춘다

```
identity 와 맞지 않는 1인칭 경험  →  🔴 금지
                                    공감 · 질문 · 가벼운 반응으로 낮춘다
```

**자격이 없다고 침묵만 하는 것이 아니다.** 역할을 낮추면 참여할 수 있다.

## §4-7 AI 티 방지 장치

```
① 고정 순서 금지                    firstRole 후보군 가중 추첨
② 같은 role 3연속 금지              maxPerRole
③ 같은 seed 반복 금지               seedReuseRate
④ 같은 hookType / ending 반복 금지   Voice Variation 직전 3회 제외
⑤ persona 별 말투 variation 사용     Architecture §5 — 5~8개
⑥ mood 에 따라 길이 · 반응 강도 변화  Architecture §6
🔴 ⑦ silenceRate — 일부 페르소나는 침묵한다
🔴 ⑧ 같은 글에 여러 페르소나가 같은 맞장구를 달지 않게 한다
```

**⑧이 seed 정책과 함께 새로 필요해진 장치다.** 개별 댓글이 자연스러워도
나란히 놓이면 기계다. **seed 배분은 글 단위로 본다.**

```
🔴 seedReuseRate · silenceRate 의 기본값은 구현 시 결정한다.
   운영 데이터 없이 임계를 정하면 오탐이거나 무력하다.
   조정 손잡이가 있다는 것만 여기서 고정한다.
```

AI 티가 났을 때 돌릴 손잡이는 이것들이다 —
`seedReuseRate` · `roleWeights` · `firstRole` 후보 · `commentCount` range · persona eligibility.

## §4-8 운영자 AI 티 태그

운영자가 승인 화면에서 *"AI 티 난다"* 를 분류할 수 있게 태그를 둔다.

| 태그 | 판정 근거 | 관문 |
|---|---|---|
| 말투 반복 | n-gram 점유율 · ending 반복 | ⑧ |
| 너무 정리됨 | 구조화 나열 · 마크다운 말투 | ⑧ 하위 축 |
| 과도한 공감 | `empathy` 가 유형 기준 초과 | 반응 지도 |
| 생활감 부족 | 오타 · 줄바꿈 · 구어 표지 없음 | ⑧ 역지표 |
| 페르소나 정체성 모순 | Identity · Memory 충돌 | ⑦ |
| 원문 구조 과복제 | 전개 순서 3개+ 동일 | ④ |
| 원문 댓글과 유사 | seed 재사용 강도 · ② 희귀도 | ① ② ⑧ |
| 조언 위험 | `advice` · `caution` 이 금지 유형에 등장 | §5 조언 제한 |
| 외부 커뮤니티 흔적 | marker 적중 | ⑨ |

🔴 **태그는 `pass`/`review` 판정과 별개다.** Gate 를 통과해도 태그가 붙을 수 있고,
**운영자가 무엇을 볼지 알려주는 힌트**다.

## §5 Persona Matcher 와의 접점

### §5-1 3단 필터

```
① 자격      이 페르소나가 이 글에 반응할 수 있는가   (Identity 대조)
      ↓
② 우선순위   여럿이 자격을 가질 때 누가 먼저인가      (Relationship Memory)
      ↓
③ 참여      자격이 있어도 오늘 말할 기분인가         (Mood · Activity Rhythm)
```

### §5-2 ① 자격 — 🔴 자기 경험과 맞지 않으면 댓글 금지

| 글 유형 | 자격 조건 (Identity) |
|---|---|
| 자녀 관련 | `children` 이 비어 있으면 **경험 공유 금지** (공감·질문은 가능) |
| 시댁 갈등 | `maritalStatus` 가 비혼이면 **경험 공유 금지** |
| 간병 | `parentCare` 가 없으면 **경험 공유 금지** |
| 갱년기 | `menopauseStatus` 와 어긋나면 **경험 공유 금지** |

🔴 **자격이 없다고 침묵만 하는 것이 아니다.** 반응 유형을 낮추면 된다 —
경험 공유는 못 해도 **공감은 누구나 할 수 있다.**

```
자녀 없는 페르소나 + 자녀 글
  🔴 금지   "우리 애도 그맘때 그랬어요"
  🟢 허용   "읽는데 마음이 무거웠어요"
```

이 판정을 통과하지 못한 생성물은 [Gate ⑦ Persona Consistency](2026-08-30-persona-safety-originality-gate-design.md) 가 잡는다.
**Matcher 가 앞에서 거르고 Gate 가 뒤에서 막는 이중 구조다.**

### §5-3 ② 우선순위 — 관계 기억이 있으면 올라간다

```
이 회원의 글에 전에도 댓글을 단 페르소나   → 우선순위 ↑
  → "저번에 말씀하신 그 일은 좀 나아지셨어요?" 가 가능해진다
  → 🔴 회원이 공개한 것만. 추론·단정 금지 (Architecture §7)
```

**관계가 쌓이는 것이 retention 의 핵심**이고, 반응 지도는 그 관계를 이어줄 페르소나를 먼저 부른다.

### §5-4 ③ 참여 — mood 가 최종 결정

자격 있고 우선순위 높아도, **오늘 `talkativeness` 가 과묵이면 침묵한다.**
같은 페르소나가 매번 같은 글에 반응하면 그것도 패턴이다.

## §6 Safety Gate 와의 접점

### §6-1 반응 지도가 Gate 를 대신하지 않는다

```
반응 지도   "무엇을 만들까"   — 생성 전 · 후보 선택
Gate       "내보내도 되나"   — 생성 후 · 9관문
```

**반응 지도가 조언형을 1개로 제한해도, 그 1개가 안전하다는 뜻은 아니다.**
Gate 는 그대로 전건 검사한다.

### §6-2 관문별 접점

| 항목 | 어디서 막는가 |
|---|---|
| 의료 · 법률 · 재무 **단정 조언** | [Gate §5 조언 제한](2026-08-30-persona-safety-originality-gate-design.md) — 반응 지도는 `advice` 비중만 낮춘다 |
| 1인칭 경험 진술 경계 | Gate §5 — ③ 식별 디테일 · ⑦ Persona Consistency 와 함께 |
| **위기 신호** | 🔴 **댓글 생성 자체를 시작하지 않는다** · 운영자 알림 (Gate §4 선행 차단) |
| 닉네임 · author 재사용 | Gate ⑥ — 실시간 대조 |
| source comment seed 등급 판정 | 🆕 [Gate §3-②](2026-08-30-persona-safety-originality-gate-design.md) — **댓글 코퍼스 59,252건** 기준 |
| 본문 생성물의 고유 표현 | Gate §3-② — **본문 코퍼스 2,504건** 기준 (🔴 코퍼스를 섞지 않는다) |
| 20자 이상 연속 일치 | 🔴 Gate ① — **댓글이라고 완화하지 않는다** |
| seed 반복 배분 | 🆕 Gate ⑧ `seedReuseRate` |
| 출처 커뮤니티 흔적 | Gate ⑨ — `SOURCE_SPECIFIC_TERMS` 8 + `SOURCE_CONTEXT_TERMS` 8 |
| 같은 말투 반복 | Gate ⑧ Voice Fingerprint |

### §6-3 🔴 위기 신호는 반응 지도보다 앞이다

```
① Trend / 글 수신
      ↓
🔴 위기 신호 감지  →  댓글 생성 시작하지 않음 · 운영자 알림
      ↓ (통과)
② 반응 지도 → ③ Matcher → ④ 생성 → ⑤ Gate → ⑥ 승인 대기열
```

**반응 지도가 "어떤 반응이 어울릴까" 를 묻기 전에 "반응해도 되는 글인가" 가 먼저다.**
자해·자살 신호에 페르소나가 위로하려다 상황을 악화시키는 것이 최악이다. **사람에게 넘긴다.**

## §7 최소 MVP 범위

```
🟢 한다
   · comment 후보 생성부터 시작
   · 글당 1~3개
   · 운영자 전건 승인 후 발행
   · 반응 유형 분배는 규칙 기반 (학습 아님)

🔴 안 한다
   · 자동 발행
   · post 생성 (댓글이 안정된 뒤)
   · 대댓글 (1차 보류)
   · 반응 유형 자동 학습
```

### 왜 comment 먼저인가

```
· 실패 비용이 작다     — 댓글은 짧고, 문제 시 회수 범위가 좁다
· 문제를 정확히 푼다   — 댓글 0개 글 65% 가 지금의 문제다
· post 는 소재 선택 · 제목 · 길이까지 얽혀 변수가 많다
```

[Gate §12](2026-08-30-persona-safety-originality-gate-design.md) 의 comment 우선 권고와 같다.

## §8 필요한 데이터

### §8-2 `story_topic` 1,304건을 쓰는 법

[학습 정책](2026-08-29-voice-m3-learning-policy.md)이 정한 용도가 그대로 적용된다.

```
🟢 쓴다      사건 구조 · 댓글 반응 구조
🔴 안 쓴다   말투 few-shot (speakerVerified 가 아니다)
```

**반응 지도에는 "무슨 말을 했나" 가 아니라 "어떤 반응이 몇 개 붙었나" 만 필요하다.**
그래서 `story_topic` 이 말투 학습에 못 쓰이면서도 여기서는 1급 자산이 된다.

### §8-3 🔴 참고하지 않을 것

```
🔴 댓글 원문           — VoiceCommentSignal 에 hash 만 있다. 원문은 애초에 없다
🔴 author / 닉네임      — authorHash 만 있다
🔴 VE-M3 notes 원문     — 판정 근거 텍스트는 지도에 넣지 않는다
🟡 likeCount           — 우나어 수집 시점 값이라 신뢰도가 낮다. 순위 보조로만
```

### §8-4 🔴 선행 과제 — 분류기 재측정

M3 착수 시 **가장 먼저 할 일**이다.

```
1) ReactionMapType 분류기 초안 (levity 추가 · advice 재정의)
2) 59,252건 재분류 — 🔴 read-only 계산. DB write 없이 집계만
3) unclassified 비율 측정      목표 30% 이하
4) 글 유형 × 반응 조합 실측    → §3 가설 교정
5) 한 글당 유형 종수 재측정    → §4-1 수치 교정
```

**②~⑤ 는 전부 read-only 로 가능하다.** 비용 0원이고 LLM 호출도 없다.
**분류기 초안 없이 §3 · §4 를 확정하지 않는다.**
