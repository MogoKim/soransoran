### 각각 무엇을 고쳤나

**#74 — 바탕이 회색이라 브랜드가 안 보였다**

## 3. 왜 그렇게 정했나

### 3-1. `#FF6F61` 은 메인 컬러이지만 난발하지 않는다

밝은 색이라 흰 글씨를 못 얹고(2.73:1), 밝은 바탕에서 면으로도 잘 안 갈린다(2.60:1).

```
🟢 쓴다    헤더 워드마크 · CTA/FAB fill · 그림자 · 활성 표시 면 · 포인트
🚫 안 쓴다  페이지 배경 전체 · 넓은 카드 면 · 본문 · 작은 라벨 · 캡션 · 메타
           링크 · 배지 텍스트 · 정보 전달 아이콘
```

**판단 한 줄**: *이 면이 없어져도 사용자가 정보를 놓치지 않는가?*

### 3-2. CTA/FAB 는 코랄 fill + 흰 글씨

```
fill    --cta        코랄
text    --cta-text   #FFFFFF
border  없음
hover   hover:brightness-95
pressed active:scale-95
shadow  --shadow-brand (FAB)
```

**클래스는 세 개로 끝난다.**
```
transition duration-150 hover:brightness-95 active:scale-95
```

hover 색 토큰도, 테두리 토큰도, pressed 색도 두지 않는다.
**상태를 색으로 늘리면 그때마다 대비를 전부 다시 재야 한다.**

### 3-3. 🔴 먹색 글씨 + 테두리 조합은 폐기했다

#82 에서 시도했고 #84 에서 걷어냈다.

```
폐기한 조합
  #FF6F61 + 먹색 #2F2624        5.41 : 1   요건 4.5 통과
  + 테두리 #B64235               바탕 5.24 : 1 통과
```

**수치는 전부 통과했는데 실기기에서 버튼으로 읽히지 않았다.**

| | 유리한 쪽 | |
|---|---|---|
| 판독성 (글자를 읽을 수 있는가) | 먹색 | 5.41 vs 2.73 |
| **버튼성** (눌러야 할 것으로 보이는가) | **흰 글씨** | |

**창업자 실기기 확인으로 버튼성을 골랐다. 수치가 아니라 실제로 눌리는가로 정했다.**

🔴 **대가**: 코랄 + 흰 글씨는 **2.73:1 로 WCAG 2.1 AA 1.4.3 에 미달**한다.
저조도·야외에서 라벨이 흐려질 수 있고, 타깃이 40~60대라 가벼운 비용이 아니다.

그래서 **범위를 큰 버튼과 FAB 으로 좁혔다** — 면적이 크고 위치가 고정돼 있어
라벨을 못 읽어도 무엇을 누르는지 맥락으로 안다.
**작은 글씨·본문·메타·라벨에는 여전히 못 쓴다.**

🟡 **다시 시도하지 마라**: 밝은 코랄 면에 어두운 글씨를 얹는 조합은 이미 한 번 실패했다.
흐릿하다고 느껴지면 테두리를 두르지 말고 **그림자를 먼저 검토한다**(대비 요건이 없다).

### 3-4. 건너뛰기 링크는 CTA 시각 정책에서 뺐다

`PageShell` 의 건너뛰기 링크는 키보드 포커스에서만 나타나는 **숨은 접근성 유틸**이다.
쓰는 사람은 **화면을 눈으로 훑지 못하거나 마우스를 못 쓰는 사용자**다.

큰 버튼의 예외 근거는 "면적이 크고 위치가 고정돼 맥락으로 안다"인데,
건너뛰기 링크는 **그 맥락이 없는 사용자를 위한 것**이라 근거가 성립하지 않는다.
코랄+흰 글씨(2.73)를 여기까지 넓히면 **접근성 유틸이 접근성에 미달한다.**

```
보이는 CTA · FAB   7 곳   bg-cta        코랄 + 흰 글씨 2.73
숨은 접근성 유틸    1 곳   bg-cta-edge   #B64235 + 흰 글씨 5.50 ✅
```

### 3-5. 카카오 색은 격리한다

```
--kakao-bg #FEE500 + --kakao-text #191919   13.75 : 1
hover 는 brightness 로만 — 색을 새로 두지 않는다
```

hover 색을 따로 두는 순간 카카오 노란색이 아니게 된다.
🚫 `--kakao-text` 를 우리 CTA 글자색으로 빌려 쓰지 않는다 — 격리가 무너진다.

### 3-6. 게시판 색은 브랜드 코랄로 수렴시키지 않는다

네 면이 색상환에서 서로 떨어져 있어야 구분된다. 코랄 하나로 모으면 아이콘이 전부
비슷해 보이고 **지금 어느 방에 있는지가 흐려진다.**

🚫 상단 메뉴 활성 표시도 보드색이다. 전 메뉴가 같은 브랜드색이면 위치가 안 보인다.
🚫 `text` 는 `stroke` 보다 어둡다. 같은 색을 글자에 쓰면 배경 위 대비가 모자란다.

## 5. 되돌리는 법

### 바탕·구분선을 중성으로

`src/app/globals.css` 세 줄.
```
--surface-page        #FFF8F6 → #F9FAFB
--border-subtle       #F2C9C1 → #E5E7EB
--border-interactive  #B87F73 → #8E949E
```
🔴 브랜드 톤이 화면 전체에서 사라진다. 되돌리기 전에 §3-1 을 읽는다.

### CTA/FAB 를 안정 조합으로

`src/app/globals.css` **한 줄.**
```
--cta: var(--brand) → #b64235
```
`#B64235` + 흰 글씨 **5.50:1** 로 완전 복귀한다. 컴포넌트는 고치지 않는다.
테두리도 hover 색도 없으니 잔여물이 남지 않는다.

**흰 글씨가 흐리다는 얘기가 나오면 이 한 줄이 답이다.**

### 헤더 워드마크를 읽는 색으로

`src/components/layouts/Header.tsx` 한 곳.
```
<Logo tone="brand" …/> → <Logo …/>
```
당시에는 `--brand-ink` 가 더 어두운 값이라 6.95:1 로 돌아왔다.
2026-08-29 개정 이후 `--brand-ink` 는 `--brand` 와 같은 값이므로 이 절차로는 대비가 오르지 않는다.

### 상호작용이 과하면

컴포넌트 클래스에서 조절한다. 색이 아니라 **크기와 시간**이다.
```
active:scale-95  → active:scale-[0.98]   눌림 폭을 줄인다
duration-150     → duration-200          느리게
hover:brightness-95 제거                  hover 를 없앤다
```
🚫 되돌린다고 색 토큰을 새로 만들지 않는다.

### FAB 그림자를 중성으로

`src/components/layouts/FAB.tsx` 한 곳.
```
shadow-[shadow:var(--shadow-brand)] → shadow-lg
```

## 7. 남은 것

### 죽은 토큰 정리 (감사 필요)

| 토큰 | 상황 |
|---|---|
| `--brand-soft` `#FFE8E3` | `--surface-soft` 와 **값이 같다.** 같은 색이 두 이름 |
| `--brand-muted` `#F2C9C1` | `--border-subtle` 과 **값이 같다** |
| `--state-info` `#1660C4` | 쓰는 곳 없음 |

값이 같아도 **의미가 다르다**(브랜드 배지 vs 표면 / 브랜드 장식선 vs 구분선).

## 8. 하나만 기억한다면

**색을 바꾸기 전에 색 정본을 먼저 고친다.**

오늘 되돌린 두 건은 전부 *"코드만 보고 판단해서"* 생겼다.
바탕색이 왜 웜 아이보리인지 문서에 적혀 있었는데 코드만 보고 회색으로 바꿨고,
CTA 글자색은 수치만 보고 정했다가 실기기에서 뒤집혔다.

**수치는 필요조건이지 충분조건이 아니다. 그리고 코드와 문서 중 하나만 고치지 않는다.**
