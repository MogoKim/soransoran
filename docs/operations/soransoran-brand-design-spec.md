## 1. 브랜드 원칙

### 1-1. 메인 브랜드 컬러는 `#FF6F61` 이다

창업자 결정이다. 흔들지 않는다.

### 1-2. 🔴 그러나 넓은 면에 무조건 칠하는 색이 아니다

```
#FF6F61 은 아름답지만 밝다 (HSL h5 · s100% · l69%).
밝은 색은 흰 글씨를 못 얹고, 밝은 바탕 위에서 면으로도 잘 안 갈린다.

  #FFFFFF on #FF6F61     2.73 : 1     요건 4.5 — 못 쓴다
  같은 조합 (큰 글씨)      2.73 : 1     요건 3.0 — 큰 글씨로도 못 쓴다
  #FF6F61 텍스트          2.60 : 1     요건 4.5 — 못 쓴다
  #FF6F61 면 vs 바탕      2.60 : 1     요건 3.0 — 테두리 없이는 못 쓴다
```

**그래서 "많이 칠하는 색"이 아니라 "정확한 포인트 색"으로 운영한다.**

### 1-3. 포인트로 쓰는 자리

```
🟢 우선 쓴다     헤더 워드마크 · 활성/현재 상태 · 눌림 피드백
                 FAB 계열 · 브랜드 신호 · 그림자 · OG 장식 면

🔴 난발 금지     페이지 배경 전체 · 넓은 카드 면 · 본문 텍스트
                 작은 라벨 · 캡션 · 메타 정보 · 정보 전달 아이콘
```

**판단 기준 한 줄**: *이 면이 없어져도 사용자가 정보를 놓치지 않는가?* 놓치지 않으면 코랄을 쓸 수 있고, 놓치면 대비 요건을 먼저 만족시켜야 한다.

### 1-4. 40~60대가 매일 읽는 화면이다

대비는 규정 통과용이 아니다. 노안 구간의 사용자가 저조도·야외에서 읽어야 한다.
**규정이 면제하는 자리에서도 "읽히는가"를 따로 확인한다.**

## 3. §3-1 — brand 와 CTA 의 분리

### 왜 나누는가

`#FF6F61` 하나로 모든 UI 를 처리하면 흰 글씨 버튼에서 대비가 무너진다(§1-2).
그래서 **브랜드 신호**와 **누르는 것**을 토큰으로 나눈다. 같은 색 계열(h5~11)이라 화면에서는 하나의 브랜드로 읽힌다.

### 분리 원칙

| 토큰 | 역할 | 쓰는 곳 | 쓰지 않는 곳 |
|---|---|---|---|
| **brand** `#FF6F61` | 브랜드 시그니처 | 헤더 워드마크 · 포인트 · 활성 표시 면 · 그림자 · OG 장식 면 · **CTA/FAB fill (§3-1-B 조건 충족 시)** | 🔴 **흰 글씨 CTA** · 본문 텍스트 · 작은 글씨 · 정보 전달 아이콘 |
| **cta** `#B64235` | 누르는 것 | §3-1-A 또는 §3-1-B | 넓은 배경 면 |
| **brand-ink** `#9A3A31` | 읽는 브랜드색 | 링크 · 작성자명 · 배지 텍스트 · 강조 텍스트 · 큰 워드마크 | 큰 면 fill |

### 🔴 `#FF6F61` 텍스트 금지 목록

```
🚫 본문 · 미리보기 · 작은 라벨 · 캡션 · 메타 정보
🚫 CTA 버튼 텍스트
🚫 링크 · 활성 탭 텍스트 · 배지 텍스트
🚫 정보 전달 아이콘 (경고 · 상태 · 기능 표시)
```

대체 토큰은 전부 `--brand-ink`(`#9A3A31`, 바탕 위 6.62:1)다.

### 비텍스트 사용 — 두 가지를 구분한다

| 구분 | 요건 | `#FF6F61` | 예 |
|---|---|---|---|
| **장식 면** | 없음 | 🟢 허용 | 배경 블록 · 밑줄 장식 · 구분 띠 · **그림자** · OG 그래픽 |
| **정보 전달 그래픽** | **3:1** (WCAG 1.4.11) | 🔴 불가 (2.60) | 상태 아이콘 · 활성 표시 · 입력 테두리 · 차트 범례 |

같은 색이라도 "예쁘라고 있는 면"과 "뜻을 전달하는 그래픽"은 요건이 다르다.

`#B64235` 는 **메인 브랜드 컬러가 아니다.** 접근성을 위해 파생한 어두운 색이다.

## 3-1-B. 🟢 CTA/FAB 코랄 전환 조건 — **가능하다**

> 이 절이 이 문서의 개정 핵심이다.
> **"CTA 는 `#B64235` 여야 한다"는 고정 규칙을 해제한다.**
> `#FF6F61` 을 CTA/FAB fill 로 쓸 수 있다. **단 아래 네 조건을 모두 지킨다.**

### 조건 1 — 🔴 흰 글씨를 쓰지 않는다

```
#FFFFFF on #FF6F61     2.73 : 1     요건 4.5 — FAIL
같은 조합 (큰 글씨)      2.73 : 1     요건 3.0 — FAIL
```

**글자를 키워도 통과하지 않는다. 흰 글씨는 길이 없다.**

채도를 유지한 채 흰 글씨를 통과시키려면 명도를 L45% 아래까지 내려야 한다. 그 지점의 색은 이미 코랄이 아니라 순빨강이다. **밝기를 낮춰 흰 글씨를 살리는 길은 코랄을 포기하는 길이다.**

### 조건 2 — 🟢 글자는 `--text-primary` 를 쓴다

| 글자색 | 토큰 | 대비 | |
|---|---|---:|---|
| **`#2F2624`** | **`--text-primary`** | **5.41** | ✅ **권장** |
| `#191919` | `--kakao-text` | 6.45 | 🔴 §4 격리 토큰 — 빌려 쓰지 않는다 |
| `#524642` | `--text-secondary` | 3.33 | 🟡 큰 글씨만 |
| `#9A3A31` | `--brand-ink` | 2.55 | 🔴 |
| `#96372E` | `--cta-hover` | 2.67 | 🔴 |
| `#B64235` | `--cta` | 2.02 | 🔴 |

**새 hex 를 만들 필요가 없다.** `--text-primary` 가 5.41:1 로 통과한다.

`--kakao-text` 가 대비는 더 높지만 그 토큰은 외부 브랜드 예외로 격리해 둔 것이다(§4). 소란소란 CTA 가 빌려 쓰면 격리가 무너진다.

### 조건 3 — 🟢 면 경계를 테두리로 만든다

```
#FF6F61 면 vs 바탕 #FFF8F6    2.60 : 1     요건 3.0 — FAIL
#FF6F61 면 vs 카드 #FFFFFF    2.73 : 1     요건 3.0 — FAIL
```

코랄 면은 밝은 바탕에서 스스로 갈리지 않는다. **테두리가 경계를 대신한다.**

| 테두리 | vs 바탕 | |
|---|---:|---|
| **`--cta` `#B64235`** | **5.24** | ✅ **권장** |
| `--cta-hover` `#96372E` | 6.94 | ✅ |
| `--brand-ink` `#9A3A31` | 6.62 | ✅ |
| `--border-interactive` `#B87F73` | 3.17 | 🟡 경계 |

### 조건 4 — 🟡 눌림은 색이 아니라 크기가 1차 신호다

| pressed 후보 | 코랄면과 차이 |
|---|---:|
| `--cta` `#B64235` | 2.02 |
| `--cta-hover` `#96372E` | 2.67 |
| 코랄을 한 단계 어둡게 | 1.36 |

🔴 **정확히 적는다**: 위 수치는 3:1 에 못 미친다. WCAG 1.4.11 은 같은 컨트롤의 **상태 간** 대비를 요구하지 않으므로 규정 위반은 아니다. 그러나 **색만으로는 눌림이 확실하지 않다.**

**눌림의 1차 신호는 `active:scale-95` 다**(§7). 색은 보조다.
코랄끼리(1.36)는 쓰지 않는다 — 구분이 안 된다.

### 권장 조합 정리

```
fill      --brand         #FF6F61
text      --text-primary  #2F2624      5.41 : 1   ✅
border    --cta           #B64235      바탕 대비 5.24 : 1
pressed   --cta           #B64235      + active:scale-95 (1차 신호)
hover     어두워지는 방향                밝아지면 대비가 더 떨어진다
shadow    --shadow-brand               유지
```

### 🔴 `--cta` 의 역할 재정의

전환하면 `#B64235` 는 **메인 액션 색이 아니라 코랄의 테두리와 눌린 상태**가 된다.

```
--cta        #B64235   테두리 · pressed · 흰 글씨가 필요한 좁은 자리
--cta-hover  #96372E   pressed 심화 · focus ring (이미 같은 값)
```

**"depth / accessibility 보조 토큰"** 으로 읽어야 한다.

### 🔴 전환은 전부 함께 한다

`bg-cta` 는 **8곳**이 쓴다. 홈에서 FAB 과 참여 유도 카드 버튼이 **같은 화면에 공존**한다.
**한 곳만 바꾸면 "누르는 것"이 두 색이 된다.** 부분 전환은 성립하지 않는다.

## 3-2. 로고 정본

### 현재 확정 상태

| 자리 | 크기 | 색 | 근거 |
|---|---:|---|---|
| **헤더 워드마크** | 24px | **`--brand` `#FF6F61`** | 포인트 색. 2.73:1 — WCAG 1.4.3 로고타입 예외 |
| **홈 hero 워드마크** | 30px | `--brand-ink` `#9A3A31` | 6.95:1. 넓은 면이라 판독 우선 |
| 에러 화면 워드마크 | 24px | `--brand-ink` | 판독 우선 |

**작은 쪽이 포인트, 큰 쪽이 읽는 색이다.** 홈에서는 둘이 한 화면에 같이 뜬다.

### WCAG 1.4.3 로고타입 예외

```
"로고 또는 브랜드명의 일부인 텍스트는 대비 요건이 없다"
```

헤더 워드마크 2.73:1 은 **규정 위반이 아니다.**

### 🔴 워드마크에 `#FF6F61` 을 쓰는 조건

| # | 조건 | 헤더 현황 |
|---|---|---|
| 1 | Pretendard 800 또는 900 | `font-extrabold` = 800 ✅ |
| 2 | 충분한 크기 | 24px ✅ |
| 3 | 충분한 여백 | 헤더 좌측 단독 ✅ |
| 4 | **실기기 모바일 판독성** | ✅ **2026-08-26 창업자 실기기 확인 완료** |

**"면제된다"는 것과 "읽힌다"는 것은 다르다.**
네 조건을 모두 통과했으므로 헤더 워드마크의 `#FF6F61` 은 확정이다.

### 판독성 미달 시

```
1순위   --brand-ink (#9A3A31) 워드마크    6.95 : 1
        색 계열이 같아 브랜드 인상이 깨지지 않는다
2순위   이미지 로고 — 자체 대비를 내장해 설계
```

🔴 **"브랜드 컬러니까"를 이유로 안 읽히는 워드마크를 유지하지 않는다.**
워드마크의 목적은 브랜드 색을 보여주는 것이 아니라 **브랜드명을 읽히게 하는 것**이다.

### 로고 마크업 규칙

로고는 `src/components/brand/Logo.tsx` 한 곳에서만 마크업한다.
페이지·컴포넌트가 직접 `<span>소란소란</span>` 을 쓰지 않는다 — 나중에 이미지 로고로 바꿀 때 한 파일만 고치면 되게 한다.

| 격리 | 리터럴이 컴포넌트에 흩어지지 않게 토큰으로 둔다 |

| 빌려쓰기 | 🔴 `--kakao-text` 를 소란소란 CTA 글자색으로 쓰지 않는다 |
| 노출 | `/login` 1곳 |

**hover 색을 따로 두는 순간 카카오 노란색이 아니게 된다.**

## 5. 게시판 색 — 🔴 브랜드로 수렴시키지 않는다

색은 `src/lib/board-registry.ts` 가 정한다. 컴포넌트는 읽기만 한다.
`BoardBadge` · `ListHeader` · `IconMenu` 전부 `icon*Var` 를 쓴다.

| 보드 | bg | stroke | text | stroke on bg |
|---|---|---|---|---:|
| 갱년기톡 | `#FCE4EC` | `#C2185B` | `#AD1457` | 4.88 |
| 자유게시판 | `#FFF1E5` | `#A1541B` | `#8F4514` | 4.99 |
| 매거진 | `#E3F2FD` | `#185FA5` | `#185FA5` | 5.71 |
| 베스트 | `#FFE9E5` | `#C4453B` | `#AD372F` | 4.23 |

🔴 **네 면이 색상환에서 서로 떨어져 있어야 구분된다.** 브랜드 코랄 하나로 수렴시키면 아이콘이 전부 비슷해 보이고, 어느 방에 있는지가 흐려진다.

🔴 **IconMenu 활성 표시도 보드색이다.** 전 메뉴가 같은 브랜드색이면 지금 어디 있는지가 안 보인다.

🔴 **`text` 는 `stroke` 보다 어둡다.** 같은 색을 글자에 쓰면 배경 위 대비가 모자란다.

보드가 늘어도 컴포넌트에 조건문이 붙지 않아야 한다. 색은 항상 registry 가 정한다.

## 7. 상호작용 상태 정본

**`hover:` 는 터치에서 sticky 가 된다. 터치 피드백의 본체는 `active:` 다.**
`active:` 가 없으면 모바일에서 무엇을 눌러도 아무 반응이 없다.

| 부류 | 대상 | hover | active |
|---|---|---|---|
| **누르는 것** | FAB · CTA · ActionButton · 카카오 | 한 단계 어둡게 | `scale-95` |
| **리스트 항목** | PostListItem · PostCard | `bg-surface-page` | `bg-surface-soft` |
| **아이콘 · 토글** | IconMenu · FontSizeToggle | `bg-surface-page` / `bg-surface-soft` | `scale-95` |
| **텍스트 버튼** | HeaderAuth · SignOutButton | `bg-surface-soft` | `scale-[0.98]` |
| **포커스** | 전역 | — | `:focus-visible` `--focus-ring` 2px + offset 2px |

### 규칙

```
transition duration-150 을 함께 붙인다 — 색만 바뀌고 시간이 없으면 딱딱하다.

disabled 가 있는 버튼은 enabled: 로 잠근다.
  disabled:opacity-60 만 두면 제출 중인 버튼도 hover 에서 색이 바뀌어
  "아직 누를 수 있다" 로 읽힌다.

iOS 기본 탭 하이라이트는 Tailwind preflight 의 html 규칙이 이미 끈다.
  컴포넌트에 [-webkit-tap-highlight-color:transparent] 를 붙이지 않는다 — 죽은 클래스가 된다.

브랜드 코랄이 드러나는 상호작용 표면은 --surface-soft(#FFE8E3) 다.
```

### 눌림에 코랄끼리 쓰지 않는다

`#FF6F61` → 한 단계 어두운 코랄은 **1.36:1** 로 구분이 안 된다. §3-1-B 조건 4 를 따른다.

## 8. 토큰 유지보수 원칙

### 8-1. hex 는 두 곳에만 있다

```
src/app/globals.css   화면에 그려지는 모든 색
src/lib/brand.ts      metadata · manifest · OG (CSS 변수를 해석하지 못하는 곳)
```

컴포넌트는 semantic token 만 쓴다. `npm run check:tokens` 가 강제한다.
색을 바꿀 때는 이 두 파일만 고치면 전체 UI 가 교체된다.

### 8-2. 🔴 토큰 정의와 유틸리티 이름이 어긋나면 토큰이 죽는다

**실제로 겪은 사고다.** `tailwind.config.ts` 에서 색을 이렇게 두면

```ts
colors: { border: { subtle: '…', interactive: '…' } }
```

Tailwind 가 중첩 객체를 `부모-자식` 으로 평탄화해 색 이름이 `border-subtle` 이 되고,
borderColor 유틸리티는 **`border-` + 색이름 = `border-border-subtle`** 이 된다.

컴포넌트는 `border-interactive` 를 쓴다. **없는 클래스다.**
`--border-interactive` 는 정의만 되고 **적용 0곳**이었다 — 테두리로 존재를 알려야 하는 버튼이 장식 구분선 색을 쓰고 있었다.

**대조군이 증거였다**: `colors.surface.page` 는 최상위 키라 `.border-surface-page` 가 정상 생성돼 있었다.

```ts
// 해법 — 보더 색은 colors 가 아니라 borderColor 에 둔다
borderColor: { subtle: 'var(--border-subtle)', interactive: 'var(--border-interactive)' }
```

**교훈**: 토큰을 새로 만들면 **빌드된 CSS 에 규칙이 실제로 생겼는지 확인한다.**
정의했다는 것과 화면에 닿는다는 것은 다르다.

### 8-3. 검증 명령

```
npm run check:tokens       컴포넌트 hex 리터럴 차단
npm run check:visibility   글 노출 정책 회귀
npm run typecheck · lint · build
```

### 8-4. 색 교체는 토큰 한 줄로 끝나야 한다

`--brand` 를 다른 값으로 바꿨을 때 컴포넌트를 한 곳도 안 고쳐도 전 화면이 바뀌어야 한다.
그렇지 않다면 어딘가에 리터럴이 샜다는 뜻이다.
