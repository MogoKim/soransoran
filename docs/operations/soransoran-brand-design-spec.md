## 1. 브랜드 원칙

### 1-1. 메인 브랜드 컬러는 `#FF6F61` 이다

창업자 결정이다. 흔들지 않는다.

### 1-2. 🔴 그러나 넓은 면에 무조건 칠하는 색이 아니다

```
#FF6F61 은 아름답지만 밝다 (HSL h5 · s100% · l69%).
밝은 바탕 위에서 면으로 잘 안 갈리고, 글자로 쓰면 대비가 낮다.

  #FFFFFF on #FF6F61       2.73 : 1    요건 4.5 미달 — CTA 예외로만 채택 (§3-1-B)
  #FF6F61 텍스트 · 바탕     2.46 : 1    요건 4.5 미달
  #FF6F61 텍스트 · 흰 카드   2.73 : 1    요건 4.5 미달
  #FF6F61 텍스트 · 배지면    2.33 : 1    요건 4.5 미달 — 가장 낮다
  #FF6F61 면 vs 바탕        2.46 : 1    요건 3.0 — 테두리 없이는 못 쓴다
```

**글자로는 쓴다 — 2026-08-29 개정(§2-1-A).**
링크 · 워드마크 · 배지 텍스트 · 작성자명 · 강조 텍스트가 이 색이다.
**대비 수치보다 브랜드 원색감을 우선한 창업자 결정이고, 위 수치를 알고 채택했다.**

🔴 **두 자리는 그대로 금지다.**

- **CTA 면 위 글자색** — 코랄 면 위 글자는 흰색 하나다 (§3-1-B 조건 2)
- **본문 · 미리보기** — `--text-primary` / `--text-secondary` 를 쓴다

**면으로는 여전히 "많이 칠하는 색"이 아니라 "정확한 포인트 색"이다.**

### 1-3. 포인트로 쓰는 자리

```
🟢 우선 쓴다     헤더 워드마크 · 활성/현재 상태 · 눌림 피드백
                 FAB 계열 · 브랜드 신호 · 그림자 · OG 장식 면
                 링크 · 배지 텍스트 · 작성자명 · 강조 텍스트 (§2-1-A)

🔴 난발 금지     페이지 배경 전체 · 넓은 카드 면
                 본문 · 미리보기 · 캡션 · 시간/조회수 같은 메타 수치
                 정보 전달 아이콘 · CTA 면 위 글자
```

**판단 기준 한 줄**: *이 면이 없어져도 사용자가 정보를 놓치지 않는가?* 놓치지 않으면 코랄을 쓸 수 있고, 놓치면 대비 요건을 먼저 만족시켜야 한다. 글자에 대한 예외는 §2-1-A 가 정한다.

### 1-4. 40~60대가 매일 읽는 화면이다

대비는 규정 통과용이 아니다. 노안 구간의 사용자가 저조도·야외에서 읽어야 한다.
**규정이 면제하는 자리에서도 "읽히는가"를 따로 확인한다.**

## 2. 색상 토큰 정본

`src/app/globals.css` `:root` 가 유일한 정의처다. 컴포넌트에 hex 를 직접 쓰지 않는다.
`npm run check:tokens` 가 이를 강제한다 — 허용 파일은 `globals.css` 와 `src/lib/brand.ts` 둘뿐이다.

### 2-1. 브랜드

| 토큰 | 값 | 역할 |
|---|---|---|
| `--brand` | `#FF6F61` | 브랜드 시그니처. 포인트·면·그림자 |
| `--brand-soft` | `#FFE8E3` | 배지·태그 배경 |
| `--brand-muted` | `#F2C9C1` | 🟡 2026-08-27 이후 **소비처 없음** — 구분선은 `--border-subtle` 중립으로 분리 |
| `--brand-ink` | `#FF6F61` | **읽는** 브랜드색 — `--brand` 와 같은 원색. 바탕 위 2.46:1 (§2-1-A) |
| **`--brand-strong`** | **`#B64235`** | **작은 브랜드 텍스트 · 연한 코랄 면 위 브랜드 텍스트.** 흰 카드 5.50:1 · 바탕 5.26:1 · 연분홍 면 4.69:1 (§2-1-B) |

### 2-1-A. 🔴 읽는 브랜드색을 원색으로 되돌린 개정 (2026-08-29)

**이전 값** `--brand-ink` · `--link` 은 더 어두운 갈색 코랄이었다 (바탕 위 6.26:1).
정확한 값이 필요하면 `05b838d` 이전 커밋을 본다.

이전 값은 갈색기가 돌아 브랜드 인상과 어긋났다. **대비 수치보다 브랜드 원색감을 우선한
창업자 결정으로** 두 토큰을 `--brand` 와 같은 `#FF6F61` 로 통일했다.
중간 명도의 대체 코랄은 도입하지 않는다.

**known tradeoff — 대비가 낮다. 알고 채택했다.**

| 표면 | 대비 | WCAG |
|---|---:|---|
| 바탕 `#F2F3F5` | **2.46 : 1** | 본문 4.5 · 큰 글씨 3.0 — 둘 다 미달 |
| 흰 카드 `#FFFFFF` | **2.73 : 1** | 둘 다 미달 |
| 연분홍 배지면 `#FFE8E3` | **2.33 : 1** | 둘 다 미달 · 가장 낮다 |

작은 글씨(배지 14~15px)에서 흐리게 보일 수 있다.
되돌리려면 `globals.css` 의 `--brand-ink` 한 줄과 `brand.ts` 의 `ink` 한 줄이다.

> 🔴 **`--link` 는 2026-09-02 개정으로 이 결정에서 빠졌다(§2-3-B).**
> 이 절이 정한 "읽는 브랜드색 = 원색" 은 `--brand-ink` 에 그대로 살아 있다.

### 2-1-B. 🔴 작은 브랜드 텍스트를 분리한 개정 (2026-09-03)

`--brand-ink` 는 `#FF6F61` 그대로 둔다. **크기에 따라 요구 대비가 달라지는 것**을 토큰으로 가른다.

| 글자 | WCAG 요구 | `#FF6F61` | 판단 |
|---|---:|---:|---|
| 큰 글씨 — 댓글 수 24px · 목록 순번 22px bold · 워드마크 32px | 3.0 | 2.61~2.73 | 🟡 `--brand-ink` 유지 — 브랜드 인상을 지는 자리(§2-1-A) |
| **작은 글씨 — `text-xs` 17px · `text-sm` 18px bold** | **4.5** | **2.33~2.73** | 🔴 **`--brand-strong` 로 옮긴다** |

WCAG 큰 글씨 경계는 bold 18.66px · 일반 24px 다. `text-xs`(기본 17px)와 `text-sm`(18px)는
bold 여도 그 경계 아래라 **일반 텍스트로 4.5:1 이 요구된다.** 같은 색인데 자리마다 기준이 다르다.

🔴 **새 색이 아니다.** `--link` · `--cta-edge` 와 같은 `#B64235` 다.
같은 값에 역할별 이름을 세 개 두는 이유는 나중에 한쪽만 움직일 수 있게 하기 위해서다.

🔴 **링크가 아닌 곳에 `text-link` 를 쓰지 않기 위한 토큰이다.**
대비만 보고 배지·라벨에 `text-link` 를 붙이면 토큰 이름과 역할이 어긋난다.

🔴 **누름 상태(정렬 탭 활성 · 헤더 버튼 · 공감 버튼)에는 쓰지 않는다.**
그 자리는 "켜졌음"을 브랜드색으로 알리는 곳이라, 진하게 하면 링크처럼 읽힌다.

🔴 **에러·경고·중립 안내에는 쓰지 않는다.** 각각 `--state-danger` · `--state-warning` · `--text-muted` 다.
`--state-danger` 와는 두 색 사이 1.19:1 이라 색만으로 구분되지 않는다.

**적용 (2026-09-03 · PR-A)** — 매거진 상세·연관 카테고리 라벨 2곳 · 운영 콘솔 페르소나 상태 배지 3곳.
댓글 작성자명 · 글 상세 작성자명 · 인기 댓글 라벨 · 인기 댓글 작성자명 4곳은 **미적용**(별도 판단 대상).

### 2-2. CTA — 누르는 것

| 토큰 | 값 | 역할 |
|---|---|---|
| `--cta` | fill 스위치 | §3-1-A 에서는 `#B64235`, §3-1-B 전환 후에는 `var(--brand)` |
| `--cta-text` | `#FFFFFF` | CTA fill 위 글자. **큰 버튼·FAB 전용 예외**(§3-1-B) |
| **`--cta-edge`** | **`#B64235`** | 🟡 **보류 토큰 — 현재 소비처 0.** 숨은 접근성 유틸용으로 값을 보존해 둔 자리다 (§2-2-A) |

🔴 **`--cta` 는 값이 아니라 스위치다.**
이 한 줄만 갈아끼우면 CTA 전체가 §3-1-A ↔ §3-1-B 사이를 오간다. 컴포넌트는 고치지 않는다(§10 rollback).

🔴 **`#B64235` 는 `--cta-edge` 로 분리해 보존한다.**
`--cta` 가 스위치가 되면서 그 값을 담을 자리가 필요했다. 새로 만든 색이 아니라 **자리를 옮긴 기존 값**이다.

### 2-2-A. 🟡 `--cta-edge` 는 아직 쓰이지 않는다 (2026-09-03 실측 정정)

**이 문서는 오랫동안 "숨은 접근성 유틸(건너뛰기 링크)이 쓴다" 고 적어 왔다. 사실이 아니다.**

```
src 전체에서 cta-edge 사용        0 건 (globals.css 의 정의·주석뿐)
PageShell 의 건너뛰기 링크        없음 — skip · 건너뛰기 · sr-only 검색 0 건
production 빌드 CSS              --cta-edge 정의 1 건 · 유틸리티 규칙 0 건
                                 (focus 변형 .focus\:bg-cta-edge 도 없다)
production HTML                  건너뛰기 링크 마크업 없음
```

건너뛰기 링크는 **계획으로만 있었고 구현된 적이 없다.** §3-1-C 는 그 계획을 기술한 것이다.

🟡 **그래도 지우지 않는다.** 값을 없애는 것이 아니라 **자리를 비워 두는 쪽**을 고른다 —
건너뛰기 링크는 언젠가 만들어야 하는 접근성 요소이고, 그때 쓸 값이 이미 정해져 있는 편이 낫다.
다만 **"쓰이고 있다" 고 적지는 않는다.** 문서가 코드보다 앞서 나가면 그 문서를 믿고 지우는 사람이 생긴다.

🔴 **`--cta-hover` 는 제거했다.**
테두리를 쓰지 않기로 하면서 쓰는 곳이 0 이 됐다. 정의만 남기지 않는다(§8-2).
같은 값 `#96372E` 는 `--focus-ring` 이 계속 갖고 있다.

### 2-3-B. 🔴 링크만 읽기 쉬운 코랄로 분리한 개정 (2026-09-02)

**이전 값** `--link: #FF6F61` (2026-08-29 §2-1-A 개정으로 `--brand-ink` 와 통일돼 있었다)

#### 무엇을 바꿨고 무엇을 바꾸지 않았나

| | 토큰 | 값 | 판단 |
|---|---|---|---|
| **유지** | `--brand-ink` | `#FF6F61` | 브랜드 인상을 만드는 자리 — 작성자명 · 배지 텍스트 · 목록 순번 · 강조 텍스트 · 워드마크 |
| **변경** | `--link` | `#FF6F61` → **`#B64235`** | 상호작용을 알리는 자리 — 판독을 인상보다 먼저 본다 |

🔴 **이것은 2026-08-29 결정(§2-1-A)의 전면 롤백이 아니다.**
그 결정의 핵심은 "브랜드색이 갈색으로 읽히면 안 된다" 였고, 그 인상을 만드는 것은
작성자명 · 배지 · 순번 쪽이다. 그 자리는 `--brand-ink` 로 **원색 그대로 남는다.**
링크는 원래 브랜드를 보여주는 자리가 아니라 **눌러야 할 것을 알려주는 자리**이고,
이 문서도 링크에만 **밑줄 필수**를 걸어 이미 다른 축으로 다뤄 왔다.
두 역할이 한 값을 겸하던 것을 이번에 갈랐다.

🔴 **새 색을 만들지 않았다.** `#B64235` 는 팔레트에 이미 있는 `--cta-edge` 와 같은 값이다.
§2-1-A 가 금지한 "중간 명도의 대체 코랄 도입" 에 해당하지 않는다 — 도입이 아니라 재사용이다.

#### 대비

| 표면 | 이전 `#FF6F61` | **현재 `#B64235`** | WCAG 본문 4.5 |
|---|---:|---:|---|
| 흰 카드 `#FFFFFF` | 2.73 : 1 | **5.50 : 1** | ✅ |
| 페이지 바탕 `#F9FAFB` | 2.61 : 1 | **5.26 : 1** | ✅ |
| 옅은 블록 `#F2F3F5` | 2.46 : 1 | **4.95 : 1** | ✅ |
| 연분홍 면 `#FFE8E3` | 2.33 : 1 | **4.69 : 1** | ✅ |

밑줄은 그대로 필수다. 대비가 올라갔다고 색 외 신호를 빼지 않는다.

🔴 **rollback 은 `globals.css` 의 `--link` 한 줄이다.** 컴포넌트는 한 곳도 고치지 않았다 —
`text-link` 소비처가 전부 토큰만 보고 있어서 값 교체로 끝난다.

### 2-3-A. 🔴 바탕을 중립으로 되돌린 개정 (2026-08-27)

**이전 값** `--surface-page: #FFF8F6` · `--border-subtle: #F2C9C1`

#### 왜 바꿨나

창업자 지적: **"전체 배경이 분홍/코랄 옅은색으로 너무 깔려 있다."**

실측으로 확인한 것 세 가지다.

1. **면적이 가장 넓은 곳에 브랜드 계열을 깔면 그 색은 더 이상 강조가 아니다.**
   같은 화면의 CTA·배지·활성표시가 바탕에 묻힌다. §1-2 가 "넓은 면에 무조건 칠하는 색이 아니다"라고
   말하는 그 원칙이 정작 **가장 넓은 면인 바탕에는 적용되지 않고 있었다.**
2. **`--border-subtle` 이 `--brand-muted` 와 같은 값이었다.**
   `globals.css` 의 전역 `* { border-color }` 를 타고 **서비스의 모든 선이 분홍**이었고,
   분홍 바탕 위 분홍 선이라 목록 구분선이 사실상 보이지 않았다(카드 위 1.27:1).
3. **목록 화면은 카드 면이 아예 없었다.**
   홈만 `bg-surface-card` 였고 `/community/[boardSlug]`·`/magazine`·`/best` 의 `<main>` 에는
   표면 지정이 없어 body 의 분홍이 그대로 드러났다. 데스크탑에서 특히 "종이 위 글자 나열"로 보였다.

#### 🔴 §11 의 사고 이력과 무엇이 다른가

§11 에 **"바탕색을 중성 회색으로 바꿨다가 브랜드 톤이 통째로 사라진 적이 있다"**가 적혀 있다.
이번 개정은 그 실패의 반복이 **아니다.** 다른 점을 명시한다 — 다음 세션이 이 문단을 근거로 판단한다.

| | 그때(실패) | 이번 개정 |
|---|---|---|
| 브랜드가 닿는 면 | 함께 사라졌다 | **CTA·FAB·배지·활성표시·`--surface-soft` 강조 블록에 그대로 남는다** |
| 텍스트 | 중립으로 같이 갈았다 | **웜 먹색 `#2F2624` 계열 유지** — 바탕에서 뺀 온기를 글자가 남긴다 |
| 보더 | 순수 회색 | **웜 뉴트럴 `#E0DEDD`** — 중립이되 차갑지 않다 |
| 카드 면 | 없었다 | **오래 읽는 화면(상세·매거진)에 흰 카드를 도입**해 회색이 "빈 화면"이 아니라 "바탕"이 된다. 커뮤니티 목록은 면 없이 바탕 위 피드다(§7-A) |

즉 **브랜드를 없앤 것이 아니라, 브랜드를 바탕에서 강조 지점으로 옮긴 것**이다.

#### rollback

- **구분선이 한 줄도 그려지지 않던 버그** — `PostCard`·`PostListItem` 의 `<a>` 가 `<li>` 의 유일한 자식이라
  `last:border-b-0` 이 **항상 참**이었다. 선은 이제 목록이 `[&>li+li]` 로 항목 사이에만 긋는다.

  아무 일도 일어나지 않는다. **hover 전용 토큰은 만들지 않는다** —
  `tailwind.config.ts` 를 건드리지 않고 기존 표면 토큰 두 개로 끝난다. 규칙은 §7-A 에 둔다.

## 3. §3-1 — brand 와 CTA 의 분리

### 왜 나누는가

`#FF6F61` 하나로 모든 UI 를 처리하면 흰 글씨 버튼에서 대비가 무너진다(§1-2).
그래서 **브랜드 신호**와 **누르는 것**을 토큰으로 나눈다. 같은 색 계열(h5~11)이라 화면에서는 하나의 브랜드로 읽힌다.

### 분리 원칙

| 토큰 | 역할 | 쓰는 곳 | 쓰지 않는 곳 |
|---|---|---|---|
| **brand** `#FF6F61` | 브랜드 시그니처 | 헤더 워드마크 · 포인트 · 활성 표시 면 · 그림자 · OG 장식 면 · **CTA/FAB fill (§3-1-B 조건 충족 시)** | 🔴 **흰 글씨 CTA** |
| **cta** `#B64235` | 누르는 것 | §3-1-A 또는 §3-1-B | 넓은 배경 면 |
| **brand-ink** `#FF6F61` | 읽는 브랜드색 | 작성자명 · 배지 텍스트 · 목록 순번 · 강조 텍스트 · 큰 워드마크 | 🔴 **링크** (§2-3-B) · 큰 면 fill |
| **link** `#B64235` | 상호작용을 알리는 글자 | 링크 (본문 autolink · 정책 · 문의 · 운영 콘솔) | 브랜드 인상을 만드는 자리 |

### `#FF6F61` 을 글자로 쓰는 범위 (2026-08-29 개정)

읽는 브랜드색이 원색과 같아졌으므로 **활성 탭 · 배지 텍스트 · 작성자명 · 목록 순번 ·
강조 텍스트 · 워드마크에 쓴다.** 대비는 낮다 — §2-1-A 의 tradeoff 를 알고 채택한 것이다.

🔴 **링크는 2026-09-02 개정으로 여기서 빠졌다.** `--link` `#B64235` 를 쓴다(§2-3-B).

```
🚫 CTA 버튼 텍스트 — 코랄 면 위 글자는 흰색 하나다 (§3-1-B 조건 2)
🚫 본문 · 미리보기 — 여기는 --text-primary / --text-secondary 다
```

정보 전달 아이콘은 각 표면의 전용 토큰(`--icon-*-text` 계열)을 그대로 쓴다.

### 비텍스트 사용 — 두 가지를 구분한다

| 구분 | 요건 | `#FF6F61` | 예 |
|---|---|---|---|
| **장식 면** | 없음 | 🟢 허용 | 배경 블록 · 밑줄 장식 · 구분 띠 · **그림자** · OG 그래픽 |
| **정보 전달 그래픽** | **3:1** (WCAG 1.4.11) | 🔴 **색이 유일한 신호일 때** 불가 (2.46) | 상태 아이콘 · 입력 테두리 · 차트 범례 |

같은 색이라도 "예쁘라고 있는 면"과 "뜻을 전달하는 그래픽"은 요건이 다르다.

🟢 **보조 신호가 함께 있으면 코랄을 표시로 쓸 수 있다.**
1.4.11 이 요구하는 것은 "색만으로 전달하지 말 것"이다. 굵기 · 고대비 텍스트 ·
`aria-current` 가 같이 있으면 코랄은 **보조 표시**가 된다.

```
예 — 게시판 정렬 탭 활성 표시
  border-brand 2px 밑줄        코랄 (보조)
  font-bold                    굵기
  text-content-primary         13.29:1
  aria-current="page"          보조기술
→ 색을 못 봐도 어느 탭이 켜졌는지 알 수 있다. 허용한다.
```

fill    --cta        #B64235

hover   hover:brightness-95      밝기만 낮춘다
면 경계  vs 바탕                  4.95 : 1   ✅  테두리 없이 갈린다

접근성을 위해 파생한 어두운 색이다.

그리고 **숨은 접근성 유틸은 계속 이 조합을 쓴다**(§3-1-C).

## 3-1-B. 🟢 CTA/FAB 코랄 전환 조건 — **가능하다**

> 이 절이 이 문서의 개정 핵심이다.
> **"CTA 는 `#B64235` 여야 한다"는 고정 규칙을 해제한다.**
> `#FF6F61` 을 CTA/FAB fill 로 쓸 수 있다. **단 아래 네 조건을 모두 지킨다.**

### 조건 1 — 🟡 흰 글씨를 쓴다 (큰 버튼·FAB 한정 예외)

> 🔴 **이 절은 실기기 확인으로 뒤집힌 판단이다.** 아래에 그 경위를 남긴다.

```
#FFFFFF on #FF6F61     2.73 : 1     요건 4.5 — 미달
같은 조합 (큰 글씨)      2.73 : 1     요건 3.0 — 미달
```

**수치로는 통과하지 않는다.** 그런데도 흰 글씨를 쓴다.

#### 폐기한 조합 — 먹색 글씨 + 어두운 테두리

```
#FF6F61 + --text-primary #2F2624     5.41 : 1     요건 4.5 — 통과
+ --cta-edge #B64235 테두리          바탕 4.95 : 1 — 통과
```

**수치는 전부 통과했지만 실기기에서 버튼으로 읽히지 않았다.**
밝은 면에 어두운 글씨와 어두운 테두리가 얹히니 "눌러야 할 것"이 아니라
"표시된 영역"으로 보였다. 버튼성이 떨어진다.

#### 무엇을 골랐나

```
판독성(글자를 읽을 수 있는가)      먹색이 유리하다      5.41 vs 2.73
버튼성(눌러야 할 것으로 보이는가)   흰 글씨가 유리하다
```

**창업자 실기기 확인으로 버튼성을 골랐다.** 수치가 아니라 실제로 눌리는가로 정했다.

🔴 **대가를 정직하게 적는다.** 이 조합은 WCAG 2.1 AA 1.4.3 에 미달한다(2.73 < 4.5).
저조도·야외에서 라벨이 흐려질 수 있다. 타깃이 40~60대라 가벼운 비용이 아니다.

#### 🔴 그래서 범위를 좁힌다

```
🟢 허용   큰 버튼 · FAB — 면적이 크고 위치가 고정돼 있어 라벨을 못 읽어도
          무엇을 누르는지 맥락으로 안다

🚫 이 예외(코랄 면 + 흰 글씨)를 적용하지 않는 자리
          작은 버튼 · 링크 · 활성 탭 · 배지 · 입력 테두리
          정보 전달 아이콘 · 숨은 접근성 유틸 (§3-1-C)
```

**이 예외는 큰 버튼과 FAB 밖으로 넓히지 않는다.**

🟡 **글자를 코랄로 쓰는 것은 별개다.** 여기서 막는 것은 "코랄 면 + 흰 글씨" 조합의
적용 범위이지 글자색이 아니다. 글자색은 §2-1-A · §3 을 따른다 —
링크 · 배지 텍스트 · 작성자명은 코랄이다.

### 조건 2 — 🟢 글자는 `--cta-text` `#FFFFFF` 하나다

코랄 면 위에 올릴 수 있는 글자색은 실측하면 이렇다.

| 글자색 | 토큰 | 대비 | |
|---|---|---:|---|
| **`#FFFFFF`** | **`--cta-text`** | **2.73** | 🟡 **채택** — 버튼성 우선(조건 1) |
| `#2F2624` | `--text-primary` | 5.41 | 🚫 폐기 — 버튼으로 안 읽힘(조건 1) |
| `#191919` | `--kakao-text` | 6.45 | 🚫 §4 격리 토큰 — 빌려 쓰지 않는다 |
| `#524642` | `--text-secondary` | 3.33 | 🚫 |
| `#FF6F61` | `--brand-ink` | 1.00 | 🚫 — 면과 같은 색이다 |
| `#B64235` | `--cta-edge` | 2.02 | 🚫 |

**새 hex 를 만들 필요가 없다.** `#FFFFFF` 는 이미 `--cta-text` 가 갖고 있던 값이다.

🔴 **글자색을 여기서 늘리지 않는다.** 코랄 면 위 글자는 흰색 하나다.
상태(hover·pressed)에서도 글자색을 바꾸지 않는다 — 색을 늘리면 대비를 다시 전부 재야 한다.

`--kakao-text` 가 대비는 더 높지만 그 토큰은 외부 브랜드 예외로 격리해 둔 것이다(§4). 소란소란 CTA 가 빌려 쓰면 격리가 무너진다.

### 조건 3 — 🚫 테두리를 두르지 않는다

```
#FF6F61 면 vs 바탕 #F2F3F5    2.46 : 1     요건 3.0 — 미달
#FF6F61 면 vs 카드 #FFFFFF    2.73 : 1     요건 3.0 — 미달
```

코랄 면은 밝은 바탕에서 스스로 갈리지 않는다. 그래서 한때 `--cta-edge` 로 테두리를 둘렀다.

🔴 **그 테두리는 폐기했다.** 어두운 테두리가 버튼을 "눌러야 할 덩어리"가 아니라
"선으로 구획된 영역"으로 보이게 만들었다(조건 1).

경계는 **그림자와 위치와 크기**가 대신한다.

```
FAB              --shadow-brand 코랄 그림자 + 화면 우하단 고정 + 56px
큰 CTA 버튼       카드/섹션 안에서 유일하게 채워진 면 + 52px
```

**밝은 면이 흰 배경에서 흐릿하다고 느껴지면, 테두리를 다시 두르지 말고
그림자를 먼저 검토한다** — 그림자는 대비 요건이 없다(§2-4).

### 조건 4 — 🚫 눌림에 색을 쓰지 않는다

색으로 눌림을 만들려면 어떤 후보든 코랄면과 충분히 갈려야 하는데, 갈리지 않는다.

| pressed 후보 | 코랄면과 차이 |
|---|---:|
| `--cta-edge` `#B64235` | 2.02 |
| `#96372E` | 2.67 |
| 코랄을 한 단계 어둡게 | 1.36 |

🔴 **정확히 적는다**: 위 수치는 3:1 에 못 미친다. WCAG 1.4.11 은 같은 컨트롤의 **상태 간** 대비를 요구하지 않으므로 규정 위반은 아니다. 그러나 **색만으로는 눌림이 확실하지 않다.**

**눌림은 `active:scale-95` 하나로 만든다**(§7).
hover 는 `hover:brightness-95` 하나다 — 밝기만 낮추고 **색 토큰을 새로 두지 않는다.**

```
🚫 pressed 색 토큰 · hover 색 토큰 · 상태별 글자색
🟢 transition duration-150 hover:brightness-95 active:scale-95
```

**상태를 색으로 늘리면 그때마다 대비를 전부 다시 재야 한다.** 크기와 밝기로 끝낸다.

### 권장 조합 정리

```
fill      --cta       → var(--brand)   #FF6F61
text      --cta-text                   #FFFFFF   2.73 : 1 — 판독성 결정(조건 1)
border    없음                          조건 3
hover     hover:brightness-95          밝기만 낮춘다. 색을 새로 두지 않는다
pressed   active:scale-95              색은 쓰지 않는다
shadow    --shadow-brand               FAB
```

**클래스는 세 개면 끝난다.**
```
transition duration-150 hover:brightness-95 active:scale-95
```
hover 색 토큰도, 테두리 토큰도, pressed 색도 두지 않는다.
**상태를 색으로 늘리지 않는 것이 이 화면의 유지보수 규칙이다.**

### 🔴 `--cta` 의 역할 재정의 — `#B64235` 는 `--cta-edge` 로 분리된다

전환 전에는 `--cta` 가 값(`#B64235`)이자 메인 액션 색이었다.
전환 후에는 **둘이 갈라진다.**

```
--cta        스위치     var(--brand)  ← fill. 되돌리면 #B64235
--cta-text   #FFFFFF   CTA fill 위 글자
--cta-edge   #B64235   숨은 접근성 유틸용으로 비워 둔 자리 (§2-2-A · 아직 소비처 0)
```

**`#B64235` 는 더 이상 "메인 액션 색"이 아니다.**
보이는 CTA 에서는 물러났고, **대비를 반드시 지켜야 하는 자리**에 남았다.

🟢 **새로 발명한 색이 아니다.** 전환 전 `--cta` 가 갖고 있던 값을 자리만 옮겨 보존한 것이다.

## 3-1-C. 🔴 숨은 접근성 유틸은 CTA 시각 정책에서 뺀다

> 🟡 **이 절은 계획이다. 2026-09-03 실측 기준 건너뛰기 링크는 구현돼 있지 않다** (§2-2-A).
> 아래 기준은 그 요소를 만들 때 따를 것으로 남긴다. 현재 `--cta-edge` 의 소비처는 0 이다.

**건너뛰기 링크**는 평소 보이지 않다가 키보드 포커스에서만 나타나는 요소다.
이 요소를 쓰는 사람은 **화면을 눈으로 훑지 못하거나 마우스를 쓰지 못하는 사용자**다.

| 조합 | 대비 | |
|---|---:|---|
| 코랄 fill + 흰 글씨 | 2.73 | 🔴 **접근성 유틸이 접근성에 미달한다** |
| **`--cta-edge` `#B64235` + 흰 글씨** | **5.50** | ✅ |
| `#B64235` 면 vs 바탕 | 4.95 | ✅ 테두리 없이도 갈린다 |

**조건 1 의 예외를 여기까지 넓히지 않는다.**
큰 버튼의 예외 근거는 "면적이 크고 위치가 고정돼 맥락으로 안다"인데,
건너뛰기 링크는 **그 맥락이 없는 사용자를 위한 것**이라 근거가 성립하지 않는다.

```
보이는 CTA · FAB    17 곳  --cta        코랄 fill + 흰 글씨   (bg-cta 15 · border-cta 2)
숨은 접근성 유틸     0 곳   --cta-edge   미구현 — 만들 때 #B64235 + 흰 글씨 5.50 : 1
```

### 🔴 전환은 전부 함께 한다

`bg-cta` 는 **8곳**이 쓴다. 홈에서 FAB 과 참여 유도 카드 버튼이 **같은 화면에 공존**한다.
**한 곳만 바꾸면 "누르는 것"이 두 색이 된다.** 부분 전환은 성립하지 않는다.

## 7. 상호작용 상태 정본

**`hover:` 는 터치에서 sticky 가 된다. 터치 피드백의 본체는 `active:` 다.**
`active:` 가 없으면 모바일에서 무엇을 눌러도 아무 반응이 없다.

| 부류 | 대상 | hover | active |
|---|---|---|---|
| **누르는 것** | FAB · CTA · ActionButton · 카카오 | 한 단계 어둡게 | `scale-95` |
| **리스트 항목** | PostListItem · PostCard | 배경 없음 · 제목색만 (§7-A) | 배경 없음 · 제목색만 |
| **아이콘 · 토글** | IconMenu · FontSizeToggle | `bg-surface-page` / `bg-surface-soft` | `scale-95` |
| **텍스트 버튼** | HeaderAuth · SignOutButton | `bg-surface-soft` | `scale-[0.98]` |
| **포커스** | 전역 | — | `:focus-visible` `--focus-ring` 2px + offset 2px |

### 7-A. 🔴 목록 행 hover 는 면을 만들지 않는다 (2026-08-29 개정)

목록에 면이 없는데 가리킬 때만 네모가 생기면 **그 네모가 글보다 먼저 읽힌다.**
행은 배경을 바꾸지 않고 **제목만 `--brand-ink` 로 반응**한다.

| 상태 | 배경 | 제목 |
|---|---|---|
| hover | **변화 없음** | `--text-primary` → `--brand-ink` |
| active | **변화 없음** | `--text-primary` → `--brand-ink` |

```
🔴 배경을 쓰지 않는다.
   흰 면·회색 면 어느 쪽도 만들지 않는다. 행이 놓인 면이 무엇이든 규칙은 하나다.
   surface prop 은 남기되 모양을 정하지 않는다 — 대비를 뒤집을 일이 없어졌다.

🔴 active 에도 면을 쓰지 않는다.
   --surface-soft 는 브랜드 계열이라 누를 때마다 코랄 블록이 깔렸다.
   모바일에서 가장 자주 보이는 상태였는데 가장 무거운 반응이기도 했다.

🔴 hover 전용 색을 새로 만들지 않는다.
   제목이 쓰는 --brand-ink 하나로 끝난다.
```

**구현** — `<a>` 에 `group`, 제목에 `transition-colors duration-150
group-hover:text-brand-ink group-active:text-brand-ink`.

**적용 9면** — 홈 인기글 · `/best` · 게시판 2 · 홈 매거진 레일 · `/magazine`
· 이어읽기 · 새로 온 이웃 · 함께 읽기.

**터치에서도 이 정책이 유리하다.** `hover:` 는 터치에서 sticky 가 되는데,
배경을 쓰지 않으므로 탭 후 눌린 줄만 면이 남는 증상이 구조적으로 생기지 않는다.

### 규칙

```
transition duration-150 을 함께 붙인다 — 색만 바뀌고 시간이 없으면 딱딱하다.

disabled 가 있는 버튼은 enabled: 로 잠근다.
  disabled:opacity-60 만 두면 제출 중인 버튼도 hover 에서 색이 바뀌어
  "아직 누를 수 있다" 로 읽힌다.

iOS 기본 탭 하이라이트는 Tailwind preflight 의 html 규칙이 이미 끈다.
  컴포넌트에 [-webkit-tap-highlight-color:transparent] 를 붙이지 않는다 — 죽은 클래스가 된다.

브랜드 코랄이 드러나는 상호작용 표면은 --surface-soft(#FFE8E3) 다.
```

### 눌림에 코랄끼리 쓰지 않는다

`#FF6F61` → 한 단계 어두운 코랄은 **1.36:1** 로 구분이 안 된다. §3-1-B 조건 4 를 따른다.

## 8. 토큰 유지보수 원칙

### 8-1. hex 는 두 곳에만 있다

```
src/app/globals.css   화면에 그려지는 모든 색
src/lib/brand.ts      metadata · manifest · OG (CSS 변수를 해석하지 못하는 곳)
```

컴포넌트는 semantic token 만 쓴다. `npm run check:tokens` 가 강제한다.
색을 바꿀 때는 이 두 파일만 고치면 전체 UI 가 교체된다.

### 8-2. 🔴 토큰 정의와 유틸리티 이름이 어긋나면 토큰이 죽는다

**실제로 겪은 사고다.** `tailwind.config.ts` 에서 색을 이렇게 두면

```ts
colors: { border: { subtle: '…', interactive: '…' } }
```

Tailwind 가 중첩 객체를 `부모-자식` 으로 평탄화해 색 이름이 `border-subtle` 이 되고,
borderColor 유틸리티는 **`border-` + 색이름 = `border-border-subtle`** 이 된다.

컴포넌트는 `border-interactive` 를 쓴다. **없는 클래스다.**
`--border-interactive` 는 정의만 되고 **적용 0곳**이었다 — 테두리로 존재를 알려야 하는 버튼이 장식 구분선 색을 쓰고 있었다.

**대조군이 증거였다**: `colors.surface.page` 는 최상위 키라 `.border-surface-page` 가 정상 생성돼 있었다.

```ts
// 해법 — 보더 색은 colors 가 아니라 borderColor 에 둔다
borderColor: { subtle: 'var(--border-subtle)', interactive: 'var(--border-interactive)' }
```

**교훈**: 토큰을 새로 만들면 **빌드된 CSS 에 규칙이 실제로 생겼는지 확인한다.**
정의했다는 것과 화면에 닿는다는 것은 다르다.

### 8-3. 검증 명령

```
npm run check:tokens       컴포넌트 hex 리터럴 차단
npm run check:visibility   글 노출 정책 회귀
npm run typecheck · lint · build
```

### 8-4. 색 교체는 토큰 한 줄로 끝나야 한다

`--brand` 를 다른 값으로 바꿨을 때 컴포넌트를 한 곳도 안 고쳐도 전 화면이 바뀌어야 한다.
그렇지 않다면 어딘가에 리터럴이 샜다는 뜻이다.

### 🟡 정의만 있고 쓰이지 않는 토큰 (2026-09-03 전수 실측)

### 12-1. 원칙

#### 🚫 이 절은 Material Design 3 를 적용하는 문서가 아니다

MD3 에서 가져온 것은 **"크기가 아니라 역할로 부른다"는 사고방식 하나뿐**이다.
크기값·컴포넌트 형태·상태 레이어·아이콘·폰트는 **가져오지 않는다.**
이 절 어디에도 MD3 의 수치는 들어 있지 않다.

#### 🔴 MD3 의 크기값을 쓰지 않는다

MD3 의 본문 기준(`body-large`)은 **16px** 다. 소란소란의 본문은 **20px** 다.
그대로 가져오면 이 서비스가 지켜 온 가독성이 네 칸 내려간다.
**크기는 우리가 실측으로 정한 값을 쓴다. 이름 짓는 방법만 배운다.**

#### 🔴 본문 가독성이 먼저다

40대 중반~60대 중반 여성이 매일 읽는 화면이다(§1-4).
"작게" 단계의 하한이 18px 인 것도 같은 이유다 — **그 아래로 내리지 않는다.**
글자를 키울 때 줄 간격을 함께 올리는 것(`body` line-height 1.75)도 같은 판단이다.

#### 🔴 색에서 이미 한 일을 타이포에서도 한다

색은 역할이 갈려 있다 — `--cta`(누르는 것) · `--link`(가는 것) · `--state-danger`(잘못된 것).
타이포는 아직 `text-sm` 하나가 **그 셋을 동시에 겸한다**(§12-3 label·link·status).
이 절은 그 현황에 **이름을 붙여 두는 것까지만** 한다. 값은 바꾸지 않는다.

### 12-2. 현재 실제 기준

#### 🔴 본문 세 가지는 크기 클래스를 쓰지 않는다

이 서비스에서 가장 많이 읽히는 세 가지는 모두 **20px** 이고, 모두 크기 클래스를 붙이지 않는다.

| 무엇 | 크기를 어디서 얻나 | 기본 크기 |
|---|---|---|
| 글 본문 | `.post-body` → `font-size: var(--text-body)` | **20px** |
| 댓글 본문 | 크기 클래스 없음 → `body` 상속 | **20px** |
| 목록 제목 | 크기 클래스 없음 → `body` 상속 | **20px** |

🔴 **그래서 클래스만 세면 본문이 보이지 않는다.**
`text-base` 는 고객 화면에 1 건뿐인데, 본문이 작아서가 아니라 **본문이 클래스를 쓰지 않기 때문**이다.
`text-sm`·`text-xs` 가 많은 것도 같은 이유다 — 그것들은 대부분 **"본문보다 작게"** 를 뜻한다.

#### 크기표 — 같은 클래스가 환경마다 다른 크기가 된다

`--text-*` 토큰이 `data-font-size` 3단계와 `.admin-shell` 에서 각각 다시 정의된다.

| 클래스 | 토큰 | 고객 기본 | 고객 작게 | 고객 크게 | 운영 콘솔 |
|---|---|---|---|---|---|
| `text-xs` | `--text-caption` | **17px** | 15px | 20px | **12px** |
| `text-sm` | `--text-sm` | **18px** | 16px | 22px | **13px** |
| `text-base` | `--text-body` | **20px** | 18px | 24px | **14px** |
| `text-lg` | `--text-title` | **24px** | 20px | 28px | **16px** |
| `text-xl` | `--text-heading` | **28px** | 24px | 32px | 24px |
| `text-2xl` | `--text-display` | **32px** | 28px | 38px | 28px |

정의 위치: `globals.css` `:root` / `:root[data-font-size='SMALL']` / `:root[data-font-size='LARGE']` / `.admin-shell`
매핑 위치: `tailwind.config.ts` `theme.extend.fontSize`

#### 🔴 운영 콘솔은 별도 영역이다

`.admin-shell` 은 `--text-*` 를 **더 작게 고정**한다. 고객용 "글자 크기" 조절도 여기서는 통하지 않는다.

- **왜** — 운영자는 정보를 빽빽하게 훑는다. "크게" 로 두면 표 한 줄이 두 줄로 접혀 목록을 볼 수 없다.
- **그래서** — 운영 콘솔의 12px·13px 는 **고객 화면의 최소 크기 규칙 밖**이다. 위반이 아니다.
- **다만** — 같은 `text-xs` 가 고객 화면에서는 17px, 운영 콘솔에서는 12px 다. **이름이 같고 크기가 다르다**(§12-4).

### 12-4. 암묵 규칙 명문화

지금까지 코드로만 지켜지던 것을 글로 옮긴다. **새 규칙이 아니다.**

#### 🔴 1. 본문에는 크기 클래스를 붙이지 않는다

`body` 와 `.post-body` 상속을 먼저 쓴다.
크기 클래스를 붙이는 순간 그 자리는 **글자 크기 3단계 축에서 한 칸 어긋난 채로 고정**된다.
본문을 키우려면 클래스가 아니라 `--text-body` 를 본다.

#### 🔴 2. `text-sm` 은 지금 여러 역할을 겸한다 — 새 자리에서는 역할을 먼저 고른다

고객 화면 `text-sm` 82곳을 기계적으로 갈라 보면 **누르는 것 33 · 상태 문구 12 · 그 밖 37** 이다.
(기준: 같은 줄에 `min-h-[52px]`/`[44px]` 가 있으면 누르는 것, `role="alert"`/`role="status"` 가 있으면 상태 문구.
클래스가 여러 줄에 걸친 곳이 있어 **"누르는 것" 33 은 하한**이다.)
새로 쓸 때는 "18px 이 적당한가" 가 아니라 **"이건 누르는 것인가, 읽는 것인가, 잘못됐다는 것인가"** 를 먼저 정한다.
§12-3 의 역할 이름으로 부른 뒤 클래스를 고른다.

#### 🔴 3. `text-xs` 는 오류 문구와 입력 라벨에 쓰기 전에 멈춘다

`text-xs` 는 고객 화면 **최소 크기**(기본 17px · "작게" 15px)다.
**메타 정보(작성자·날짜·조회수)에는 알맞고, 사용자가 반드시 읽어야 하는 것에는 위험하다.**
지금도 오류 문구 2곳·입력 라벨 4곳이 이 크기다(§12-6 A3).

#### 🔴 4. 운영 콘솔의 `text-xs` 는 고객 화면의 `text-xs` 와 다른 크기다

고객 17px · 운영 콘솔 12px. **클래스 이름이 같아서 헷갈린다.**
운영 화면을 만들 때 "고객 화면에서 이 정도였으니까" 로 옮기면 크기가 다섯 칸 줄어든다.
§12-2 크기표를 보고 정한다.

아래 둘은 **문제로 확인됐지만 이번에 고치지 않는다.** 시각이 바뀌므로 시안이 먼저다.

#### 🟡 카드 제목이 3종이다

| 화면 | 클래스 | 크기 | 굵기 |
|---|---|---|---|
| 목록 (커뮤니티·베스트) | *(없음)* | 20px | `font-medium` |
| 홈 카드 | `text-base` | 20px | `font-bold` |

목록 컴포넌트에는 이미 근거 주석이 있다 — *"같은 목록인데 화면마다 제목 크기가 달라지면 어디를 보고 있는지가 흐려진다"* 며 홈·베스트를 한 급 키웠다가 되돌린 기록이다.
**그 판단이 매거진·마이페이지에는 적용되지 않았다.**

🔴 고칠 때 20px 로 내릴지 24px 로 올릴지는 **홈·매거진·마이 세 화면의 인상을 동시에 바꾼다.** 시안 없이 정하지 않는다.

#### 🟡 페이지 제목이 2종이다

| 크기 | 클래스 | 어디 |
|---|---|---|
| 28px | `text-xl` | 글쓰기 · 마이 · FAQ · 약관 · 개인정보 · 규칙 · 404 · 목록 헤더 (22곳) |
| **32px** | `text-2xl` | 글 상세 · 매거진 상세 · 로그인 · 온보딩 (5곳) |

🟡 **"읽는 화면만 크다"는 위계로 읽히지만, 그 근거가 코드에도 문서에도 없다.**
규칙으로 남길지 한 종으로 합칠지는 아직 정하지 않았다.

#### 🟡 그 밖에 기록만 해 두는 것

- `<h2>` 하나가 `text-sm`(18px)이라 **본문보다 작다** — 마이페이지 "안내" 머리. 다른 모든 `<h2>` 는 24px 다.

| `control` 별칭 | 글자 크기 토글의 3크기는 역할이 아니라 미리보기 그 자체다 |

### 12-7. `text-meta` 도입 기록 (2026-09-03 · A4 1차)

> 🟢 **시각 변화 0.** 별칭 값이 `text-xs` 와 완전히 같다 — `var(--text-caption)` · line-height 1.4.
> 글자 크기 3단계도 그대로 따라간다(작게 15px · 기본 17px · 크게 20px).

#### 무엇을 했나

**별칭 추가와 소비처 교체를 같은 변경에 넣었다.** 별칭만 만들고 쓰는 곳이 없으면 죽은 토큰이 된다(§12-6).

```
tailwind.config.ts    fontSize.meta 추가 — 값은 xs 와 동일
src/lib/utils.ts      extendTailwindMerge 로 font-size 그룹에 등록
소비처 11곳           text-xs → text-meta
```

#### 🔴 `src/lib/utils.ts` 를 함께 고쳐야 하는 이유

tailwind-merge 는 `text-*` 가 크기인지 색인지를 **이름 모양으로** 판별한다. `xs`·`sm` 은 크기로 알지만
`meta` 는 모르므로 **색 클래스로 분류**한다. 그러면 진짜 색과 같은 그룹이 되어 뒤엣것만 남는다.

```
등록 전   cn('text-meta', 'text-content-muted')  →  'text-content-muted'   ⛔ 크기 소실
등록 후   cn('text-meta', 'text-content-muted')  →  둘 다 유지
          cn('text-meta', 'text-sm')             →  'text-sm'  (크기끼리는 정상 충돌)
```

🔴 **빌드 CSS 로는 잡히지 않는다.** CSS 는 멀쩡하고 클래스 문자열이 런타임에 지워지기 때문이다.
그래서 별칭을 늘릴 때마다 `tailwind.config.ts` 와 `src/lib/utils.ts` 를 **함께** 고친다.

#### 어디를 바꿨나 — 고객 화면 메타 행 11곳

```
PostCard · CommentItem · CommentSection · PostListItem
MagazineCard · RelatedMagazineList
magazine/[slug] · community/[boardSlug]/[postId]
my/posts · my/comments · my/scraps
```

전부 **작성자 · 날짜 · 조회수 · 댓글수 · 배지가 나열되는 줄**이다. 전부 `cn()` 밖의 평문 className 이다.

#### 🚫 같은 `text-xs` 인데 바꾸지 않은 것

**클래스가 같다고 역할이 같은 것이 아니다.** `text-xs text-content-muted` 20곳 중 역할이 meta 인 것은 11곳뿐이었다.

| 남긴 것 | 왜 |
|---|---|
| 입력 라벨 3곳 (이름 · 비밀번호 ×2) | 역할이 label 이다. A3 에서 18px 로 올릴 대상이라 지금 이름을 붙이면 그 판단을 고정한다 |
| 안내문 3곳 (비회원 폼 · 신고 안내) | 역할이 body-compact 다 |
| 공감 상태 1곳 | 역할이 status 다. status 는 크기가 3종이라 A3 전에는 별칭을 만들 수 없다 |
| 글씨 크기 토글 라벨 1곳 | 역할이 control 이다 |
| 홈 매거진 레일 1곳 | 메타 *행* 이 아니라 단일 값이다. 애매해서 뺐다 |
| 운영 콘솔 120곳 | `.admin-shell` 에서 12px 로 렌더된다. 같은 이름이 다른 크기가 되면 이름이 거짓말이 된다 |

#### 다음 별칭을 만들 수 있는 조건

- `status` — **A3 뒤에.** 지금은 같은 역할이 20px 9곳 · 18px 12곳 · 17px 3곳으로 갈려 있다.
- `card-title` · `page-title` — **S1 · S2 시안 뒤에.** 크기가 갈려 있어 지금 이름을 붙이면 어느 쪽으로든 화면이 바뀐다.
- `label` · `body-compact` · `caption` — 만들지 않는다(§12-6). 서로 구분되지 않는다.

### 12-8. A3 저위험 교정 기록 (2026-09-03)

> 🟡 **시각 변화가 있다.** 6곳이 17px → 18px 로 올라간다(높이 요소당 +3px).
> 바꾸는 축은 **크기 하나뿐**이다 — 색·굵기·간격·행간·구조는 그대로다.

#### 🔴 이것은 접근성 위반 수정이 아니다 — 역할 위계 정리다

6곳 모두 **현재도 WCAG AA 를 통과한다.** 실측:

```
오류 #b3261e on 연분홍 #ffe8e3   5.57:1  ✅      오류 #b3261e on 흰 #ffffff    6.54:1  ✅
오류 #b3261e on 회색   #f2f3f5   5.89:1  ✅      라벨 #6f5e59 on 흰 #ffffff    6.14:1  ✅
라벨 #6f5e59 on 회색   #f2f3f5   5.53:1  ✅      라벨 #2f2624 on 연분홍        12.58:1 ✅
```

🔴 **17px 도 18px 도 WCAG 큰 글씨(bold 18.66px · 일반 24px) 미만이라 둘 다 4.5:1 을 요구한다.**
즉 이 변경은 요구 기준선을 넘나들지 않는다. 대비 판정은 전후가 같다.

고치는 이유는 규정이 아니라 **같은 역할이 자리마다 다른 크기였다는 것**이다.

#### 무엇이 어긋나 있었나

**오류 문구** — 서비스 표준에서 이 둘만 이탈해 있었다.

```
role="alert" 오류 문구 (고객 화면)
  text-sm  18px   9곳   ← 표준
  text-xs  17px   2곳   ← DeleteButton · ReportButton  (이번 대상)
  무클래스 20px   2곳   ← 온보딩(본문 상속)
```

특히 DeleteButton 은 **같은 폼 안에서 형제끼리 크기가 달랐다.**

```
안내  "이 댓글을 지울까요? 되돌릴 수 없습니다."   18px
오류  "비밀번호가 맞지 않습니다."                 17px   ← 더 작다
```

되돌릴 수 없는 삭제 확인 자리에서 **"지금 실패했다"가 "되돌릴 수 없다"보다 작았다.**

**입력 라벨** — 라벨이 입력 내용보다 작았다(production 실측).

```
입력창 글자   20px      ← 사용자가 입력하는 것
라벨          17px      ← 무엇을 넣는 칸인지 알려주는 것
안내문        17px      ← 라벨과 같은 무게였다
```

서비스 안 다른 입력 라벨과 비교하면 게스트 3곳이 가장 작고 가장 약했다.

```
온보딩 닉네임    20px  w700  primary
마이 닉네임      18px  w500  primary
게스트 3곳       17px  w400  muted     ← 이번 대상
```

#### 바꾼 6곳

| 위치 | 역할 | 전 → 후 |
|---|---|---|
| `DeleteButton` 오류 | status | `text-xs` → `text-sm` |
| `ReportButton` 오류 | status | `text-xs` → `text-sm` |
| `ReportButton` "신고 사유" | label | `text-xs` → `text-sm` |
| `GuestCommentForm` "이름" | label | `text-xs` → `text-sm` |
| `GuestCommentForm` "비밀번호" | label | `text-xs` → `text-sm` |
| `GuestCommentControls` "비밀번호" | label | `text-xs` → `text-sm` |

```
기본 17px / 23.8px → 18px / 27px      작게 15px → 16px      크게 20px → 22px
```

#### 🚫 이번에 함께 바꾸지 않은 것

| 남긴 것 | 왜 |
|---|---|
| `text-state-danger` · `text-content-muted` 색 | 대비가 이미 통과한다. 색은 상태를 말하는 축이라 크기 정리와 섞지 않는다 |
| 오류 문구를 굵게 | 표준 9곳이 전부 w400 이다. 굵게 하면 이 둘이 반대 방향으로 튄다 |
| "신고 사유" 의 `font-bold`+`primary` | 다른 라벨 3곳(w400+muted)과 계열이 다르지만, **크기 축 하나만 움직여야** 시각 변화가 그것뿐임을 증명하기 쉽다. 통일은 별건 |
| 운영 콘솔 `text-xs` 120곳 | 고객 화면만 대상이다 |

#### 🟡 `my/page.tsx` 의 `<h2>` 는 A3 에서 뺐다 — S2 판단 대상으로 이관

§12-5 에 "본문보다 작다"고 적었으나, 코드를 다시 읽으니 **실수가 아니라 역할이 다른 것**이다.

```
<section aria-label="내 활동">      ← 보이는 제목이 없다
<section aria-labelledby="my-guide">
  <h2>안내</h2>                     ← 여기만 보이는 제목이 있다
```

두 섹션이 비대칭이고, 이 `<h2>` 는 `section-title` 이 아니라 **group-label** 이다.
섹션 제목 표준(24px bold)으로 올리면 이름(h1 28px)에 육박하고, 제목 없는 첫 섹션과 더 어긋난다.
h1 에는 이미 *"이름이 이 화면의 주인공이다 — 섹션 제목보다 크게 둔다"* 는 근거가 적혀 있다.

🔴 **손대려면 "내 활동" 섹션에 제목을 줄지부터 정해야 한다.** 그것은 페이지 제목 위계 문제라 **S2** 다.
현재 값(18px w500 muted)은 그 역할에 맞고 최소 크기도 아니다.

### 12-9. S1 제목 체계 — 역할 2종으로 정리 (2026-09-04 · E안)

> 🟡 **시각 변화가 있다.** 카드·목록 제목 6곳이 바뀐다.
> 게시판 1파일만 고친 1차 시안(PR #353 · A안)은 **채택하지 않고 닫았다** — 아래 경위를 남긴다.

#### 어긋나 있던 것 — 제목 5종

같은 "목록에서 글 하나를 가리키는 제목"인데 크기·굵기·행간이 전부 달랐다(2026-09-03 전수 실측).

```
20px / w500 / lh1.5     PostListItem      홈 · 베스트 · 이어서 읽기
20px / w700 / lh1.35    PostCard          게시판 목록
20px / w700 / lh1.4     RelatedMagazine   매거진 상세 하단
24px / w700 / lh1.4     MagazineCard      매거진 목록
24px / w700 / lh1.4     HomeMagazineRail  홈 매거진 레일
24px / w700 / lh1.35    my/posts · my/scraps
```

**같은 글이 홈에서 20px/500, 게시판에서 20px/700, 마이에서 24px/700 으로 보였다.**

#### 왜 A안(전부 20/w500)이 아니라 E안(20/w600)인가

창업자가 고른 기준은 홈 "지금 뜨는 이야기"(20/w500/1.5)였다. 그대로 복사한 A안을 시안으로 만들어 보니
**게시판에서 제목이 약해졌다.** 원인은 굵기가 아니라 **구조**였다.

```
홈 PostListItem    순번 + 제목 + 배지·메타       제목이 유일한 "읽는 텍스트"
게시판 PostCard    제목 + 미리보기 2줄 + 메타    제목과 미리보기가 경쟁
```

w500 은 미리보기(w400)와 **한 단계** 차이뿐이라 두 블록이 한 문단처럼 읽혔다.
w700 은 잡히지만 두 줄 제목에서 덩어리가 무거웠다.
**w600 은 미리보기와 두 단계 차이라 제목이 잡히면서도 무겁지 않다.**

🔴 그리고 w600 은 **미리보기가 있는 카드와 없는 목록 양쪽에서 모두 성립했다.**
그래서 한때 검토했던 *"미리보기가 있으면 700, 없으면 500"* 규칙이 **필요 없어졌다.**

#### 역할 2종

| 역할 | 값 | 코드 상수 | 적용처 | 왜 |
|---|---|---|---|---|
| **`title-ranked`** | 20px / **w500** / lh1.5 | `TITLE_RANKED` **1곳** | 홈 "지금 뜨는 이야기" · 베스트 · 이어서 읽기 (`PostListItem`) | **순번(22px 코랄 이탤릭)이 위계를 지므로** 제목은 덜 굵어도 잡힌다 |
| **`title-card`** | 20px / **w600** / lh1.5 | `TITLE_CARD` **6곳** | 게시판 목록 · 매거진 목록 · 홈 매거진 레일 · 함께 읽어보세요 · 마이 글·스크랩 | 제목이 혼자 서야 하는 목록 |

🔴 **두 역할 모두 코드에 상수로 존재한다.** 값을 바꿀 때 `src/lib/typography.ts` 한 곳만 고친다.

**두 역할의 차이는 "순번이 있는가" 한 가지다.** 코드에서 바로 판별되고 말로 설명된다.

#### 🔴 크기 클래스를 붙이지 않는 것이 규칙의 일부다

둘 다 본문(`--text-body`)을 상속한다. 글자 크기 3단계를 온전히 타기 위해서다(§12-4).
`text-lg` 로 고정하면 그 제목만 축에서 한 칸 어긋난 채 커진다 — 실제로 매거진이 그랬다.

```
작게 18px / 27px      기본 20px / 30px      크게 24px / 36px
```

#### 어디에 이름을 남겼나 — `src/lib/typography.ts`

```ts
export const TITLE_CARD = 'font-semibold leading-[1.5]'
```

🔴 **Tailwind fontSize alias(`text-title-card`)를 쓰지 않았다.**
fontSize alias 는 font-size + line-height 만 준다. 이 역할의 핵심은 **굵기**라
`text-title-card font-semibold` 처럼 둘로 갈라져 **역할이 절반만 이름을 갖는다.**
게다가 값이 `text-base` 와 같은 변수를 가리켜 토큰만 늘어난다.

일반 유틸 문자열이라 tailwind-merge 가 정상 인식하므로 `cn()` 안에서도 안전하다 —
`text-meta` 때 필요했던 `src/lib/utils.ts` 등록이 **이 방식에는 필요 없다**(§12-7 참조).

```ts
export const TITLE_RANKED = 'font-medium leading-[1.5]'
```

🟢 **`title-ranked` 도 상수로 연결했다.** `PostListItem` 이 쓰던 값과 **바이트 단위로 같아 시각 변화는 0** 이다.
홈 "지금 뜨는 이야기" 는 한 픽셀도 바뀌지 않는다.

#### 🚫 `newcomer-greetings` 는 연결하지 않았다

같은 `font-medium leading-[1.5]` 를 쓰지만 **제목이 아니라 인사말 본문**(`g.content`)이다.
`my/comments` 첫 줄과 같은 유형이다 — 값이 같다고 역할이 같은 것이 아니다(§12-7 과 같은 판단).

🔴 여기에 `TITLE_RANKED` 를 붙이면 **역할 사전이 거짓말이 된다.** 나중에 제목 굵기를 조정할 때
인사말 본문까지 함께 바뀐다. 값이 같은 것은 우연이고, 이 자리는 제목 역할이 아니다.
