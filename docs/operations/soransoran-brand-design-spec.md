## 1. 브랜드 원칙

### 1-1. 메인 브랜드 컬러는 `#FF6F61` 이다

창업자 결정이다. 흔들지 않는다.

### 1-2. 🔴 그러나 넓은 면에 무조건 칠하는 색이 아니다

```
#FF6F61 은 아름답지만 밝다 (HSL h5 · s100% · l69%).
밝은 바탕 위에서 면으로 잘 안 갈리고, 글자로 쓰면 대비가 낮다.

  #FFFFFF on #FF6F61       2.73 : 1    요건 4.5 미달 — CTA 예외로만 채택 (§3-1-B)
  #FF6F61 텍스트 · 바탕     2.46 : 1    요건 4.5 미달
  #FF6F61 텍스트 · 흰 카드   2.73 : 1    요건 4.5 미달
  #FF6F61 텍스트 · 배지면    2.33 : 1    요건 4.5 미달 — 가장 낮다
  #FF6F61 면 vs 바탕        2.46 : 1    요건 3.0 — 테두리 없이는 못 쓴다
```

**글자로는 쓴다 — 2026-08-29 개정(§2-1-A).**
링크 · 워드마크 · 배지 텍스트 · 작성자명 · 강조 텍스트가 이 색이다.
**대비 수치보다 브랜드 원색감을 우선한 창업자 결정이고, 위 수치를 알고 채택했다.**

🔴 **두 자리는 그대로 금지다.**

- **CTA 면 위 글자색** — 코랄 면 위 글자는 흰색 하나다 (§3-1-B 조건 2)
- **본문 · 미리보기** — `--text-primary` / `--text-secondary` 를 쓴다

**면으로는 여전히 "많이 칠하는 색"이 아니라 "정확한 포인트 색"이다.**

### 1-3. 포인트로 쓰는 자리

```
🟢 우선 쓴다     헤더 워드마크 · 활성/현재 상태 · 눌림 피드백
                 FAB 계열 · 브랜드 신호 · 그림자 · OG 장식 면
                 링크 · 배지 텍스트 · 작성자명 · 강조 텍스트 (§2-1-A)

🔴 난발 금지     페이지 배경 전체 · 넓은 카드 면
                 본문 · 미리보기 · 캡션 · 시간/조회수 같은 메타 수치
                 정보 전달 아이콘 · CTA 면 위 글자
```

**판단 기준 한 줄**: *이 면이 없어져도 사용자가 정보를 놓치지 않는가?* 놓치지 않으면 코랄을 쓸 수 있고, 놓치면 대비 요건을 먼저 만족시켜야 한다. 글자에 대한 예외는 §2-1-A 가 정한다.

### 1-4. 40~60대가 매일 읽는 화면이다

대비는 규정 통과용이 아니다. 노안 구간의 사용자가 저조도·야외에서 읽어야 한다.
**규정이 면제하는 자리에서도 "읽히는가"를 따로 확인한다.**

## 2. 색상 토큰 정본

`src/app/globals.css` `:root` 가 유일한 정의처다. 컴포넌트에 hex 를 직접 쓰지 않는다.
`npm run check:tokens` 가 이를 강제한다 — 허용 파일은 `globals.css` 와 `src/lib/brand.ts` 둘뿐이다.

### 2-1. 브랜드

| 토큰 | 값 | 역할 |
|---|---|---|
| `--brand` | `#FF6F61` | 브랜드 시그니처. 포인트·면·그림자 |
| `--brand-soft` | `#FFE8E3` | 배지·태그 배경 |
| `--brand-muted` | `#F2C9C1` | 🟡 2026-08-27 이후 **소비처 없음** — 구분선은 `--border-subtle` 중립으로 분리 |
| `--brand-ink` | `#FF6F61` | **읽는** 브랜드색 — `--brand` 와 같은 원색. 바탕 위 2.46:1 (§2-1-A) |

### 2-1-A. 🔴 읽는 브랜드색을 원색으로 되돌린 개정 (2026-08-29)

**이전 값** `--brand-ink` · `--link` 은 더 어두운 갈색 코랄이었다 (바탕 위 6.26:1).
정확한 값이 필요하면 `05b838d` 이전 커밋을 본다.

이전 값은 갈색기가 돌아 브랜드 인상과 어긋났다. **대비 수치보다 브랜드 원색감을 우선한
창업자 결정으로** 두 토큰을 `--brand` 와 같은 `#FF6F61` 로 통일했다.
중간 명도의 대체 코랄은 도입하지 않는다.

**known tradeoff — 대비가 낮다. 알고 채택했다.**

| 표면 | 대비 | WCAG |
|---|---:|---|
| 바탕 `#F2F3F5` | **2.46 : 1** | 본문 4.5 · 큰 글씨 3.0 — 둘 다 미달 |
| 흰 카드 `#FFFFFF` | **2.73 : 1** | 둘 다 미달 |
| 연분홍 배지면 `#FFE8E3` | **2.33 : 1** | 둘 다 미달 · 가장 낮다 |

작은 글씨(배지 14~15px)에서 흐리게 보일 수 있다.
되돌리려면 `globals.css` 의 `--brand-ink` 한 줄과 `brand.ts` 의 `ink` 한 줄이다.

> 🔴 **`--link` 는 2026-09-02 개정으로 이 결정에서 빠졌다(§2-3-B).**
> 이 절이 정한 "읽는 브랜드색 = 원색" 은 `--brand-ink` 에 그대로 살아 있다.

### 2-2. CTA — 누르는 것

| 토큰 | 값 | 역할 |
|---|---|---|
| `--cta` | fill 스위치 | §3-1-A 에서는 `#B64235`, §3-1-B 전환 후에는 `var(--brand)` |
| `--cta-text` | `#FFFFFF` | CTA fill 위 글자. **큰 버튼·FAB 전용 예외**(§3-1-B) |
| **`--cta-edge`** | **`#B64235`** | **숨은 접근성 유틸 전용 fill.** 흰 글씨 **5.50:1** · 바탕 위 **4.95:1** |

🔴 **`--cta` 는 값이 아니라 스위치다.**
이 한 줄만 갈아끼우면 CTA 전체가 §3-1-A ↔ §3-1-B 사이를 오간다. 컴포넌트는 고치지 않는다(§10 rollback).

🔴 **`#B64235` 는 `--cta-edge` 로 분리해 보존한다.**
`--cta` 가 스위치가 되면서 그 값을 담을 자리가 필요했다. 새로 만든 색이 아니라 **자리를 옮긴 기존 값**이다.
지금은 **숨은 접근성 유틸**(건너뛰기 링크)이 쓴다 — §3-1-C.

🔴 **`--cta-hover` 는 제거했다.**
테두리를 쓰지 않기로 하면서 쓰는 곳이 0 이 됐다. 정의만 남기지 않는다(§8-2).
같은 값 `#96372E` 는 `--focus-ring` 이 계속 갖고 있다.

### 2-3-B. 🔴 링크만 읽기 쉬운 코랄로 분리한 개정 (2026-09-02)

**이전 값** `--link: #FF6F61` (2026-08-29 §2-1-A 개정으로 `--brand-ink` 와 통일돼 있었다)

#### 무엇을 바꿨고 무엇을 바꾸지 않았나

| | 토큰 | 값 | 판단 |
|---|---|---|---|
| **유지** | `--brand-ink` | `#FF6F61` | 브랜드 인상을 만드는 자리 — 작성자명 · 배지 텍스트 · 목록 순번 · 강조 텍스트 · 워드마크 |
| **변경** | `--link` | `#FF6F61` → **`#B64235`** | 상호작용을 알리는 자리 — 판독을 인상보다 먼저 본다 |

🔴 **이것은 2026-08-29 결정(§2-1-A)의 전면 롤백이 아니다.**
그 결정의 핵심은 "브랜드색이 갈색으로 읽히면 안 된다" 였고, 그 인상을 만드는 것은
작성자명 · 배지 · 순번 쪽이다. 그 자리는 `--brand-ink` 로 **원색 그대로 남는다.**
링크는 원래 브랜드를 보여주는 자리가 아니라 **눌러야 할 것을 알려주는 자리**이고,
이 문서도 링크에만 **밑줄 필수**를 걸어 이미 다른 축으로 다뤄 왔다.
두 역할이 한 값을 겸하던 것을 이번에 갈랐다.

🔴 **새 색을 만들지 않았다.** `#B64235` 는 팔레트에 이미 있는 `--cta-edge` 와 같은 값이다.
§2-1-A 가 금지한 "중간 명도의 대체 코랄 도입" 에 해당하지 않는다 — 도입이 아니라 재사용이다.

| 표면 | 이전 `#FF6F61` | **현재 `#B64235`** | WCAG 본문 4.5 |
|---|---:|---:|---|
| 흰 카드 `#FFFFFF` | 2.73 : 1 | **5.50 : 1** | ✅ |
| 페이지 바탕 `#F9FAFB` | 2.61 : 1 | **5.26 : 1** | ✅ |
| 옅은 블록 `#F2F3F5` | 2.46 : 1 | **4.95 : 1** | ✅ |

밑줄은 그대로 필수다. 대비가 올라갔다고 색 외 신호를 빼지 않는다.

`text-link` 소비처가 전부 토큰만 보고 있어서 값 교체로 끝난다.

### 2-3-A. 🔴 바탕을 중립으로 되돌린 개정 (2026-08-27)

**이전 값** `--surface-page: #FFF8F6` · `--border-subtle: #F2C9C1`

#### 왜 바꿨나

창업자 지적: **"전체 배경이 분홍/코랄 옅은색으로 너무 깔려 있다."**

실측으로 확인한 것 세 가지다.

1. **면적이 가장 넓은 곳에 브랜드 계열을 깔면 그 색은 더 이상 강조가 아니다.**
   같은 화면의 CTA·배지·활성표시가 바탕에 묻힌다. §1-2 가 "넓은 면에 무조건 칠하는 색이 아니다"라고
   말하는 그 원칙이 정작 **가장 넓은 면인 바탕에는 적용되지 않고 있었다.**
2. **`--border-subtle` 이 `--brand-muted` 와 같은 값이었다.**
   `globals.css` 의 전역 `* { border-color }` 를 타고 **서비스의 모든 선이 분홍**이었고,
   분홍 바탕 위 분홍 선이라 목록 구분선이 사실상 보이지 않았다(카드 위 1.27:1).
3. **목록 화면은 카드 면이 아예 없었다.**
   홈만 `bg-surface-card` 였고 `/community/[boardSlug]`·`/magazine`·`/best` 의 `<main>` 에는
   표면 지정이 없어 body 의 분홍이 그대로 드러났다. 데스크탑에서 특히 "종이 위 글자 나열"로 보였다.

#### 🔴 §11 의 사고 이력과 무엇이 다른가

§11 에 **"바탕색을 중성 회색으로 바꿨다가 브랜드 톤이 통째로 사라진 적이 있다"**가 적혀 있다.
이번 개정은 그 실패의 반복이 **아니다.** 다른 점을 명시한다 — 다음 세션이 이 문단을 근거로 판단한다.

| | 그때(실패) | 이번 개정 |
|---|---|---|
| 브랜드가 닿는 면 | 함께 사라졌다 | **CTA·FAB·배지·활성표시·`--surface-soft` 강조 블록에 그대로 남는다** |
| 텍스트 | 중립으로 같이 갈았다 | **웜 먹색 `#2F2624` 계열 유지** — 바탕에서 뺀 온기를 글자가 남긴다 |
| 보더 | 순수 회색 | **웜 뉴트럴 `#E0DEDD`** — 중립이되 차갑지 않다 |
| 카드 면 | 없었다 | **오래 읽는 화면(상세·매거진)에 흰 카드를 도입**해 회색이 "빈 화면"이 아니라 "바탕"이 된다. 커뮤니티 목록은 면 없이 바탕 위 피드다(§7-A) |

즉 **브랜드를 없앤 것이 아니라, 브랜드를 바탕에서 강조 지점으로 옮긴 것**이다.

#### rollback

`--surface-page` 한 줄이다 (§8-4). `#FFF8F6` 로 되돌리면 컴포넌트를 한 곳도 고치지 않고 전 화면이 복귀한다.
구분선까지 되돌리려면 `--border-subtle` 을 `#F2C9C1` 로 함께 되돌린다.

#### 함께 고친 것 (같은 PR)

- **구분선이 한 줄도 그려지지 않던 버그** — `PostCard`·`PostListItem` 의 `<a>` 가 `<li>` 의 유일한 자식이라
  `last:border-b-0` 이 **항상 참**이었다. 선은 이제 목록이 `[&>li+li]` 로 항목 사이에만 긋는다.
- **hover 가 보이지 않던 문제** — 원인은 hover 토큰이 없어서가 아니라
  **행이 놓인 면과 hover 색이 같아서**였다. 바탕 위 행에 `hover:bg-surface-page` 를 주면
  아무 일도 일어나지 않는다. **hover 전용 토큰은 만들지 않는다** —
  `tailwind.config.ts` 를 건드리지 않고 기존 표면 토큰 두 개로 끝난다. 규칙은 §7-A 에 둔다.

🔴 **`--state-danger` `#B3261E` 와 `--cta` `#B64235` 는 명도가 거의 같다(1.19).**
색만으로 구분되지 않는다. danger 는 fill 버튼을 쓰지 않고 **아웃라인 + 텍스트 + 확인 모달**을 동반한다.

### 2-6. 외부 브랜드 · 보드 색

`--kakao-bg` `#FEE500` · `--kakao-text` `#191919` → §4
`--icon-{meno,free,magazine,best}-{bg,stroke,text}` 12개 → §5

## 3. §3-1 — brand 와 CTA 의 분리

### 왜 나누는가

`#FF6F61` 하나로 모든 UI 를 처리하면 흰 글씨 버튼에서 대비가 무너진다(§1-2).
그래서 **브랜드 신호**와 **누르는 것**을 토큰으로 나눈다. 같은 색 계열(h5~11)이라 화면에서는 하나의 브랜드로 읽힌다.

### 분리 원칙

| 토큰 | 역할 | 쓰는 곳 | 쓰지 않는 곳 |
|---|---|---|---|
| **brand** `#FF6F61` | 브랜드 시그니처 | 헤더 워드마크 · 포인트 · 활성 표시 면 · 그림자 · OG 장식 면 · **CTA/FAB fill (§3-1-B 조건 충족 시)** | 🔴 **흰 글씨 CTA** |
| **cta** `#B64235` | 누르는 것 | §3-1-A 또는 §3-1-B | 넓은 배경 면 |
| **brand-ink** `#FF6F61` | 읽는 브랜드색 | 작성자명 · 배지 텍스트 · 목록 순번 · 강조 텍스트 · 큰 워드마크 | 🔴 **링크** (§2-3-B) · 큰 면 fill |
| **link** `#B64235` | 상호작용을 알리는 글자 | 링크 (본문 autolink · 정책 · 문의 · 운영 콘솔) | 브랜드 인상을 만드는 자리 |

### `#FF6F61` 을 글자로 쓰는 범위 (2026-08-29 개정)

읽는 브랜드색이 원색과 같아졌으므로 **활성 탭 · 배지 텍스트 · 작성자명 · 목록 순번 ·
강조 텍스트 · 워드마크에 쓴다.** 대비는 낮다 — §2-1-A 의 tradeoff 를 알고 채택한 것이다.

🔴 **링크는 2026-09-02 개정으로 여기서 빠졌다.** `--link` `#B64235` 를 쓴다(§2-3-B).

```
🚫 CTA 버튼 텍스트 — 코랄 면 위 글자는 흰색 하나다 (§3-1-B 조건 2)
🚫 본문 · 미리보기 — 여기는 --text-primary / --text-secondary 다
```

정보 전달 아이콘은 각 표면의 전용 토큰(`--icon-*-text` 계열)을 그대로 쓴다.

### 비텍스트 사용 — 두 가지를 구분한다

| 구분 | 요건 | `#FF6F61` | 예 |
|---|---|---|---|
| **장식 면** | 없음 | 🟢 허용 | 배경 블록 · 밑줄 장식 · 구분 띠 · **그림자** · OG 그래픽 |
| **정보 전달 그래픽** | **3:1** (WCAG 1.4.11) | 🔴 **색이 유일한 신호일 때** 불가 (2.46) | 상태 아이콘 · 입력 테두리 · 차트 범례 |

같은 색이라도 "예쁘라고 있는 면"과 "뜻을 전달하는 그래픽"은 요건이 다르다.

🟢 **보조 신호가 함께 있으면 코랄을 표시로 쓸 수 있다.**
1.4.11 이 요구하는 것은 "색만으로 전달하지 말 것"이다. 굵기 · 고대비 텍스트 ·
`aria-current` 가 같이 있으면 코랄은 **보조 표시**가 된다.

```
예 — 게시판 정렬 탭 활성 표시
  border-brand 2px 밑줄        코랄 (보조)
  font-bold                    굵기
  text-content-primary         13.29:1
  aria-current="page"          보조기술
→ 색을 못 봐도 어느 탭이 켜졌는지 알 수 있다. 허용한다.
```

## 3-1-A. CTA 기존 안정 조합

```
fill    --cta        #B64235
text    --cta-text   #FFFFFF     5.50 : 1   ✅
hover   hover:brightness-95      밝기만 낮춘다
면 경계  vs 바탕                  4.95 : 1   ✅  테두리 없이 갈린다
```

**대비에 여유가 있는 조합이다.** `#B64235` 는 **메인 브랜드 컬러가 아니다.**
접근성을 위해 파생한 어두운 색이다.

지금은 §3-1-B 로 전환한 상태이고, 이 조합은 **`--cta` 한 줄을 되돌리면 돌아오는 자리**다(§10).
그리고 **숨은 접근성 유틸은 계속 이 조합을 쓴다**(§3-1-C).

## 3-1-B. 🟢 CTA/FAB 코랄 전환 조건 — **가능하다**

> 이 절이 이 문서의 개정 핵심이다.
> **"CTA 는 `#B64235` 여야 한다"는 고정 규칙을 해제한다.**
> `#FF6F61` 을 CTA/FAB fill 로 쓸 수 있다. **단 아래 네 조건을 모두 지킨다.**

### 조건 1 — 🟡 흰 글씨를 쓴다 (큰 버튼·FAB 한정 예외)

> 🔴 **이 절은 실기기 확인으로 뒤집힌 판단이다.** 아래에 그 경위를 남긴다.

```
#FFFFFF on #FF6F61     2.73 : 1     요건 4.5 — 미달
같은 조합 (큰 글씨)      2.73 : 1     요건 3.0 — 미달
```

**수치로는 통과하지 않는다.** 그런데도 흰 글씨를 쓴다.

#### 폐기한 조합 — 먹색 글씨 + 어두운 테두리

```
#FF6F61 + --text-primary #2F2624     5.41 : 1     요건 4.5 — 통과
+ --cta-edge #B64235 테두리          바탕 4.95 : 1 — 통과
```

**수치는 전부 통과했지만 실기기에서 버튼으로 읽히지 않았다.**
밝은 면에 어두운 글씨와 어두운 테두리가 얹히니 "눌러야 할 것"이 아니라
"표시된 영역"으로 보였다. 버튼성이 떨어진다.

#### 무엇을 골랐나

```
판독성(글자를 읽을 수 있는가)      먹색이 유리하다      5.41 vs 2.73
버튼성(눌러야 할 것으로 보이는가)   흰 글씨가 유리하다
```

**창업자 실기기 확인으로 버튼성을 골랐다.** 수치가 아니라 실제로 눌리는가로 정했다.

🔴 **대가를 정직하게 적는다.** 이 조합은 WCAG 2.1 AA 1.4.3 에 미달한다(2.73 < 4.5).
저조도·야외에서 라벨이 흐려질 수 있다. 타깃이 40~60대라 가벼운 비용이 아니다.

#### 🔴 그래서 범위를 좁힌다

```
🟢 허용   큰 버튼 · FAB — 면적이 크고 위치가 고정돼 있어 라벨을 못 읽어도
          무엇을 누르는지 맥락으로 안다

🚫 이 예외(코랄 면 + 흰 글씨)를 적용하지 않는 자리
          작은 버튼 · 링크 · 활성 탭 · 배지 · 입력 테두리
          정보 전달 아이콘 · 숨은 접근성 유틸 (§3-1-C)
```

**이 예외는 큰 버튼과 FAB 밖으로 넓히지 않는다.**

🟡 **글자를 코랄로 쓰는 것은 별개다.** 여기서 막는 것은 "코랄 면 + 흰 글씨" 조합의
적용 범위이지 글자색이 아니다. 글자색은 §2-1-A · §3 을 따른다 —
링크 · 배지 텍스트 · 작성자명은 코랄이다.

### 조건 2 — 🟢 글자는 `--cta-text` `#FFFFFF` 하나다

코랄 면 위에 올릴 수 있는 글자색은 실측하면 이렇다.

| 글자색 | 토큰 | 대비 | |
|---|---|---:|---|
| **`#FFFFFF`** | **`--cta-text`** | **2.73** | 🟡 **채택** — 버튼성 우선(조건 1) |
| `#2F2624` | `--text-primary` | 5.41 | 🚫 폐기 — 버튼으로 안 읽힘(조건 1) |
| `#191919` | `--kakao-text` | 6.45 | 🚫 §4 격리 토큰 — 빌려 쓰지 않는다 |
| `#524642` | `--text-secondary` | 3.33 | 🚫 |
| `#FF6F61` | `--brand-ink` | 1.00 | 🚫 — 면과 같은 색이다 |
| `#B64235` | `--cta-edge` | 2.02 | 🚫 |

**새 hex 를 만들 필요가 없다.** `#FFFFFF` 는 이미 `--cta-text` 가 갖고 있던 값이다.

🔴 **글자색을 여기서 늘리지 않는다.** 코랄 면 위 글자는 흰색 하나다.
상태(hover·pressed)에서도 글자색을 바꾸지 않는다 — 색을 늘리면 대비를 다시 전부 재야 한다.

`--kakao-text` 가 대비는 더 높지만 그 토큰은 외부 브랜드 예외로 격리해 둔 것이다(§4). 소란소란 CTA 가 빌려 쓰면 격리가 무너진다.

### 조건 3 — 🚫 테두리를 두르지 않는다

```
#FF6F61 면 vs 바탕 #F2F3F5    2.46 : 1     요건 3.0 — 미달
#FF6F61 면 vs 카드 #FFFFFF    2.73 : 1     요건 3.0 — 미달
```

코랄 면은 밝은 바탕에서 스스로 갈리지 않는다. 그래서 한때 `--cta-edge` 로 테두리를 둘렀다.

🔴 **그 테두리는 폐기했다.** 어두운 테두리가 버튼을 "눌러야 할 덩어리"가 아니라
"선으로 구획된 영역"으로 보이게 만들었다(조건 1).

경계는 **그림자와 위치와 크기**가 대신한다.

```
FAB              --shadow-brand 코랄 그림자 + 화면 우하단 고정 + 56px
큰 CTA 버튼       카드/섹션 안에서 유일하게 채워진 면 + 52px
```

**밝은 면이 흰 배경에서 흐릿하다고 느껴지면, 테두리를 다시 두르지 말고
그림자를 먼저 검토한다** — 그림자는 대비 요건이 없다(§2-4).

### 조건 4 — 🚫 눌림에 색을 쓰지 않는다

색으로 눌림을 만들려면 어떤 후보든 코랄면과 충분히 갈려야 하는데, 갈리지 않는다.

| pressed 후보 | 코랄면과 차이 |
|---|---:|
| `--cta-edge` `#B64235` | 2.02 |
| `#96372E` | 2.67 |
| 코랄을 한 단계 어둡게 | 1.36 |

🔴 **정확히 적는다**: 위 수치는 3:1 에 못 미친다. WCAG 1.4.11 은 같은 컨트롤의 **상태 간** 대비를 요구하지 않으므로 규정 위반은 아니다. 그러나 **색만으로는 눌림이 확실하지 않다.**

**눌림은 `active:scale-95` 하나로 만든다**(§7).
hover 는 `hover:brightness-95` 하나다 — 밝기만 낮추고 **색 토큰을 새로 두지 않는다.**

```
🚫 pressed 색 토큰 · hover 색 토큰 · 상태별 글자색
🟢 transition duration-150 hover:brightness-95 active:scale-95
```

**상태를 색으로 늘리면 그때마다 대비를 전부 다시 재야 한다.** 크기와 밝기로 끝낸다.

### 권장 조합 정리

```
fill      --cta       → var(--brand)   #FF6F61
text      --cta-text                   #FFFFFF   2.73 : 1 — 판독성 결정(조건 1)
border    없음                          조건 3
hover     hover:brightness-95          밝기만 낮춘다. 색을 새로 두지 않는다
pressed   active:scale-95              색은 쓰지 않는다
shadow    --shadow-brand               FAB
```

**클래스는 세 개면 끝난다.**
```
transition duration-150 hover:brightness-95 active:scale-95
```
hover 색 토큰도, 테두리 토큰도, pressed 색도 두지 않는다.
**상태를 색으로 늘리지 않는 것이 이 화면의 유지보수 규칙이다.**

### 🔴 `--cta` 의 역할 재정의 — `#B64235` 는 `--cta-edge` 로 분리된다

전환 전에는 `--cta` 가 값(`#B64235`)이자 메인 액션 색이었다.
전환 후에는 **둘이 갈라진다.**

```
--cta        스위치     var(--brand)  ← fill. 되돌리면 #B64235
--cta-text   #FFFFFF   CTA fill 위 글자
--cta-edge   #B64235   숨은 접근성 유틸 전용 fill (§3-1-C)  ← 기존 값이 여기로 옮겨왔다
```

**`#B64235` 는 더 이상 "메인 액션 색"이 아니다.**
보이는 CTA 에서는 물러났고, **대비를 반드시 지켜야 하는 자리**에 남았다.

🟢 **새로 발명한 색이 아니다.** 전환 전 `--cta` 가 갖고 있던 값을 자리만 옮겨 보존한 것이다.

## 3-1-C. 🔴 숨은 접근성 유틸은 CTA 시각 정책에서 뺀다

**건너뛰기 링크**(`PageShell`)는 평소 보이지 않다가 키보드 포커스에서만 나타난다.
이 요소를 쓰는 사람은 **화면을 눈으로 훑지 못하거나 마우스를 쓰지 못하는 사용자**다.

| 조합 | 대비 | |
|---|---:|---|
| 코랄 fill + 흰 글씨 | 2.73 | 🔴 **접근성 유틸이 접근성에 미달한다** |
| **`--cta-edge` `#B64235` + 흰 글씨** | **5.50** | ✅ |
| `#B64235` 면 vs 바탕 | 4.95 | ✅ 테두리 없이도 갈린다 |

**조건 1 의 예외를 여기까지 넓히지 않는다.**
큰 버튼의 예외 근거는 "면적이 크고 위치가 고정돼 맥락으로 안다"인데,
건너뛰기 링크는 **그 맥락이 없는 사용자를 위한 것**이라 근거가 성립하지 않는다.

```
보이는 CTA · FAB    7 곳   --cta        코랄 fill + 흰 글씨
숨은 접근성 유틸     1 곳   --cta-edge   #B64235 + 흰 글씨 5.50 : 1
```

### 🔴 전환은 전부 함께 한다

`bg-cta` 는 **8곳**이 쓴다. 홈에서 FAB 과 참여 유도 카드 버튼이 **같은 화면에 공존**한다.
**한 곳만 바꾸면 "누르는 것"이 두 색이 된다.** 부분 전환은 성립하지 않는다.

헤더 워드마크 2.73:1 은 **규정 위반이 아니다.**

### 🔴 워드마크에 `#FF6F61` 을 쓰는 조건

| # | 조건 | 헤더 현황 |
|---|---|---|
| 1 | Pretendard 800 또는 900 | `font-extrabold` = 800 ✅ |
| 2 | 충분한 크기 | 24px ✅ |
| 3 | 충분한 여백 | 헤더 좌측 단독 ✅ |
| 4 | **실기기 모바일 판독성** | ✅ **2026-08-26 창업자 실기기 확인 완료** |

**"면제된다"는 것과 "읽힌다"는 것은 다르다.**
네 조건을 모두 통과했으므로 헤더 워드마크의 `#FF6F61` 은 확정이다.

### 판독성 미달 시

```
1순위   이미지 로고 — 자체 대비를 내장해 설계
```

## 7. 상호작용 상태 정본

**`hover:` 는 터치에서 sticky 가 된다. 터치 피드백의 본체는 `active:` 다.**
`active:` 가 없으면 모바일에서 무엇을 눌러도 아무 반응이 없다.

| 부류 | 대상 | hover | active |
|---|---|---|---|
| **누르는 것** | FAB · CTA · ActionButton · 카카오 | 한 단계 어둡게 | `scale-95` |
| **리스트 항목** | PostListItem · PostCard | 배경 없음 · 제목색만 (§7-A) | 배경 없음 · 제목색만 |
| **아이콘 · 토글** | IconMenu · FontSizeToggle | `bg-surface-page` / `bg-surface-soft` | `scale-95` |
| **텍스트 버튼** | HeaderAuth · SignOutButton | `bg-surface-soft` | `scale-[0.98]` |
| **포커스** | 전역 | — | `:focus-visible` `--focus-ring` 2px + offset 2px |

### 7-A. 🔴 목록 행 hover 는 면을 만들지 않는다 (2026-08-29 개정)

목록에 면이 없는데 가리킬 때만 네모가 생기면 **그 네모가 글보다 먼저 읽힌다.**
행은 배경을 바꾸지 않고 **제목만 `--brand-ink` 로 반응**한다.

| 상태 | 배경 | 제목 |
|---|---|---|
| hover | **변화 없음** | `--text-primary` → `--brand-ink` |
| active | **변화 없음** | `--text-primary` → `--brand-ink` |

```
🔴 배경을 쓰지 않는다.
   흰 면·회색 면 어느 쪽도 만들지 않는다. 행이 놓인 면이 무엇이든 규칙은 하나다.
   surface prop 은 남기되 모양을 정하지 않는다 — 대비를 뒤집을 일이 없어졌다.

🔴 active 에도 면을 쓰지 않는다.
   --surface-soft 는 브랜드 계열이라 누를 때마다 코랄 블록이 깔렸다.
   모바일에서 가장 자주 보이는 상태였는데 가장 무거운 반응이기도 했다.

🔴 hover 전용 색을 새로 만들지 않는다.
   제목이 쓰는 --brand-ink 하나로 끝난다.
```

**구현** — `<a>` 에 `group`, 제목에 `transition-colors duration-150
group-hover:text-brand-ink group-active:text-brand-ink`.

**적용 9면** — 홈 인기글 · `/best` · 게시판 2 · 홈 매거진 레일 · `/magazine`
· 이어읽기 · 새로 온 이웃 · 함께 읽기.

**터치에서도 이 정책이 유리하다.** `hover:` 는 터치에서 sticky 가 되는데,
배경을 쓰지 않으므로 탭 후 눌린 줄만 면이 남는 증상이 구조적으로 생기지 않는다.

### 규칙

```
transition duration-150 을 함께 붙인다 — 색만 바뀌고 시간이 없으면 딱딱하다.

disabled 가 있는 버튼은 enabled: 로 잠근다.
  disabled:opacity-60 만 두면 제출 중인 버튼도 hover 에서 색이 바뀌어
  "아직 누를 수 있다" 로 읽힌다.

iOS 기본 탭 하이라이트는 Tailwind preflight 의 html 규칙이 이미 끈다.
  컴포넌트에 [-webkit-tap-highlight-color:transparent] 를 붙이지 않는다 — 죽은 클래스가 된다.

브랜드 코랄이 드러나는 상호작용 표면은 --surface-soft(#FFE8E3) 다.
```

### 눌림에 코랄끼리 쓰지 않는다

`#FF6F61` → 한 단계 어두운 코랄은 **1.36:1** 로 구분이 안 된다. §3-1-B 조건 4 를 따른다.

## 8. 토큰 유지보수 원칙

### 8-1. hex 는 두 곳에만 있다

```
src/app/globals.css   화면에 그려지는 모든 색
src/lib/brand.ts      metadata · manifest · OG (CSS 변수를 해석하지 못하는 곳)
```

컴포넌트는 semantic token 만 쓴다. `npm run check:tokens` 가 강제한다.
색을 바꿀 때는 이 두 파일만 고치면 전체 UI 가 교체된다.

### 8-2. 🔴 토큰 정의와 유틸리티 이름이 어긋나면 토큰이 죽는다

**실제로 겪은 사고다.** `tailwind.config.ts` 에서 색을 이렇게 두면

```ts
colors: { border: { subtle: '…', interactive: '…' } }
```

Tailwind 가 중첩 객체를 `부모-자식` 으로 평탄화해 색 이름이 `border-subtle` 이 되고,
borderColor 유틸리티는 **`border-` + 색이름 = `border-border-subtle`** 이 된다.

컴포넌트는 `border-interactive` 를 쓴다. **없는 클래스다.**
`--border-interactive` 는 정의만 되고 **적용 0곳**이었다 — 테두리로 존재를 알려야 하는 버튼이 장식 구분선 색을 쓰고 있었다.

**대조군이 증거였다**: `colors.surface.page` 는 최상위 키라 `.border-surface-page` 가 정상 생성돼 있었다.

```ts
// 해법 — 보더 색은 colors 가 아니라 borderColor 에 둔다
borderColor: { subtle: 'var(--border-subtle)', interactive: 'var(--border-interactive)' }
```

**교훈**: 토큰을 새로 만들면 **빌드된 CSS 에 규칙이 실제로 생겼는지 확인한다.**
정의했다는 것과 화면에 닿는다는 것은 다르다.

### 8-3. 검증 명령

```
npm run check:tokens       컴포넌트 hex 리터럴 차단
npm run check:visibility   글 노출 정책 회귀
npm run typecheck · lint · build
```

### 8-4. 색 교체는 토큰 한 줄로 끝나야 한다

`--brand` 를 다른 값으로 바꿨을 때 컴포넌트를 한 곳도 안 고쳐도 전 화면이 바뀌어야 한다.
그렇지 않다면 어딘가에 리터럴이 샜다는 뜻이다.

```
2. 밝은 코랄 면이 40~60대에게 눈부시지 않은가            ✅ 확인 완료
```

헤더 워드마크 판독성(§3-2 조건 4)은 2026-08-26 에 확인이 끝났다.

## 11. 이 문서를 고쳐야 하는 때

```
색을 바꾸기 전         — 코드보다 이 문서가 먼저다
새 토큰을 만들 때       — §2 표에 행을 추가한다
대비 수치가 달라질 때   — 바탕색이 바뀌면 모든 수치를 다시 잰다
새 규칙이 생겼을 때     — 사고로 배운 것은 §8 에 남긴다
```

🔴 **문서 없이 구현하면 다음 세션이 되돌린다.**
바탕색을 중성 회색으로 바꿨다가 브랜드 톤이 통째로 사라진 적이 있다. 문서에 적혀 있었는데 코드만 보고 판단했기 때문이다.

**코드와 이 문서 중 하나만 고치지 않는다.**
