# 원문 작성자를 복제하지 않는다 — 화자 상대 사실 정본

> 📜 **좁은 기술 계약의 역사 기록 — 제품 정책·현재 상태 정본이 아니다.** 현재 권위와 상태는
> [`README.md`](./README.md)가 가리키는 네 문서와 main/runtime 실측이 정한다.

작성 2026-09-23. 근거는 당시 실측 사슬과 코드다.

## 1. 우리가 하는 일

소란소란은 **원문 작성자를 복제하지 않는다.** 인기 있고 반응 좋은 원문의
**소재·상황**을 고른 뒤, 그것을 **우리 Persona 의 생활사와 말투로 다시 쓴다.**

```
원문 선택
  → source-invariant / source-speaker-relative 사실 분리
  → speaker-relative 사실을 Persona 정본으로 자동 변환
  → 초안 생성
  → Persona 정합성 검증
  → 자동 보정
  → 의미 보존이 불가능할 때만 HOLD
```

## 2. 🔴 실패 사슬 — 후보 `cmudal78h…` (P02 · 2026-09-23)

| 단계 | 실제 값 |
|---|---|
| ① source evidence | `낼44인데 아직도 어리단소리들어요 ㅋ` |
| ② `plan.selfBasis` | `noLifeFactNeeded` |
| ③ `plan.protectedFacts` | `[{kind:'number', text:'80퍼'}, {kind:'number', text:'44'}]` 🔴 |
| ④ `plan.warrants` | `[]` |
| ⑤ `draft.body` | `제가 곧 44인데 아직 어리다는 소리도 듣고 그래요.` |
| ⑥ `review.semantic.lifeContradictions` | `[]` — 못 잡았다 |

**원인 확정**: `readSpeakerPlan` 의 `protectedFacts` 검증은 세 가지만 물었다 —
증거에 있는가 · 개인정보인가 · `kind` 가 맞는가. **"이것이 원문 화자 자신의 사실인가"를
묻는 단계가 없었다.** 그래서 44 가 `source-invariant` 로 잘못 분류돼 초안까지 갔다.

## 3. 사실 분류

| source-speaker-relative (바꾼다) | source-invariant (지킨다) |
|---|---|
| 화자 자신의 나이 | 실제 사건 |
| 혼인 · 자녀 | 공개 인물 · 상품 · 장소 |
| 직업 · 지역 | 이야기의 핵심 행동과 결과 |
| 부모 돌봄 · 갱년기 | 의미를 성립시키는 금액 · 기간 |

🔴 **자기 나이라는 이유만으로 원문 숫자를 `protectedFacts` 에 넣지 않는다.**

🔴 **제3자의 사실은 걷어내지 않는다.** "아는 분이 44인데" 의 44 는 그 사람 것이고
우리 화자와 무관하다 — 원문 이야기의 일부다.

### 판정을 뒤집은 이유

원문은 카페 글이라 1인칭 주어를 자주 생략한다("낼44인데"). 보수적 정본
`readSelfAgeClaim` 은 주어가 없으면 읽지 않는다. 그래서 `speakerRelativeAxisOf` 는
**"자기 나이가 확실한가"가 아니라 "제3자 것이 확실한가"** 를 묻는다.

🔴 **원문 화자의 나이를 지켜서 우리가 얻는 것은 없다.** 애매하면 걷어내는 쪽이 안전하다.

## 4. Persona 정확 나이 — birth anchor

`ageBand` 만 있어서 초안이 원문 숫자를 베꼈다. 이제 **생일 기준점**을 둔다.

- 🔴 **Pool 카드의 `birthDate` 줄 한 곳이 정본이다.** 해시로 유도하지 않는다 —
  규칙 판이나 `ageBand` 가 바뀌어도 같은 사람의 생일은 그대로여야 한다
- 발행 KST 날짜로 나이를 계산한다 → **해가 바뀌면 나이도 는다**
- 🔴 **사람이 매년 고치는 구조를 만들지 않는다**
- 🔴 birth anchor 자체는 **글에 나오지 않는다** — 나오는 것은 계산된 나이뿐
- 🔴 `ageBand` 와 어긋나면 **쓰지 않는다** (fail-closed)
### 🔴 `birthDate` 와 `ageBand` 의 관계

| | 역할 |
|---|---|
| **`birthDate`** | **안정적인 정본.** 한 번 정하면 바뀌지 않는다 |
| `ageBand` | **초기 설계 분류이자 검증 기준.** 발행일 `exactAge` 가 이 범위 안인지 확인한다 |

🔴 `exactAge` 가 `ageBand` 를 벗어나면 **낡은 `ageBand` 로 조용히 되돌아가지 않는다** —
`OUT_OF_BAND` 로 막고 카드를 갱신하라고 말한다. 다만 밴드 맨 위를 쓰지 않아
**최소 1년**은 사람이 손대지 않아도 된다.

### 🔴 DB migration·write 가 필요 없다

이 값은 Pool 문서(코드 저장소)와 함수만으로 나온다. `Persona.identity` 를 쓰지 않으므로
**운영 DB 25명 일괄 write 도 필요 없다.**

## 5. 자동 변환

```
sourceSpeakerAge : 42
personaAge       : 49
outputRule       : 42를 복제하지 않고 Persona 49로 서술
```

- Persona exact age 가 없으면 **연령대로** 표현한다
- 원문에 나이가 없으면 **임의로 더하지 않는다**
- 제3자 나이는 Persona 나이로 바꾸지 않는다
- 🔴 기존 생성 요청 안에서 변환한다 — **별도 유료 호출이나 사람 검토를 더하지 않는다**

## 6. 의미 의존성

| 나이의 역할 | 처리 |
|---|---|
| `incidental` — 피부·패션·일상·감정 | **자동 변환** |
| `loadBearing` — 의료·임신·법률·보험·지원 자격·연령 제한 | 숫자만 바꾸지 않는다. **Persona·stance 재계획**, 그것도 안 되면 HOLD |

🔴 **광범위 금지 낱말 목록을 새로 만들지 않는다.** 기존 semantic review 와
source evidence 로 판단한다.

## 7-a. 🔴 이번 PR 의 범위 — age 세로 경로 하나

관계·직업·지역·갱년기는 **`protectedFacts` 에서 걷어내지 않는다.** 완전한 변환과
검증이 없는 채로 걷어내면 **내용이 사라진다.** 공통 타입은 두되 활성화하지 않았다.

## 8. age 외 여섯 축 전수 조사 — 같은 구조의 결함이 있다

🔴 조사 결과를 **직접 코드로 재확인**한 것만 적는다.

| 축 | protectedFacts 로 보호되나 | 자동 변환 가능 | Persona 재선택 | 진짜 HOLD | 처리량 병목 |
|---|---|---|---|---|---|

### 🔴 확인된 협공 구조

1. `protectedFacts` 가 원문 화자의 관계를 잡는다
2. 프롬프트가 **"이 말들은 그대로 씁니다"** 로 지시한다
   (`content-core-prompts.mts:199-201` — 직접 확인)
3. 생성기가 원문 값을 쓰면 → `lifeContradictions` → hold
4. 생성기가 우리 값을 쓰면 → `protectedFactMissing` → 실패
5. 🔴 그 hold 는 **`terminal`** 이라 원천이 **영구 제외**된다
   (`review.ts:377` `if (c.complete) return false` → `supply-workset.ts:253-257` — 직접 확인)

**자동으로 고칠 수 있는 축 불일치 하나가 원천을 영구히 태운다.**

### 이번에 고친 것

- `speakerRelativeAxisOf` 가 **관계 낱말도** 축으로 판정한다 (maritalStatus·children·parentCare)
  🔴 "아는 분 남편" 처럼 **제3자 소유면 지킨다** — 원문 이야기의 일부다
- `hasFact` 를 **양방향**으로 받는다 (`spouse`·`parentCare`·`menopause`)
  앞판은 `'있음'` 만 받아, 우리 풀에 **실제로 있는** 이혼·무간병·갱년기 전 Persona 의
  자격을 세울 수 없었다 → `requiredValueUnmet` → `speakerUnqualified` → **비재시도 결론**
- 프롬프트 계약도 같이 맞췄다

### 아직 안 고친 것

- 🔴 **`terminal` 판정 자체** — 자동 변환 가능한 불일치까지 영구 제외한다.
  `artifactRetryable` 이 `semanticCompletion.complete` 면 무조건 `false` 를 낸다.
  이것은 별도 판단이 필요하다 (재시도 자격을 넓히면 같은 원천을 반복해서 돌 위험)
- 🔴 `work`·`region` 은 `hasFact` 가 **카드 값을 그대로 비교**해 항상 참이다
  (프롬프트가 카드 값을 베끼라고 지시한다). 계획 단계 검증이 사실상 없다
- 🔴 **자동 보정** — 생성 후 남은 원문 값을 Persona 값으로 고치는 단계
