# Voice Engine v0 계약 (VE-0)

> **이 문서의 역할**: Voice Engine 을 만들기 전에 **입력 · 출력 · 금지선 · 붙는 자리**를 확정한다.
> LLM 을 붙이는 구현 문서가 아니다. **코드 0줄 · schema 0 · LLM 호출 0.**
>
> 🔴 **문서가 코드보다 우선하지 않는다.** 코드 · fixture · DB · Sheet 실측과 어긋나면
> 실측을 믿고 이 문서를 고친다. §11 참조.
>
> 작성 2026-08-27 · 기준 커밋 `96112d4` · Micro Seed 발행 4건 · 상세 원문 7건
>
> 🔴 **2026-08-27 보강**: 이 계약의 초판은 **소란소란 Micro Seed 5건만 보고 썼다.**
> S-0/L-0 감사에서 우나어에 **원문 33,031건 · 댓글 원문 154,872개**가 이미 있음을 실측했다.
> §3-4 와 §8-1 · §9 를 그에 맞춰 고쳤다.

## 1. North Star

**Voice Engine 은 소란소란의 핵심 장치이자 장기 자산이다.**

목표는 *"AI 가 쓴 티를 지우는 것"* 이 아니다. 그건 결과이지 목적이 아니다.
목적은 **실제 우리 타겟의 말투 · 생활감 · 반응 구조를 자산화해, 소란소란만이 만들 수 있는
오리지널 콘텐츠 생산 능력을 갖는 것**이다.

말투를 흉내 내는 것과 말투를 이해하는 것은 다르다.
흉내는 문장 몇 개로 끝나지만, 이해는 **"이 나이대 사람이 무엇을 어떻게 걱정하는가"** 를 안다.
후자만이 자산이 된다.

### 1-1. 타겟

**40대 후반~60대 초반 여성** (핵심 50대).

| 🚫 절대 금지 | ✅ 대체 표현 |
|---|---|
| 시니어 · 어르신 · 노인 · 실버 | **우리 나이** · **우리 또래** · **40대 후반~60대 초반 여성** · **인생 2막** |

이 금지는 문서 · 코드 주석 · 프롬프트 · 산출물 전부에 적용된다.
Voice Engine 이 만드는 문장에 이 단어가 들어가면 그 자체로 실패다 —
**우리 회원이 스스로를 부르지 않는 말로 그들에게 말을 거는 것**이기 때문이다.

### 1-2. 성공 판정

**North Star 는 주간 재방문 참여 유저 수다.** Voice Engine 도 예외가 아니다.

생성량 · 말투 변주 수 · 처리한 원문 건수는 전부 **하위 진단 지표**다.
"이번 주에 초안 50개를 만들었다" 를 성과로 삼는 순간 우나어의 실패를 반복한다.

물어야 할 것은 하나다 — **이 작업이 회원이 댓글을 쓰게 만드는 데 기여하는가.**

## 2. 레인 분리 — 🔴 이 문서에서 가장 중요한 절

세 레인은 **입력도 다르고 노출 정책도 다르다.** 섞이면 되돌릴 수 없다.

| 레인 | 입력 | 노출 | 상태 |
|---|---|---|---|
| **Micro Seed** | **원문 그대로** (82cook · 네이버 카페 한정) | 🔴 **영구 noindex · internal** | 운영 중 (4건 발행) |
| **Voice Engine / Derived Vault** | 원문 · 댓글에서 **패턴 · 라벨만** 추출 | — (발행하지 않는다) | **미착수** |
| **Original Content / Index** | **Derived 만** | index 가능 (별도 정책 필요) | **미착수** |

### 2-1. Micro Seed — 원문 레인

헌법 확정 정책이 이미 정해 놓았다.

- 정책 7 — **본문 + 일부 원문 댓글 그대로 사용**을 허용한다
- 정책 8 — Micro Seed 글은 **영구 noindex / internal** 이다
- 정책 10 — **index 전환은 영구 금지**다
- 정책 15 — 목적은 **SEO 가 아니라 커뮤니티 생활감 · 활성화**다

**Micro Seed 는 검색 자산이 아니라 커뮤니티 반응의 씨앗이다.**
글이 몇 개 걸렸는가가 아니라 그 아래 대화가 붙었는가로 판정한다.

### 2-2. Voice Engine / Derived Vault — 추출 레인

원문과 댓글에서 **패턴 · 라벨 · 말투 · 반응 구조**를 뽑는다.
**이 레인은 아무것도 발행하지 않는다.** 산출물은 다른 레인의 입력일 뿐이다.

### 2-3. Original Content / Index — 오리지널 레인

Derived 를 바탕으로 소란소란 오리지널 글을 만든다.

🔴 **아직 존재하지 않는 레인이다.** 헌법 §10-5 가 `index 커뮤니티 글` 은 **Derived 만**
쓴다고 이미 정했지만, 그 레인의 정책 · 검증 · 게이트는 **하나도 서 있지 않다.**

**Micro Seed 와 별도의 정책과 검증이 필요하다.** 같은 테이블 · 같은 게이트로 운영하면
어느 글이 원문 그대로이고 어느 글이 오리지널인지 사후에 구분할 수 없게 된다.

### 2-4. 🔴 경계가 무너지는 지점

```
❌ rewrittenBody 를 Micro Seed 본문 자리에 넣는다
   → 정책 7 · 헌법 M2 완료조건("원문 그대로 사용")과 충돌한다.
     Micro Seed 는 noindex 라서 원문 사용이 허용된 레인이다.
     본문을 고쳐 쓰는 순간 그 예외의 근거가 사라진다.

❌ Derived 없이 원문을 다듬어 index 레인에 올린다
   → §10-5 위반. index 레인은 Derived 만 쓴다.

❌ Micro Seed 와 Original Content 를 한 테이블에서 운영한다
   → "이 글은 원문인가 오리지널인가" 를 나중에 아무도 답할 수 없다.
```

## 3. 입력 데이터 계약

Voice Engine v0 가 **쓸 수 있는** 입력.

| 필드 | 현재 보유 | 비고 |
|---|---|---|
| `rawTitle` / `originalTitle` | ✅ | 목록 제목은 37자에서 잘린다 — 상세 제목 우선 (PR #72) |
| `rawBody` | ✅ | 상세 7건 · 62~1071자 · 합계 2,922자 |
| `rawComments` | 🔴 소란소란 **없음** / 🟢 **우나어 154,872개** | 3-2 · **3-4** |
| `sourceSite` · `sourceUrl` · `sourceArticleId` | ✅ | |
| `sourceBoardName` | ✅ | 현재 전부 `자유게시판` |
| `sourceCommentCount` | ✅ | **수집 시점 스냅샷**이다. 최신 글일수록 0에 가깝다 |
| `sourceCapturedAt` | ✅ | |
| `qualityFlags` | 🟡 **JSONL 에만** | 아래 3-1 |
| `qualitySignals` | 🟡 **JSONL 에만** | `matched` 에 판정 근거 어휘가 있다 |
| 발행 성공 여부 | ✅ | `createdPostId` 유무 |
| **창업자 승인 / 보류 / 거절 판단** | 🔴 **사실상 없음** | 아래 3-3 |
| **보류 · 거절 이유** | 🔴 **사실상 없음** | `declineReason` 필드는 있으나 전부 null |
| 댓글 반응 포인트 | 🟢 **우나어로 가능** | 소란소란만 보면 불가. **3-4 참조** |

### 3-1. `qualityFlags` 는 원장에 남지 않는다

Q-1(PR #72 · #75)이 12종 플래그와 판정 근거를 계산하지만, **importer 가 필드를 골라 읽어
`qualityFlags` 를 버린다.** 설계상 의도였다 — 원장과 Sheet 17열을 늘리지 않기 위해서다.

결과적으로 지금은 **로컬 JSONL 에만** 있고, 그 파일은 `.gitignore` 대상이다.
**VE-1 의 첫 과제가 이것이다.**

### 3-2. 댓글 원문은 수집하지 않는다

collector 가 **의도적으로** 댓글 본문을 파싱하지 않는다. 목록의 댓글 **수**만 신호로 쓴다.
`MicroSeedRawContent.rawComments` 필드는 존재하지만 **5건 전부 null** 이다.

그런데 헌법은 댓글을 핵심 자산으로 규정한다.

- 정책 14 — **댓글이 핵심이다.** 원문 댓글은 부속물이 아니라 반응 지도이자 활성화 패턴의 핵심 자산
- §10-4 — Derived 필수 산출에 `댓글이 달린 포인트` · `댓글 유형 분포` · `댓글 단위 인용 적합성 라벨`
- §11-2 — 댓글 **단위** 역추적 요구

**댓글 원문을 쓰려면 별도의 수집 · 저장 · 라벨링 계약이 필요하다.**
`rawComments` 가 JSONB 인 한 댓글 하나만 내리거나 라벨링할 수 없다 —
**별도 테이블 승격이 선행되어야 한다.**

> 🔴 **2026-08-27 정정**: "댓글 원문이 없다" 는 **소란소란만 봤을 때의 이야기다.**
> 우나어 `CafePost.topComments` 에 **댓글 원문 154,872개**가 있다(§3-4).
> `topComments` 도 JSON 배열이라 같은 승격 문제를 갖는다.

### 3-3. 🔴 창업자의 판단이 가장 값진 학습 신호인데 지금 사라진다

실제로 있었던 판단들이다.

```
4232060 사위 이야기    승인   741자 · 가족 경험담 · 위험 0
4232047 눈썹거상       보류   본문에 연예인 실명 + 피부과 + 가격 문의
4232041 창고형 약국    보류   127자로 얇다
4231978 제주도관광     보류   본문 62자 · URL 65%  (댓글 수 1위였다)
```

**이 판단들은 세션 보고서에만 있다.** `declineReason` 컬럼이 있지만 한 번도 쓰이지 않았고,
`HOLD` 로 남겨두면 "보류"인지 "아직 안 봤다"인지 구분되지 않는다.

Voice Engine 이 학습해야 할 정답지가 바로 이것이다 —
**무엇이 좋은 후보인가를 사람이 이미 판정해 왔는데, 그 기록이 남지 않는다.**

`approve-live`(PR #78)가 이 판단이 통과하는 첫 구조화된 입구다. VE-1 에서 다룬다.

### 3-4. 🔴 우나어 legacy 가 최대 입력이다 (2026-08-27 추가)

초판은 이 자산을 **입력 계약에서 통째로 빠뜨렸다.** 실측은 이렇다.

| 자산 | 소란소란 Micro Seed | **우나어 legacy** |
|---|---|---|
| 원문 | 5건 | **33,031건** |
| 댓글 원문 | **0개** | **154,872개** |
| 분석 라벨 | 0건 (JSONL 에만) | **30,139건** (`aiAnalyzed`) |
| 타겟 일치분 | — | **24,297건** (`ageSignal` 50s/60s) |
| 사람 선별 판단 | 기록 안 됨 | **6,494건** (`usedAt`) |

**헌법 정책 12 · §10-1 이 이미 정해 놓았다** —
*"우나어 legacy 는 직접 발행 소스가 아니라 Voice Vault 학습 · 분석 자산이다."*
학습 자산으로 쓰라고 명시된 것을 **입력 계약에서 빼놓고 있었다.**

그리고 `CafePost` 는 헌법 §10-4 가 요구하는 Derived 산출을 **이미 상당 부분 갖고 있다** —
`desireCategory`(21종) · `emotionTags` · `emotionalPeak` · `psychInsight` · `urgencyLevel` ·
`ageSignal` · `viralType` · `conflictTrigger` · `commentSplit` · `topComments`.

**Voice Engine 은 백지에서 시작하지 않는다.**

> ⚠️ 이관 방식(복제 vs 참조 vs 추출물만)은 **심층 감사 후 결정한다.**
> 우나어 DB 와 소란소란 DB 는 별개다.

## 4. 출력 데이터 계약

Voice Engine v0 의 산출. **전부 Derived Vault 자산이며 그 자체로 발행되지 않는다.**

| 출력 | 내용 |
|---|---|
| `toneNotes` | 말투 습관 — 어미 · 문장 길이 · 호흡 · 존댓말 정도 |
| `lifeDetailNotes` | 생활 디테일 — 등장하는 사물 · 장소 · 관계 · 일과 |
| `emotionFlow` | 감정 흐름 — 어디서 시작해 어디로 가는가 |
| `concernStructure` | 고민 구조 — 무엇을 묻는가 · 무엇이 진짜 걱정인가 |
| `titleSense` | 제목 감각 — 원문 제목이 무엇을 앞세웠는가 |
| `targetFit` | 우리 또래 적합성 |
| `riskFlags` | 위험 라벨 (§7) |
| `sourceRetentionNotes` | 보존 판단 근거 — `deletedDetectedAt` · `retentionUntil` |
| `founderTitle` 제안 | 🟡 **창업자 편집칸 제안값.** 사람이 덮어쓸 수 있어 안전한 첫 출력 |
| `rewriteDirection` | 🔴 **방향만.** 완성된 본문이 아니다 (§4-1) |
| `originalityNotes` | 무엇을 바꿔야 소란소란 것이 되는가 |
| `commentReactionMap` | 댓글이 붙은 포인트 지도 — **댓글 원문 확보 후에만** |

**품질 · 위험 축 (2026-08-27 추가)** — 상세: [`voice-engine-style-strategy.md`](./2026-08-27-voice-engine-style-strategy.md)

| 축 | 방향 |
|---|---|
| `naturalnessScore` · `voiceRetention` · `originalityDelta` | 🟢 높을수록 좋다 |
| `overSanitizedRisk` (과교정) · `overMimicryRisk` (과모방) | 🔴 **서로 반대 방향** — 함께 봐야 한다 |
| `sequenceSimilarityRisk` · `expressionRisk` | 🔴 복제 위험 |
| `typingArtifacts` · `punctuationHabit` · `spacingVariance` · `mobileInputTrace` · `communityRegister` | 🟢 **Voice 자산** (노이즈 아님) |

### 4-1. `rewriteDirection` 은 본문이 아니다

```
✅ rewriteDirection  "딸 결혼 후 사위와의 거리감. 3인칭 관찰이 아니라
                     본인 당황스러움에서 출발하도록. 제목은 '해맑다'는
                     표현을 살리되 판단어를 빼는 방향"

❌ rewrittenBody     (완성된 대체 본문)
```

**방향은 사람이 읽고 판단하는 재료이고, 완성본은 사람을 건너뛴다.**
v0 는 사람을 건너뛰지 않는다.

### 4-2. v0 에서 **제외**하는 것

| 제외 | 이유 |
|---|---|
| `rewrittenBody` 를 **Micro Seed 본문에 넣는 것** | 정책 7 · M2 충돌 (§2-4) |
| 댓글 자동 생성 · 반응 조작 | 정책 14 — 댓글은 반응 지도이지 만들어낼 숫자가 아니다 |
| index 글 자동 발행 | 그 레인의 정책 · 게이트가 하나도 없다 (§2-3) |
| **publisher 변경** | 원문 그대로 발행이 계약이다 (§10-3) |

## 5. "AI 티 제거" 기준

🔴 **이건 문체 취향이 아니라 판정 기준이다.** 아래에 걸리면 그 산출물은 실패다.

### 5-1. 금지 — 이렇게 되면 실패다

| 금지 | 왜 |
|---|---|
| **너무 정돈된 문장** | 사람은 한 문단 안에서 화제를 바꾸고 되돌아온다 |
| **블로그 · 상담문 말투** | *"~하시는 것을 추천드립니다"* — 우리 회원은 서로에게 이렇게 말하지 않는다 |
| **과하게 친절한 요약문** | *"정리하자면 세 가지입니다"* — 커뮤니티 글은 정리해주지 않는다 |
| **감정이 매끈하게 정리된 문장** | 실제 감정은 뒤섞이고 결론이 안 난 채 끝난다 |
| **생활 디테일 없는 일반론** | *"나이가 들면 관계가 어려워집니다"* 는 누구의 이야기도 아니다 |
| **댓글이 "공감합니다" 수준으로 납작해지는 것** | 반응이 아니라 채움이 된다 |

### 5-2. 살려야 하는 것

```
빈틈        말하다 만 문장, 괄호 안의 딴소리
망설임      "뭐라고 해야 하나", "이런 말 해도 되나 싶은데"
생활감      구체적인 물건 · 장소 · 시간 · 금액 · 사람
구체적 상황  "작년 연말에 결혼한 딸부부" 는 되고 "결혼한 자녀" 는 안 된다
반응 포인트  원문과 댓글에서 사람들이 실제로 걸린 지점
```

### 5-3. 🔴 반대 방향의 위험도 있다 (2026-08-27 추가)

**AI 티를 줄이는 것은 모든 문장을 매끈하게 고치는 것이 아니다.**
**과도한 교정 · 과도한 요약 · 너무 반듯한 구조 · 교과서 같은 공감 문구가 곧 AI 티다.**

```
overSanitizedRisk ↑                    overMimicryRisk ↑
   매끈하게 다림질                          오타를 흩뿌림
        ↖                                    ↗
                   자연스러운 지점
```

한쪽만 보면 반대편으로 넘어간다. 그리고 **오타 · 띄어쓰기 · 문장부호 습관 ·
모바일 입력 흔적은 지울 노이즈가 아니라 Voice 자산**이다 —
다만 **낮은 빈도로만** 반영한다(`artifactFrequency`).

상세: [`voice-engine-style-strategy.md`](./2026-08-27-voice-engine-style-strategy.md) §3 · §4

### 5-4. 판정 방법

**사람이 읽고 판정한다.** v0 에 자동 판정기를 만들지 않는다 —
"AI 티" 를 기계가 재는 순간 그 지표에 최적화된 또 다른 AI 티가 나온다.

## 6. 원문 보존과 오리지널리티의 균형

이 절이 Voice Engine 의 윤리적 · 법적 경계다.

### 6-1. 보존하는 것

**원문의 핵심 상황 · 감정 · 생활 디테일은 보존한다.**
그것이 자산의 실체다. 바꿔버리면 남는 것은 우리가 지어낸 이야기뿐이다.

### 6-2. 재구성할 수 있는 것

**표현 · 구성 · 제목 · 흐름은 소란소란에 맞게 재구성할 수 있다.**

### 6-3. 지켜야 하는 것

| 원칙 | |
|---|---|
| **출처 추적 가능성 유지** | 어떤 원문에서 나왔는지 항상 역추적된다 (`dedupKey` · `sourceUrl`) |
| **원문 의미를 왜곡하지 않는다** | 재구성은 표현의 일이지 사실의 일이 아니다 |
| **원문 그대로 복붙한 index 콘텐츠 금지** | §10-5 |
| **Micro Seed 만 원문 사용 예외** | 그리고 그 예외의 대가가 **영구 noindex** 다 |

### 6-4. 🔴 예외에는 대가가 있다

Micro Seed 가 원문을 그대로 쓸 수 있는 이유는 **검색에 노출되지 않기 때문**이다.
noindex 를 풀면 그 예외의 근거가 사라진다. 그래서 정책 10 이 **index 전환 영구 금지**다.

**"원문 그대로" 와 "검색 노출" 은 함께 갈 수 없다.** 둘 중 하나를 고르는 것이 레인 분리다.

> **단 하나의 예외**는 이미 collector 에 있는 것뿐이다 — 본문이 0자인 글.

## 8. 비용 최소화

| 단계 | 방법 |
|---|---|
| **LLM 호출 전** | Q-1 플래그로 후보를 좁힌다. 이미 12종이 돌고 있다 |
| **대상 조건** | `targetLikely && !위험플래그 && bodyLength >= 150 && 발행됨` |
| **위험 플래그 보유분** | LLM 대상에서 **제외하거나 후순위**. 어차피 발행하지 않을 글이다 |
| **착수 조건** | 🔴 **원문 30~50건 전에는 LLM 구현을 시작하지 않는다** (§8-1) |
| **dry-run 기본** | 전 스크립트 공통 계약 |
| **첫 실행** | `--limit=1` |
| **캐시** | `dedupKey` 기준. **같은 원문 재호출 금지** |
| **실패 · 보류 이유** | 버리지 않고 학습 데이터로 남긴다 (§3-3) |

실측 7건에 위 조건을 적용하면 **3건**만 남는다.

### 8-1. 🔴 착수 조건 — 2026-08-27 정정

초판은 이렇게 적었다.

```
보유 원문   7건 · 2,922자   →  "원문 30~50건 전에는 LLM 을 붙이지 않는다"
```

**이 판단의 전제가 틀렸다.** 소란소란 신규분만 셌기 때문이다.
우나어 legacy 를 포함하면 **원문 33,031건 · 댓글 154,872개**로 이미 충분하다.

**따라서 blocker 는 "데이터 부족" 이 아니라 "데이터 구조 미확정" 이다.**

```
❌ 원문이 모자라서 못 한다        → 사실이 아니다
✅ 담을 그릇이 아직 없어서 안 한다  → 이것이 실제 이유다
```

착수 순서는 다음과 같다.

```
① 우나어 심층 데이터 감사 (read-only)
② VoiceSource / VoiceDerived / VoiceJudgment 구조 확정
③ schema PR
④ offline analyzer (LLM 없이)
⑤ 제한적 LLM 실험
```

> ✅ **2026-08-27 — ①~④ 완료.** ③ schema PR(`0006`·`0007`) · ④ offline analyzer(VE-M2, 비용 0원).
> ⑤ 의 착수 계약은 [VE-M3 LLM 실험 계약](./2026-08-27-voice-m3-llm-experiment-contract.md)에 있다.
> 🔴 모델 · 단가는 미확정이며 10건 실험 전 창업자 승인 사항이다.

**법률 검토는 완료됐다** — 창업자가 10명 이상의 변호사에게 자문했고,
우나어 원문 · 댓글을 LLM 내부 분석과 말투 · 패턴 추출에 쓰는 것은 진행 가능하다.
🔴 **"법적 검토가 안 됐으니 보류" 를 blocker 로 세우지 않는다.**
이후 판단 기준은 **비용 · 품질 · 원문 복사 방지 · 데이터 구조 · 운영 안정성**뿐이다.

## 10. 현재 Micro Seed 와의 연결

```
collect  ─ ✅ Q-1 (제목 라벨)          ← Derived 의 첫 조각이 이미 여기 있다
fetch    ─ ✅ Q-1 (본문 라벨)
   ↓
import   ─ 🔴 VE-1 의 자리. flags · signals 를 원장에 남긴다
   ↓
Sheet    ─ 🟡 founderTitle 제안만. 17열 계약은 건드리지 않는다
승인      ─ 🔴 VE-1. approve-live 가 창업자 판단이 지나는 첫 구조화된 입구다
   ↓
publisher ─ ⛔ 절대 손대지 않는다
recover  ─ ⛔ 원장 정합성만 담당한다
```

### 10-1. Q-1 은 이미 Derived Vault 다

`targetLikely` · `riskFlags` · `bodyLength` · `linkCharRatio` · `matched(근거 어휘)` 는
§10-4 가 요구하는 `target fit` · `risk labels` · `본문 길이 밴드` · `글 유형` 에 그대로 대응한다.

**Voice Engine 은 백지에서 시작하지 않는다.** 이미 돌고 있는 것을 원장에 남기는 데서 시작한다.

### 10-2. `approve-live` 가 판단의 입구다

`--candidate` · `--at` · `--apply` 를 사람이 직접 적는 순간이 **승인이 구조화되는 유일한 지점**이다.
여기에 보류 이유를 남길 자리를 만들면 학습 신호가 쌓인다.

### 10-3. 🔴 publisher 는 원문 변경을 맡지 않는다

publisher 가 쓰는 `content` 는 `rawBody` 그대로여야 한다.
이 경계가 무너지면 **"우리가 원문을 고쳤는가"** 를 사후에 확인할 수 없다.

**Voice Engine 은 publisher 앞단, 또는 완전히 별도 레인에서만 동작한다.**

### 10-4. `recover` / divergence 는 정합성만 본다

DB 와 Sheet 가 같은 것을 말하는지만 판정한다. 품질도 말투도 보지 않는다.
Voice Engine 산출물이 늘어도 이 경계는 그대로다.
