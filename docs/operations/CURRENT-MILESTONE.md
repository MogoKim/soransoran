## 1. 목적과 이번 단계의 성공

소란소란은 40대 중반부터 60대 중반 여성, 특히 50대 여성이 자기 이야기를 편하게 쓰고,
사람 같은 반응을 받고, 기억되고, 다시 돌아오는 커뮤니티다.

이번 단계의 성공은 PR 수나 후보 수가 아니다. 아래 루프가 창업자의 글별 승인 없이 실제 운영에서
돈다. D3·D5·D10도 사람이 수동으로 실행하는 시험이 아니라 controller가 스스로 승격하고 예약
작업이 글·댓글·감사·READY 보충까지 완주해야 한다.

```text
원천 -> 후보 -> 자동 READY -> Persona 배정 -> 슬롯 발행 -> 60분 내 댓글
     -> 발행 후 감사 -> 장애 복구와 자동 감속/승격
```

장기 North Star는 주간 재방문 참여 실사용자다. 다만 **지금 P0는 아니다.**
서비스의 글, 댓글, 감사와 무인 실행이 먼저 정상화된 뒤 측정을 연결한다.

물량과 생동감은 둘 다 합격해야 한다. 목표 수를 자동으로 채워도 원문의 참여 동력을 지워
모든 글을 반복적인 일반론으로 만들거나, 안전한 논쟁거리를 광범위하게 버리거나, Persona들이
같은 말투로 말하면 이 단계는 실패다. 잔잔한 원문을 잔잔하게 살리는 것은 실패가 아니다.

## 2. 제품 원칙

- 잔잔한 원문은 잔잔해도 된다. 논쟁, 가십, 관계, 돈, 건강, 일상 불만이 원문의 참여 동력이면
  그 이유를 지우지 않는다. 반대로 원문에 없는 갈등을 억지로 만들지 않는다.
- 주제를 막지 않고 위해를 막는다. 개인정보, 실제 회원 원문 노출, 명예훼손성 단정, 괴롭힘,
  혐오 선동, 확정적 의료 지시, 실질 복제는 계속 차단한다.
- Persona 카드의 고정 생활사와 말투 근거는 지킨다. `피함`, `침묵`, `noGo`를 광범위한
  주제 검열로 사용하지 않는다.
- `지금`, `오늘`은 결함이 아니다. 실제로 신선할 때 빨리 내보내고, 늦어졌을 때만 보류한다.
- 별도 SEO 정보형 레인을 만들지 않는다. 검색 노출은 유용한 공개 대화의 결과다.
- Persona, 봇, 운영자 활동을 실사용자 성과로 세지 않는다.
- 같은 제목·도입·길이·마무리·질문 패턴을 양산하지 않는다. Persona 간 생활사·관점·말투 차이가
  실제 공개 글과 댓글에서 보여야 한다.

## 4. 병렬 P0 - 셋을 직렬로 기다리지 않는다

### P0-A. 무인 글 루프

완료 조건:

1. 창업자 판정을 반영한 품질 계약이 실제 hard defect를 막고, 논쟁적이지만 좋은 글은 통과시킨다.
2. 새 계약의 연속 표본이 한 번의 인증된 bootstrap 검토를 통과한다.
3. 자동 READY 도장 -> 슬롯 발행 -> Queue/Post/ActivityLog -> 독립 감사까지 실제 운영에서 1회 돈다.
4. 결함이 있으면 다음 회차가 닫히고, 시스템 실패는 재시도 후 복구된다.
5. 중복, 상한 초과, 미정산 비용은 0이다.

### P0-B. 무인 반응 루프

완료 조건:

1. 새 공개 글에 60분 안에 Persona 댓글 1건이 실제로 달린다.
2. bootstrap 단계에서는 글당 1건부터 시작하고 하루 cap을 지킨다.
3. 실사용자 댓글 3건 이상인 글에는 Persona가 끼어들지 않는다.
4. 초기 단계에서 Persona끼리 답글을 만들지 않는다.
5. organic 단계의 Persona 댓글 비율 30% 상한은 실제 댓글이 생긴 뒤 적용한다.
6. 중복 댓글, 자기 글 댓글, 생활사·말투 충돌은 0이다.

### P0-C. 무인 운영 루프

완료 조건:

1. 노트북 덮개, 절전, 세션 종료에 기대지 않는 실행 주체가 있다.
2. supply, publish, comment, audit job의 최근 성공과 실패 이유를 한 화면에서 읽는다.
3. 단계 writer가 재고·품질·비용·오류에 따라 승격 또는 감속한다.
4. 실패한 한 경로만 격리하고 다른 수집·공급·감사는 계속 돈다.
5. rollback 명령과 이전 runtime SHA가 항상 확인된다.

### P0-D. 콘텐츠 생동감과 Persona 용량

완료 조건:

1. Founder gold의 좋은 논쟁·연예·관계·돈·건강·일상 불만 글은 주제나 거친 말투만으로 막히지 않는다.
2. 최근 HOLD·DROP에서 안전한 논쟁 소재의 false positive를 별도로 계측하고 회귀를 0으로 만든다.
3. 수집·선택이 조회수·댓글·댓글 증가 속도·신선도를 사용하고, 각 원천의 실제 참여 동력을 기록한다.
4. 공개 글이 원천의 논쟁·공감·궁금증·시의성·생활 효용·웃음을 보존하며 일반론으로 평탄화되지 않는다.
5. 잔잔한 원문에 억지 논쟁을 넣지 않고, 남녀 갈등 원문의 구체적 쟁점도 성별 일반론으로 왜곡하지 않는다.
6. 다음 단계 목표 이상의 **계약 유효 Persona**가 있다. 이름만 다른 계정은 세지 않는다.
7. 연령·생활 단계·가족·일·돌봄·경제·지역·관점·말투의 부족 축을 측정해 Persona를 보강한다.
8. 글 작성 cadence와 댓글 cadence를 함께 적용해도 다음 날 목표량을 다시 낼 수 있다.

- 근거 없이 이름만 다른 Persona를 대량 생성하기: 금지한다. 반대로 측정된 부족 축을 채우는
  계약 유효 Persona 확장은 지금 P0-D이며 늦추지 않는다.
- 별도 SEO 대량 콘텐츠: 금지한다.
- 광범위한 UI 개편과 무관한 리팩터링: 현재 P0를 끝낸 뒤다.

## 7. 마스터 운영 규칙

1. **운영 결과가 완료 단위다.** helper, PR, CI, 배포된 dormant 코드는 완료가 아니다.
2. **한 agent만 쓴다.** 다른 세션과 같은 파일을 동시에 수정하지 않는다.
3. **독립 작업은 병렬이다.** 관측 회차를 기다리는 동안 댓글·호스트·scheduler 작업을 멈추지 않는다.
4. **새 게이트는 예외다.** 운영 반례와 실제 위해가 없으면 새 차단 규칙을 만들지 않는다.
5. **실패 범위를 격리한다.** 한 후보나 한 runner 실패로 전체 프로젝트를 대기시키지 않는다.
6. **창업자 수동 작업은 0이 기본이다.** 예산, 비밀값, 비가역 정책 같은 진짜 결정만 요청한다.
7. **비용은 cap이지 목표가 아니다.** 필요한 검증을 가장 작은 유료 회차로 실행한다.
8. **보고는 같은 순서다.** 현재 판정 -> 고객 영향 -> 운영 증거 -> 남은 blocker -> 다음 실행 하나.
9. **완료 이름을 정확히 쓴다.** code PASS, deployed PASS, operating PASS를 절대 합치지 않는다.
10. **정본을 즉시 갱신한다.** 창업자 결정이 바뀌면 이 문서와 전역 canon을 같은 작업에서 고친다.
11. **red merge는 배포하지 않는다.** 필수 check 실패는 통합 트리에서 고친 뒤 한 번만 배포한다.
12. **다음 canary를 늦추지 않는다.** 한 단계 운영 PASS와 다음 단계 계약 green이 동시에 확인되면
    controller가 다음 운영 가능일에 바로 자동 승격 시험한다.
13. **수동 성공은 규모 성공이 아니다.** 사람이 실행한 공급·발행·댓글·stage override는 진단으로만
    기록하고 D3/D5/D10 PASS로 세지 않는다.

## 8. 창업자 개입 경계

창업자에게 요청할 수 있는 것은 새 예산, credential, 법적·브랜드 정책, 비가역 운영 전환뿐이다.
글별 승인, 반복 파일 업로드, 정기 명령 실행, 로그 확인은 운영 시스템의 실패이며 기본 업무로 만들지 않는다.

## 9. 단계별 수치

이 문서는 현재 분기 목표의 단일 실행 정본이다. 최종 규모 목표는 공개 글 **100건/day**,
글당 Persona 댓글 **1~5건**이다. 계산식과 전체 단계 수치는 코드가 정본이고,
아래 명령이 현재값을 만든다.

| 단계 | 14일 READY 재고 목표 |
|---|---:|
| d3 | **42** |
| d5 | **70** |
| d10 | **140** |

재고 100·300·700은 성장 마일스톤이지 d3 진입을 막는 별도 규제가 아니다.
위 표가 코드와 달라지면 문서를 유지하려고 검사를 고치지 말고 코드 정본에서 다시 생성한다.

```bash
npm run d100:readiness
npm run persona:comment-health
```

공개량은 D3 -> D5 -> D10 -> D20 -> D30 -> D50 -> D100으로 확대한다.
발행량은 North Star가 아니라 살아 있는 커뮤니티를 만들기 위한 수단이다.

## 10. 정본·코드 충돌 장부

충돌은 문장으로 덮지 않고 구현 작업으로 닫는다.

| ID | 충돌 | 최신 판정 | 닫는 조건 |
|---|---|---|---|
| C1 | Master의 옛 d1·runner 미등록·M0~M5 상태가 현재처럼 읽힘 | Master는 기술 지도·역사 증거 | 문서 위계 검사 green, 옛 절에 역사 스냅샷 표시 |
| C2 | Micro Seed 헌법의 글별 Founder 승인·internal·hard cap 10 | 현재 자동 READY·공개 D100에 폐기 | 헌법 적용 경계 표시, 자동 운영 회귀 검사 유지 |
| C3 | 코드의 고정 7/14/21일 관측이 다음 자동 canary를 막음 | canary PASS와 지속 안정성 증거 분리 | controller가 green preflight 다음 운영일에 자동 시험 |
| C4 | 공인·연예 소재를 상세 전 일괄 제외 | 안전한 화제성 소재 과차단 | 필터 보정 + founder gold/recent HOLD·DROP false positive 0 |

파일은 병렬로 진행한다. 한 트랙의 운영 관측 대기가 다른 트랙의 구현을 멈추지 않는다.
