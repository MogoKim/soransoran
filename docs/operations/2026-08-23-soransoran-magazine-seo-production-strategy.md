## 1. 한 줄 판정

> **매거진은 SEO 블로그가 아니라 커뮤니티 성장 엔진이다.**

글을 몇 편 냈는지는 성과가 아니다. 성과는 **그 글을 읽고 들어온 사람이 소란소란에
자기 이야기를 남겼는가**다.

우나어는 3,000페이지를 만들고도 88~90%가 노출 0이었고, 매거진은 **전부 0클릭**이었다.
페이지 수를 목표로 삼은 것이 실패의 시작이다. 소란소란은 그 지표를 쓰지 않는다.

## 2. 목적과 North Star

```
검색 유입        롱테일 질문 정확매칭으로 1페이지 진입
   ↓
매거진 공감      "나만 이런가"를 받아주는 글
   ↓
커뮤니티 전환    글 끝 CTA 로 게시판으로 넘긴다
   ↓
글 · 댓글        자기 이야기를 남긴다          ← 여기가 목적지
   ↓
재방문           다시 온다
```

### North Star

> **4050/5060 여성이 소란소란에서 자기 이야기를 남긴 횟수**

글 수도, 방문자 수도, 색인 수도 아니다. **남긴 이야기의 수**다.
매거진이 월 10만 유입을 만들어도 전원이 읽고 나가면 North Star 는 0이다.

### 보조 지표

| 지표 | 무엇을 보는가 |
|---|---|
| 매거진 → 커뮤니티 클릭 | 전환이 실제로 일어나는가 |
| 회원 원본 글 수 | 목적지가 살아 있는가 |
| 댓글 수 | 이야기가 오가는가 |
| 7일 재방문 | 한 번 오고 마는가 |

⚠️ **페이지 수·색인 수를 지표로 삼지 않는다.** 우나어가 3,000페이지로 실패한 지점이다.

## 3. 운영 원칙 8개

**원칙 1 — 제작과 공개를 분리한다.**
만드는 날과 공개하는 날은 다르다. 3~5건을 몰아서 만들고, 하루 1건씩 공개한다.
6-E-7 에서 3건이 한 번에 공개된 것은 이 분리가 시스템에 없었기 때문이다.

**원칙 2 — 창업자는 매일 검수하지 않는다.**
매일 승인을 받는 구조는 365일을 못 간다. 창업자는 **주간 리포트와 예외만** 본다(§10).

**원칙 3 — LOW/MEDIUM 은 자동 QA PASS 시 자동 공개한다.**
기계가 판정할 수 있는 것을 사람이 반복해서 볼 이유가 없다.

**원칙 4 — HIGH 는 자동 공개하지 않는다.**
병원·증상 감별·약·치료·검사, 금전 손해 직결 주제는 `BLOCKED` 로 두고 사람이 연다.

**원칙 5 — 미래 글은 어디에도 노출하지 않는다.**
`publishAt` 이 오지 않은 글은 목록·상세·sitemap·관련글·시리즈 UI 전부에서 숨긴다(§6).

**원칙 6 — 창업자 PC 가 꺼져도 예약된 글은 공개된다.**
생산은 로컬 PC 에 의존하지만 **공개는 의존하지 않는다.** 이 분리가 없으면 하루 쉬면 끊긴다.

**원칙 7 — Search Console/Naver 제출 게이트를 유지한다.**
매거진 글만 늘어도 게이트는 열리지 않는다(§8).

**원칙 8 — 주제는 큐가 아니라 캘린더로 운영한다.**
계절·공휴일·생활 이벤트를 4050/5060 여성의 검색과 감정으로 변환한다(§7).

## 4. 시간 정책

| | 시각(KST) | 무엇을 하는가 | 의존 |
|---|---|---|---|
| **생성** | **01:00** | 로컬 브라우저로 ChatGPT 원고·이미지 제작 → draft 저장 | 창업자 PC 켜짐 |
| **공개** | **10:30** | `publishAt` 이 지난 글이 공개된다 | **PC 무관** |

**01:00 은 생산 시간이지 공개 시간이 아니다.**
창업자 PC 가 켜져 있는 시간대에 로컬 Playwright·ChatGPT 작업을 몰아서 한다.
이 시각에 만들어진 글은 곧바로 나가지 않고 **예약 대기열에 들어간다.**

**10:30 을 공개 기본값으로 두는 이유**

```
✅ 4050/5060 여성이 오전에 휴대폰을 보는 시간대
✅ 문제가 생기면 그날 안에 대응할 수 있는 시간
✅ 새벽 공개보다 자연스러운 발행 리듬
```

⚠️ **발행 시간이 검색 순위를 직접 올리는 마법은 아니다.**
사용자 반응·발행 리듬·운영 대응성을 고려한 **기본값**일 뿐이다.
근거 없이 "몇 시에 올리면 SEO 에 좋다"고 주장하지 않는다.

## 5. 예약 재고 정책

**재고 = 오늘 이후 `SCHEDULED` 상태로 남아 있는 글의 일수.**

| 재고 | 그날 생산량 |
|---|---|
| **14일 이상** | 생산하지 않는다 |
| **7~13일** | **3건** 생산 |
| **0~6일** | **5건** 생산 |

```
목표  14일
최소   7일   ← 이 아래로 내려가면 생산량을 올린다
최대  21일   ← 이 위로는 쌓지 않는다 (계절 주제가 어긋난다)
```

**최대 21일을 두는 이유**: 재고가 너무 많으면 계절·공휴일 주제가 시기를 놓친다.
9월 초에 만든 추석 글이 10월에 나가면 의미가 없다.

### 재고는 스크립트가 센다 (7-A-4)

```bash
node scripts/magazine-inventory.mjs          # 사람이 읽는 출력
node scripts/magazine-inventory.mjs --json   # producer 가 읽는 출력
```

**01:00 local producer 는 이 결과를 보고 생산 수를 정한다.** 스스로 판단하지 않는다.

```
inventoryDays  가장 늦은 예약까지 남은 일수 (KST 기준)
produceCount   위 표대로 계산된 오늘 생산량
nextPublishAt  다음 공개 예정 시각
warnings       21일 초과 · 3일 이하일 때
```

읽기 전용이다 — 파일을 쓰지 않고 네트워크도 쓰지 않는다.

### PC 가 꺼진 날

```
생산   실패한다 (그날은 새 draft 가 없다)
공개   계속된다 (예약분이 publishAt 기준으로 나간다)
```

**재고가 0이 되면 그날은 신규 공개가 없다.** 기존 글은 그대로 있고, 다음 실행 때 보충한다.
빈 글이나 미완성 글을 내보내지 않는다 — 공백이 저품질보다 낫다.

## 6. publishAt / status 공개 엔진

### 6.1 런타임 필드는 둘뿐이다 (7-A-2 확정)

| 필드 | 값 | 없으면 |
|---|---|---|
| `status` | `DRAFT` / `SCHEDULED` / `PUBLISHED` / `BLOCKED` | `PUBLISHED` 로 본다 |
| `publishAt` | ISO 8601 with offset — `2026-08-25T10:30:00+09:00` | `publishedAt` 을 KST 10:30 으로 해석 |

**둘 다 선택 필드다.** 그래서 이미 공개된 글은 한 글자도 고치지 않는다.

**`qaStatus` 와 `riskLevel` 은 런타임 필드로 두지 않는다.**

```
QA        발행 전 절차다. scripts/magazine-qa.mjs 가 실행 시점에 판정한다
riskLevel 제작·검수 단계의 값이다. topic queue 에 있고 articles.ts 에는 없다
HIGH 차단 검수 단계에서 하고, 런타임에서 막아야 하면 status: 'BLOCKED' 로 표현한다
```

⚠️ **런타임에 `qaStatus` 를 두면 두 개의 진실이 생긴다.**
스크립트가 판정한 결과와 파일에 적힌 값이 어긋나는 순간 어느 쪽이 맞는지 알 수 없다.
QA FAIL 인 글은 애초에 `articles.ts` 에 넣지 않는 것이 게이트다.

### 6.2 공개 조건 — 전부 만족해야 보인다

```
status !== 'DRAFT' 이고 status !== 'BLOCKED'
publishAt <= now        (publishAt 이 없으면 publishedAt 의 KST 10:30)
```

### 6.3 숨김 조건 — 하나라도 걸리면 숨긴다

```
publishAt 이 미래
status === 'BLOCKED'
status === 'DRAFT'
```

발행 전 게이트(아래)를 통과하지 못한 글은 **애초에 `articles.ts` 에 들어오지 않는다.**

```
자동 QA FAIL
hero 가 REQUIRED 인데 없음
riskLevel HIGH 인데 창업자 승인 없음
```

### 6.4 공개 판정 드리프트 감지 (7-A-4)

공개 판정 규칙이 **두 곳에 산다.**

```
src/lib/magazine.ts              런타임 (Next.js 가 실행)
scripts/lib/magazine-gate.mjs    스크립트 (QA · 재고 계산기가 실행)
```

스크립트가 TS 를 실행하지 못해 import 할 수 없어서다.
두 구현이 조용히 갈라지면 **QA 가 "공개"라고 본 글이 런타임에서는 숨겨지거나 그 반대**가 된다.
아무 에러도 나지 않고 아무도 모른다. 자동화가 하루 여러 번 이 판정을 쓰므로 치명적이다.

**`assertGateInSync()` 가 `magazine.ts` 를 텍스트로 읽어 대조한다.**
주석이 아니라 실제 코드 문자열·상수·조건을 본다.

```
KST 기본 공개 시각이 'T10:30:00+09:00' 인가
DRAFT · BLOCKED 검사가 있고 false 를 돌려주는가
publishAt 이 없을 때 publishedAt + KST 시각을 쓰는가
공개 조건이 resolvePublishAt(article) <= now 인가
관문이 isPublicMagazineArticle 로 filter 하는가
```

어긋나면 **QA FAIL** 이다. `--published` · `--scheduled` · 전체 실행 어디서든 검사한다.
⚠️ **판정 규칙을 고칠 때는 양쪽을 같이 고친다.** 한쪽만 고치면 QA 가 막는다.

### 6.5 적용 위치 — 다섯 곳 전부

```
/magazine 목록
/magazine/[slug] 상세      ← 미래 글은 404
sitemap                     ← 공개 글만
관련글 (같은 cluster)
시리즈 UI (이전/다음/목차)
```

⚠️ **한 곳이라도 빠지면 사고다.** 목록에서 숨겼는데 sitemap 에 남으면
검색엔진이 404 를 크롤하고, 관련글에 남으면 사용자가 404 를 밟는다.

**구현(7-A-2)은 이것을 관문 하나로 강제한다.**
`src/lib/magazine.ts` 의 `getAllMagazineArticles()` 가 유일한 입구이고,
`getMagazineArticleBySlug` · `getSeriesArticles` 도 `MAGAZINE_ARTICLES` 를 직접 읽지 않고
이 관문을 거친다. 상세 페이지는 관문이 `undefined` 를 주면 기존 `notFound()` 가 404 를 낸다.

⚠️ **`/magazine` 은 `force-dynamic` 이어야 한다.**
지금은 `HeaderAuth` 의 `auth()` 부작용 때문에 우연히 동적이지만,
인증 구조가 바뀌면 정적이 되어 **예약 공개가 아무 에러 없이 멈춘다.**
그 우연에 기대지 않도록 지시자를 명시해 뒀다.

## 7. 마케팅 캘린더 전략

**topic queue 를 topic calendar 로 고도화한다.**
단순 목록이 아니라 "언제 무엇이 검색되는가"를 담는다.

### 7.1 콘텐츠 유형 비율

| 유형 | 비율 | 성격 |
|---|---|---|
| **Evergreen** | **60%** | 언제 검색해도 유효한 질문. 검색 유입의 기반 |
| **계절·캘린더형** | **25%** | 특정 시기에 수요가 몰리는 주제 |
| **커뮤니티 대화형** | **15%** | 게시판에 실제로 올라온 질문에서 뽑는다 |

### 7.2 콘텐츠 축 비율

| 축 | 비율 |
|---|---|
| 갱년기·건강 | **35%** |
| 수면·마음 | **20%** |
| 가족·관계 | **20%** |
| 돈·일 | **15%** |
| 일상·뷰티·관리 | **10%** |

건강 일색이면 ① YMYL 리스크가 사이트 전체로 번지고 ② 40대 중반 사용자가
"나는 아직"이라며 이탈하며 ③ 같은 주제 반복이 중복 신호가 된다.

### 7.3 월별 주요 시즌

| 월 | 시즌 | 주제 방향 |
|---|---|---|
| 1월 | 새해 | 건강 계획 · 돈 계획 |
| 2월 | 설 명절 | 명절 노동 · 가족 스트레스 |
| 3월 | 환절기 | 피부 · 무기력 |
| 4월 | 봄 | 걷기 · 알레르기 |
| 5월 | 가족의 달 | 어버이날 · 자녀 · 돌봄 |
| 6월 | 초여름 | 더위 · 안면홍조 |
| 7월 | 장마 | 무기력 · 불면 |
| 8월 | 폭염 | 열감 · 휴가 피로 |
| 9월 | 추석 | 명절 노동 · 가족 관계 |
| 10월 | 가을 | 건강검진 |
| 11월 | 연말 준비 | 국민연금 · 퇴직 · 돈 |
| 12월 | 송년 | 외로움 · 한 해 정리 |

### 7.4 계절형 발행 시점

> **이벤트 2~4주 전에 발행한다.**

검색은 이벤트 당일이 아니라 **준비하는 기간**에 일어난다.
추석 글을 추석 당일에 내면 이미 늦었다. 색인되고 순위가 잡히는 시간도 필요하다.

## 8. 소란소란식 주제 변환법

**정보 주제를 커뮤니티 대화 주제로 바꾼다.**
"무엇을 알려줄까"가 아니라 **"무엇을 털어놓고 싶을까"**로 뒤집는다.

| 시즌/이벤트 | ❌ 정보 블로그식 | ✅ 소란소란식 |
|---|---|---|
| 폭염 | 여름철 갱년기 관리법 | **더운 밤에 잠이 안 오는 게 갱년기 때문일까요** |
| 추석 | 명절 스트레스 해소법 | **가족 만나고 오면 왜 며칠씩 기운이 빠질까요** |
| 건강검진 | 건강검진 항목 총정리 | **50대 여성이 건강검진 전에 놓치기 쉬운 질문** |
| 어버이날 | 어버이날 선물 추천 | **가족은 챙기는데 나는 왜 아무도 안 챙겨줄까요** |

### 변환 규칙

```
1. 독자가 실제로 검색창에 칠 문장으로 쓴다
2. "관리법" "총정리" "추천" 같은 정보 블로그 어미를 쓰지 않는다
3. 감정이 먼저 오고 정보가 뒤에 온다
4. 답이 아니라 질문으로 끝나도 된다 — 그게 댓글을 부른다
```

## 9. SEO 안전 원칙

색인 규칙의 정본은 [SEO 색인 정책](./2026-08-23-soransoran-seo-index-policy.md)이다.
여기서는 **매거진 예약 공개와 맞물리는 부분만** 다시 적는다.

```
sitemap        공개 글만 (미래 publishAt · BLOCKED · HIGH · QA FAIL 제외)
미래 글 상세    404
canonical      자기 경로 (/magazine/{slug})
robots         매거진 상세에 지정 없음 = index (전역 정책)
```

### Search Console / Naver 제출 게이트 — 4개 AND

| # | 조건 | 현재(2026-08-24) |
|---|---|---|
| A | sitemap 글 상세 URL **20건 이상** | 8건 (회원 3 + 매거진 5) |
| B | **회원 원본 글 10건 이상** | 3건 |
| C | 최근 14일 내 회원 글 3건 이상 | 미확인 |
| D | robots·canonical·sitemap·vercel.app 감사 PASS | 미실시 |

> ⚠️ **매거진 글만 늘어도 게이트는 열리지 않는다.**
> 매거진은 조건 A 만 채우고 **조건 B 는 채우지 못한다.**
> 매거진 20건 + 회원 글 3건 상태로 제출하면 "편집팀 블로그"로 인식된다.
> 매거진은 커뮤니티로 보내는 **통로**이고, 통로만 색인되고 목적지가 비어 있으면
> 유입이 그대로 이탈한다. North Star 가 오르지 않는다.

## 11. 운영 리포트

### 11.1 계기판 (7-E-lite-A)

```bash
node scripts/magazine-dashboard.mjs          # 사람이 읽는 5줄 요약
```

### 11.2 매일 보는 5줄 — 이 순서를 바꾸지 않는다

```
1. 재고 n일 · 오늘 생산 n건 · 다음 공개 YYYY-MM-DD
2. 매거진 공개 n건 · 예약 n건 · 차단 n건

4. 회원 원본 글 n/10 · 최근 14일 n/3 · sitemap detail n/20

```

**3번이 있어야 1·2번이 의미를 갖는다.**
3번 없이 1·2번만 보면 그건 성장 계기판이 아니라 "글 수 대시보드"다.

### 11.3 매주 확인하는 질문

```

```

⚠️ **경고 신호 — 매거진 +10건인데 North Star 변화 0**
그때는 **글을 더 쓰지 않는다.** 생산을 멈추고 CTA·주제·전환을 본다.
글을 더 쓰는 것으로 해결하려 하면 우나어의 3,000페이지가 된다.

## 13. 제작 파이프라인

### 13.1 역할 분리 (정본: 매거진 전략 §3.0)

| 주체 | 하는 일 | 하지 않는 일 |
|---|---|---|
| **원고를 쓰지 않는 Claude 세션** | 주제 해석 · 검색 의도 · 구조 · 위험 문장 후보 · 리스크 분석 · ChatGPT 지시서 | **최종 원고를 쓰지 않는다** |
| **ChatGPT 채팅** | **최종 원고** · 톤 정리 · AI티 제거 · hero 이미지 | 주제를 정하지 않는다 |
| **Claude Code** | 파일화 · 자동 QA · 검증 · 검수 패킷 · 발행 준비 | **원고를 쓰지 않는다** |
| **창업자** | 월간 캘린더 승인 · 예외 판단 · HIGH 검수 | — |

**②(분석)와 ③(원고)을 다른 도구에 두는 것이 핵심이다.**
같은 도구가 원고도 쓰고 위험 문장도 뽑으면 위험하다고 판단한 문장은 애초에 안 썼을 것이므로,
검수 자료가 자기 검열의 결과물이 된다.

### 13.2 흐름

| # | 단계 | 주체 | 산출물 |
|---|---|---|---|
| 1 | 캘린더에서 오늘 항목 확인 | Claude Code | topic calendar |
| 2 | brief.md · review.ts 파일화 | Claude Code | `drafts/magazine/{slug}/` |
| 3 | ChatGPT 탭에 brief 투입 | MCP Playwright | — |
| 4 | 응답 완료 대기 | MCP Playwright | — |
| 5 | **원고를 blob download 로 회수** | MCP Playwright | `.playwright-mcp/{slug}.md` |
| 6 | 마크다운 → `article-draft.ts` | `magazine-md-to-draft.mjs` | draft |
| 7 | hero 이미지 생성·회수 | MCP Playwright | `public/magazine/{slug}/hero.webp` |
| 8 | riskSentences ↔ 원고 대조 | `magazine-packet.mjs` | — |
| 9 | 자동 QA | `magazine-qa.mjs` | PASS/FAIL |
| 10 | **예약 등록** (`SCHEDULED` + `publishAt`) | Claude Code | — |
| 11 | 10:30 자동 공개 | 공개 엔진 | — |

**5번이 설계의 핵심이다.** 원고를 Claude Code 의 컨텍스트로 읽어와 다시 타이핑하면
오탈자 교정·문장 다듬기가 끼어들 여지가 열린다. blob download 로 파일이 직행하면
**Claude Code 가 원고를 읽지 않고도 제자리에 놓인다.**

**10번이 지나면 `drafts/{slug}/` 는 제작 당시의 사본이다.** 정본은
`src/content/magazine/articles.ts` 다. 정본을 나중에 고쳐도 draft 사본은
**자동으로 따라가지 않는다.**

🔴 **이미 발행·예약된 slug 의 draft 를 보고 품질을 판정하지 않는다.**
사본에는 등록 시점의 내용이 그대로 남아 있어 정본과 갈라질 수 있다.
실제로 갈라진 적이 있다.

```
health-insurance-after-retire   정본에서 medical 플래그를 뺐다   draft 사본에는 medical: true 가 남았다
less-sleep-with-age             정본 callout 에 진료 주체를 넣었다   draft 사본에는 옛 문장이 남았다
```

`magazine-qa.mjs` 가 `freshDrafts` 필터로 **이미 `articles.ts` 에 있는 slug 의 draft 를
검사에서 빼는 이유가 이것이다.** 두 번 검사하면 정본과 사본 중 어느 쪽이 맞는지
알 수 없게 된다. 대신 `draft "..." 는 이미 발행됐다 — articles.ts 가 정본이다` 로 알린다.

⚠️ **사본 동기화나 삭제는 별도 정책 변경이다. 지금 기준에서는 하지 않는다.**
`article-draft.ts` 를 가진 draft 23건이 전부 이미 발행된 상태이므로 2건 청소가
아니라 23건 전체에 적용될 결정이고, 지우면 `magazine-batch-qa.mjs --all` 의
회귀 검사 대상이 사라진다. 운영 영향은 없다 — QA FAIL 0 이고 `magazine-register.mjs`
가 `이미 articles.ts 에 있다` 로 재등록을 막는다.

### 13.3 playwright 를 npm 에 설치하지 않는다 (6-H-2 확정)

MCP Playwright 로 Claude Code 가 대화 턴에서 브라우저를 조작한다.

| | npm 설치 | **MCP (채택)** |
|---|---|---|
| 새 의존성 | playwright + 브라우저 바이너리 | **0** |
| 세션 | `storageState` 파일 저장 필요 | **창업자 Chrome 세션 그대로** |
| CI 유출 | package.json 에 있으면 CI 도 설치 가능 | **구조적으로 불가** |
| 검증 | 미검증 | **6-H-0.1 · 6-H-1 · 6-H-2-2 에서 성공** |

`storageState` 를 파일로 떨어뜨리지 않는 것도 이 선택의 이득이다 —
credentials·secret 을 코드·repo 에 두지 않는다가 자동으로 지켜진다.

### 13.4 실패 시 동작 (우나어 교훈)

| 실패 | 동작 |
|---|---|
| ChatGPT/Claude 미로그인 | **즉시 중단.** 무한 대기 금지 |
| 응답 타임아웃 | **중단. 재시도 금지** |
| riskSentences 원고 대조 실패 | 파일화까지만 하고 중단 |
| 이미지 생성 실패 | draft 를 이미지 없이 남긴다. 임시·외부 URL 로 채우지 않는다 |
| 이미지 나이 부적합 | 1회 재생성 · 2회 실패 시 창업자 판단 |
| 자동 QA FAIL | **패킷을 만들지 않는다** |
| 어느 단계든 실패 | **다음 단계로 진행하지 않는다.** 그날 발행하지 않아도 된다 |

### 13.5 기술 안전장치

```
🚫 Claude 세션이 최종 원고 작성      — 원고는 ChatGPT (§13.1)
🚫 Claude Code 가 원고 작성          — 받은 것을 형식화·검증만
🚫 자동 공개 (HIGH · QA FAIL)        — §6 공개 조건 미충족분
🚫 자동 commit                       — 사람이 diff 를 본 뒤에만
🚫 자동 push                         — 창업자 승인 후
🚫 자동 Search Console/Naver 제출    — 게이트 미달 (§9)
🚫 서버 · CI · 크론에서 브라우저 실행
✅ draft-only                        — 자동화가 쓸 수 있는 경로는 drafts/ 뿐
✅ 실패 시 보류                       — 로그인·이미지·QA 실패는 전부 중단
```

**LOW/MEDIUM 자동 공개는 "무검수 발행"이 아니다.**
자동 QA 18항목을 통과하고, 위험 문장이 원고와 대조되고, 캘린더가 사람 승인을 받은 뒤의 공개다.

### 13.6 producer 의 두 레인 — HIGH 는 초안까지 만든다

§13.5 가 막는 것은 **자동 공개**이지 초안 생성이 아니다. 매거진 전략 §5.1 도
HIGH 를 "만들지 않는다"가 아니라 **"창업자가 본문 전문을 10~15분 읽는다"** 로 정의했다.

그런데 `magazine-producer-plan.mjs` 는 한동안 `autoEligible=false` 인 항목을
선정 이전에 걸러냈고, HIGH 는 전부 `autoEligible=false` 였다. 결과는 이랬다.

```
HIGH → 초안 없음 → 검수할 원고 없음 → 큐가 그 자리에서 멈춤
```

큐 앞자리(day 10 · 18 · 22)가 HIGH 라 뒤 항목까지 함께 밀렸다.
**등급 정책이 아니라 파이프라인이 만든 병목이다.** 그래서 레인을 둘로 나눈다.

| 레인 | 대상 | 하루 상한 | 어디까지 자동인가 |
|---|---|---|---|
| **auto** | LOW · MEDIUM 이면서 `autoEligible=true` | `produceCount` (재고에 따라 0·3·5) | 초안 → QA → **등록·공개까지** |
| **review** | `riskLevel: HIGH` (`autoEligible` 무관) | `reviewCount` = 1 (재고가 목표 이상이면 0) | **지금은 초안까지.** 등록은 창업자 승인 뒤 — **최종 목표는 고강도 자동 검수 PASS 시 자동 등록**(§13.7) |

**auto 레인을 먼저 채우고 review 레인을 뒤에 붙인다.** 순서를 바꾸면 day 번호가 앞선
HIGH 가 `produceCount` 와 시리즈 슬롯을 선점해 LOW·MEDIUM 이 밀린다 —
병목이 사라지는 게 아니라 옆으로 옮겨간다.

**HIGH 하루 1건**인 이유는 검수 시간이다. 전문 검수가 10~15분이라 2건이면 30분이고,
밀리기 시작하면 창업자가 전문을 읽지 않게 된다. 그 순간 HIGH 등급은 이름만 남는다.

⚠️ **이 상한은 사람이 읽는 동안만 유효한 값이다.** 자동 고강도 검수가 붙으면
검수 시간이 상한을 정하지 않으므로 `reviewCount` 는 다시 계산해야 한다(§13.7).

**멈추는 자리는 등록이다.** `magazine-register.mjs` 의 `AUTO_RISK = {LOW, MEDIUM}` 이
HIGH 를 `BLOCKED` 로 돌려보낸다. 이 차단은 producer 쪽에서 풀 수 없다.

```
riskLevel=HIGH — 창업자 검수 대상
autoEligible=false — 민감 주제
```

🔴 **다만 HIGH 를 막는 곳은 여기 하나가 아니다.** M-AUTO-1 감사에서 최소 세 곳이 확인됐다.

```
① scripts/lib/magazine-brief-policy.mjs   G5   HIGH 는 auto-brief HOLD
② scripts/magazine-batch-qa.mjs           ①    AUTO_RISK = {LOW, MEDIUM}
③ scripts/magazine-register.mjs                AUTO_RISK = {LOW, MEDIUM}
   (+ scripts/magazine-packet.mjs 도 HIGH 를 검수 사유로 올린다)
```

**한 곳만 열면 앞 단계에서 다시 막힌다.** M-AUTO-4 는 세 곳을 함께 다뤄야 한다 —
`register` 만 여는 설계는 성립하지 않는다.

**`autoEligible=false` 이면서 HIGH 가 아닌 항목은 예전처럼 제외한다.**
그쪽(`clinic-or-wait` · `menopause-supplements-talk`)은 초안이 없어서 막힌 게 아니라
주제를 다룰지 자체를 사람이 정해야 하는 자리다.

작업 패키지에는 표지가 남는다 — `run.json` 의 `needsFullReview: true`,
`brief.todo.md` · `review.todo.md` 머리의 **"🔴 현재 임시 수동 검수 게이트"** 블록,
리포트 선정 줄의 `🔴 현재 임시 수동 검수 게이트 (자동 등록 대기)`.

🔴 **이 표지는 "영구히 사람이 읽는다"는 뜻이 아니다.** 자동 고강도 검수 게이트가
완성되기 전까지 그 자리를 사람이 대신 서 있다는 뜻이다. 최종 목표와 남은 구현은 §13.7 이다.

### 13.7 자동화 목표 상태 — 지금은 어디고 최종은 어디인가

§13.6 의 "HIGH 는 초안까지"는 **최종 상태가 아니라 중간 다리다.**
이 절이 없으면 임시 게이트가 영구 운영처럼 굳는다.

#### 자동화 목표 (서비스 North Star 에 종속된다)

⚠️ **먼저 — 이것은 §2 의 North Star 를 대체하지 않는다.**
서비스 North Star 는 여전히 **"4050/5060 여성이 소란소란에서 자기 이야기를 남긴 횟수"** 다.
검색 유입·색인 수는 지표가 아니다(§2). 우나어가 3,000페이지로 실패한 지점이다.

그 위에서 매거진 자동화가 가진 목표는 이것이다.

> **매거진은 SEO 유입 엔진이다.**
> 검색엔진에 "4050 여성 커뮤니티 · 갱년기 · 생활 · 건강 · 돈 · 관계" 정체성을
> **끊기지 않고** 전달하고, 들어온 사람을 홈·게시판·가입·글쓰기·공감·댓글로 넘긴다.
> 최종 운영은 **완전 자동화**다.
> 창업자는 **매일의 검수자가 아니라 기준을 정하는 사람**이다.

**"끊기지 않고"가 핵심이다.** 사람이 매일 검수해야 도는 파이프라인은 창업자가 바쁜 주에
멈춘다. 멈추면 검색엔진에 보내는 신호도 끊긴다. **사람을 게이트에 세워 두는 것 자체가
North Star 의 리스크다** — 유입이 끊기면 커뮤니티로 넘길 사람도 없다.

동시에 **속도가 목적이 아니다.** 자동화의 목적은 발행량이 아니라 **끊기지 않는 것**이다.
원칙 6(하루 2건보다 하루 1건 품질)은 자동화 이후에도 그대로다.

#### 자동화 11단계 — 지금 어디까지 왔나

| # | 단계 | 지금 | 최종 |
|---|---|---|---|
| 1 | Topic selection | ✅ 자동 (`topic-queue` + producer 2레인) | 유지. 큐는 사람이 만든다(원칙: AI 가 주제를 정하지 않는다) |
| 2 | Brief generation | 🟡 반자동 (`*.todo.md` 골격 → 세션이 채움) | 자동 |
| 3 | Draft generation | 🟡 반자동 (ChatGPT) | 자동 |
| 4 | Safety QA | 🟡 부분 (`magazine-qa.mjs` — 문자열·구조만) | **의미 판정까지** |
| 5 | SEO QA | 🟡 부분 (description·h2·중복 제목) | 검색 의도 충족·중복 주제까지 |
| 6 | Brand/tone QA | 🔴 없음 | 자동 |
| 7 | Image generation/selection | 🔴 수동 | 자동 생성 + 나이 적합 판정 |
| 8 | Register / schedule | 🟡 LOW·MEDIUM 자동 · **HIGH 차단** | 등급별 PASS 시 자동 |
| 9 | Publish / sitemap | ✅ 자동 (`publishAt` + `isPublicMagazineArticle`) | 유지 |
| 10 | Performance monitoring | 🔴 없음 | Search Console · GA · 가입 전환 |
| 11 | Feedback loop | 🔴 없음 | 성과가 큐·brief 로 되돌아온다 |

**막힌 자리는 8 이고, 8 을 막고 있는 것은 4·5·6 이다.** 등급 정책이 아니다.

#### 위험도별 최종 목표

| 등급 | 자동 검수 | PASS 하면 | 지금과의 차이 |
|---|---|---|---|
| **LOW** | 기본 QA | **자동 등록** | 이미 그렇다 |
| **MEDIUM** | 강화 QA | **자동 등록** | 이미 그렇다 |
| **HIGH** | **고강도 QA** | **자동 등록** | 🔴 지금은 무조건 차단 |
| — | **FAIL** | 자동 보류 | 이미 그렇다 (QA FAIL → 패킷 생성 안 함) |
| — | **UNKNOWN** | **창업자 예외 확인** | 🔴 지금은 HIGH 전체가 여기 있다 |

**판정은 셋이다. 둘이 아니다.**

```
PASS      기준을 만족한다고 기계가 말할 수 있다        → 자동 등록
FAIL      기준을 어겼다고 기계가 말할 수 있다          → 자동 보류
UNKNOWN   기계가 말할 수 없다                          → 창업자 확인
```

**UNKNOWN 이 있어야 이 구조가 안전하다.** 판정을 PASS/FAIL 둘로만 두면
"모르겠는 것"이 어느 한쪽으로 밀린다. FAIL 쪽으로 밀면 지금과 같고,
PASS 쪽으로 밀면 검수 없이 나간다. **모른다고 말할 수 있어야 한다.**

**창업자가 보는 것은 UNKNOWN 뿐이다.** 그리고 UNKNOWN 이 반복되는 유형은
기준으로 옮겨 다음부터 PASS/FAIL 로 판정되게 한다 — 이것이 창업자가
"검수자"에서 "기준을 정하는 사람"으로 옮겨가는 실제 경로다.

#### 3층이 할 수 있는 것과 못 하는 것

세 층 전부 **문자열·구조·집합**을 본다. **의미는 어느 층도 보지 않는다.**

```
할 수 있다   금지어(시니어·어르신·노인·실버) · 의료 단정 표현 목록 매칭
            description 길이 · h2 개수 · CTA 1개 · CTA 내부 경로
            외부 링크 · h1 · 허용 밖 block type · hero alt·확장자·실제 크기
            제목·description 완전 일치 중복 · slug 중복 · seriesOrder 충돌
            cluster ↔ medical 플래그 정합 · 런타임 공개 게이트 동기화
            riskSentences 5/5 원고 대조 · forbiddenPatterns 위반
            거절문 · 한국어 비율 · 잘린 응답 길이

할 수 없다   사실관계 정확성        검진 항목·세율·제도 요건이 실제로 맞는가
            배치                   위험 신호가 눈에 띄는 자리(앞쪽 h2)에 있는가
            의미                   금지어를 피해 우회한 문장이 진단으로 읽히는가
            원인 단정              "갱년기라서"로 읽히게 쓰였는가
            톤·브랜드              우리 또래 화법인가 · 1인칭 화자가 섞였는가
            검색 의도              이 원고가 그 검색어에 실제로 답하는가
            주제 중복(의미)        완전 일치 문자열만 본다. 소재가 겹치는 것은 못 본다
            이미지                 나이·상황이 맞는가
```

3개 파일 전수 grep 에서 `1인칭·화자` · `검색 의도` · `유사도` · `배치` · `톤` ·
`사실관계` 키워드가 **하나도 나오지 않는다.** 검사가 느슨한 게 아니라 **없다.**

**오른쪽이 HIGH 를 막고 있는 실체다.** 등급이 아니라 **검사 능력의 공백**이다.

#### 실측 사례 — sleep-habit-two-weeks

> ⚠️ 이 절의 이전 판에는 "QA FAIL 0 · WARN 0 으로 통과했는데도 반려됐다"고 적혀 있었다.
> **사실이 아니다.** `article-draft.ts` 가 없어 `magazine-qa.mjs` 를 실행조차 하지 못한
> 상태에서 "통과"로 적은 것이다. M-AUTO-1 에서 QA 규칙을 원고에 적용해 다시 측정했다.

| QA 가 잡은 것 | 사람이 반려한 이유 |
|---|---|
| **FAIL** `cluster "sleep" 는 medical: true 가 필요하다` | 1인칭 화자 (`제가`·`해봤습니다` 24회) |
| **WARN** description 80자 — 권장 밖 | 제목에 검색 의도 없음 |
| **WARN** 본문 1199자 — 하한 1200 미달 | sleep 시리즈 기존 4편과 소재 중복 |

**교집합 0 건이다.** QA 가 잡은 셋은 전부 **구조**(플래그·길이)이고,
사람이 반려한 셋은 전부 **편집·의미·브랜드**다.

**"자동 QA 가 통과시켰다"가 문제가 아니라, 자동 QA 가 애초에 그 축을 보지 않는다는 것이
문제다.** 금지어 목록을 늘려도 이 셋은 잡히지 않는다.

다만 넷 중 셋은 LLM 없이 잡을 수 있다 — 1인칭 빈도, 제목 ↔ brief 검색어 어절 대조,
같은 cluster 안 n-gram 유사도. 이것이 M-AUTO-2 의 1순위다.

#### D4 실측 — "앞쪽 h2 배치" 는 코퍼스와 반대였다

M-AUTO-1 설계 초안은 **"위험 신호는 앞쪽 h2 에 있어야 한다"** 였다. **틀렸다.**

등록 25건에서 진료 권고 문장이 몇 번째 h2 구간에 있는지 쟀다.

```
위치비(권고가 든 h2 순번 / 전체 h2)
  0.2  ██                 1건
  0.4  ████               2건
  0.6  ████████████████   8건   ← 중앙값이자 최빈값
  0.8  ████               2건
  1.0  ██████████         5건
```

**대부분 뒤쪽 절반에 있다.** "앞쪽 절반" 을 임계로 걸면 18건 중 15건이 걸린다.

§4.4 도 배치를 이렇게만 규정한다 — **"증상을 설명한 직후"** 이지 "앞쪽" 이 아니다.
증상 설명이 2~3번째 h2 니까 권고가 0.6 에 오는 것이 정상이다.

**두 가지를 섞은 것이 원인이다.**

| 유형 | 성격 | 적절한 위치 | 코퍼스 |
|---|---|---|---|
| **일반 진료 권고** | "오래가면 병원에서 확인해 보세요" | 증상 설명 직후 (0.4~1.0) | 18건 |
| **응급 위험 신호** | 흉통 · 호흡곤란 · 실신 · 마비 | **앞쪽** — 이탈 전에 읽혀야 한다 | **0건** |

응급 위험 신호를 다루는 글이 코퍼스에 **하나도 없다**. `palpitations-menopause` ·
`dizziness-menopause` 가 아직 나오지 않았기 때문이다. **baseline 이 없어 임계를
실측으로 정할 수 없다.**

|---|---|---|---|---|
| **D4-A** | `medical: true` | 진료 주체 + 권고 동사가 **한 문장 안**에 | **FAIL** | 🟢 구현 |
| **D4-B** | 응급 위험 신호 글 | 위험 신호 목록이 앞쪽 h2 에 | — | 🔴 **보류** |

**D4-A 는 처음에 WARN 이었다가 FAIL 로 승격했다.**

처음 넣을 때 등록 19건 중 2건이 걸렸다. 둘 다 이미 나간 글이라 FAIL 로 두면
발행분이 QA 실패 상태가 된다. 그래서 WARN 으로 두고 **먼저 두 건을 정리했다.**

```
health-insurance-after-retire   오탐    건보료 글인데 medical: true 가 과했다
                                        본문 1,467자에 의료 어휘 0회 · 행정 어휘 82회
                                        money-work 3건 중 혼자만 true 였다  →  플래그 제거
less-sleep-with-age             진짜    "시간과 상관없이 확인이 필요합니다" 만 있고
                                누락    확인 주체가 없었다. 혼자 확인하라는 뜻으로도 읽힌다
                                        sleep-series 4편 중 이 글만 빠져 있었다  →  callout 에 주체를 넣었다
```

정리 후 `medical: true` 18건 전부 이 문장을 갖췄고, **회귀 없이 승격했다.**

⚠️ **순서가 중요하다.** 게이트를 먼저 올리고 글을 고치면 그동안 발행분이 FAIL 로 남는다.
**오탐과 진짜 누락을 먼저 가려 정리한 뒤 올린다.** 오탐을 남긴 채 올리면
"QA 가 또 틀렸다" 가 쌓여 게이트를 아무도 믿지 않게 된다.

**FAIL 로 올리면 무엇이 달라지나**

| | WARN | **FAIL** |
|---|---|---|
| QA 출력 | 경고 | **실패** |
| L3 자동 승인 관문 | 통과 | **BLOCKED** (조건 ③ `magazine-qa FAIL 0`) |
| 검수 패킷 생성 | 됨 | **안 됨** (§13.5 `자동 QA FAIL → 패킷을 만들지 않는다`) |

`medical: true` 인데 본문에 진료 권고가 없는 글은 **자동 등록 경로에서 완전히 막힌다.**
§4.4 는 이 문장을 "둔다" 고 하지 "두면 좋다" 고 하지 않는다 —
**병원으로 가야 할 사람을 집에 머물게 하는 것**이 이 검사가 막는 일이다.

**주체와 동사는 같은 문장 안에 있어야 한다.** 글 전체에 "병원" 과 "확인" 이 흩어져 있는
것은 권고가 아니다 — "병원에 갈 정도는 아닙니다" 와 "혼자 확인해 보세요" 가 따로 있는
글도 통과해버린다.

**D4-B 를 보류하는 이유** — 코퍼스 사례 0건이다. **데이터 없이 임계를 지어내지 않는다.**
D3 를 폐기한 것과 같은 이유다. 대상 글 초안이 나온 뒤 실제 원고를 보고 규칙을 쓴다.
그때까지 HIGH 차단 3곳(G5 · batch-qa · register)이 두 글을 막고 있어 안전하다.
**M-AUTO-4 에서 "증상 감별" 유형을 가장 나중으로 둔 것이 이 때문이다.**

#### LLM judge 의 경계

**원칙 3 은 그대로다 — 서비스 런타임에 AI API 를 두지 않는다.**
소란소란이 요청을 처리하는 경로에는 LLM 호출이 없다. 이 선은 움직이지 않는다.

**출판 전 자동 검수에는 LLM judge 를 쓴다.** 제작 파이프라인은 이미 ChatGPT 로 원고를
받고 있고, 같은 자리에서 검수만 사람이 해야 할 이유가 없다. 위 "할 수 없다" 중
의미·톤·검색 의도 축은 문자열 규칙으로 닫히지 않는다 — 금지어 목록을 늘리면
우회 표현이 늘어날 뿐이다.

```
✅ 허용   로컬 스크립트 · 출판 전 · 원고를 판정하는 용도
🚫 금지   서비스 런타임 · 요청 처리 경로 · 사용자에게 보이는 응답 생성
🚫 금지   LLM 이 원고를 쓰는 것 (§13.1 역할 분리 — 판정과 작성은 다른 자리다)
```

**LLM judge 의 출력은 PASS / FAIL / UNKNOWN 셋이다.** 둘로 만들지 않는다.

| 출력 | 뜻 | 처리 |
|---|---|---|
| PASS | 기준을 만족한다고 판정했다 | 다른 게이트를 통과하면 자동 등록 |
| FAIL | 기준을 어겼다고 판정했다 | 자동 보류 |
| **UNKNOWN** | **판정하지 못했다** | **자동 등록 금지. 창업자 확인** |

🔴 **UNKNOWN 은 자동 등록되지 않는다.** 판정 실패·신뢰도 미달·응답 파싱 실패는
전부 UNKNOWN 이고, "검사하지 않았다"도 UNKNOWN 이다 — **PASS 로 흘려보내지 않는다.**

지금 구조에 이미 그 구멍이 있다. `magazine-batch-qa.mjs` 는 큐에 항목이 없으면
`자동 승인 조건 ①riskLevel ②autoEligible 은 검사하지 않았다` 로 넘어간다.
M-AUTO-3 에서 **미검사 → UNKNOWN** 으로 매핑해야 한다.

**LLM judge 는 사람을 대체하지 안전 기준을 낮추지 않는다.** 사람이 보던 것을
기계가 보게 되는 것이지, 보지 않아도 되는 것이 되는 게 아니다.

#### M-AUTO-2 실측 — 규칙 셋 중 하나는 폐기했다

| 규칙 | 예상 | 실측 | 결과 |

| **D1** 1인칭 화자 | 가능 | 등록분 화자 **0회** · 반려분 4회 · 경험 종결어미 **1.57‰ vs 22.84‰** | 🟢 **채택** |
| **D2** 제목 ↔ brief 검색어 | 가능 | **분리 실패** — 반려분 0.67 이 정상 글 9건보다 높다 | 🟡 **재설계 후 채택** |
| **D3** n-gram 유사도 | 가능 | **분리 실패** — 어떤 임계로도 안 잡힌다 | 🔴 **폐기** |

**D2 원안이 실패한 이유** — brief 의 "검색 의도" 목록은 **제목을 이미 아는 사람이 쓴다.**
자기 참조라 검증력이 없다. 실데이터(Search Console)가 들어오는 M-AUTO-6 이전에는
이 대조를 쓰지 않는다.

대신 **제목 말미 형태**를 본다. 등록 25건이 질문형 10 · 상황형 15 로 전부 갈리고,
반려된 `잠자리 습관을 바꿔 본 2주` 만 어느 쪽도 아니다 — **완전 분리다.**

**D3 를 폐기한 이유** — 소재가 겹쳐도 문장을 새로 쓰면 유사도가 오르지 않는다.

```

반려된 sleep-habit vs sleep 4편   문자 최대 0.046 · 명사 최대 0.101
정상 draft 2건                    명사 0.141 · 0.127   ← 반려분보다 높다
```

**잘 쓴 재탕이 가장 안 잡힌다.** 억지 임계값을 만들면 오탐만 늘고 게이트 신뢰를 잃는다.
소재 중복(N10)은 **J6 — LLM judge 대상**으로 옮긴다.

**임계는 코퍼스 실측에서 나왔다.** 추측한 값이 아니다.

```
D1  FAIL  화자 대명사 ≥ 3회  또는  경험 종결어미 ≥ 5.0‰
    WARN  화자 대명사 ≥ 1회  또는  경험 종결어미 ≥ 2.0‰
D2  FAIL  제목 말미가 질문형(~나요·~까요·~가요)·상황형(~때·~이유·~것) 어느 쪽도 아님
```

⚠️ **D1 경험 종결어미 WARN 여유가 0.43‰ 로 얇다** (등록분 최대 1.57‰).
3인칭 회상이 잦은 글이 들어오면 WARN 이 뜰 수 있다 — FAIL 이 아니라 발행은 막지 않는다.

⚠️ **오탐 3종을 걸러내야 성립한다.** 단순 빈도로는 등록분에서 47건이 걸렸다.

```
나는 → "땀이 나는" · "달아오르는"          동사 활용. 패턴에서 제외
내가 → "그때의 내가" · "내가 받을 금액"    화자가 아니라 독자를 가리킨다. 제외
저는 → "저는 저녁만 되면 그래요"           따옴표 안 남의 말. 인용문 제거 후 판정
```

**이 검사는 등록을 열지 않는다.** `AUTO_RISK` · brief `G5` · batch-qa 의 HIGH 차단은
그대로다. **검사를 늘리는 것과 게이트를 여는 것은 다른 일이다.**

### 13.8 clinic 유형 규칙 — D5 · D7 · D8 (2026-08-30)

`which-clinic-menopause` 를 첫 HIGH 샘플로 쓰기 전에, clinic 글이 **처방으로 읽히는 것**을
기계로 막는다. 큐가 이 주제에 건 금지선이 근거다 —
**"과 선택은 정보 제공까지만. 가야 한다 / 안 가도 된다를 판단해 주지 않는다."**

#### 구현한 셋

| ID | 판정 | 무엇을 막는가 | 코퍼스 29건 |

등록분 6건이 **진료과를 말하면서도 선을 지킨 실문장**이다.

전부 **관찰형**("경우가 많습니다"·"이야기됩니다") 또는 **허용형**("받아도 됩니다"·"편이 좋습니다")이다.
과를 말하는 것 자체는 정보다. 막아야 하는 것은 **독자 대신 고르는 문장**이다.
`memory-worry-menopause` 는 이미 which-clinic 과 거의 같은 상황을 다뤘고 통과한다 —
**따라 쓸 템플릿이 코퍼스에 이미 있다.**

#### 실측으로 잡은 함정 셋

`비용` 이라는 낱말도 넣지 않는다 — "비용이 부담된다고 이야기합니다" 가 걸린다.

#### 검증은 합성 샘플로 한다 (`scripts/magazine-editorial-check.mjs`)

등록 29건에 **양성 사례가 하나도 없다.** 코퍼스가 선을 지키고 있다는 뜻이지만,
그래서 규칙이 죽어도 아무도 모른다. 양성은 손으로 쓰고 **음성은 등록분 실문장을 그대로** 쓴다 —
지어낸 문장으로 오탐을 확인하면 실제 원고에서 나는 오탐을 놓친다.

### 13.9 창업자 승인 HIGH 등록 — `--founder-approved` (2026-08-30)

`which-clinic-menopause` 가 원고·hero·QA·전문 검수를 모두 끝냈는데 **등록할 방법이 없었다.**
`riskLevel=HIGH` · `autoEligible=false` 라 register 가 막고, 그 차단을 푸는 옵션이 없었다.

#### 감사 결과 — 기존 경로는 없다

```
magazine-register.mjs:141-142   AUTO_RISK(LOW·MEDIUM) 밖이면 BLOCKED. CLI 플래그는
                                --slug · --publish-at · --write · --json 뿐
magazine-batch-qa.mjs:157-158   같은 두 조건으로 block
magazine-packet.mjs             "승인하지 않는다" 명시 — 자료를 모아 보여줄 뿐
ReviewData 타입                  승인 필드 0개
```

`MagazineStatus.BLOCKED` 가 *"사람이 열기 전까지 언제나 숨김 (HIGH 등급 대기 포함)"* 으로
정의돼 있어 흔적은 있으나, **register 가 BLOCKED 레코드를 만들어 주지 않아 죽은 경로**다.
게다가 우리가 원하는 것은 숨김이 아니라 공개 예약이라 목적에도 맞지 않는다.

> ⚠️ 감사 중 발견한 비대칭 — 두 스크립트 모두 이 검사가 `if (queueItem)` 안에 있다.
> **큐에서 빠지면 batch-qa 는 HIGH 도 READY 를 낸다.** register 는 큐에 없으면 BLOCKED 라
> 실제 등록은 막히지만, **"batch-qa READY" 를 등록 가능 신호로 읽으면 안 된다.**

#### 세 안을 놓고 C 를 골랐다

**A안 — 수동 등록 커밋** 🟡
register 가 하는 일(`publishedAt` 주입 · `status: 'SCHEDULED'` · 들여쓰기 · ANCHOR 삽입 ·
큐 블록 제거)을 손으로 재현해야 한다. **`publishedAt` 을 손으로 채워 register 가 BLOCKED 를
낸 사고가 실제로 있었다.** 슬롯·hero·publishWindow·중복 검사도 통째로 건너뛴다. 1회성이라
남은 HIGH 8건에서 같은 판단을 매번 다시 해야 한다.

**B안 — `review.ts` 에 `founderApproved`** 🔴 **반대**
`review.ts` 는 **Claude Code 가 쓰는 파일**이다. 승인 플래그를 여기 두면 검수 데이터를
적으면서 같은 파일에 승인까지 적을 수 있다. 템플릿이 이미 이 위험을 경고한다 —
*"작성 권한까지 가지면 '쓴 사람이 곧 커밋하는 사람'이 되어 원칙 4가 무너진다."*
**승인을 파일에 두면 자동화가 조용히 켤 자리가 된다.** 게이트로서 가장 약한 형태다.

**C안 — register 에 명시 옵션** ✅ **채택**

```
node scripts/magazine-register.mjs --slug <slug> --publish-at <날짜> --founder-approved --write
```

```
① 승인이 파일이 아니라 명령에 있다     B안의 자기 승인 경로가 생기지 않는다
② 나머지 검사가 전부 살아 있다        hero·슬롯·publishWindow·중복·큐 존재·publishedAt 주입
③ --write 와 같은 명시적 opt-in       이 repo 가 이미 쓰는 패턴이다
④ AUTO_RISK 를 넓히지 않는다          자동 경로는 LOW/MEDIUM 그대로
⑤ 재사용 가능                        남은 HIGH 8건에 같은 절차가 적용된다
```

**완화하는 것은 두 줄뿐이다** — `riskLevel` 과 `autoEligible`. 그 외에는 아무것도 건드리지 않는다.

#### M-AUTO-4 와의 층 구분 — 충돌하지 않는다

```
M-AUTO-4      유형 단위 · 자동 등록 · 기계가 판정   ← 아직 열지 않았다
--founder-approved   글 단위 · 수동 등록 · 사람이 판정   ← 지금 여는 것
```

§13.7 이 말하는 과도기 — *"창업자가 보는 것은 UNKNOWN 뿐"* — 에서 **그 UNKNOWN 을
통과시킬 손잡이가 없어서 생긴 공백**을 메운다. 자동화를 앞당기는 것이 아니라,
사람이 이미 내린 판단을 반영할 자리를 만드는 것이다.

#### 이 옵션이 열지 않는 것

```
🚫 AUTO_RISK            LOW·MEDIUM 그대로. 상수 변경 0줄
🚫 brief G5             HIGH 는 여전히 HOLD
🚫 batch-qa HIGH 차단    변경 0줄
🚫 register 자동 경로     플래그 없으면 지금과 100% 동일
```

⚠️ **한계를 적어 둔다.** `.claude/settings.json` 훅은 register 를 막지 않는다. 이 플래그는
**규칙으로만 통제**되며 세션이 임의로 붙이지 않는다는 전제에 의존한다. A안(파일 직접 수정)도
같은 수준이고, B안보다 눈에 띈다는 점만 낫다. **출력·JSON 에 `approvalMode: 'manual-high'` 와
문구를 남기는 이유가 이것이다** — 나중에 로그만 보고도 사람이 켠 것인지 알 수 있어야 한다.

#### 이 절을 읽고 하지 말아야 할 것

```
🚫 "최종 목표가 자동화니까" 라며 지금 AUTO_RISK 를 넓히는 것
🚫 topic-queue 의 autoEligible 을 개별로 true 로 뒤집는 것
🚫 M-AUTO-3 없이 M-AUTO-4 로 건너뛰는 것
🚫 UNKNOWN 을 없애고 PASS/FAIL 둘로 만드는 것
🚫 UNKNOWN·미검사를 PASS 로 흘려보내는 것
🚫 register 의 AUTO_RISK 만 열고 G5·batch-qa 를 그대로 두는 것
🚫 LLM judge 를 서비스 런타임에 넣는 것 (원칙 3)
✅ 게이트를 여는 것은 검사 능력이 생긴 뒤다. 목표를 적었다고 능력이 생기지 않는다
```

## 14. 시리즈와 내부링크

### 14.1 혼합 리듬

```
주 5편 기준
  시리즈 2편 (같은 시리즈의 연속 회차)
  단발  3편 (독립 롱테일 질문)
```

시리즈만 하면 검색 진입면이 좁아지고, 단발만 하면 체류·회귀가 없다.
시리즈는 **5편 완결**을 기본으로 한다.

### 14.2 내부링크 구조 (우나어 L6 대응)

```
시리즈 글        ← 이전 회차 · 다음 회차 · 시리즈 목차
     ↓
같은 클러스터 단발 글 2~3개 (관련글)
     ↓
커뮤니티 게시판 (CTA)
```

**네비게이션 링크가 아니라 본문·하단의 contextual 링크**여야 한다.
우나어는 내부링크 47,124개 중 대부분이 메뉴라 SEO 신호가 되지 못했다.

### 14.3 필드 정책

| 필드 | 정책 |
|---|---|
| `seriesId` | 영문 kebab-case. 없으면 단발 글 |
| `seriesOrder` | 1부터. 같은 `seriesId` 안에서 유일 |
| previous / next | **저장하지 않는다.** `seriesId` + `seriesOrder` 로 계산 |
| related | **저장하지 않는다.** 같은 cluster 에서 계산 |

⚠️ previous/next/related 를 데이터로 저장하면 글이 늘 때마다 손으로 고쳐야 하고 반드시 어긋난다.

## 15. 글 단위 QA 와 CTA

### 15.1 자동 QA

```bash
node scripts/magazine-qa.mjs                  # 발행 글 + draft + 충돌 검사
node scripts/magazine-qa.mjs --published      # 발행 글만
node scripts/magazine-qa.mjs --draft <경로>    # 특정 draft
node scripts/magazine-qa.mjs --json           # 다른 도구가 읽는 JSON
```

FAIL 이 하나라도 있으면 **그 글은 공개하지 않는다.**
`runQa()` 가 export 돼 있어 검수 패킷 생성기가 import 해서 결과를 그대로 쓴다.

검사 항목(18): 금지어 · 의료 단정 · 약/치료 인접어 · description 길이 · h2 개수 · CTA ·
hero alt · slug 중복 · seriesOrder 충돌 · 제목/description 중복 · body h1 · 외부 링크 ·
출처 없는 통계 · 분량 · block type · medical 플래그 · hero 파일과 크기 · 캘린더 충돌

### 15.2 CTA 템플릿

```
갱년기톡 CTA
  비슷한 증상을 겪는 분들이 갱년기톡에서 이야기를 나누고 있어요.
  여러분은 어떠셨나요? → [갱년기톡 바로가기]

자유게시판 CTA
  이런 고민, 혼자만의 것이 아니에요.
  자유게시판에서 또래들의 이야기를 들어보세요. → [자유게시판 바로가기]
```

⚠️ CTA 는 **본문 흐름의 결론**이어야 한다. 광고 배너처럼 끼워 넣지 않는다.
CTA 가 North Star 로 가는 유일한 다리다.

## 16. 검색엔진 기준과 우나어 교훈

### 16.1 Google / Naver 공식 기준

| 기준 | 실무 번역 |
|---|---|
| **Helpful content** | 검색엔진용 키워드 나열이 아니라 실제 질문에 답하는 글 |
| **E-E-A-T** | 편집팀 명시 · 의료 안전 문구 · 출처 없는 수치 금지 |
| **YMYL** | 건강·돈은 더 엄격. 진단·치료·약 권유 금지 |
| **중복·유사 콘텐츠** | 같은 주제를 제목만 바꿔 반복하지 않는다 |
| **크롤 예산** | 빈 페이지·저품질 페이지를 sitemap 에 넣지 않는다 |
| **Naver 원본성** | 외부글 재작성이 원본성 신호를 무너뜨린다 |
| **Naver 대표 문서** | 무엇이 우리 원본인지 명확해야 색인된다 |

### 16.2 우나어 실패에서 버릴 것

| # | 실패 | 소란소란 대응 |
|---|---|---|
| **L1** | 볼륨 우선 — 1일 3편 × 365일 | **하루 1건 공개.** 재고가 없으면 공백을 둔다 |
| **L2** | 에세이형 제목 — 아무도 검색 안 함 | **검색 질문 그대로 제목에** |
| **L3** | 외부글 수집·재작성 | 금지 |
| **L4** | 자동 발행 파이프라인 (생성→발행이 사람 없이) | **캘린더 승인 + QA PASS + 등급 제한**을 통과한 것만 |
| **L5** | 얇은 글 3,000편 → 품질 신호 희석 | 글 수를 목표로 삼지 않음 |
| **L6** | 네비게이션 내부링크만 (47,124개) | 본문 contextual 링크 + 시리즈 (§14) |
| **L7** | 광고가 본문을 끊음 | 광고 0건 |
| **L8** | 구글 색인 API 자동 호출 | 제출 자체를 보류 (§9) |

⚠️ **L4 는 이번 고도화로 해석이 바뀌었다.** "사람이 매번 승인"에서
"사람이 캘린더와 등급을 승인하고, 기계가 그 안에서 공개"로 옮겼다.
자동화되는 것은 **공개 시점**이지 **판단**이 아니다.

### 16.3 우나어 자산에서 가져올 것

**코드를 복사하지 않는다. 판단 기준만 가져온다.**

| 자산 | 가져올 것 |
|---|---|
| `longtail-keywords.ts` | 선정 기준: 월 100~500회 · 경쟁 낮음 · 질문/비교/상황/계산/방법형 |
| `keyword-research/scorer.ts` | 의도 분류 · 민감도 등급 · 민감 키워드 제목 순화 |
| `series-plan.ts` | `seriesId` · 회차 순서 개념. 48시리즈 × 5편 규모는 버린다 |
| `prompt.ts` | "시니어·어르신" 금지 · 표 금지 · H1 금지 · 연도 하드코딩 금지 |
| 진단서 Phase 1 | 키워드-퍼스트 전환 · 필라 + 본문 contextual 링크 |
| `chatgpt-scraper.ts` | **미로그인이면 즉시 중단** — 무한 대기 금지 |
| `local-image-generator.ts` | **실패 시 임시 URL 저장 금지, null 반환** |

## 17. 현재 주제 큐 현황

> **정본은 `drafts/magazine/topic-queue.ts`** 다. 이 절은 현황 요약이다.
> 7-C 에서 topic calendar v2 로 고도화하면서 이 절도 함께 갱신한다.

```
공개된 글      5건
  menopause-basic  #1 when-does-menopause-start   · #2 menopause-waking-up-at-3am
                   #3 hot-flash-how-long
  sleep-series     #1 less-sleep-with-age
  단발             pension-early-vs-normal

큐 잔여        27건 (day 4~30)
다음 order     menopause-basic #5 · sleep-series #2 · body-change #1
```

### 큐 운영 규칙

```
발행하면 큐에서 그 항목을 지우고 PUBLISHED_SLUGS 로 옮긴다
남겨 두면 자동 QA 가 "queue slug 가 이미 발행됐다"로 FAIL 을 낸다 (중복 발행 방지)
day 번호는 재번호하지 않는다 — 큐 안에서만 쓰는 고유번호다
```

⚠️ 현재 큐는 **7.1 유형 비율(Evergreen 60 / 계절 25 / 대화형 15)이 반영되기 전** 버전이다.
계절 항목이 거의 없다. 7-C 에서 캘린더로 재구성한다.

| **7-A** | **publishAt / status 예약 공개 구조** | 제작·공개 분리가 없으면 나머지가 전부 수동으로 남는다 |
